# 开发调试内容热更新

状态：verified

设计与实施计划：

- [设计](design.md)
- [阶段计划](phase-plan.md)

## 用户目标

在 Editor 启动的开发调试 App 保持运行时，修改剧情或资源并重新构建后，让尚未影响当前游戏状态的内容直接生效；对于已经影响当前状态的修改，依据影响位置提示返回当前 Group 开头或重新开始游戏应用。

用户明确的行为规则：

- 调试存档/运行状态记录当前 Group、最近 Group 交接处的初始状态，以及本次游戏已经经过的 Group。
- 未经过的 Group，以及当前 Group 中当前 Entry 之后的 Entry 发生变化时，直接热更新。
- 当前 Group 中当前 Entry 或它之前的 Entry 发生变化时，Editor Toast 和调试面板提示返回当前 Group 开头应用；客户端复用现有 Group 入口缓存和调试返回能力。
- 已经经过的 Group 发生变化时，提示重新开始游戏应用；用户需要开始新游戏建立新进度。
- 首期暂不考虑 Group 环路及同一 Group 的重复经过。

## 问题

当前外部调试会话在作者内容变化后会把源码映射标记为过期，需要重新启动测试才能采用新内容。现有 Runtime 已有 Group 自然入口缓存、回到 Group 入口、作者 Entry 定位、执行代次及旧请求失效机制，但尚无把新版编译内容、资源和源码映射发布到正在运行的调试 App，并按已执行范围决定直接应用、返回或重开的完整流程。

## 范围

- Editor 保存并构建候选调试内容，只有完整构建和校验成功后才允许发布。
- 比较当前运行构建与完整候选构建的 Group 和稳定作者 Entry，结合当前 Group、当前 Entry 边界和已经经过的 Group，计算修改影响等级。
- 未经过的 Group 使用新版内容；当前 Group 只在尚未开始的作者 Entry 边界采用新版内容。
- 当前 Entry 视为已执行前缀的一部分。新增、删除、移动和参数修改均按稳定作者身份和执行边界分类，不以显示行号判断。
- 保留当前 Group 的入口缓存用于返回开头；内容换代时清除与旧内容绑定的其他定位/追帧缓存和迟到操作。
- 运行内容和作者源码映射只在命令成功后一起提交，防止部分换代。
- 已保存或原子发布的内容变化自动构建、安装和分类；Direct 自动应用并 Toast 成功，Return/Restart 立即 Toast 对应要求且调试面板持续显示待处理动作。顶部菜单和面板热更新按钮只保留为手动重试入口。多次修改由 Editor 重新分类，重新开始要求高于返回当前 Group 开头要求。
- 候选构建、传输或切换失败时继续运行完整旧版本，并报告失败原因。
- Editor UI 修改直接使用作者事务记录的 Group/Entry 范围分类；Entry 本地化文本不因保存到 I18n 文件而变成全局变化。Editor 内无 Entry 范围的 Graph、资源、settings 等变化及外部文件重载，统一要求重新开始游戏；已经持有或播放中的对象保持到正常释放。
- 构建完成后用当前作者签名校验结果；面板 Busy 串行化用户触发的构建。

## 非目标

- CLR、C# 程序代码或 Contracts/Entry schema 的运行中热替换。
- Group 环路、同一 Group 多次自然进入后的影响归属与状态迁移。
- 对已经经过的剧情自动重放、自动合并变量或迁移旧运行状态。
- 正在播放的动画、视频、音频或当前呈现对象原地无缝替换。
- 将旧存档自动迁移为与修改后的历史剧情等价的新存档。
- 面向正式玩家发行包的在线补丁下载、安装或运行中热装卸。

## 验收标准

1. 修改未经过的 Group，构建成功后无需重启 App；首次进入该 Group 执行新版内容。
2. 修改当前 Group 当前 Entry 之后的内容，当前 Entry 正常结束后执行新版后缀，不重复当前 Entry 或已执行前缀。
3. 修改当前 Entry 或当前 Group 已执行前缀，当前运行不混用新旧版本；Editor 显示“返回当前 Group 开头应用”提示，菜单操作使客户端激活最新版并复用现有入口缓存重建执行。
4. 修改已经经过的 Group，显示“重新开始游戏应用”提示；返回当前 Group 开头不能清除该要求，用户通过新游戏建立新进度。
5. 同时出现多类修改时选择最严格的影响等级；后续保存能重新计算并解除已经不再存在的要求。
6. 当前 Group 入口缓存可以跨候选内容发布保留；依赖旧内容位置或指纹的其他缓存、断点操作和异步结果不会写入新版运行。
7. 图片、音频、视频等非 Entry 内容变化要求重新开始；已经持有的资源不会被强制替换或提前释放，新 Run 读取完整候选资源。
8. 构建失败、发布取消、App 断开或连续快速保存不会产生新旧内容、源码映射或资源索引的部分组合，旧运行仍可继续。
9. 热更新后 Editor 的当前高亮、Entry 定位和断点均使用已发布版本的源码映射；旧版本命令被执行代次拒绝。
10. Contracts、模块程序集或程序代码改变时明确要求重启调试 App，不伪装成内容热更新成功。

## 约束

- 复用现有外部调试协议、执行代次、Group 入口缓存和 Debug 面板/顶部菜单能力，避免另建一套回退运行时。
- Runtime 在 Engine 构造时复制运行图并保持拓扑稳定；设计必须通过明确的内容换代边界处理新版 Group，不能依赖修改现有 Engine 借用的作者对象。
- 保留取消、清理和资源所有权保证；旧 Engine、活动 primitive、媒体后端和资源句柄需按既有生命周期收束。
- 设计优先扩展少量现有职责明确的方法和机制，先消除重复，不仅为拆文件增加新调度层。
- 额外日志、截图、测试报告和临时验证文件统一放在仓库根目录 `output/`，不提交 Git。

## 假设

- 首期执行路径不含环，因此已经经过的 Group、当前 Group 和未来 Group 可以按一次性前进路径分类。
- “当前 Entry 之后”指尚未开始执行的稳定作者 Entry；一个 Composite 作者 Entry 展开的全部 primitive 共享同一分类。
- 当前正在执行的 Entry 即使尚未自然完成，也属于已执行前缀。
- 现有最近自然入口缓存是“返回当前 Group 开头”的状态来源；热更新不会另外发明一套入口快照。
- 普通内容修改与 Contracts/程序模块修改可以在构建结果中可靠地区分。

## 开放问题

当前没有阻塞产品范围的开放问题。已确认的实现边界：

- GameSnapshot 保存按自然进入顺序排列的 Group ID；当前编译边界和活动 primitive 由 inspect 实时报告。
- 客户端始终安装完整最新候选，内部只持有当前运行与最新候选两个对象引用；不拼接新旧 Graph，也不暴露内容版本号。
- Editor 是影响分类和提示的唯一权威；客户端只校验、安装并执行明确命令。
- 无法按作者 Entry 精确归属的 Graph、资源和会话级内容，以及外部文件重载，保守要求重新开始；不从构建产物摘要反推 Editor 操作范围。
