# 音频结束策略、重复播放与资源回收

用户已授权实现本轮整理的待办，并明确将资源缓存回收纳入范围。沿用现有 audio.play/enqueue/stop/next 等原语，不新增另一套播放控制。

## 设计与验收

- `completion` 使用 `discard`（默认）或 `requeueTail`。仅自然结束触发重新入队；失败、显式停止、替换、next、scope 清理不重新入队。多首曲目遵循 FIFO 和已有容量/溢出策略。
- `loopCount` 为非负整数，默认 1，0 表示无限重复；单项重复优先于 completion。有限次数进度保存到 AudioItemState，读档从当前轮开头继续剩余轮次。旧数据省略参数仍为一次播放并丢弃。重复由 Runtime 重新发出 Start，不宣称无缝，不改变后端播放协议。
- 自动推进 ticket 在完整逻辑播放（含重复与轮播）终止时完成；无限播放需要停止/跳过才能完成等待。每轮生成新后端 identity，旧事件不能消耗新轮。
- 淡出逻辑项立即离开存档状态，但运行时保留 retiring voice；玩家音量/静音仍能控制它。后端终态清理 retiring，scope 清理强制停止；retiring 不入存档。
- 复用现有 AssetManager / AssetFileMaterializer 引用计数，不新增音频专属缓存或 LRU 层。加载中、活动与淡出声音持有独立 AssetFileLease，播放器先释放、租约后释放；最后一个使用者释放时，已有 materializer 删除文件。其他声音、视频/Gallery 的租约不受影响。
- 不实现 seek、精准恢复、无缝循环、自然结尾交叉淡化、其他 DSP 或音轨重构。

## 阶段

1. **verified**：Core/Contracts 参数、Runtime 重复/轮播与持久化；有限/无限、FIFO、失败/停止、暂停/恢复及旧代事件已通过测试。
2. **verified**：retiring voice 与后端终态；淡出期间音量、静音、scope 清理及真实 LibVLC 淡出终态已通过测试。
3. **verified**：voice 租约正确归还；并发共享、跨消费者持有、取消加载、停止/自然结束/淡出/销毁的释放已通过原生测试。用户指出已有计数层后，移除初稿的音频专属缓存方案，直接修复后端租约持有范围。

## 总结与边界

本轮修复了实际租约持有范围，没有修改共享资源计数层，也没有留下音频专属缓存。循环与轮播属于 Runtime 逻辑调度，不承诺无缝；不恢复精确音频游标。当前仅验证本地 LibVLC dummy 输出及平台无关测试，未作真实设备听感验收。没有修改旧的首期总结或其他任务中的代码/构建配置。
