# 设计

## 数据与边界

宿主观察原语执行，读取执行前已读状态及解析后的文本。以 GroupId、同源稳定 ID 的紧邻编号（rawId#n → rawId#(n+1)）和本次实际执行关联播放 ticket；ReadingBoundaryId 则保护整句快照边界。条件未执行或其他原语打断会清除候选，不跨源推断。Quick/CatchUp 未真正播放时仍保留该次执行的语音资源描述，不借用旧 ticket。

GameHost 的历史 journal 保存不可变展示记录；每次执行用独立 visit，展示成功后追加。状态表只记录历史条数游标，稳定快照在当前对白之前，实际保存按其游标截取历史，从而读档重显当前句不会重复。存档正文使用平台无关、可选的 opaque Attachments 字典，只在宿主实际保存时附加，不在运行状态中累积。此为上一轮“存档附加数据”的具体接口选择；引擎忽略其内容。

执行验证补充：readingBoundaryId 前导原语到阅读原语之间不发布稳定快照，否则读档可能只重执行文本，遗漏同源音频。Engine 以领域无关的 reading preamble 标志保护整句边界。条件未执行的原语通过可选 dispatcher 通知清除宿主的待关联音频；有效推进也通过可选通知停止临时播放，包括仅补全文字的推进。

临时语音直接使用既有后端独立 voice ID 和 generation，在原 track/bus 上接受现有混音。临时播放不进入 AudioRuntime 的持久队列；有效推进、选择、开启播放模式、关闭历史及运行释放均停止，迟到事件不得影响新播放。

## 展示

共享历史覆盖层由 GamePage 拥有，三主题承载同一内容。打开取消自动/快速并锁住剧情输入，关闭保持手动。虚拟化 ListBox 每次打开 ScrollIntoView 最后一行。富文本历史即时渲染，忽略延迟指令。

已读颜色作为 typewriter 普通 runs 的可继承默认色，显式颜色保持优先。每行保留进入时 WasRead，设置变化只刷新默认 runs，不重启打字机。

## 风险与验证

重点验证：快照游标与历史前缀一致；异步展示完成不能写入旧代；同句循环与条件跳过音频；调试回放；迟到音频事件；按钮/滚轮不穿透；大量历史虚拟化；自动等待原语回归。
