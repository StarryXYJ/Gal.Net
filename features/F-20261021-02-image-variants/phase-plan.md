## P1：定义与纯解析

### 目标、前置条件与模块

把命名规则、位置语义和回退算法变为可独立验证的纯逻辑。先固定语义，再接文件系统和展示。

无前置实现依赖。涉及 Core 资源/场景的中立 DTO、纯定义构建及解析逻辑，对应 Core 测试；作者 JSON codec 的具体归属按已有依赖边界确定。

### 任务

1. 区分作者描述和运行时不可变定义；定义维度稳定 key、显示 label、位置、选项、默认变体及变体到 sprite ID 的映射。
2. 定义构建器接收已枚举的图片事实，不在 Core 访问目录。空段、重复键、跨扩展名冲突、大小写碰撞、错误默认图、显式维度不足等返回有位置的诊断。
3. dimensions 省略时生成 d1/d2 等 key；完整描述不得因重复构建或枚举顺序变化而变动。选项采用稳定顺序，label 不参与身份比较。
4. 定义完整请求与实际结果；初始化从默认图填已有维度，显式初始覆盖形成保护集合。
5. 实现原位置精确匹配、从后向前累积删除未保护维度、显式 default；返回候选链和削减维度。候选不能通过拼接压缩把第 2 维误当第 1 维。
6. 明确未知维度/未知值为输入错误，合法值缺组合才回退；空保护集合、默认图无后续维度、同值重复选择均有确定结果。

### 测试与退出条件

- 用户五张示例的完整命中、weap 削减命中和返回 smile 时保留 skirt。
- 三维时依次删第 3、第 2 维；保护第 2 维时跳过它，最终只剩第 2 维的候选不得命中第 1 维同名文件。
- 有 idle_skirt 但没有 smile_skirt 时，切换服装不会把表情自动改成 idle。
- 多维初始覆盖、未选择维度、同值重新选择、最终 default 不满足保护值仍返回明确 Default 原因。
- 扰乱图片事实输入顺序不改变定义、选项顺序和解析结果；验证定义/选择不被外部可变集合修改。

退出条件：以上行为测试通过，Core 不增加文件系统/平台依赖；更新 design.md 中的精确定义和实际名称。此阶段不注册半成品用户入口。

### 风险

删除维度容易被误写成通配符匹配；必须用反例约束。可变字典/数组若逃逸会让实例之间串状态，不能只验证单实例路径。

## P2：资源编译与发布

### 目标、前置条件与模块

同一份图集在开发项目和发行包中得到相同定义；运行时只读取资源 ID，不扫描源目录。

前置：P1 verified。涉及资源类型 catalog、Assets、文件系统适配、Editor.Shared 的项目校验/构建与 GamePackageExporter、编辑器及游戏宿主资源组合根，对应资源和编辑器共享测试。

已检查的当前接点：IAssetDecoder 接收资源源字节；PakBuilder 只将 IGameFile 序列化到归档，GamePackageExporter 收集资源后交给它。因此图集编译应在资源准备/导出层提供已编译 payload，不能把业务扫描塞入通用归档序列化器。

### 任务

1. 注册描述扩展名、metadata DTO 和运行时定义 decoder；组合根贯穿同一个冻结 catalog，保留自定义资源类型能力。
2. 建立共享作者索引编译入口：按 Assets 内目录直接子文件收集 sprite 事实，交给 P1 构建器。解析相对路径时检查实际目录边界，包括链接/重解析点，不能仅检查字符串前缀。
3. 明确本地定义获取路径：作者准备层产出与发布相同的编译定义；普通运行时 decoder 不隐式依赖项目目录遍历。不同项目、内容代次的定义不能共享过期缓存。
4. 发布保留图集资源 ID/type/path 身份，替换该类型待打包 payload 为编译定义；全部 sprite 依赖入包，拒绝缺失/错误类型引用。保持通用 PAK 格式，除非真实证据表明格式本身不足。
5. project.validate/build 与 GUI/CLI 共用诊断；空图集、缺目录、缺 metadata/default、坏 ID 等构建失败，不伪装成正常回退。
6. 定义目录/文件刷新失效机制和取消边界；查询刷新不自动补建 metadata 或写作者文件。显式导入创建 sidecar 的事务先接好，GUI 向导留 P4。
7. 资源移动/目录复制操作维护稳定 ID 和相对 folder 引用；复制生成新的资源 ID 并重编译关系。若移动/改名使 default 或维度语义失效，应在事务预检中明确处理或拒绝，禁止静默保存坏定义。

### 测试与退出条件

- 真正使用 producer 生成 PAK，再从 PakFileProvider/AssetManager 获取定义并解析；移开源目录后仍成功。
- 相同输入本地与发行定义逐项一致；所有图片仍可按 sprite ID 获取。目录枚举顺序不影响产物。
- 覆盖目录越界/链接、不同路径分隔符、重复文件主名、缺 sidecar/图片、错误资源类型、坏 default 的真实项目夹具。
- 移动、复制、撤销/重做、保存重开后关系可用；项目关闭/重开和刷新期间的旧加载不能发布到新代次。
- 普通 sprite 和自定义 catalog 的既有导出行为无回归。

退出条件：本地与 PAK 两条获取路径可用且一致，发布不需要原始图片目录，错误被 project.validate/build 拦截。同步 assets 规范中已经验证的资源行为和诊断，不提前记录运行指令。

### 风险

最大的接入风险是作者 JSON 和发行 payload 语义不同却共享错误 decoder，或普通文件改动没有使编译定义失效。必须分别验证真实本地/发行路径；不能用手工构造定义替代整条资源链。

## P3：图层指令与状态恢复

### 目标、前置条件与模块

完成独立显示与单维切换，复用现有 Layer 和 presenter，支持 CatchUp 与存读档。

前置：P2 verified。涉及 Contracts.Builtins、Primitives.Builtins、Core Layer/GameState、展示抽象及必要宿主注入；对应契约、运行时、展示与架构测试。

### 任务

1. 固定 variants.show/select 的 DTO 和 schema，接入内置契约集合、完整 ID、模块选择和执行覆盖检查。图集能力使用唯一 Layer 状态注册；核对选择部分内置模块时所需服务依赖。
2. Layer 附加可选图集状态，保存图集 ID、完整请求、保护集合和实际变体；AssetId 继续表示实际图片。明确状态复制、序列化、验证及注册版本。
3. show 加载定义后创建实例；select 校验目标和输入，解析后在状态更新中原子提交，再通知已有图片 presenter。切图保留变换、透明度、显示模式、层级与连续属性动画。
4. 普通 layer.replace 清除图集模式；hide 删除完整实例；同 handle 再 show 重置选择。静态图、颜色、视频、Flipbook 与图集互斥；检查所有重建/复制 Layer 的代码路径，避免丢状态或残留绑定。
5. 定义 acquire/释放的所有权与执行顺序；使用既有异步 primitive 协议等待定义获取，防止取消/旧加载覆盖替换后的同 handle 实例。
6. CatchUp 只更新状态；统一恢复前加载定义，按保存的保护集合重算并校验实际结果，然后由已有 Layer 恢复流程展示。坏存档/内容不一致在正式状态替换前被拒绝。

### 测试与退出条件

- 使用公开注册入口和真实 compiled primitive 执行 show/select；验证完整命中、削减、default、多实例隔离、同值重复选择和非法输入不部分提交。
- 缺目标/非图集目标 select 明确失败；hide/re-show/replace/视频来源切换后无图集幽灵状态。
- 带变换及活动连续属性动画时切图，后续采样仍作用于同一实例；验证图片句柄替换与释放。
- 在 Reduced 和 Default 状态存档，读档后继续切换；Normal/CatchUp 最终请求与实际图一致。
- 故障注入覆盖定义加载失败、取消、快速连续切换、隐藏/替换和会话关闭；旧任务不得覆盖新实例。
- 在可用 Avalonia 测试环境验证 presenter 接收实际 sprite 并保留布局；无原生渲染能力时明确保留人工项。

退出条件：无需编辑器专属 UI 即可运行包含图集的内容；完整状态和恢复链经过验证，原普通 Layer/Flipbook 行为无回归。同步 entry-types/runtime 与必要状态规范，记录实际快照兼容决定。

### 风险

现有 ReplaceLayer 重建 Layer、状态恢复异步预检和注册依赖容易产生遗漏。不得用单独平行状态表或 CatchUp 专用算法掩盖这些问题。

## P4：编辑器创作与诊断

实施拆分：P4a 先验证任务 3 的基础资源/对象选择、任务 4 的场景分析与引用身份，以及这些入口的资源代次和历史保护；P4b 完成目录创建、配置/预览、初始选择与维度/值联动、影响诊断及其完整保存流程。P4a 通过不代表 P4 整体通过，原任务和整体退出条件继续约束 P4b。拆分不改变匹配语义或首版范围。

### 目标、前置条件与模块

作者可完成创建、配置、预览和剧情切换，不必手写完整图片资源 ID；所有修改进入既有历史与保存体系。

前置：P3 verified。涉及 Editor.Abstraction/Shared、Editor 资源 inspector/选择器、共享 SchemaForm、场景查询和四语本地化，对应共享与实际挂载 UI 测试。

### 任务

1. 资源面板支持创建图集：选择目录、自动识别维度、配置标签和显式 default；创建与图片导入 sidecar 使用已有事务，不把扫描回调当写入口。
2. 属性区支持目录/维度/default 配置、扫描诊断和预览；候选来自全图集。展示请求、实际图、原因及削减链，不自动隐藏缺组合的值。
3. show 的资源和初始选择字段、select 的对象/维度/值字段提供联动编辑器；手动编辑仍走相同参数与业务校验。
4. 新指令接入 SceneTargetAnalysis 与 Locator：show 创建普通 Layer 能力及图集身份提示，select 更新可知资源事实但保留对象/连续属性能力，replace 清除图集身份。条件/分支无法确定定义时提供保守候选和不完整原因，不执行游戏求答案。
5. 源定义改变使属性选项、场景查询、预览和旧手势失效；保留已有未知/失效作者值供用户修正，禁止刷新自动改写历史。
6. 维度 key/顺序改动及图片改名提供影响诊断；修改应原子提交或保留原文拒绝，第一版不加入全项目隐式引用迁移。
7. 配置编辑、撤销/重做、保存、保存全部、关闭重开遵循既有内容会话；补齐四语 UI 资源，避免将算法内部术语直接作为常规操作标签。

### 测试与退出条件

- 真实挂载完成创建→配置→选值→查看回退→写 show/select 条目；选择器使用正确资源类型和维度选项。
- smile_skirt→weap→smile 预览恢复 skirt；请求和实际图不混淆。
- 单次作者修改对应单次历史；撤销/重做及保存重开保留 default、维度和选择。扫描刷新不产生 dirty。
- 条件分支中定义不唯一时不提供虚假的确定选项；Timeline 能定位新图层和已有动画属性，未知语义仍保守。
- 打开控件期间刷新/改目录/关闭项目后旧选择不能提交；检查焦点、虚拟化、资源释放和错误文本可见性。

退出条件：常规作者流程完整可用，GUI 与 CLI/build 对同一坏配置给出一致结论，相关 UI/历史/场景查询回归通过。同步编辑器规范与操作手册中的已验证行为。

### 风险

动态字段联动容易把后台刷新当用户提交；旧选项在新项目 scope 仍可见不代表有效。以会话和定义代次校验提交，不能仅靠控件当前是否打开。

## P5：集成验收与收尾

### 目标、前置条件与模块

把各阶段能力串为可交付示例，核对全部验收条件并完成文档收尾。

前置：P4 verified。涉及 Sample/项目夹具、构建验证、相关正式规范/手册及本 feature 记录；不夹带无关重构。

### 任务与验证

1. 提供最小立绘示例（用户五张命名）和三维场景夹具；素材使用可分发的现有资产或可辨识占位图，不引入未经授权外部素材。
2. 从 Editor 创建并保存项目，用 CLI validate/build 和正式导出链生成安装包；脱离作者目录运行，验证显示、回退、移动、普通动画、hide/re-show。
3. 在回退状态存读档后继续切换，快速/追赶模式最终结果一致；核对实例隔离与内容不一致诊断。
4. 跑与变更相关的 Core/Runtime/Editor.Shared/Editor/Presentation/Architecture 测试和解决方案构建、格式与文档链接检查。已通过阶段验证仅在最终集成有影响时重跑对应部分；记录既有失败和环境跳过。
5. 检查大图集选项/索引构建和快速切图的实际耗时、内存及关闭释放；基于仓库与素材记录可重复样本，不凭空设性能阈值或宣称无限规模支持。
6. 整理 summary.md、review.md，逐项映射 feature 验收；正式规范说明格式/状态/错误边界，手册说明创建与切换、命名限制和回退示例。整理已确认 lessons，不将设计猜测写为长期事实。

退出条件：所有必须验收项有证据、引入的回归已解决，剩余人工或环境限制明确列出；阶段状态如实更新，并提交最终相关变更。必要人工验证未执行时不能宣称整项功能全部 verified。
