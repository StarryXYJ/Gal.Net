# 单 Graph 资源化、剧情分包与资源覆盖设计

状态：根据 2026-10-28 用户讨论整理的实施设计，P1/P2 已验证；未实现部分仍为目标状态。范围与状态见 [feature 清单](feature.md)。

实现顺序与退出条件见 [阶段计划](phase-plan.md)。

## 1. 目标与已确认约束

1. 项目继续只有一张 Graph，Sample 自动启动该图；章节按钮传初始存档变量，由图入口条件分支选路。不新增多图管理、选图或按图隔离变量。
2. 运行时 Graph 与编译后 Group 和普通资源一样放入 PAK，使用稳定资源 ID 寻址。作者源文件与运行产物继续分离。
3. 构建先处理唯一 Graph 的全部非补丁 Group 及本体公共内容，再按名称处理剧情补丁。基础内容内部去重；每个剧情补丁只扣除本体资源，不扣除其他剧情补丁的资源。
4. 剧情补丁通过 Group 的字符串包名标记，空字符串表示本体；同名聚合。正常导出时一并生成，无独立剧情补丁面板。
5. 资源补丁独立制作、独立导出。编辑器使用资源矩阵：行是剧情使用的原资源，列是资源补丁，单元格是替换资源；不按剧情是否属于补丁筛掉行。
6. 资源补丁以寻址映射覆盖原资源；原资源与替换资源在作者项目内各自保持独立 ID。运行时统一按包内优先级排序，同优先级按 PAK 内容 SHA-256 的字典序排序，不引入语言条件或冲突选择流程。
7. 资源依赖由 metadata 类型实现接口暴露。依赖分析、包归属、物理切包和运行时覆盖分别负责，不互相代替。

非目标：多 Graph 管理、选图、跨图存档、按图隔离变量和跨图跳转/调用；任意 Graph 节点拼接协议；运行中热装卸补丁；通用远程下载系统；二进制差分；自动共享包优化；资源补丁的语言匹配、冲突选择 UI；Gallery 的补丁聚合、覆盖与扩展；在本次设计阶段修改业务代码。

## 2. 当前事实与目标差异

- `Core.Assets.AssetMeta` 描述资源 ID、路径、type ID、压缩等；`ResourceTypeRegistration` 按 type ID 注册 metadata DTO、JSON resolver 和创建工厂。
- 多个资源类型当前共用 `AssetMeta`。依赖接口落到 metadata 后，有结构化依赖的类型需要自己的 DTO，不能因为当前共用 CLR 类型就把它们视为同一种资源语义。
- `IGameFile` 已提供 metadata 和字节读取；PAK 已保存类型化 metadata JSON，依赖信息可沿现有通路进入归档。
- 图集当前由 `LocalAssetCompiler` 根据作者描述和 sprite 索引生成运行定义；sprite ID 在编译后 payload 中，现有 metadata 不提供该依赖列表。
- Graph/Group 当前属于特殊内容，由固定的 `Graph/graph.json` 和 Group 路径加载。`GameContent` 仅暴露一个 Graph；`GameRun` 接收 Graph 实例，不是全局静态 Graph 单例。
- `GraphLoader` 当前不恢复持久 Graph ID，而使用模型生成的 ID；Graph 资源化必须使用稳定资源身份，不能每次加载随机生成寻址 ID。这不要求新增图选择能力。
- `GamePackageExporter` 当前生成一个 `000-base.pak`，Graph、I18n、settings、Gallery 另行发布。
- 现有资源 provider 支持按顺序查找同 ID，但这不等于已经实现本设计的独立映射包和包完整性。
- 当前存档包含 NodeId/EntryIndex，未记录 Graph ID；项目保持单图，本期不为跨图恢复新增该字段。

以上是现状；下文均为目标设计，不写入 `docs/spec` 作为已实现事实。

## 3. 资源身份与运行内容

### 3.1 Graph / Group

新增运行时资源类型 `graph` 和 `group`，具有各自稳定的资源 ID。作者目录布局可以继续使用 Graph 目录，不要求用户先移动现有工程文件；构建适配层统一产出 `IGameFile`。新建资源的 sidecar/作者身份布局需要由实现阶段统一确定，不能让路径成为发行身份。

P2 已确定：单图使用保留 ID `galnet:graph:main`，Group ID 为 `galnet:group:<稳定节点ID>`；生成 metadata，不额外写作者 sidecar。开发编译目录经 CompiledStoryAssetProvider 适配，发行内容直接读 PAK，共用 CompiledStoryResources 的剧情 payload 生成。每个游戏内容作用域独立，因此不引入用于跨游戏合并的全局 Graph 身份。

Graph 资源保存稳定 Graph 身份、节点、边、变量声明，以及节点引用的 Group 资源 ID 和所属剧情包。Node ID 与 Group 资源 ID 分开：前者标识图中位置，后者标识被加载的正文。

Group 运行资源只保存编译后的 primitive 内容。作者 raw 不进入运行 PAK。同一 Group 的所属剧情包只有一个作者真源，唯一 Graph 编译时复制其标记作为节点描述；不在两处提供独立可编辑的包名。

项目保持唯一 Graph，不维护 Graph 列表、`defaultGraphId` 或显式选图 API。游戏清单保存该 Graph 的资源 ID，Sample 和宿主按它启动；这是加载信息，不是需要用户选择的默认值。Graph 缺失或清单非法则报错，不扫描另选一张图。

Graph 的稳定 ID 仅用于底层寻址。章节按钮不引用 Graph ID，共用带参数的新游戏命令，传不同章节变量值，唯一 Graph 的入口条件分支负责选路；不新增章节 Graph 描述对象或第二套章节别名目录。

共享宿主提供新游戏初始存档变量入口（具体类型命名在实现时确定）：在新 Run 初始化唯一 Graph 的默认值后、执行入口前，校验并应用一批显式 save 变量。标题按钮可共用一个启动命令、传不同章节参数；不通过修改旧 Run 的存档变量来传递新游戏参数。玩家解锁/通关状态仍为 player 变量；没有活动 Run 时可由玩家服务写入，不能与新游戏的 save 初始化混为一谈。读档使用存档本身的变量和游标，不再次应用新游戏参数。多次 Run 的 save 值独立，不增加按图存储层。同一 Run 内图中章节直接衔接可保留变量，从标题页新开章节默认重建 save 值；不同 Run 之间状态传递由项目显式定义。

首页替换复用现有 DI 与 View 映射：只换外观则替换 TitlePageViewModel 对应 View；换行为则用派生 VM 替换标题服务注册并映射实际 VM 类型。此能力已存在，本 feature 仅补齐新启动参数及示例，不新增 UI 编辑器。

### 3.2 最小启动目录

保留一个可在打开剧情资源前读取的轻量游戏目录/manifest，提供项目身份、唯一 Graph 的资源 ID、基础 PAK 清单、格式/构建版本及必要宿主配置入口，不包含 Graph 列表或默认/显式选图配置。无需把宿主设置全部强行改成普通资源。

Graph 与 Group 不再靠 loose `Graph/**` 路径参与发行加载。开发项目与安装内容分别适配成同一种资源访问视图。

### 3.3 共用 PAK 格式，区分包用途

三种包共用同一 PAK 二进制格式、资源表、metadata、压缩与数据校验；包头的版本化控制描述使用 `kind` 区分用途：

| kind | 内容与额外描述 | 装载规则 |
| --- | --- | --- |
| `base` | 本体资源，基础构建身份与分片标识 | 按游戏清单加载，缺少受管分片是错误 |
| `story` | 命名剧情正文及依赖，剧情包名、目标基础构建、分片清单 | 整组完整才视为已安装；整组未安装时按 Graph 描述跳过 |
| `override` | 原资源到替换资源的映射、替换载荷与依赖、优先级 | 校验后按 `(priority, pakSha256)` 应用映射 |

`kind` 是包用途，`typeId` 是每项资源类型，二者独立；一个 `story` 包可以包含 group、sprite、audio。控制描述不作为普通可覆盖资源，不能通过资源映射修改包用途、优先级或基础构建身份。未知 kind/不支持的格式版本明确拒绝，不根据文件名猜包用途，也不以旧 provider 扫描顺序替代用途校验。剧情包的完整性校验与 override 的覆盖排序分别处理。

## 4. Metadata 依赖协议

### 4.1 接口归属

允许 metadata DTO 实现依赖接口，不要求 metadata 读取文件系统、查目录或自行递归加载其他资源。以下为形状示意，最终命名可在实现时调整：

```csharp
public interface IAssetDependencies
{
    AssetDependencyInfo GetDependencies();
}

public sealed record AssetDependencyInfo(
    IReadOnlyList<AssetDependency> Direct,
    bool Complete);

public sealed record AssetDependency(
    string AssetId,
    string? ExpectedTypeId = null,
    string? RequiredStoryPackage = null);
```

- `Direct` 只含直接依赖，不能包含递归闭包；可带预期类型，便于在解码前诊断。
- `Complete=false` 表示资源存在无法完整分析的引用，不等于没有依赖；诊断另带资源/参数来源位置。
- 普通叶资源无需实现该接口。但必须在类型注册中明确声明为无依赖；未实现接口且未声明无依赖的扩展类型按未知处理，不静默判空。
- `RequiredStoryPackage` 仅用于 Graph 对可选剧情 Group 的引用。普通图片、图集、音频依赖均为必需依赖，不提供任意的“缺失忽略”。
- 接口依赖 Core 中立数据，不引入 Editor、文件系统、运行时 decoder 或呈现框架。
- 类型注册、metadata JSON resolver 和接口实例必须使用同一冻结目录；不依赖反射扫描发现接口实现，不绕过 NativeAOT 源生成约束。

### 4.2 依赖事实如何生成

作者 `.meta` 与构建/本地预览得到的有效 metadata 快照需要区分：

- 若引用本来就在 metadata 中，接口直接返回这些引用。
- 若引用来自正文，资源编译器在生成运行 payload 的同一过程中生成依赖，填入新的有效 metadata 快照。该快照进入 PAK；正常扫描/构建不自动回写作者 sidecar。
- 图集由运行定义列出的全部 sprite ID 生成依赖；Group 从 composite 展开后的指令与参数 schema 生成依赖；Graph 从编译后的节点引用生成依赖。
- 不独立扫描第二遍文件夹来猜测最终运行内容。payload 和依赖 metadata 同属一次不可变编译结果。
- 从已有 PAK 导入/验证时，已知结构化类型应能对照 payload 校验依赖，拒绝遗漏、过时或身份不一致；不把人为删除 metadata 依赖当作合法瘦包技巧。
- shader 正文自身若没有外部资源引用，不凭文本猜测依赖；指令/配置的纹理参数由拥有这些引用的 Group 或配置资源报告。

### 4.3 动态引用与递归边界

资源引用由 schema/类型契约声明，不猜 GUID 字符串、不从路径文本推断。动态拼接 ID 的自定义指令必须提供声明依赖或通过额外包含补足覆盖范围。构建报告保留不完整诊断；发行导出不能无提示忽略该问题。首版默认阻止未处置的不完整依赖，显式额外包含/声明覆盖范围后才允许发布。

闭包算法按规范化资源 ID 去重，维护 visited 防循环。Graph 的执行回环不等于资源依赖循环；通用收集器不强制整个项目必须为 DAG。具体类型如有禁止循环的解码约束，由对应类型校验。

依赖表示“发布内容应能提供”，不表示同 PAK、不要求同时加载，也不自动 acquire 所有依赖。图集加载定义不应因此一次解码整套图片。

## 5. 本体与剧情补丁的构建

### 5.1 根集合

本体根包括唯一 Graph 资源、其全部非补丁 Group，以及显式 UI/启动资源、基础 Gallery 引用和额外包含资源。所有非补丁 Group 均纳入，不用运行可达性裁剪掉作者仍保留的剧情。

剧情补丁根为同一包名的全部 Group，以及该包所需文本、人物和显式额外资源。引用分类必须覆盖这些非媒体内容，不能只拆 Group 和图片而丢失补丁文本。Gallery 保持既有基础导出路径，本期不设计按补丁拆分或新增贡献。

Graph 到补丁 Group 的边在本体遍历时只保留描述，不跨入其正文闭包；构建该剧情包时才以该 Group 为根收集正文及必需资源。禁止普通必需引用绕过这条边界依赖缺席的补丁 Group。

### 5.2 确定性算法

令 `B` 为本体闭包，`C(P)` 为剧情包 P 的闭包：

```text
本体有效资源 = B
剧情包 P 的资源 = C(P) - B
```

其他剧情包的资源不参与扣除。A/B 都使用 X、本体无 X 时，两包各自携带 X；本体有 X 时，两包均省略 X。基础资源只去重一次；每个剧情包内部各自去重。

同 ID 的重复副本必须具有相同的有效内容和 metadata；若两包携带同 ID 的不同内容，则是冲突，不能借 provider 文件名排序实现隐式资源补丁。显式资源覆盖由另一机制负责。

每个集合按稳定 ID 排序，再按配置的未压缩编译载荷大小目标切 PAK；目标是软上限，单资源超限独占一包。未压缩口径使边界可预测，输出报告另列实际压缩大小和索引开销。当前 Archive 整包内存读取语义意味着默认阈值必须结合实际内存验收，本文不预设未经测试的数值。

资源身份按 ID 去重，不将字节相同的不同 ID 合并身份。每次构建输出 ID、内容/metadata 指纹、归属、依赖和物理 PAK 的布局报告，为后续发布增量提供基线。

### 5.3 导出结果

正常游戏导出一次完成基础与全部剧情包生成，不新增剧情补丁面板：

```text
Output/
  Game.galpak
  StoryPatches/
    afterstory-000.pak
    afterstory-001.pak
    extra-ending-000.pak
```

基础 `.galpak` 不要求安装这些外部剧情包。包名是稳定机器键，空串表示本体；拒绝路径穿越、仅大小写冲突等不确定名称。编辑器可以提供已有名称候选，重命名须作为引用重构而非仅修改输出文件名。

目录导出与 galpak 导出共用相同的准备、归属和验证流程。先私有暂存、验证完整产物再发布；失败不能留下被识别为已安装的半包。

## 6. 剧情包装载与跳过

基础 Graph 保留节点和边，以及 `groupResourceId` / `storyPackage`。不为缺席正文生成同 ID 的空 Group 资源。

- `storyPackage` 为空：正文必需，缺失是内容错误。
- 非空且对应包没有安装：不读取正文，沿该 Group 的唯一正常出口继续。
- 包已安装且完整：加载正文并执行。
- 检测到该包部分文件、错误版本、哈希不匹配或缺失必需资源：明确报告不完整，不能降级成“未安装”。

允许连续跳过多个可选 Group；若跳过路径形成无执行推进的循环，须有校验/运行保护。若没有后继则按正常剧情结束处理。将来出现多出口可选节点时必须另设明确 fallback，首版不推测出口。

跨过补丁后主线所需变量必须有基础默认值；不能让基础必需人物、文本或资源依赖补丁才能成立。

每个剧情包记录 project ID、包 ID、格式版本、目标基础构建、分片列表和校验信息。描述可以嵌入 PAK 控制区；具体二进制布局在实现时版本化，不能伪装成可被剧情覆盖的普通资源。首版匹配明确基础构建，后续兼容范围必须有验证依据。不以文件名排序判断有效版本。

## 7. 独立资源补丁

### 7.1 作者面板

矩阵行来自唯一 Graph 及其全部 Group 的静态资源引用，包括剧情补丁内容；不因包是否安装隐藏作者资源。默认聚合相同原资源，保留使用位置，支持跳转到编辑器文件管理器。可展开间接依赖或手动添加动态引用资源。

新建资源补丁增加一列；格子为替换资源 ID 或空值。空值表示该列不贡献覆盖，不表示删除原资源。图集可整体替换，也可展开后替换单张 sprite。首版限制媒体/普通业务资源覆盖；不借此面板替换 Graph/Group、游戏包清单或宿主配置，剧情结构更新另立范围。

每列具有稳定 patch ID、显示名称和写入包内的整数优先级（默认 0）。资源补丁独立保存、验证和导出，不依赖执行一次完整 galpak 导出。不提供语言条件、手动冲突选择或 Gallery 贡献编辑；不混入剧情分包标记。首版每列导出一个资源补丁 PAK，剧情包的大小分片规则不自动套用到资源补丁。

### 7.2 映射与自包含

作者 A/B 各自保持独立 ID，补丁保存 `A -> B` 并携带 B 的依赖闭包。独立导出默认携带全部替换载荷和依赖，不因当前作者项目存在某资源而省略它；只有选定真实已发布基线后，才允许显式优化扣除，并记录基线要求。

运行目标须精确标识来源包及目标 ID；补丁携带的 B 和依赖不是自动全局覆盖所有同 ID 资源。仅声明的 A 映射改变全局寻址，避免夹带依赖隐式覆盖其他素材。物理查找需要包来源上下文，同 ID 在基础/补丁中的不同字节不可由模糊 provider 顺序决定。

每次逻辑引用只做一次映射：选择 A 的目标 B 后读取该物理资源，不继续把 B 当新映射源串成 C。B 内容中对 sprite 等的独立引用是新的寻址请求；必须使用一致的来源和覆盖规则。自映射/循环映射应诊断，不依赖无限重定向。

### 7.3 固定覆盖顺序

对所有启用的资源补丁，按 `(priority, pakSha256)` 升序排列，后者覆盖前者，即优先级数值较大者优先，同优先级时 hash 字典序较大者优先。hash 是最终 PAK 文件字节的 SHA-256，统一为小写十六进制并使用 ordinal 比较；在写完包后从外部计算，不把自身 hash 写回包内形成自引用。相同 hash 的重复包只装载一次；路径、文件名和目录枚举顺序不参与比较。

同一原资源出现多个映射是正常覆盖，直接按上述规则选取最终映射，不阻止装载，也不要求用户解决冲突。可在诊断中显示最终来源，无需新增冲突 UI。资源类型与图集变体键兼容性属于内容有效性检查，仍需保留。独立包可在无完整目标游戏时导出结构合法载荷，挂载时必须补做目标存在性和兼容检查。所谓资源 i18n 仅是作者用此面板制作替换素材的用途，运行时不根据语言自动选包；启用的包始终按同一规则生效。

资源补丁可以覆盖仅属于剧情补丁的资源：剧情包缺席时映射不使其自动变成已安装剧情；剧情包存在时才有相关使用请求。

### 7.4 查询、缓存与生命周期

正式 ID 查询、Acquire、原始文件查询和媒体实体化必须使用同一覆盖视图，避免画面替换而视频仍读旧资源。编辑器源文件定位继续使用作者目录视图，不因为运行覆盖而丢失 A 的位置。Gallery 的新覆盖语义另行设计，本期不扩展其行为。

一次内容会话冻结包集合与映射代次，缓存以实际资源来源/版本及目标 CLR 类型隔离。语言不是资源补丁解析或缓存的维度。首版启停资源补丁在重启或重新准备相关会话时生效，不原地修改已借用 handle；租约和媒体文件仍按原有所有权释放。

## 8. 文本、人物与 Gallery 范围

- 文本仍按 culture + key 解析，不把每行译文变成独立资源。基础与剧情包保存各自文本贡献，挂载后验证有效内容的默认语言完整性。没有安装的剧情包不要求其文本出现在本体。
- 人物按稳定 ID 合并。基础引用项不能仅存在于可选包。两个剧情包重复携带同一基础外定义时必须一致，不能成为彼此的隐式依赖。
- Gallery 由用户明确延期。本期不新增补丁条目合并、覆盖、删除、解锁迁移或 type 扩展协议；不在资源补丁面板聚合替换资源的 Gallery 标注。既有 Gallery 基础导出路径与其独有资源保留，不将本期实施扩大为 Gallery 重构。
- 原有 External 翻译来源的保留与优先级不能在迁移中丢失；包内 key 合并不等于整份文本文件覆盖。

## 9. 存档、版本与发布边界

存档继续在项目唯一 Graph 中恢复 NodeId、EntryIndex、save 变量及呈现状态；仅补充分包恢复所需的内容包/兼容信息，不增加跨图 Graph ID 或选图流程。恢复前验证正文、资源和内容版本；新游戏章节参数不参与读档，不把旧存档重定向到另一个章节入口。

本设计不解决已有 Group 中插入/重排 entry 后的 EntryIndex 迁移；稳定资源 ID 不能保证旧执行位置仍有相同语义。首版应明确拒绝不兼容构建或另行提供可验证迁移，不能跳过当前存档所需的补丁并假装正常恢复。已存在的画面状态可能引用补丁资源，也属于恢复依赖。

PAK 控制描述、Galpak 游戏目录、Graph/Group 和存档的格式变化均需显式版本化。当前安装器按旧 manifest 验证安装内容，需区分基础受管文件与额外包位置，不能把任意投放 PAK 直接视为完整升级协议。是否支持旧项目/发行包自动转换，尚未获得用户要求；实现前明确格式策略，不承诺静默兼容。

基础与所有剧情包在同一构建快照生成。后续基于已发布清单的修复更新应新增变更包或整体替换一组已验证文件，不重排旧 PAK 造成无关更新；该自动增量流程不属于首版必做范围。

## 10. 模块职责与取舍

| 层 | 责任 |
| --- | --- |
| Core | metadata 依赖接口、资源身份、Graph/Group 引用与中立包描述契约 |
| Contracts.Builtins | 内置 metadata DTO、JSON resolver、无依赖类型声明、已知参数引用契约 |
| 内容编译/Assets | 编译 payload 与有效 metadata、闭包计算、PAK 读写、来源明确的覆盖解析 |
| Editor.Shared | 本体/剧情包规划、基线、布局报告、导出准备与验证；不能仅靠 GUI 操作才能使用 |
| Storage | 目录/galpak 安装、包发现与校验、开发源适配；文件系统不进入 Core |
| GameHost | 加载唯一 Graph、冻结有效内容会话、应用新游戏初始变量、准备运行、存档兼容检查 |
| Editor GUI | Group 包名编辑、资源补丁矩阵、文件定位、导出入口与诊断 |

采用 metadata 接口的理由：延续现有 sidecar 与 PAK metadata 通道，依赖可枚举、可序列化且可校验。没有选择让 metadata 自行读文件的分析器模式，因为这会把文件系统/编译职责带入 DTO；正文产生的依赖由已有编译过程填充解决。

没有采用遍历时先遇到先归属，因为会使基础内容依赖可选包；没有自动创建共享包，因为用户明确要求 A/B 独立携带基础外共享资源；没有合并剧情与资源补丁，因为两者导出时机、缺席语义和作者操作不同。

## 11. 验收重点

1. 唯一 Graph 能按清单资源 ID 从 PAK 启动；Sample 无需选图配置，章节初始变量在入口执行前生效，读档保持原位置与变量。
2. 图集全部直接 sprite 进入闭包；叶资源、未知依赖、动态额外包含可区分；构建不回写源 `.meta`。
3. 本体与补丁共同使用 X 时只在本体；A/B 共同使用 X 且本体不用时各一份；目录扫描顺序改变不改变归属。
4. 唯一 Graph 的所有非补丁 Group 都进入基础构建；UI、Gallery 独有和额外包含资源不丢失。
5. 剧情包未安装可连续跳过并结束；安装完整则执行；分片丢失、错版、坏 Group/依赖不能被静默跳过。
6. 资源补丁独立导出 A→B，带齐 B 的图集依赖；关闭补丁恢复 A；B 的夹带依赖不隐式覆盖无映射资源。
7. 优先级较大者覆盖；同优先级按 SHA-256 ordinal 较大者覆盖；相同文件去重。更改文件名/扫描顺序不改变结果；多包重复映射无需人工解决冲突；语言不影响资源补丁解析。一次映射、原始字节/解码/媒体的有效来源一致，旧 handle 不被原地变更。
8. 缺少剧情包的存档明确拒绝恢复；新游戏的初始参数不覆盖存档变量；不同 Run 的 save 值不串用，不兼容 EntryIndex 不伪装兼容。
9. 目录导出、galpak 导出和开发预览共用有效编译事实；无 GUI 的导出入口可运行同样规划与校验。
10. 失败输出不替换有效旧产物；反射关闭路径能反序列化新增 metadata；大包内存和取消路径实际验收。
