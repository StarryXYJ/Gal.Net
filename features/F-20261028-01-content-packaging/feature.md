# F-20261028-01 — 单 Graph 资源化与游戏内容分包

状态：`completed`，2026-10-28。P1–P6 全部 verified，按用户要求每阶段独立 Git 提交。实现结果、验证与限制见 [summary](summary.md)，收尾核对见 [review](review.md)。

## 用户目标

项目继续只有一张 Graph，将 Graph、Group 纳入 PAK 资源寻址；按依赖自动生成本体和可选剧情包；允许作者通过资源矩阵独立制作和导出覆盖包。保留默认 Sample 的简单启动，通过初始存档变量和单图入口分支实现章节选择，首页沿用现有定制接口。

## 当前问题

- 内容加载固定一张 loose Graph，Graph/Group 尚未与资源 ID、PAK 管线统一。
- 导出仅生成一个基础资源 PAK，没有基于 metadata 依赖的分包规划与剧情包完整性语义。
- 资源 provider 的顺序查找不足以表达独立的 A→B 覆盖映射和确定排序。
- 新游戏启动没有显式初始存档变量参数，标题按钮设置当前状态后再开始可能被新 Run 初始化覆盖。

## 范围

### 1. 资源依赖与 PAK 类型

- 有依赖的 metadata DTO 实现接口，返回直接依赖、预期类型和分析完整性；叶资源与未知依赖明确区分。
- 图集、Group、Graph 编译时同步生成有效依赖 metadata，不自动回写作者 sidecar。
- PAK 共用格式，以包头 `kind=base/story/override` 区分用途；资源 `typeId` 独立存在。
- 递归收集、缺失/错类型检查、动态额外包含、稳定切包与布局报告共用一套服务。

### 2. 单 Graph 资源化与章节启动

- 项目只有一张 Graph；运行 Graph/编译 Group 作为 PAK 资源按稳定 ID 获取。
- 游戏清单记录唯一 Graph 的资源 ID，Sample 自动读取，不引入 `defaultGraphId`、Graph 列表或选择 API，也不要求首页按钮填写 Graph ID。
- 存档继续恢复节点、游标、存档变量和呈现状态，仅增加分包兼容所需校验，不为本 feature 引入跨图存档身份。
- 存档变量属于本次 Run，继续使用唯一 Graph 的声明和默认值；不同 Run 的值互相独立，玩家变量仍在 profile 内共享，不增加按 Graph 隔离的变量层。
- 新游戏可传初始存档变量，初始化默认值后、入口执行前一次校验并应用；读档只用存档，不重新套用新游戏参数。
- 章节按钮共用启动命令、传不同章节初始变量，由唯一 Graph 的入口条件分支选路；不新增章节 Graph 或第二套章节目录。图内自然衔接保留当前 Run 变量，从标题页新开章节则创建新 Run，不自动继承上一 Run 的 save 值。

### 3. 本体与剧情补丁

- Group 有剧情包名称字符串：空表示本体，同名聚合。
- 先处理唯一 Graph 的全部非补丁 Group 及基础资源，再独立处理各剧情包。
- 剧情包只扣除本体已有资源，不扣除其他剧情包资源；本体没有、A/B 共用的资源两包各带一份。
- 每个集合内部去重，再按大小目标切 PAK；正常导出一并生成基础 galpak 与外部剧情 PAK，不新增剧情补丁面板。
- 基础 Graph 保留补丁节点及所属包描述；包完全未安装时跳过正文并沿正常出口继续，部分安装/损坏/错版明确报错。
- 文本、人物及动态引用额外包含不能在拆包时丢失。

### 4. 独立资源补丁与作者矩阵

- 行是唯一 Graph 及其全部 Group 引用的原资源，包含剧情补丁；支持使用位置、依赖展开和编辑器文件管理器定位。
- 每个资源补丁一列，每个格子选择替换资源；空值不贡献覆盖。每列可独立导出一个 override PAK。
- 原资源和替换资源各有独立作者 ID；覆盖包保存 A→B，携带 B 的依赖闭包，来源明确，不让夹带资源隐式全局覆盖。
- 优先级数值较大者优先，相同则最终 PAK SHA-256 ordinal 较大者优先；相同文件去重。无需语言匹配或人工冲突处理。
- 原始文件、解码、媒体实体化使用一致覆盖视图；重启/重建相关会话采用补丁变化，不原地修改现有资源 handle。
- 项目定义支持保存、重开、撤销/重做和作者快照导出。

### 5. 默认应用模板边界

- 延续现有 TitlePageViewModel 派生、DI 别名替换、VM→View 映射和项目服务注册，不新增通用 UI 编辑器。
- 补齐新游戏初始变量入口并提供章节按钮示例；新能力落在共享宿主接口，Sample 做项目组合。
- 现有标题外观/行为替换已经有代码与集成测试，不将既有能力列为本 feature 的待实现成果；仅做必要回归与文档衔接。

## 非目标

- 多 Graph 管理、Graph 选择、跨图存档识别、按图隔离变量、跨图跳转/调用栈。
- 任意剧情图拼接、二进制差分、下载器、自动共享包优化。
- 资源补丁的语言条件、冲突选择 UI、运行中热装卸。
- Gallery 补丁聚合、覆盖、删除、解锁迁移或 type 扩展；保留既有基础功能。
- 通用可视化 UI 制作器或通过 galpak 自动创建任意业务页面。
- 未经要求的旧项目自动转换或旧存档语义迁移。

## 验收标准

1. 唯一 Graph 可从开发/导出/安装内容按资源 ID 启动，Sample 自动使用清单入口；无需新增 Graph 选择配置或跨图存档字段。
2. 图集与编译剧情依赖完整进入闭包；构建不修改作者 `.meta`，缺失与未知依赖有明确诊断。
3. 本体先行、补丁独立去重和物理切包符合上述公式；包扫描顺序不影响归属。
4. 未安装剧情可跳过，坏包不能被静默跳过；正文、文本、存档和资源闭包一致。
5. A→B 可独立导出运行，按 priority/hash 确定结果，依赖不泄漏覆盖，raw/decoder/media 来源一致。
6. 编辑器可完成包名编辑、正常导出、创建补丁列、选择资源、定位原文件及独立导出，定义保存重开不丢失。
7. 单图章节按钮传入初始变量可在首次入口判断前生效；新 Run 不继承旧 Run 存档变量，读档不被新游戏参数覆盖。
8. 正式文档只记录已验证实现；每阶段退出条件和检查证据如实记录。

## 约束、假设与开放事项

当前没有等待用户决策的产品阻塞。具体二进制字段、作者身份文件布局及切包默认阈值由实现阶段结合现有结构和验证确定；格式/API 需显式版本化，不隐式接受不支持的旧内容。遇到与已确认行为冲突时记录原因，不能擅自增加共享包依赖、语言匹配或冲突门禁。

范围修正：用户明确项目保留唯一 Graph。先前记录的多 Graph 管理、默认/显式选图、跨图存档和按图变量隔离均已移出本 feature；章节选择采用单图入口分支与初始变量。Graph 资源化保留，它与支持多图不是同一项能力。
