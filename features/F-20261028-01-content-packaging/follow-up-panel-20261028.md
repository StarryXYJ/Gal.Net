# 后续调整：资源补丁面板与分包阈值

状态：`verified`，2026-10-29。用户要求提高默认包大小，简化资源补丁面板，使编辑自动持久化、导出只导出，并参考既有页面的图标按钮与对齐风格。本轮作为一个独立可验证阶段提交。

## 实现范围

- 默认未压缩软阈值由 32 MiB 提高到 128 MiB；超限单项仍完整独占，不拆文件。Archive 仍是整片缓冲，约 2 GiB 数组容量和实际内存约束不因阈值改变而解除。
- 面板复用 AuthoringPanelResources / EditorIconButton，资源搜索工具栏、补充原资源图标弹层及两行列头，导出/删除/定位使用图标并提供 tooltip 和可访问名称；取消仅导出期间出现。间接资源复选框垂直居中。
- 名称完成编辑、数字优先级、列和映射操作经原有历史与 PublishStructureAsync 发布，只变更 resourceOverrides 节；撤销/重做同步落盘，其他工作版内容仍未发布。不新增全局自动保存行为。
- 移除面板的草稿注册、放弃草稿和保存并导出语义。非法名称显示错误并回到有效值，不阻塞其他页面保存。导出只捕获已保存定义和独立资源快照，不调用项目 SaveAsync。

## 验证计划

实际挂载验证图标按钮、名称失焦/数字编辑、矩阵操作、多列布局、复选框居中、撤销/重做、即时落盘和重开。另验证未保存剧情及无关未完成输入不被补丁编辑/导出提交；导出内容与已存映射一致。检查四语键、默认大小和超限完整保留；渲染截图需实际查看。

新增的“局部保存后其他内容仍 dirty”检查发现 `ProjectContentBaseline.Node` 漏比较 StoryPackage。加入该字段，确保单独修改 Group 包名会被判断为未保存；资源补丁保存/撤销/导出均不抹掉未发布剧情。相关用例已通过，经验另存于 agent lesson。

本轮没有重跑其余无关默认套件，原始 P6 的 2,064 项记录仍只对应 P6；本轮交付证据以上表为准。变更 C# 的 whitespace / IDE0005 验证及 git diff --check 通过。无阻止本轮交付的已知问题。

## 延期事项：流式 PAK 与大文件支持

2026-10-29 用户明确要求先记录、以后再做；当前不实施，也不作为本轮未完成项。

- 当前整个 PAK 与单资源解压结果使用 byte[]，资源长度还受 int.MaxValue 校验，单 PAK/单资源无法支持超过约 2 GiB；游戏总容量可通过多个 PAK 超过该值。
- 压缩、复制、解压存在临时缓冲，小于该容量也可能因可用内存不足而失败；128 MiB 仅是分包软目标。
- 后续考虑流式写包、只加载索引并按资源范围读取，以及媒体通过流或临时文件交给后端，避免整包/大媒体同时驻留内存。
- 需一并评估资源读取 API、64 位偏移/长度、压缩及哈希校验、取消与文件租约生命周期；保持现有分包归属和覆盖优先级语义。
- 届时用超过 2 GiB 的单文件/单 PAK、随机读取、损坏输入及峰值内存验证，不仅验证多个小包的总容量。
