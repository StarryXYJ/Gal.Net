# Sample 操作设置与多输入设备快捷键

2026-10-16 已实现操作分类、键鼠统一录入、输入偏好持久化、游戏动作、Windows XInput 手柄适配与触屏手势。对白历史只保留可选页面回调，未实现历史页面。自动验证与硬件验证边界见 [summary.md](summary.md)。下文“当前基线”为实施前调查事实。

## 用户目标

Sample 的设置页面在现有“游戏、画面、音频”等一级设置项旁新增“操作”设置项；“操作”页面用于快捷键绑定，并在其内部用局部 TabControl 区分：

- 键鼠
- 手柄
- 触屏

快捷键至少覆盖快速、隐藏 GUI、存档（写入第一个空存档槽）等游戏操作，并沿用现有游戏工具栏/页面动作的语义。

## 当前基线

- `IPlayerSettingsService` 已提供只读设置分类，三个官方主题的设置页通过 `SettingsCategories` 使用局部 TabControl。
- Sample 当前已经注册名为 `game` 的一级分类，其中放置语言、文字速度、快速已读限制、快速间隔和自动间隔；它还没有 `operation` 分类和快捷键编辑器。
- `GamePageViewModel` 已拥有快速、自动、跳过、存档、读档、设置、截图、隐藏界面等动作；`GamePage` 已处理剧情区域点击和键盘事件，但没有可配置输入映射层。
- `IGameSessionService` 已提供槽位列表和按槽保存；`FileSaveService` 另有独立 quick save 文件。用户要求的“第一个空”应使用普通槽位，不应误用 quick save。
- 玩家设置通过 `player` 变量持久化；剧情 `GameSnapshot` 不应携带快捷键偏好。

## 目标

1. 在现有设置页一级分类中新增“操作”，不改变现有“游戏”分类的职责。
2. 在“操作”分类内提供键鼠、手柄、触屏三个二级 Tab，设备不可用时显示原因而不是静默消失。
3. 建立设备无关的动作目录和输入映射模型，使工具栏、键鼠、手柄和触屏调用同一动作入口。
4. 将快捷键保存为 Sample 的玩家偏好；修改、恢复默认、冲突检测和保存失败都有明确反馈。
5. “存档”动作在执行时选择最小索引的空普通槽位；没有空槽时进入存档页，不覆盖已有存档。

## 范围

- GameView 侧的输入动作/绑定契约、输入事件路由和设置页数据边界。
- Sample 侧的默认绑定、玩家变量读写和游戏动作适配。
- 三套主题的“操作”页内快捷键区域及输入捕获控件；外层沿用现有设置页布局。
- 键盘/鼠标、手柄按钮、触屏手势的统一显示和可用性状态。
- 快捷键绑定的重复冲突、清空、恢复默认、主/备用绑定和本地化文本。
- 键盘和鼠标统一录入控件；Ursa 无法承载完整行为时参考其实现自定义控件。完整建议动作清单及暂缓项见 design.md 第 3 节，新增玩法能力仍需按该处的范围说明处理。

## 非目标

- Editor 的快捷键或编辑器命令绑定。
- 将输入映射放入 Core、Runtime 或剧情存档快照。
- 轴类连续控制、复杂组合轴、触屏坐标区域编辑器和逐项目脚本化输入系统。
- 通过快捷键直接覆盖已有存档。
- 运行期切换游戏主题。

## 初步验收标准

1. 设置页一级 Tab 包含游戏、操作、画面、音频；进入操作后能看到快捷键区域及键鼠、手柄、触屏三个二级 Tab。
2. 现有游戏参数仍可修改；快捷键修改不改变剧情存档，也不产生设置导航历史。
3. 修改一个绑定后，游戏页对应动作、工具栏对应按钮和其他输入设备都走同一动作语义；按键自动重复不会重复执行保存、导航或模式切换。
4. 键鼠/手柄显式激活后捕获下一次输入，允许组合键；激活编辑器的按键不被录入。Escape 或当前手柄取消键取消并保留原绑定，独立清除与恢复默认操作可用，冲突被阻止并指出动作。
5. 快速、自动、跳过的互斥/确认/已读语义保持现有实现；隐藏 GUI、截图、设置、读档等动作不会绕过页面生命周期。
6. 存档动作只选择当前最小索引空普通槽；没有空槽、保存失败或会话不可保存时均不覆盖已有槽并给出反馈。
7. 缺少手柄/触屏后端时，Tab 仍可见但明确显示不可用原因；接入对应宿主能力后无需改动绑定数据模型。
8. 清空玩家数据后快捷键恢复默认；应用重启后绑定正确恢复，损坏或未知版本的绑定数据安全回退默认。
9. 按最近有意输入设备默认选择操作子页；进入后的手动选择与绑定捕获不会被设备事件打断。手柄确认布局可切换 A 确认/B 取消或相反，并统一影响界面导航、选项与捕获取消。
10. 触屏通过 ComboBox 选择单击、双击、长按、双指点击、双指长按、滑动等手势；一次手势只执行一次动作，不与兼容鼠标事件双触发。

## 假设与开放问题

- 本设计不改变现有 `game` 分类；新增稳定 ID 为 `operation` 的一级分类，与游戏、画面、音频并列。
- “操作”分类不是新的导航路由，而是沿用现有 `SettingsPageViewModel`/`SettingsCategories` 的局部分类内容；外层主题布局、滚动、错误和保存提示与其他设置分类一致。
- 初版每个动作提供一个主绑定和一个备用绑定；底层模型仍使用列表以便后续扩展。
- 默认键位是设计建议，不是已经确认的产品常量；实现前应确认是否接受 Tab/H/Ctrl+S 等惯例。
- 当前仓库尚未提供统一的手柄/触屏事件源；Sample 桌面端的能力枚举与真实输入适配需要在 Phase Plan 中单独验证。

## 2026-10-16 追加需求

- 提交已验证的操作设置与模块化快捷键；提交为 `b62bff6`，不包含用户的 Editor/agent 文档改动。
- 为 Control 等键值绑定入口本身增加输入框式描边与悬停前景反馈，不为每条配置项套外框；这是用户对上一轮视觉实现的明确修正。不改变设置应用/保存数据流，并消除空白 Tooltip。
- 设置、存读档、鉴赏与详情、关于等页面默认用 Esc 返回；通过共享基类和单个壳级模块实现，不为每个页面重复监听。捕获/下拉框先取消，长按不连续返回。
