# 音频效果创作与目标分析设计

2026-10-27，状态：designed，尚未实现。用户确认效果类型通过 ComboBox 选择、创建实例身份自动分配并隐藏，停止时先选 Track/Bus 再选择已有的效果；选择、身份和分析尽量复用 Layer 等已有机制。本文件补充 [后端设计](design.md)，不改变已验证的 PCM/DSP 架构，也不将这些目标行为记为当前实现事实。

## 当前事实与问题

当前 `audio.seffect.apply` 的 `id`、`instanceId` 仍是普通文本，`parameters` 为 JSON。`targetId` 已根据 `scope` 选择项目声明的 Track 或 Bus。运行时按 `(scope, targetId, instanceId)` 保存效果；同键 apply 为更新，stop 只移除该键，找不到时无操作。空 `instanceId` 当前也可能代表一个实际的未命名实例，不能改解释为“全部”。

Editor 已有 `SceneAuthoringSemantics` 输出/引用声明、`SceneAuthoringIdentities` 自动身份和批量复制重映射、剧情位置分析、项目查询代次和选择 lease、`ResourcePickerPanel`。音频效果目前在场景语义中属于中立条目，尚无音频效果候选。场景对象结构包含动画属性等视觉专用数据，不能直接把音频效果当作可动画 Layer。

## 作者交互

### 创建效果

表单顺序：作用对象类型（Track/Bus）→ 具体目标 → 效果类型 ComboBox → 类型对应的参数字段。

- 类型选项来自 `ISEffectCatalog`，按 `SupportedScopes` 筛选。展示本地化名称“增益、低通、高通、混响”，保存稳定类型键，如 `seffect.reverb`；不再提供常驻 ID 文本输入。
- GUI 创建条目时一次性生成隐藏 `instanceId`。刷新、展开表单、改参数、改效果类型、保存重开和运行该条目均不重新生成。循环再次执行同一条目更新同一目标上的该实例，不不断追加处理器。
- 参数使用共享表单字段和数值校验，混响显示空间大小、衰减时间、高频阻尼和干湿比例，滤波显示截止频率与 Q。以目录元数据生成，不在控件中另写一套类型/范围判断。
- 目录补充稳定的默认值及展示元数据；参数默认值由契约、DSP 和作者表单共用，不能只改 UI 默认值。语言资源在 Editor 中适配，音频契约不引用 Avalonia。
- 修改类型时保留实例身份；该次明确操作原子替换为新类型及其参数，旧类型参数不按同名猜测迁移。打开/刷新未知类型或未知参数时保留原 JSON 并提示，不自动换成第一个有效选项。
- 改 scope/target 会重新筛选类型；不再适用的旧类型显示诊断，等待明确选择。目标改变不会自动改写其他条目引用；旧 stop/update 引用应被诊断，避免暗中改停另一个目标。

### 停止效果

表单顺序：作用对象类型 → 具体目标 → 该目标在当前剧情位置之前已有的效果。效果下拉显示类型、创建来源与一定/可能存在标记；同类型多个实例分别列出，例如“混响 · 房间进入/第 3 条”和“混响 · 梦境开始/第 2 条”。来源标签不作为持久身份，不要求作者取名或填写 GUID。

列表只包含直接挂载在选中目标上的实例。Track 经过 Bus 混响并不表示 Track 自己挂了混响；停止这个 Bus 的混响必须选择该 Bus。不能按效果类型批量猜测要停止哪个实例。

“全部效果”是明确选项，序列化为独立的 `all: true`；默认 `all: false`。单个实例选择保存 `instanceId`。`all=true` 与非空实例同时给出属于无效输入；`all=false` 的遗留空实例仍按旧的精确空键处理，GUI 不再创建这种实例。清空字段、候选为空和引用失效都不代表停止全部。

运行时停止全部只移除该目标执行时已经存在的所有效果，包含静态分析未能列出的实例；不影响以后新增的效果或其他目标。逐实例清理和后端命令沿用已有平滑移除路径，逻辑状态在同一次状态更新中完成。

### 修改已有实例

编辑原创建条目的参数属于创作修改，不产生新实例。剧情后续位置调整已有实例需要引用语义，不能伪装成另一个自动生成身份的创建者。

设计建议新增 `audio.seffect.update`：先选目标和已有实例，再按其类型展示参数；不选择新的类型、不生成输出身份、不暴露 `id`。提交的参数为字段 patch，Runtime 从当前实例合并后，用相同目录完成整体验证，再更新该实例并保持链位置。目标不存在时无操作，不隐式复活。缺少新类型选择也避免把“调整混响”误用为“替换成滤波器”。

新增 update Entry 是本轮提出的实现方式，尚未实现。若后续拆期，创建/停止的目标分析先交付，后续修改作为独立阶段；不能通过手工填写隐藏身份作为临时产品入口。update 候选在分支中类型不唯一时不能伪造参数表单，应提示先选择类型一致的来源或调整剧情结构。

## 数据与身份

| 字段/概念 | 作用 | GUI 表现 |
| --- | --- | --- |
| `scope` + `targetId` | 指向项目声明的 Track 或 Bus | 两级选择，共用目标字段适配 |
| `id` | 稳定效果类型键 | ComboBox 的值，显示类型名称 |
| `instanceId` | 挂载实例身份 | 创建时隐藏输出；stop/update 中通过选择候选写入 |
| Locator | Group/稳定 Entry/输出槽位等作者来源 | 选择与重查依据，不替换 Runtime 的线格式 |
| `all` | stop 的显式整目标操作 | “全部效果”选项 |

音频使用独立 `AudioEffect` 身份域；运行时匹配和分析键均包含 `(scope, targetId, instanceId)`。即使遗留内容在不同 Track/Bus 复用同一字符串，也不能串选、串停或误重映射。新 GUI 输出虽使用 GUID，分析与复制仍不能依赖字符串全局唯一的假设。

自动生成、输出隐藏、引用索引和复制统一消费输出/引用语义声明。Group/Graph 批量复制先分配新输出，再在同身份域和相同原挂载目标内重映射批内引用；外部实例引用、Track/Bus 声明 ID、效果类型 ID、普通参数字符串不改。Undo/Redo 复用该次操作生成的身份。改 Entry 类型只保留角色与身份域相容的输出。

同一运行时键可能来自不同分支的不同创建者，查询应保留来源集合与类型可能集合；不能随意选一个 Locator 代表全部来源。停止可按同一精确键操作；类型不一致会限制后续参数编辑，但不会让停止变成类型匹配。

## 复用架构

目标是复用一套作者位置、Graph 传播、身份和选择有效性规则，不复制一份只把 Scene 改名为 Audio 的分析器。

| 层 | 复用与新增职责 |
| --- | --- |
| 作者语义声明 | 在既有输出/引用目录增加音频域、目标限定和 apply/stop/update 语义；支持“对某个目标的全部实例”这一非单实例操作 |
| Editor.Shared 纯分析 | 复用 Graph 遍历、条件分叉、固定点、预算、Group 前缀缓存和位置边界；增加独立音频效果状态与转移，不依赖设备/播放器 |
| 项目查询服务 | 共用作者快照、位置和生命周期；分域提供场景对象、播放控制、音频效果结果与完整性，避免一个域未知就污染所有域 |
| 目录/选择适配 | 复用候选来源描述、快照与写入方版本检查、失效取消；音频适配增加 scope/target 过滤与类型名称 |
| 字段控件 | 复用 ComboBox、共享参数表单、必要时的 ResourcePickerPanel；控件不扫描 Graph，也不持有 Runtime |
| Runtime/音频后端 | 保留目标级混音/DSP；补 stop-all 和 update 的明确契约，执行不依赖 Editor 的候选列表 |

实现时只提取两类消费者确实需要的公共位置、身份与数据流机制，保留现有 Scene 查询外观作为适配。不同领域的 payload、状态转移和完整性独立；不为了命名统一强制重命名全部 Scene API，不引入可执行项目扩展的通用插件分析框架。已有视觉/播放候选顺序、属性能力和失效语义必须回归。

目前音频条目对视觉场景中立，这一点仍成立；增加音频转移不能让视觉分析把它当未知场景操作。相反，已知纯视觉条目对音频域中立。未知自定义条目无法证明不修改音频时，音频事实应保守降级，不调用该条目求结果。

## 音频事实与查询规则

数据流：已提交作者快照 + 项目音频声明 + 效果目录 → 共享位置/Graph 分析 → 音频状态结果 → 按作用目标筛选候选 → 选择 lease → 提交前重查 → 单次作者历史写入。

查询使用消费者 Entry **执行前**的位置；候选不包含本条目的输出和后续创建者。Graph 分支确定集合取交、可能集合取并，条件为未知时合并执行/跳过两路，循环使用有限事实固定点。无效参数、未知语义、不可达位置和预算耗尽显式报告不完整/不可分析，不能把查询失败当作“确定没有效果”。

| 操作 | 音频域转移 |
| --- | --- |
| apply | 创建或更新精确挂载键，记录来源与类型；重新执行同键不增加实例 |
| update | 仅更新存在实例的已知参数，保留身份/类型；不把“可能存在”提升为“一定存在” |
| 单实例 stop | 删除该精确键；空键仍按旧单实例规则 |
| stop all | 清除该目标所有已知实例；可以消除这些实例自身的类型/元数据问题，不能抹掉上游未知语义造成的全局不完整 |
| play/stop/next/clear 等音源控制 | 保留挂载链，音源停止不表示效果或混响尾音停止 |
| `audio.mix.set` | 保留效果身份，仅改变独立目标音量/静音 |

音频实例不会因为时间过去或音源结束就从分析里移除。不同分支中效果链顺序可能不同，选择器不承诺一个确定运行时序号；以来源区分实例，不做链顺序编辑或推测尾音。首期不新增 Timeline 音频事件类型，也不把音频参数暴露成 Timeline 可动画属性。共享查询保留事件前位置扩展能力，但不能靠分析单方面宣称 Runtime 已支持音频事件。

选择有效性同时包含作者位置、查询结果版本、写入方上下文和 scope/target。改变目标、删除创建者、相关上游编辑、撤销重做、关闭项目等按既有 lease 规则失效；无关名称/语言刷新不写数据。切换目标后旧实例引用显示未解析并保留原文，必须明确重选；不能仍被当成新目标上的有效实例，更不能自动选第一项或转为全部。条目删除后再撤销也不能让旧弹窗获得提交权。

## 兼容、边界与取舍

- 保留已有 `id`、`instanceId`、`scope`、`targetId` 线字段和旧显式身份；主要变化是作者表现和声明式引用语义，不为隐藏两个字段而重命名 JSON。新增 stop `all` 默认 false，新增 update 是可加的 Entry；单纯这些改动不要求提升现有音频存档表版本。
- 读取既有内容不补 GUID、不改引用、不丢未知类型/参数。遗留空身份作为未命名精确键显示，并明确其来源；需要修复时通过显式作者操作完成，不能打开项目就批量改身份。
- 新 GUI 身份和批量复制重映射不能用来推断唯一依赖；引用索引需覆盖未打开 Group 和跨 Group 复制。重复来源/冲突应诊断，不偷偷修复。
- 不采用运行中后端枚举来决定作者候选；编辑器不需要播放到该处，也不访问设备。目录在无设备时仍可用于创作。
- 不在此轮加入 Bus 跨路由/Send、效果链拖动排序、自定义效果命名系统、实时音频预听、卷积混响或其他平台设备实现。
- 不按类型停效果：同目标可有多个同类型实例，类型是算法身份，实例键才是操作身份。显示层隐藏 ID 不等于删除底层身份。

## 交付与验收边界

实施顺序建议如下；属于待实现计划，不改变 P1–P4 的历史验证结果。

1. 共享语义/身份：独立音频域、目标限定、自动输出隐藏和批量复制；旧视觉/播放身份回归。
2. 共享分析/查询：音频状态转移、确定/可能结果、精确目标过滤、分域完整性与选择 lease。
3. 创建/停止表单与契约：类型 ComboBox、元数据参数表单、已有实例与全部选择、stop-all 原语；完成可实际操作的闭环。
4. 后续参数更新：引用现有实例的 update Entry、patch 合并与完整验证、类型歧义提示；复用同一查询和字段适配。

关键验收包括：

- 挂载后的真实 ComboBox 可选择类型，参数按类型切换，界面没有常驻类型 ID/输出身份文本；无设备时仍可编辑。
- 同目标两个混响各自可选/可停；Track 和同名 Bus 不串选，Track 不列出所属 Bus 的挂载效果；没有正在播放的音源仍可选效果。
- 顺序、条件、跨 Group、分支合并、循环、不可达、未知条目和预算耗尽按既有保守规则；未来创建者不能出现在消费者候选里。
- 新建、复制、跨 Group 粘贴、换类型、Undo/Redo、保存重开保持身份及引用约束；遗留相同 instanceId 位于不同目标不串改。
- 删除/改目标/撤销造成旧选择失效，名称和语言变化不提交参数；原未知 JSON、遗留空键、未解析引用保留。
- “全部效果”只作用于精确目标，缺失单实例无操作；stop 不重启声音，沿用平滑移除，不影响之后新增的效果。
- update 不创建缺失实例、不更改类型或链顺序；参数 patch 保留未改值，合并后验证失败不部分更新。
- 共享机制提取后，现有 Layer/视觉效果/播放选择、引用诊断与 Timeline 事件前查询相关回归仍通过。既有非音频 Timeline UI 失败继续单独记录，不能据此宣称全仓验收已通过。
