# 外部游戏调试设计草案

日期：2026-10-21。状态：proposed，未实施、未验证；用户明确约束见 [feature.md](feature.md)。

## 1. 核心选择

采用可选宿主调试组件、Engine 内有限调试端口、Editor 客户端三部分。定位采用“可恢复逻辑检查点 + 有界执行历史 + 正向重放”的统一模型，不逐指令实现逆操作，不从 Graph 拓扑猜历史。

作者目标代表“此 Entry 执行之前”；历史定位还必须指明哪一次访问。展示中对白与下一条执行游标分别报告。媒体恢复遵循逻辑检查点语义，不承诺原时间点画面完全一致。

## 2. 已核实的现状与缺口

- Engine 已有唯一执行门、活动实例管理、scope 取消、Choice、状态事件、稳定快照与展示同步；没有完整调试暂停/单步/任意定位端口。
- GameSession 串行化开始、运行替换与停止；IGameRun 不暴露 Engine。不能为调试强迫所有游戏运行实现新增大接口。
- GameSnapshot v4 保存 Save 变量和模块状态，不包含 Player 变量；正常读档不得回滚 Player 或已读进度。
- GameRuntime 从变量服务复制两类变量。VariableStore 及 PlayerVariableService 各有内存数据，直接改某个字典不会自动完成全链同步。
- Runtime 的变量“快照”查询当前返回内部字典/对象，调试 DTO 必须在受控边界复制，不能将其直接交给网络序列化。
- 当前 CatchUp 沿当前路径跳到未读/Choice；可复用呈现压缩和清理机制，需提取目标/预算策略，不能直接循环调用玩家 Advance 实现定位。
- GalgroupCompiler 产出 SourceMap，primitive 有 StableId；需要将本次编译的双向映射与内容指纹一起交给调试会话。

## 3. 模块边界与低耦合

拟定职责（程序集名可在实施前收敛）：

| 位置 | 拥有的职责 | 禁止拥有 |
| --- | --- | --- |
| Runtime 调试端口 | 受控读取、边界通知、调度命令、执行暂停/步进/定位原语 | 网络、JSON 协议、Editor 文档、Avalonia、进程启动 |
| Shared/Debugging | 协议 DTO、App/运行会话、历史与定位协调、可选宿主适配 | Editor 视图、文件选择、具体 presenter |
| Infrastructure 调试传输 | 本机连接、帧解析、鉴权、收发及释放 | 直接写 Runtime 状态 |
| 游戏组合根/可选 GameHost 适配 | 显式启用、可选开始回调、运行绑定、UI 调度、Player 沙箱和展示恢复 | 协议细节散落到各 primitive |
| Editor.Shared | 调试客户端模型、启动配置、源码映射、命令与断线状态 | 游戏对象引用或具体 UI |
| Editor | 菜单、Dock、输入草稿与高亮 | 重放游戏规则 |

Runtime 只增加少量平台中立能力，通过可选 observer/controller 连接；未启用不采集历史、不读取网络、不创建全局调试单例。执行回调不得在调度门内等待 Editor；暂停是在边界让执行返回并保存暂停状态，释放门后再等待恢复请求。

可选 GameHost adapter 组合 GameSession/GameRun，不让 IGameRun 或 IGameRuntime 为调试膨胀。自定义宿主只实现必要适配；历史恢复、开始游戏、Player 恢复、完整媒体冻结等按能力独立公布。初期不引入通用插件框架。

App 调试连接独立于 Engine。宿主注册可选 StartGameAsync，随后每次创建运行显式 Attach，释放 binding 即解绑。App 可在标题页已连接，进入运行后增补能力；停止游戏不等于关闭 App。

## 4. 启动、内容和协议

“测试 → 启动应用”首次配置可执行路径、参数列表、工作目录、测试 profile，项目设置可修改。机器绝对路径放项目本地 Editor 配置，不写进发行 GameSettings。默认先保存、完整校验并编译后启动；未保存临时副本作为后续选项。

Editor 先监听，再通过独立参数启动 App。连接携带本次会话凭据，游戏目录和 profile 参数兼容现有 Sample 接入；新参数名称在实现中定义。另提供等待外部连接，供 IDE 自行启动。默认仅 loopback TCP，长度前缀 JSON；传输接口与调试模型分离，限制单帧大小、队列和日志缓冲。

握手校验协议 major、项目身份、实际内容指纹、契约指纹及能力；连接成功不代表内容一致。源码映射依赖完全相同的编译内容；Editor 编辑后标记待重新加载，不允许将旧运行位置映射成新内容位置。

请求含 requestId、sessionId、runId、engineGeneration 和必要的状态证据；事件含连续序号。Choice 另有 choiceId，变量另有值版本。runId 表示一次游戏测试运行，历史恢复替换 Engine 时推进 engineGeneration 并保留兼容历史；真正开始新游戏创建新 runId。超时修改请求不盲重试，通过有限请求结果缓存查询结果；重连全量同步，缺失事件触发重同步。

开始、停止、定位、修改变量等操作通过同一宿主控制序列进入 Engine 门，不能与 GameSession 运行替换竞争。停止/取消可先发出取消信号，再等待队列清理，避免长定位占用命令队列后停止永远排不到。旧代异步结果不发布到新运行。

## 5. 当前实例变量 Dock

独立于作者“变量”面板，提供 Player/Save 页签、名称搜索、类型、当前值、编辑草稿、应用/还原及同步状态。读取当前运行的实际变量，包括运行中创建的项；声明名称/默认值只作为可用的辅助信息，不能用作者值覆盖运行值。

初次订阅在执行边界取得两作用域的独立 DTO 和 revision，之后发布有序增量；值修改、恢复导致的删除/新增、运行替换都必须通知。序号断层全量刷新。面板关闭停止订阅，重开重新读取；切运行取消旧草稿与提交。后台变化只更新“当前值”，不覆盖正在输入的草稿，必要时标冲突。

提交包含 runId/generation、scope、运行变量 UID/名称、原类型、expectedValueRevision、新类型化值。实际执行时重查身份、权限与该变量版本；其他变量变化不应使本次提交无故失败。拒绝类型变化、NaN/Infinity、超出 Int32、过期变量或只读项。默认不提供运行变量的新增/删除/改名；自定义宿主可声明部分系统项只读。

Engine 适配器调用权威运行时写入口；Player/Save scope 使用明确作用域，避免同名或前缀归一化误写。返回权威新值后面板才标记同步完成，事件回显不得再次提交。存档变量随后续存档保存；Player 变更进入测试 profile 的正常持久化策略，UI“已同步游戏”不等价于“已落盘”。不改项目 dirty、声明默认值或作者 Undo 栈。

手动修改记入调试历史。在历史位置修改后创建新分支，旧后续历史只读保留至预算淘汰；不继续套用原路径的条件结果。第一版可只在 UI 显示一个活动历史分支，不必提供复杂分支编辑器。

## 6. 统一定位模型

### 6.1 历史身份和检查点

历史事件具有单调序号；位置包含 nodeId、groupId（若适用）、sourceEntryId、primitiveId、访问 occurrence/GroupExecutionId 以及边界种类。Graph 非 Group 节点也记录控制流。循环中的同一 Entry 是多个不同事件，画布上下左右不定义时间次序。

DebugCheckpoint 独立于 GameSnapshot 文件格式，包含：

- 经过当前状态 catalog 校验的 GameSnapshot、精确边界及历史事件偏移。
- 该时刻隔离测试环境中的游戏 Player 变量完整副本，含不存在项的替换语义。
- 可影响执行条件的测试已读进度等可恢复宿主状态、随机源状态或已记录外部输入。
- 内容/契约/状态 catalog 指纹、宿主扩展版本及恢复完整性标记。

与剧情无关的窗口设置、设备等玩家偏好不自动回滚；宿主需明确区分可回溯游戏数据和应用偏好。普通存档继续保持不回滚 Player 的原语义；调试恢复只作用于已启用的沙箱。恢复需同步 Runtime 内变量与宿主变量服务，并批量发布完整重置，不能只 RestoreFrom 普通快照或只替换服务缓存。

只在可恢复的逻辑边界建立检查点。不能把正在运行任意阻塞 primitive 时读到的内存直接宣称为可恢复检查点；缺少活动执行内部状态时记录历史位置，并使用更早的合法检查点。初始状态、可恢复的 Group 入口/稳定边界以及周期边界优先缓存；Group 入口有跨组活动实例时不能强行标记完整。

历史有内存/数量预算，初始检查点尽量保留；淘汰后若完整日志与初始状态仍在，可从更早位置重放，否则明确可回溯范围。不得声称任意长度历史都能回放。

### 6.2 顺着执行历史前进

定位目标在当前分支的后面且尚无编辑分叉：可以从当前可重放边界 CatchUp；若当前处于不适合压缩的阻塞状态，使用适用检查点重新构建。沿历史消耗 Choice、手动变量修改及已记录外部输入，校验实际控制流是否符合历史。

定位未访问目标时，条件由实际变量求值；遇到未指定 Choice 暂停询问路径或使用预设，不能自动选第一项。Graph 路径可作为候选，拓扑可达不代表条件可达。循环/指令数/耗时有预算，可取消，返回最后实际位置和原因。

### 6.3 回到更早历史

统一算法：找到目标之前最近的兼容完整检查点 C，恢复 C，再正向重放到目标 T 之前并暂停。不逆运算变量，不倒放 primitive，不把当前场景直接带回早先位置。

示例：历史为 A#1 → B#1 → A#2 → C#1。当前 C#1，跳回 A#1 或 A#2 必须选择访问身份；分别从各自之前的检查点重放。同一变量在 C 才获得的值随测试 Player/Save 状态恢复，不得泄漏回 A。

历史仍完整且未修改时，可以沿原历史向前回到 C；在 A 修改变量、选择其他选项或执行不同输入，则创建新历史分支。旧未来不会被静默当作新分支已经发生的事实。

### 6.4 跨 Group

跨 Group 继续使用同一个 runId 下的检查点和历史，不单独从目标 Group 开头运行。Group B 可能继承 A 的背景、音轨、变量和循环动画，检查点必须覆盖完整逻辑状态。若 B 多次进入，优先展示最近访问，也允许选其他 occurrence。

未访问 Group 无历史上下文时，界面提供“沿指定路径运行至此”“使用测试预设从此处运行”“保留当前状态强制跳转”三种明确选择。后两者创建新的测试历史分支/基线，标为合成上下文；不能标成已还原真实历史。强制跳转也要取消旧实例/Choice、清理并重建保留的逻辑状态，不直接赋游标。

### 6.5 恢复与失败边界

定位协调器先校验目标/指纹/能力并产生定位计划，再阻止旧执行、取消 Choice/活动 scope、等待展示清理、恢复隔离状态、追帧、重建展示并暂停；所有完成事件带新 generation。

能使用独立候选运行时先在候选中重建，成功后替换；共用窗口/媒体后端的宿主未必能原子交换，需明确恢复中状态。失败尝试恢复定位前的合法检查点，若无完整回退状态则保持停止/故障并提供重启，禁止宣布原运行毫无变化。取消是显式状态，返回实际已恢复/已定位的边界，不能留下两个活动 Engine。

### 6.6 重放能力与副作用

CatchUp 是执行优化，不能推导自定义模块都可确定性重放。记录 Choice、手动变量修改、可影响逻辑的外部输入；随机/时钟由宿主可记录源提供，或相应模块标为屏障。条件结果用于校验，修改变量后应重新计算，不能强制复用旧结果。

模块/宿主公布“可恢复、可重放、需记录输入、不可重放”的最小能力；缺省未知应保守。网络提交、成就上报、任意磁盘写入等不可逆副作用不在追帧时重复执行，须由宿主沙箱/重放适配控制；未适配则在屏障前停止。只发送给 Editor 的提示不允许被当作执行事实。

第一版保证受支持内置逻辑与已接入宿主的逻辑定位；音频/视频从检查点重新播放，动画/粒子依既有状态恢复，不保证视觉时间精确。调试已读/解锁的可回溯状态与正式玩家档分离。

## 7. 暂停、断点和其他调试能力

默认暂停阻止新分发、自动推进、blocking 自然完成后的继续及 Choice 结果提交；媒体完整冻结另报 capability。暂停期间可收到后台完成，但执行只能在恢复/单步授权下继续。

普通断点在作者 Entry 之前命中一次，Composite 展开的后续 primitive 不重复命中；高级 primitive 断点可后续扩展。玩家“推进一次”和“单步作者 Entry”分别定义；单步遇到 Choice 或不能自然完成的 blocker 返回等待状态，不通过未经授权的 Skip 强行完成。清楚报告 paused/waiting/running，而非统一显示“已暂停”。

菜单包括启动应用、等待连接、开始游戏、暂停/继续、推进/单步、停止游戏、重新开始、断开和面板入口。Graph/Entry 右键定位。面板包括当前变量、日志/异常与位置；场景检查按能力增量补充。停止游戏与关闭由 Editor 启动的 App 分离，附加 App 默认不归 Editor 管理进程退出。

## 8. 候选取舍、兼容与迁移

| 方案 | 结论 |
| --- | --- |
| 直接改 NodeId/EntryIndex | 仅能作为明确的强制跳转内部步骤，无法还原旧状态 |
| 每条指令定义 Undo | 插件成本大，随机/外部副作用不可逆，放弃 |
| 每个位置都保存完整运行内存 | Task/媒体句柄不可恢复，开销大，放弃 |
| 每次从起点重跑 | 作为缓存缺失时的后备；正常用最近合法检查点缩短重放 |
| 检查点 + 历史 + 重放 | 推荐；需显式处理 Player、宿主扩展、重放屏障和预算 |

调试协议独立版本；不改变普通存档 v4 的 Player 语义，不为未来调试历史预先增加发行文件字段。DebugCheckpoint 初版仅内存，跨 App 重启历史持久化不在默认承诺中。旧内部 Preview 变量 UI 的复用只共享纯行模型/类型编辑器，不让外部客户端依赖旧 PreviewHost。

## 9. 验收重点

- 无调试依赖泄漏；未启用无采集；默认和自定义宿主均能接入最小能力。
- 运行重开/恢复时旧变量提交、旧 Choice、迟到事件无效；断线与超时无重复副作用。
- 双向变量同步、草稿冲突、同名归一化、恢复后的删除和 Player 服务缓存一致。
- 暂停与自然完成/Choice/自动推进交错；控制序列不会让停止卡在定位之后。
- 同组回溯、跨组继承、循环重复访问、历史分叉、预算淘汰、不可达/不可重放与取消失败。
- 调试回溯能恢复测试 Player；普通读档依旧不回滚 Player，正式 profile 不受影响。
