# 外部游戏调试设计草案

日期：2026-10-21。状态：accepted-for-implementation；已验证部分见阶段记录，其余不表示已实现。用户明确约束见 [feature.md](feature.md)。

2026-10-22 实施结果：核心范围已完成，实际 API/默认值以 [Runtime 规范](../../docs/spec/runtime/execution.md) 和[接入手册](../../docs/manual/editor/preview-and-debugging.md) 为准。本文保留最初的建议及开放问题作为设计历史；最终采用保留当前变量、目标前暂停、目标作者范围一次条件豁免、最近自然入口 LRU 缓存和全量轮询。固定/热点前缀预计算延期。验收边界见 [phase-6.md](phase-6.md)。

2026-10-24 补充：Editor 本地启动测试需为连接等待和调试请求设上限，并将 Editor 侧启动阶段、请求时长、进程输出与退出状态写入 profile 内的有界会话日志。超时只解除 Editor 操作等待，不自动杀 App；后续状态轮询用来确认迟到连接或仍在运行的操作。详见 [phase-liveness-diagnostics.md](phase-liveness-diagnostics.md)。

## 1. 当前选择及修订

采用可选宿主调试组件、Engine 内有限调试端口、Editor 客户端三部分。用户最新要求是沿指定路线追帧、忽略所有流程条件，重建用于测试的场景；不还原真实游玩历史。本版替代早先“检查点 + 输入历史 + Player 回滚”的方案，也不采用仅移动游标的跳转。

已明确：Graph 当前 Group 高亮、Group 右键跳转、多路线列表、合法选中 Group 链优先、Group 页作者 Entry 高亮和跳转。推荐采用按需缓存，固定场景预计算须有完整证明。变量写入和目标落点的具体默认值仍是下文建议，不能当作已获确认的产品事实。

## 2. 已核实的基础

- Engine 有唯一执行门、活动实例、scope 取消、Choice、状态事件、稳定快照和展示同步；需扩展有限调试控制策略，不能建立另一个剧情执行器。
- GameSession 串行化运行替换/停止；IGameRun 不暴露 Engine，自定义运行不能被迫实现庞大调试接口。
- GameSnapshot v4 含 Save 和模块状态，不含 Player；本功能不改变普通存档语义。
- GameRuntime 与 PlayerVariableService 各有变量内存，调试写入必须通过当前运行的权威入口；查询所得字典/对象也必须复制成隔离 DTO。
- 当前 CatchUp 用于跳到未读，仍检查条件并停在 Choice。新定位需要明确的 IgnoreConditions + ExplicitRoute 策略，不能误用普通 Advance 或永久改写 Entry.Condition。
- GalgroupCompiler 将 primitive.Id 重新按编译后顺序编号；StableId 为作者 Entry ID 加展开序号，并返回 SourceMap。不是保留 rawgroup 数字序号，但具备稳定映射基础。
- SceneTargetAnalysis 仅做有限作者事实分析，不产生完整可恢复快照；目前字面 false 不执行、其他条件保守合并，与本次无条件追帧不同。

## 3. 低耦合、生命周期与连接

| 位置 | 职责与边界 |
| --- | --- |
| Runtime 中立调试端口 | 受控状态复制、位置通知、暂停/步进及有界追帧；不引用网络、JSON、Editor、Avalonia |
| 可选 Debugging 组件 | App/运行会话、协议 DTO、定位协调；不持有 Editor 文档或具体 presenter |
| Infrastructure 传输 | loopback TCP、长度前缀 JSON、鉴权、收发/释放；不直接写 Runtime |
| 游戏组合根/可选 GameHost adapter | 显式启用、可选 StartGameAsync、Attach/Detach 当前运行、UI 调度、场景恢复和 profile |
| Editor.Shared | 客户端、启动配置、纯路线规划、编译映射、可选纯预分析；不引用具体 UI |
| Editor | 菜单、Dock、选择、路线列表、高亮和草稿；不执行游戏 Entry |

以上是职责划分，不要求每行独立程序集。优先保持少量可选组件，不引入通用插件框架；IGameRuntime/IGameRun 不为调试膨胀，默认与自定义宿主按能力接入。

App 连接独立于 Engine：标题页可已连接，进入游戏 Attach 后增加运行能力，binding 释放即解绑。开始回调可省略。未启用不建立连接或收集调试数据。Engine 在门内提交状态，通知/网络等待在门外；暂停让执行在边界返回，不持门等待 Editor。

首次“测试 → 启动应用”配置 exe、独立参数、工作目录和 profile，项目设置可修改；机器路径放本地 Editor 配置。默认保存、校验并编译后运行；先监听再启动，另支持等待 IDE 自行启动的 App。测试 profile 隔离正式玩家数据。

握手检查协议、项目、内容/契约指纹和能力，源码映射只用于匹配内容。请求带 requestId/sessionId/runId/executionGeneration，Choice 带 choiceId，变量带值版本；运行替换和定位都推进执行代次，旧请求/事件失效。修改请求超时查询结果而非盲重试。重连全量刷新，消息/队列/日志有上限。

宿主命令序列与 Engine 执行门负责互斥；停止/取消先发取消信号，不能排在长追帧后面永远等待。未知宿主恢复能力按能力禁用，不靠协议层推测。

## 4. Graph 与 Group 交互、作者映射

Graph 为执行 Group 设置独立运行标记，不修改作者选择集合；因此高亮 B 不会破坏用户选择的 B/C/D/E 路线。转移时更新标记，当前处于分支或定位中时明确显示过渡状态；图页面/Group 页面不打开也不影响游戏。

Group 页面标记当前显示/活动作者 Entry，并单独提供下一执行位置。当前 EntryIndex 常已指向下一条，不能直接据此高亮。多个并发实例可报告主阻塞条目和其他活动条目，不伪造唯一活动 primitive。

通过 SourceMap 建立 sourceEntryId → primitive 范围及 primitiveStableId → sourceEntryId，绑定编译指纹。展示 raw 作者行号按当前匹配版本的有序列表派生，不从编译数字 ID 或字符串拆分猜测。Composite 展开多个 primitive 仍高亮一条作者 Entry；跳到该行从展开范围开头开始。零展开条目保留虚拟作者边界，落在下一个编译位置或 Group 末尾，不能随便选一个不存在的 primitive。

Group 右键以该 Group 入口为目标，Entry 右键以该作者条目前为目标。建议定位完成先暂停；显式“从此处执行”时一次性忽略目标作者 Entry 的条件（覆盖其展开范围），越过该作者范围后恢复普通条件判定。若最终交互改为自动播放目标，必须明确相同的一次条件豁免，不让 false 目标定位后马上消失。此落点交互仍待确认。

## 5. 路线计划

路线请求由起点基线、起点位置、经过的 edge/outlet 序列、终点 Group/Entry 和策略组成。使用边身份可以区分相同节点对之间的不同出口；不能只有 Group ID 数组。

Group 集合形成路线的条件：起点、终点正确，所有选中 Group 恰好使用，连续元素为前一元素的直接后继，能推导唯一顺序。多选本身通常无序，不能信任点击或枚举顺序。满足时优先使用；断链、分叉、方向相反、缺起点/终点都不擅自丢弃选中节点，而是说明原因并进入路线选择。若将来允许在 Group 间隐藏非 Group 分支节点，须解析完整真实边序列；多种连接方式仍要选择，不能放宽为任意可达。

例：当前 B，目标 E，选中 B/C/D/E 且存在唯一 B→C→D→E 链，采用该链。若 B→X→E 和 B→Y→E 都可用且没有有效选中链，弹出路线列表，显示经过 Group、分支出口和基线。只列有限、优先短且无重复节点的候选，并提供继续指定途经点；不枚举图中所有路线。候选数量、深度、时间均有预算，超过上限明确提示。

追帧沿选定出口，不求 Graph 条件和 Choice 可见性；Entry 条件无论 true/false 都不拦截。循环路径可由显式路线编辑器带重复次数表达；普通 Group 多选不支持表示 B→C→B，默认不自动遍历环。目标拓扑不可达或边不存在仍拒绝。

## 6. 无条件追帧语义与基线

忽略条件只影响本次调试重建：Entry.Condition、Graph 条件及 Choice 过滤不判定；DTO/资源/参数验证、表达式类型、模块能力和后继边仍须有效。互斥条件下的两条 show 在同一 Group 时会按原顺序全部执行，后一次覆盖前一次；这是明确的调试合成场景，不代表任何真实可达分支。

变量策略建议：保留定位开始时当前 Player/Save 值，冻结副本供场景参数读取；场景追帧跳过 variable.set、Gallery 解锁、已读记录及外部持久副作用。这样用户在变量面板准备的测试值不会在回跳或重复追帧中被覆盖，也避免 x=x+1 重复累加。忽略条件本身并不必然意味着跳过变量赋值，此策略需确认；若选择执行赋值，必须在独立重建变量环境中从明确基线重放并纳入缓存键，不能直接累加到当前变量。

每次定位必须有明确的场景起点，不能把当前 B 中途的场景当作 B 入口。可用起点：游戏初始逻辑场景、已捕获的本次运行 B 入口、选定路线前缀的合法缓存，以及已证明固定的锚点。普通运行捕获的入口代表它的实际来路，不等同于从游戏起点全程忽略条件所得状态；计划/缓存标识其来源。

推荐：在当前 B 向 E 指定 B/C/D/E 时，默认从 B 当前执行边界继续，先按 CatchUp 规则收束/清理已有呈现，再执行 B 剩余条目、C/D，到 E 入口，不把 B 从头重复执行。也可以显式选择 B 入口基线重新构建；两者的起点与缓存身份必须不同。同组往早跳从该次 Group 入口重建到目标之前，往后可从当前合法边界继续；回跳后的场景不携带目标之后的对象。跨组往之前/未访问 Group 时，当前 B 不能到达目标就从更早合法基线/游戏入口重新选择路线，不反向执行边。路线重建语义由基线决定，不承诺不同起点生成完全相同的场景。

没有兼容基线时提供从游戏初始场景选择路线重建；如果该 Group 与入口断开，可以显式选择“初始空场景 + 此 Group 作为测试起点”，不自动伪造它有合法来路。任意目标都可以作为独立测试起点，但缺少依赖对象的结果/错误应可见。

定位步骤：校验计划与指纹 → 暂停旧执行 → 取消 Choice/活动 scope 并等待清理 → 恢复基线场景 → 以 CatchUp 呈现策略沿路线执行目标前缀 → 重建呈现 → 发布位置并暂停。阶段受取消/预算控制；失败回到可恢复场景或进入明确 Faulted/Stopped，不声称原运行完全没变。宿主需要重建部分 Engine/展示时仍保持只有一个有效执行代。

追帧不是播放完每段动画/等待对白：内置模块按既有 CatchUp 逻辑提交场景终态、抑制一次性展示；循环媒体依逻辑恢复规则重新开始，不保持原时钟。未知自定义条目需要显式重建适配，默认不能在后台执行它以“试算”状态；不支持则报告条目和原因。

## 7. 缓存与预计算

用户最终确认：调试期间每个 Group 只保存最近一次自然进入时的一份入口场景，不累积访问历史；再次自然进入覆盖旧值，并失效旧基线的中间缓存。恢复该入口和组内追帧不是再次自然进入，不覆盖原基线。入口捕获在第一条 Entry 之前，复制完整逻辑场景，含持久非阻塞呈现的恢复描述；不保存 Task/后端句柄，不回滚当前变量。普通读档/内容换代/新运行使不兼容入口缓存失效。最初版本以此单份基线为准，热点前缀和固定预计算是后续优化，不改变基线语义。

Group 末尾是游标等于编译条目数、尚未跨出边的明确执行边界。追帧停在这里后维持 Manual，不自动播放或借自然完成回调跨组；下次显式 Advance 才离开。不能通过终态 Stop 实现。取消或失败不返回“到达末尾”的成功状态。

### 7.1 性能顺序

先实现无缓存、按明确基线追帧的正确性，再加按需缓存；项目打开/游戏启动不枚举所有路线、不预跑全部 Entry。无条件场景重建通常可压缩对白、等待和一次性媒体，实际成本须测量。记录首次/重复定位耗时、执行 primitive 数、恢复/资源加载时间和内存字节，避免只优化计算却忽略纹理解码成本。

优先缓存合法 Group 入口和热点 Entry 前缀，长 Group 可按已执行指令成本/时间间隔增加稀疏缓存。缓存纯逻辑状态及恢复描述，不含 Task、控件、纹理或媒体句柄；按 LRU 和字节上限淘汰。异步计算有预算/取消，UI 只接收匹配代次的结果。

路线专属缓存键包含内容/契约/模块与恢复能力版本、资源版本、IgnoreConditions/变量副作用策略、基线身份、精确路线前缀和目标位置。读变量的场景还包含冻结输入指纹；第一版可粗粒度使用全部游戏变量 revision，后续证明读集后再细化。变量手改、内容/资源/模块改变均使相关缓存失效；不同来路不能仅凭相同 groupId 命中。

### 7.2 固定入口与固定 Entry

用户提出的“所有入路场景一样”是正确的合流优化方向；“没有 Possible，只有 Definite 对象”只是部分必要信息，不是证明。至少还要覆盖：

- 对象集合完全已知且相同，没有未知/额外对象。
- 对象类型、handle、资源、完整属性、排序和附着关系相同。
- 要恢复的效果、粒子/动画计划、对白/NVL、音轨/队列等域状态相同，或明确不在该缓存域中。
- 没有未记录的时钟、随机、自定义状态或输入依赖；否则只能带依赖键复用。
- 忽略条件策略下的分析完整且已收敛，包含所有结构入路/循环，不仅样本执行路径。

例如两条路线都必有背景 bg，一条显示白天，一条显示夜晚：对象都是 Definite，场景仍不固定。即使画面相同但 BGM 不同，也不能合成共享的完整恢复快照。Graph 汇合点/支配关系也不证明状态相同。

可按域证明和缓存：固定图层不能覆盖路线特有音频；恢复需保持域依赖，未知效果引用图层时不能随意拼接。完整固定入口只在所有纳入恢复的域都闭合并相同后授予；否则继续使用路线专属缓存，不丢弃差异。

若入口固定，Group 前缀又全部是确定、可纯计算的场景状态变换，则特定 Entry 前状态也固定，可以预计算；入口不固定时，前缀显式完整清场并重新设置全部相关域，也可能在中途形成固定锚点。只 show 一个背景不是完整清场，未提及对象和音轨可能仍在。

预计算只调用模块声明的纯状态变换器/恢复描述，不实例化游戏、不加载真实媒体/执行任意自定义代码。不能纯计算时不预计算，首次真实安全追帧后按需缓存。证明不足/不收敛只取消优化，不阻止 P4 基本定位。

### 7.3 与现有查询的边界

SceneTargetAnalysis 目前的 Definite/Possible 是目标存在性抽象，Values 也只保留部分可动画数值；不是完整场景状态。普通作者查询按条件合并，调试分析必须显式使用 IgnoreConditions 并在缓存键分离；不能直接改现有查询使 Timeline 作者语义变化。

可以复用纯 schema、编译映射和状态变换工具；当前查询的候选/Complete 不当作生成运行快照的凭据。固定证明由独立、覆盖模块状态的结果承担；第一版只实现明确支持域的保守证明，其余返回 Unknown。

## 8. 实例变量面板与其他能力

独立 Player/Save Dock 查询当前运行实际值，不覆盖作者声明；支持搜索、类型、当前值、草稿、应用/还原与同步状态。初次原子复制 DTO，之后有序增量，断层/恢复全量刷新；后台变化不覆盖草稿。写入携带运行代次、scope、变量 UID/名称、类型及每变量 expected revision，执行时重查；旧行、旧 Choice、迟到结果不能写新运行。

拒绝改类型、非有限 Float、越界 Int、只读项与过期版本；明确作用域避免前缀归一化误写。写成功以权威新值回显，不产生项目 dirty/Undo。Player 正常持久化进测试 profile，“已同步游戏”与“已落盘”分开；面板手改推动依赖缓存失效。

流程暂停阻止新分发、自动推进、blocking 自然完成后继续和 Choice 提交；媒体完整冻结另报 capability。断点在作者 Entry 前；单步作者 Entry 与玩家推进一次分离。菜单保留启动/连接、开始、暂停、步进、停止、重开、断开和面板入口；停止游戏不等于关闭外部 App。

## 9. 取舍、兼容与验收

直接改游标无法重建场景，不采用。真实历史回放需要输入日志/Player 回滚，已不在当前范围。全路径预计算易指数膨胀且拖慢启动，不采用。推荐指定路线无条件追帧、按需缓存，再对白名单可证明固定域做共享预计算。

调试策略限定在一次请求及目标执行豁免范围，普通游玩继续使用原条件和变量语义；不修改原作者文档、普通存档格式及既有 Timeline 查询。可选组件按实际依赖同步架构检查，不让 Runtime 反向引用 Editor 或通信层。

重点验证：真实跨进程连接和变量同步；合法多选链/路线歧义/环/平行边；Entry false 和 Choice 不拦追帧但坏参数仍拒绝；同组倒退和跨组无后续场景残留；Composite 与零展开映射；取消/停止/旧代事件；缓存命中等价及失效；Definite 但资源/属性/音轨不同不错误合流；首次/重复跳转性能与缓存上限。

实现阶段及每阶段 Git 提交要求见 [phase-plan.md](phase-plan.md)。
