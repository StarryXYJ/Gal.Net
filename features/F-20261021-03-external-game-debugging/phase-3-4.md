# P3 / P4：作者边界控制与路线定位

状态：implemented，定向验证通过；完整跨进程/媒体验收归 P6。

## 已实现

- DebugSession 仍复用 Engine 唯一执行门，按编译 primitive 范围接受作者断点和单步；Editor 从 SourceMap 生成范围，不让 Runtime 依赖作者文档。
- 断点在条目前触发，继续会越过本次命中，循环再次到达仍命中。追帧忽略断点，定位目标前暂停。单步在一个作者范围内按普通条件/阻塞/Skip 规则推进，遇到阻塞即暂停，不能跨到下一个作者范围；它不会强行完成不可跳过的媒体。
- 定位请求可携带目标作者范围的 end；显式继续/单步时仅该展开范围豁免条件，越界恢复普通条件，普通读档/新定位使旧豁免失效。原作者 Condition 不修改。
- 自然入口捕获不在跨组追帧中触发；回到此前自然进入的 Group 仍恢复其原始入口，不会被合成场景污染。
- 活动条目 DTO 增加 Group 身份，避免并发跨组呈现的同名 primitive 被映射到错误作者条目；下一执行位置仍独立在状态中提供。
- Graph 可显式选择“以初始场景从此处测试”，用于与根断开的独立 Group；不会暗中将不可达目标视为合法路线。
- 路线候选显示节点名称和出口编号，截断有提示；唯一完整选中链必须在预算内完整证明，搜索被截断时不伪报唯一。

## 验证

- Runtime 107 项通过（原 104 + 3）；覆盖目标 false 条件复合展开、下一条条件保持、断点前停/单步不越作者范围、自然入口不被跨组追帧覆盖及独立起点。
- Debugging 5 项、路线规划 3 项通过；实际挂载 UI 的 TCP 集成测试加入断点标记、单步与作者历史保持。
- 测试取消断言改用 `CatchAsync<OperationCanceledException>`：Task 取消可能抛其子类 TaskCanceledException，不能用精确类型断言制造偶发失败；超时 TimeoutException 仍失败。

## 边界

UI 更新采用有界全量轮询，无增量位置事件。单步不会完整冻结正在播放的媒体；自然完成仅停止后续分发。当前没有图上编辑重复环次数的专用工具，运行端可以接受显式重复边序列，常规多选/候选不会遍历环。固定入口证明、热点前缀预计算还未启用。
