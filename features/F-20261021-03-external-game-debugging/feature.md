- 日期：2026-10-21
- 状态：discovery；需求已记录，设计与阶段计划为待评审草案，尚未实施。
- 工作流：create → design → phase-plan → implement → review → closeout。
- 设计：[design.md](design.md)
- 阶段计划：[phase-plan.md](phase-plan.md)

## 用户原始目标

Editor 对接外部游戏 App 进行 debug 和测试。底层提供可选调试层，由开发者显式决定是否启用；App 启动后即可与 Editor 通信。顶部“测试”菜单可以启动外部 App，首次配置可执行路径，也可从项目设置修改；启动时通过参数传入游戏工程目录等信息。

调试接入可选注册“开始游戏”方法。有回调时 Editor 提供开始游戏入口；没有回调时允许玩家在 App 自行进入游戏，再开始运行调试。需要支持任意位置定位、跨 Group 调试。

2026-10-21 用户补充：

1. 采用 feature 流程，保持较低耦合。
2. 实施时每个阶段验证完成后提交一次 Git，只包含本阶段相关变更并报告 commit。
3. 独立面板显示当前游戏实例的玩家变量与存档变量，支持手动修改并同步游戏。
4. 重点设计顺着剧情前进、回到历史位置及跨 Group 定位的统一方案。

## 问题与范围

- 区分 App 连接与游戏运行：尚无 Engine 时仍可连接；运行替换后旧操作必须失效。
- 显式启用、可选启动回调、默认宿主适配与自定义宿主接入。
- Editor 启动配置、连接/断开、开始/停止运行、基本日志及执行位置。
- 当前运行的变量查询、类型校验、双向状态同步与冲突保护。
- 流程暂停/继续、作者 Entry 断点与单步，选择分支操作。
- 任意作者目标定位：历史上下文恢复、可达路径追帧、没有上下文时明确选择测试预设/从此处运行。
- 测试数据隔离、调试检查点、执行历史、跨 Group 和循环访问的身份。

## 非目标

- 本轮文档工作不修改业务代码、运行配置或正式 spec 中的当前实现事实。
- 初版不做 CLR 调试器、任意表达式执行、原生进程附加或程序代码热更新。
- 不承诺媒体/粒子/动画逐帧逆播，不对任意插件承诺无条件确定性重放。
- 不默认支持远程设备或公网连接；内容热替换、通用自动测试脚本平台留后续评估。
- 不修改变量声明、作者默认值或项目内容历史。

## 验收标准

1. 未启用调试时没有连接与历史采集；Core/Runtime 不引用 Editor、Avalonia 或通信实现。
2. 首次启动可设置路径与参数，后续可修改；支持 Editor 启动和开发者自行启动后连接。
3. 开始回调可选；当前运行绑定/解绑独立于 App 连接，重开后的旧请求被拒绝。
4. 运行变量 Dock 同时支持 Player/Save 两作用域；游戏改值能刷新，手动提交经运行调度与类型校验生效，失败明确回显，不改作者内容。
5. 后台刷新不覆盖未提交草稿；已替换运行的旧行、旧 Choice 和旧异步结果不能写入新运行。
6. 历史定位以实际执行次序及访问身份定位，同 Group、跨 Group、循环重复进入都可区分。
7. 回到更早历史位置通过检查点恢复和正向重放实现；缺少完整检查点或可重放路径时明确说明，不伪装为上下文已还原。
8. 未执行目标可在明确路径/预设下定位；分支不明确、目标不可达或插件有重放屏障时给出可行动结果。
9. 测试默认隔离玩家数据；调试回溯的 Player 恢复与普通存档不回滚 Player 的规则分离。
10. 每个实施 Phase 具备行为测试、适用构建检查、文档记录和独立 Git 提交。

## 约束、假设与开放问题

- 用户已确认低耦合、变量面板及按阶段 Git 提交；其余具体接口、默认值和定位策略是推荐方案，尚未被用户逐项确认。
- “前/后”不按画布位置解释：设计统一称为沿执行历史前进、回到更早历史、定位未访问目标。
- 默认建议仅一个活动受控运行；协议保留实例身份，暂不设计多运行并行控制 UI。
- 检查点数量/内存预算、是否持久化调试历史、完整媒体冻结均待实施前实测/范围确认。
- 正确回溯需要宿主提供测试 Player/进度隔离和必要状态扩展；自定义宿主缺少能力时应降级公布能力。
