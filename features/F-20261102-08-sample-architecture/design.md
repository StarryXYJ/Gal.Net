# 设计

## 边界与判断

CrossPlatform App 持有宿主与 scope；Android/iOS 负责把平台事件送到 App，不能把平台生命周期逻辑分散到页面。当前状态变更由 App 串行处理，但平台恢复先等待音频再设置活动状态；期间新的暂停可能被旧恢复覆盖。先通过可控异步测试确认交错，优先合并为一次状态更新，保证在事件发生时同步记录全部相关状态；继续使用现有串行保护与会话取消，不新建通用调度系统。

Headless 控制台的选项和推进共享标准输入。`WaitAsync` 不会取消已启动的同步 `Console.ReadLine`，不同请求可能争用输入。应使同一会话只有一个输入所有者，明确请求取消、旧结果与结束时的归属；先用可控输入测试确定实际行为，不在旧读取仍活动时盲目重启读取。

鉴赏页当前创建全部卡片与缩略图，属于潜在规模问题；先采集条目数、首屏与占用数据。保留 GalleryThumbnailCollection 的取消代次和 Bitmap 释放，不在无性能证据时引入虚拟化。存档双卡可考虑单卡加现有行的当前命令，但必须保证重命名、CanExecute、预览和模式切换；不能为了省控件复制命令生命周期。

继续检查发现：`GalleryNavigationService.OpenTypeAsync` 等待页面 `ActivateAsync` 完成后才导航，而图片/视频/场景页通过 `GalleryThumbnailCollection.ActivateAsync` 顺序等待全部已解锁缩略图。已有卡片基准预先填充模型，不能代表从点击分类到首屏的等待，也不能证明只优化网格就能解决首屏。下一切片应先以可控加载器记录首次呈现与全部完成两个时点，并单独处理异常观察、切页取消、同页重新激活和 scope 释放；不得通过丢弃 Task 来提前返回。缩略图何时交付和释放属于页面生命周期契约，不能简单把加载任务转成 fire-and-forget。

GamePage 测量涉及控件宽度、折叠、菜单和对白净空。仅在可重复的布局/性能证据支持时提取小型纯计算或减少重复遍历，保留可见性、字体变化与导航行为。App 聚合多个生命周期职责；优先消除实际重复或状态交错，保留明确的取消、清理和后台工厂收束，不为拆文件增加新层。

Sample 页面各自可修改；相似的鉴赏页不因形式相似强行合并。原生平台验证条件、benchmark 基线和未实施事项在阶段记录中保留。
