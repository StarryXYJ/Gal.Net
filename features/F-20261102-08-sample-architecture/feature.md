# Sample 职责与可靠性整理

状态：implementation。用户要求基于 Sample 全面分析新建 feature 并开始实现，代码职责清晰、耦合低；保持现有视觉和可定制性。

## 目标与范围

- 以可复现的证据检查并修正平台生命周期交错、Headless 输入所有权等可靠性风险。
- 检查鉴赏大列表、存档卡重复、工具栏测量和启动组合；有收益且不破坏所有权时实施，否则记录测量与取舍。
- 补足有意义的交错、取消、资源释放和导航回归，更新已验证的开发文档。
- 用户进一步确认：存读档及全部 Gallery（包括音乐）采用分页，并以异步缩略图和 Skeleton 占位减少进入页面的等待。

## 非目标和约束

- 保留现有视觉语言，允许按用户要求增加分页与加载占位；不改变存档格式、内容契约、平台支持承诺或页面可定制性，不靠额外调度层掩盖重复。
- 保留启动取消、原生资源所有权、页面输入和生命周期行为；Android/iOS 未经对应设备验证不标记为设备通过。
- 工作树已存在上轮 Sample 设置页面样式和文档变更，属于本 feature 之前的工作；不得覆盖或混入本 feature 的提交。
- 大列表和测量路径先建立规模证据，不因推测而重构；任何不可复现的风险如实标记。

## 验收

各阶段有明确测试证据；用户可独立理解最终职责、行为和未验证平台。详见 [设计](design.md) 与 [阶段计划](phase-plan.md)。
