# 阶段计划

## P1 移动端状态交错 — verified（共享逻辑与 Android 构建）

复核平台回调及 App 状态，建立可控交错测试；修正确认的问题，覆盖快速暂停/恢复、音频焦点与关闭。验证共享宿主及平台编译条件，设备验证单独报告。退出条件：最终状态对应最新平台事件，已有暂停/清理契约不回退。

可控重现：旧恢复先等待音频，暂停排队后旧恢复仍写入 active=true，回归测试失败；将恢复的两个字段在等待前一起更新后，两项交错与启动/清理等共 24 项通过。此测试核对 App 内状态，不声称完成 Android/iOS 设备验收。Android 首次构建未传 NDK 路径而失败；使用本机 NDK 28.2、默认目录和现有缓存重新构建通过（0 警告/错误）。iOS 未在 Mac 上编译或实机验证。保留现有串行、暂停及清理流程。

## P2 Headless 输入所有权 — verified

用可控输入证明取消、选择、推进和 EOF 的归属，按需要收敛为单一输入机制。验证取消后旧读取不能窃取新请求，错误可观察，退出不无限等待。退出条件：回归通过，生命周期边界明确。

实现：同一 ConsolePresentation 的推进与选项使用单一输入所有者；请求等待可取消，底层未完成读取保留给下一请求，等待者不阻塞于底层不可取消读取。同步包装的 TextReader 读取在后台执行。可控测试覆盖推进取消后选项接收同一行、排队取消、EOF；与 P1 共 6 项通过，调试和非调试锁定还原通过。初次测试使用精确异常类型断言误判 TaskCanceledException，已改为接受 OperationCanceledException 子类；首轮测试编译的命名空间错误已修复。未验证真实终端进程退出时阻塞读取被系统中断的行为；读取不由应用强制取消。

## P3 页面规模及重复 — in-progress

用户明确选择所有存读档与 Gallery（含音乐）分页，并希望使用 Skeleton 与异步缩略图；每页固定 12 项，宽屏增加列数，必要时页内滚动。详细方案见 design。

检查和测量鉴赏/存档规模；只对有证据的热点或明确重复实施最小改动。保存模式、空槽、重命名、图片释放与导航均须验证。无法建立可信证据的优化保留为后续。

P3a 存档卡重复已完成：每个槽位仅创建一张卡，行模型选择现有保存/读取命令，保留命令原有的空槽、损坏槽与重命名等待语义。两种模式的实际卡片数、命令及可用性，以及预览像素、重命名、会话和布局共 77 项通过。鉴赏大列表规模测量与是否优化仍待 P3b，不以卡片改动代替性能基线。

P3b 首轮基准：实际 Sample 鉴赏页 100/1000 条 Headless 挂载各成功测量；1000 条平均 931.7 ms、托管累计分配 222.39 MiB。固定 2560×1440 PNG 的 768 宽解码为 30.49 ms，原尺寸 17.91 ms；未测原生峰值，不把限宽视为已验证优化。具体夹具、误差、复现及限制见 [benchmark.md](benchmark.md)。虚拟化的交互和所有权设计及改动后对照仍待完成。

进一步发现导航在顺序加载全部缩略图后才展示页面，现有挂载基准不涵盖此等待。可控 5 ms 延迟加载器的 8/64 条 activation 实测 122.7/994.7 ms；当前计时器每次等待约 15 ms，不能将该合成数据视为真实解码或实际首屏时延。详见基准记录。

- P3c 存读档分页：Ursa 页码、每页 12 项，当前页预览后台解码和 Skeleton；覆盖集合边界、切模式、卡片交互与切页释放。状态 in-progress，键盘/手柄焦点仍需验证。
- P3d 图片/视频/场景分页及异步缩略图：先展示当前页并加载当前页；覆盖快速翻页的过期结果与作用域释放等待。状态 in-progress，真实媒体和设备待验证。
- P3e 音乐分页：页码切换不调用停止播放，状态对象保留所有曲目的播放和位置；已验证 UI 页码与状态，真实音频播放跨页待验证。
- P3f 回归与基准：页面回归与 Headless 挂载测量见 benchmark.md；新旧测量主题条件不同，不视为严格 A/B。键盘/手柄、实际媒体与设备验证仍待完成。
- P3g 手柄分页 — verified（Headless）：当前导航范围的 LB/RB 控制可见分页，首末页停住；焦点在标签中时最近标签优先，否则分页优先于标签回退。真实存档、图片、视频、场景、音乐页面覆盖切页、边界与焦点，真实设置页及含分页的嵌套标签覆盖焦点优先级；音乐状态检查为模型模拟，非真实音频播放。

P3g 首轮在先前工作区通过肩键测试；并行的内容安装修改曾导致构建失败，用户选择等待，其他任务提交后重新构建。首轮 67 项中 66 项通过，旧 Start 配置迁移断言因已提交的兼容清理失效；更新为有效肩键绑定和非法 Start 恢复默认值后，手柄用例全部通过。扩大输入回归 54 项中 53 项通过，Classic 主题悬停颜色断言失败，与其他任务已报告的失败一致；本次未修改样式。真实手柄仍待验。

## P4 启动和布局职责 — verified（代码审查及 Headless 回归）

审查 App 与 GamePage 的真实重复、状态和性能；只实施能降低整体复杂度的改动，保留模板可定制性与资源生命周期。执行相关启动、布局和导航测试。

工具栏初步基准：跨 450/1280 宽度调整 Headless 页面平均 360.4 μs/次，托管分配 27.82 KiB/次；只测布局总成本而非 GPU 或独占方法，迭代时间较短，详见 [benchmark.md](benchmark.md)。当前无足够证据证明新增缓存及失效机制值得其复杂度，保持现有实现。

代码职责审查见 [responsibility-audit.md](responsibility-audit.md)：保留现有启动编排及工具栏布局，列出音频全量准备和同步释放的边界。上述 67 项回归中的启动、平台状态和响应式布局测试全部通过；设备生命周期仍需实测。
