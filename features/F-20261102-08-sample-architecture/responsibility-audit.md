# Sample 启动与布局职责检查

## App

`App` 是跨平台入口的组合根，集中保存宿主、启动、窗口和平台状态。`CreateHostView` 负责把已有内容重新挂入窗口，`PrepareEnvironmentAsync` 在宿主创建前准备路径、本地化、窗口位置和日志，`CreatePlayerAsync` 配置依赖并安装显示面。`StartAsync` 协调启动，`RestartAsync` / `ShutdownCoreAsync` 使用同一个 `_composition` 锁和代次隔离启动及清理；`ReleasePlayerAsync` 按所有权顺序清理开场、宿主、界面和日志。平台层只转发平台事件。

这些方法中的路径、本地化、日志和宿主创建确实属于不同工作，但当前状态共享、发布和清理边界集中且有明确执行顺序。未发现可以直接消除的重复或已证实的职责冲突；单纯把方法移入新的协调类会增加状态转交及取消耦合，本轮不拆。已有 `SampleOpeningTests` 覆盖开场期间关闭、清理失败后的资源释放，`SamplePlatformLifecycleTests` 覆盖暂停/恢复交错；设备生命周期仍需真实平台验证。

## GamePage

布局资源与外观由 Sample 模板定义，`GamePage` 只在可用尺寸已知时计算工具栏字体、完整/紧凑布局、历史入口和对白净空，并管理菜单打开/关闭。`MeasureButtons` 复用两种工具栏的测量过程，模板重应用时解除旧菜单订阅。布局依赖真实模板内容、字体和可见性，不应缓存宽度而缺少可靠失效机制。

现有跨断点 Headless 基准平均约 360 μs/次，测的是整个布局调整而非方法独占或 GPU 帧时间；尚无证据支持引入缓存或单独的布局调度层。现有 `ResponsiveLayoutTests` 覆盖窄宽切换、菜单关闭、对白和工具栏布局；模板定制与原生设备表现仍需在实际宿主中验证。

## 后续关注

- 鉴赏音乐当前在进入页面前仍等待全部已解锁曲目的时长准备；分页限制了 UI 行数，但没有测量真实音频库的准备耗时。若实际素材证明是热点，再按音频对象和取消的所有权单独处理。
- 图片鉴赏页实现了异步作用域销毁并等待未完成加载；同步 `Dispose` 只能取消，不能等待不响应取消的解码。Sample 正常异步宿主释放路径之外的同步调用方不应假定它已经排空异步工作。
- 未完成的手柄真机、真实媒体和移动平台验证不能由 Headless 测试替代。
