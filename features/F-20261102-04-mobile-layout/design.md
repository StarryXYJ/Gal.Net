# 设计

## 承载与所有权

仅移动宿主把借用的同一 GameShell 从 PlayerSurface 的外层 GameCanvasHost 移到 PlayerContent 实际视口。保留原有命名 GameCanvas 的可见性信号，shell 跟随该信号；解绑时移除 shell、释放可见性订阅，再走现有 surface 清理。不复制页面、VM、scope 或 presenter，不改变外层模态遮罩和安全区所有权。桌面完全沿用原承载。

Sample GamePage 内部用 GameCanvasHost 承载同一 scene/dialogue/NVL/choice，设计空间仍为 1920×1080。桌面外层已是该尺寸，内部缩放为 1；移动时内部画布按实际视口等比显示。历史作为全页阅读覆盖层使用实际页面空间，仍在工具栏之上。独立工具栏仍属于同一 GamePage 的交互树，复用原命令与 State。

## 工具栏

桌面保留完整按钮顺序、样式和边距。移动模式按实际视口测量按钮，目标最小 48×48 逻辑单位；完整工具栏能放下时保留，不能放下则显示快进、自动、历史（可用时）和更多，低频命令在更多菜单保留。极窄视口的大字号不能放下四项时，历史也收入更多，不缩小整套字号。居中优先使用场景宽度，按钮确需更多宽度时才伸入黑边，最大不超过安全视口减边距。

为避免触摸条盖住对白，移动端只补足对白底部的必要净空，换算回设计空间；不修改对白宽度、字体或场景坐标。竖向留黑已有足够空间时不额外抬高对白。菜单展开/关闭和返回不触发推进，切页/卸载关闭菜单并清理临时状态。

操作条以 320 逻辑单位作为不超过场景宽度的最小舒展宽度，并受安全视口上限约束；不强行拉满场景。只在所需按钮更宽时增长。用户否定了首版大底板和直接使用设计字号的视觉方案：最终工具文字按画布基准折算为 12–18 逻辑单位，菜单为 14–18；外层 48×48 透明命中区与内层自然尺寸标签分开，底色/选中反馈只贴合标签，不绘制整块工具条背景。保持原有 PlayerTypography 配置值。打开按钮 Flyout 时输入路由暂停游戏动作，不改写共享 IsInteractionBlocked；触摸 UI 会清理此前等待双击判定的单击。

## 普通页面

Sample 通过 inheritable 移动模式标记和局部 mobile-player 样式控制页面边距、页头、返回按钮和内容区空白。桌面不进入此样式。存档/鉴赏面板按实际可用宽度调整列数或项目宽度，保持图片比例与默认桌面列数/尺寸。

设置行和操作绑定行在宽度不足时重新安排同一批子控件的 Grid 行列，不重建字段编辑器、录入控件或设置 VM。原有音频/视频窄屏布局继续复用。大字号采用用户当前 PlayerTypography，不在本 feature 重新调整。

## 截图与安全区

仅场景截图仍针对内部设计画布的 scene，完整 PNG 1920×1080，存档预览仍为 480×270。包含 UI 的截图继续捕获实际 GameShell：桌面仍为原设计空间；移动改为当前安全视口尺寸，包含黑边和独立工具栏，预览仍限制在 720×405 内。此尺寸变化明确记录到规范，不改变内容、profile 或存档格式。

不重复扣除平台 InsetsManager 已提供的安全区。普通视口宽度包括当前安全内容区，旋转后重新测量。完整竖屏游戏重构不在本轮承诺范围。

## 验证

修改前先用同一字体、对白和 1280×720 Headless 视口采集桌面游戏 PNG/几何。修改后对比像素和位置，检查桌面未进入移动模式。移动测试覆盖普通横屏、超宽横屏和窄视口的布局、命中、更多/返回、资源与状态保留、截图尺寸。Headless 不代替真机安全区或手指操作验收。
