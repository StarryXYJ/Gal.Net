# Sample 与默认宿主的项目扩展边界

状态：implementation。用户已确认范围并授权实现、验证及 Git 提交。

## 用户目标

以 Sample.Avalonia 作为未来游戏模板。开发者可以在自己的项目中定制 UI、数据模型、设置、服务、Gallery 和剧情交互；优先开放必要接口、组合和局部重载，不为手机、小游戏、商城逐项建设框架。代码增量应小，设计简洁、低耦合。

## 范围

- 默认设置/启动服务可替换，消费者不强制依赖默认偏好 DTO。
- 复用现有页面注册、DI 与导航；允许扩展默认 VM、替换服务和手写 XAML。
- 项目服务可绑定玩家 scope 与当前运行，并随失败、停止和释放清理。
- 外部变量写入与 Engine 的执行/恢复同步，立即存档不丢失显式修改。
- 整理共享本地化适配和 Headless 的错误传播/资源所有权。
- 以真实接入测试和手册说明验证模板可扩展性。

## 非目标

不实现手机、小游戏、商城、通用活动/覆盖层系统、订单协议、任意复杂状态的原地续玩或主题运行期切换；项目通过已有模块、状态恢复、XAML 和服务自行实现业务。

## 约束与依赖

- 底层重构 F-20261026-01 已 completed；以当前接口为基线，不重复它的配置/模块分层工作。
- 开工时 EntryModule、PrimitiveArgumentHelper、PrimitiveRegistry、CompositeGameView 及 InvocationFieldDecodingTests 存在其他改动；不修改、不提交这些内容。
- 无兼容层要求；保留有真实用途的现有 API，避免平行框架。
- 不持有执行锁等待 UI/网络，不将服务/Task 写入存档。

## 验收

1. 自定义设置模型与手写 View 能复用默认会话；默认设置继续恢复、应用、保存。
2. 自定义标题 VM/按钮/页面可从启动进入并返回；DI 服务可在注册前后替换。
3. 玩家/运行绑定在正常结束和失败时按所有权释放；过期运行写入被拒绝。
4. 显式外部变量更新在当前剧情可读，合法检查点立即保存包含更新，玩家变量可落盘重开。
5. 本地化 culture-first/覆盖/空译文语义保持；Headless 对 EOF/引擎失败返回失败。
6. 相关构建与回归通过，正式文档、review、summary 完成，提交仅含本 feature。
