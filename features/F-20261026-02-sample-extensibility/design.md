# 设计：开放现有边界，复用默认实现

## 决策

1. 设置宿主依赖一个小接口，只消费 PlaybackOptions、AudioMixOptions、文本速度及接入/保存/窗口生命周期；项目 DTO 不进入接口。页面仍通过已有 IPlayerSettingsService 读取可选分类，纯 XAML 可直接使用项目服务。
2. 默认 DI 使用 TryAdd，默认页面 VM 开放继承和必要命令重载。项目通过现有类型注册将默认 VM 别名指向自己的派生 VM，并注册自己的 View；无需新建路由角色/菜单贡献框架。完整 Shell 可由组合根替换。
3. 将调试专用的运行绑定推广为项目运行绑定，并补玩家绑定；使用 IDisposable 表达借用关系。玩家绑定在资源与设置就绪后接入，运行绑定在 Prepare 完成后接入；停止后释放绑定，最后释放玩家和资源。
4. 外部变量更新提供小型、带显式 player./save. 作用域的 Engine 批量入口；校验在提交前完成，执行门与状态同步边界内修改。保留稳定检查点的游标与领域状态，仅合入外部显式修改的存档变量。请求绑定调用时的运行 scope，恢复/停止后拒绝旧请求。不把它包装成万能业务事务或任意异步 Runtime 回调。
5. 本地化的通用查询与 Avalonia provider 桥接分别归中立宿主和 Avalonia 宿主，Sample 只配置资源。保留 culture-first 与按源覆盖的规则，不引入 Runtime 对 UI 库的依赖。
6. Headless 使用现有玩家服务所有权和 Engine 终态事件，观察输入及保存任务的失败；取消不能伪装成可取消的 Console.ReadLine。

## 用户故事的落点

- 标题按钮/新页面：派生默认 VM 或自有页面 VM + DI + Register。
- 手写设置：自己的模型/服务实现设置接口，自己的 XAML 绑定；自动 DTO UI 可选。
- Gallery：已有类型→页面注册；任意图鉴可使用普通页面和自己的数据。
- 小游戏/手机：项目模块、阻塞 primitive、自己的 XAML/状态/恢复，使用运行绑定与变量入口。
- 商城：项目玩家级服务、自己的订单与幂等规则；通过玩家绑定取得 profile 服务，运行期修改走 Engine 入口。

## 取舍与风险

- 选择可替换接口和局部继承，避免给每个具体类增加接口或把所有成员 virtual。
- 变量入口保证显式批量值的预校验及执行同步；不保证网络事务、任意业务回调回滚，也不改变已有阻塞活动的稳定快照语义。
- 注册/绑定失败必须清理已取得的资源；停止和销毁均不能留下旧回调。
- 用户已有源码改动不属于本 feature，验证以当前组合工作区为准，提交精确选择本次文件。
