# 设计

## 当前事实

CLI 已有机器帮助、契约查询、原始查询、校验及文档批次；文件操作只允许单条，不能与文档操作混批。Editor 使用 ProjectContentSession 管理工作版/保存基线，Repository 另持作者源字节基线。GUI 历史操作可能持有 DTO/文件身份，不能直接重载磁盘后继续执行旧历史。

## 数据流与职责

外部 Agent → CLI 查询/生成/预览/发布 → 项目磁盘 → Editor 文件监听与定期复核 → 后台候选快照 → 会话门内采纳 → 既有文档/资源通知 → 打开视图刷新。

1. Shared 负责候选读取与验证，以及在项目会话中更新保存基线。读取先后核对文件集合/哈希，拒绝正在变化的候选；使用 Authoring 校验，不因合法的未知/不完整作者参数而拒绝刷新。
2. Editor 的项目级监听器合并通知、有限重试，并在 UI 线程采纳候选。自己的保存以基线哈希去重；发布中的事务不读取。周期复核弥补监听事件合并/遗漏。
3. 自动采纳仅发生于会话干净、无输入草稿、无编辑/保存执行、无 RepairRequired 时。冲突保留内存和磁盘双方，不自动写盘。明确的“从磁盘重新加载”在确认后放弃本地作者修改，不关闭项目或 Dock。
4. 采纳保持项目 scope 和已有 Group 文档身份；按稳定节点/Entry 身份同步视图。保存基线、settings 原始字节、Repository 的源基线及受管理文本一起推进。源节点被删时关闭对应 Group 页，其他页面和布局保留。
5. 采纳是旧历史的边界：释放 Undo/Redo 后再允许编辑；刷新本身不制造 AI 专属 Undo。Git restore/revert 造成的磁盘变化走同一热重载路径。

## 外部批次

CLI 的事务 publication manifest 是外部写入边界。Editor 在存在 prepared/publishing/repair-required 事务时推迟采纳，不靠固定延迟猜测批次完成。任意程序的普通文件保存通过稳定哈希快照处理；没有提交协议的多个保存不能声称来自同一个原子事务。

批量应用采用明确的项目变更清单，给新建作者文件和资源提供同一个发布入口。清单中的写入/删除必须有期望原哈希，新增文件要求原先不存在。预览和正式执行都校验最终候选项目，正式执行复核原文件及输入载荷后通过既有作者事务发布。大资源从暂存文件复制，不把图片/音频嵌入 JSON。

## Skill 与 Git

Skill 说明“发现 CLI → 查询项目/契约 → 检查已有修改 → 生成预览 → 应用 → 校验 → 展示 diff”。CLI 帮助是参数真相来源，不在 Skill 复制所有指令。项目 Git 是可选的版本控制；回退已有成功变更需要 Git 或用户备份，CLI 的失败补偿不宣称持久 Undo。

## 取舍与边界

首版保守地在项目存在本地未保存内容时暂停自动采纳，不实现自动三方合并。它保留本地历史和草稿，常见“保存 Editor → 外部 Agent 改项目 → 自动刷新”的路径直接可用。契约 DLL 的 scope 重建涉及平台实现和预览生命周期，本阶段显式提示而不沿用变化后的 DLL。普通作者内容和资源热重载不重启 Editor。

验证重点是候选读取/采纳交错、自己的保存不误刷新、草稿/坏 JSON 保留、结构创建删除与已开 Group 同步、采纳后 Save All 不再报旧基线冲突，以及 Git 恢复文件后可再次采纳。
