# 递归字段树与属性遍历设计

此文保留前期讨论历史，正式设计与当前实施状态见独立 [F-20261027-03-recursive-properties](../F-20261027-03-recursive-properties/feature.md)。

状态：design；用户于 2026-10-27 提出嵌套结构采用类似 Unity 的迭代序列化方式，统一编辑和检查逻辑。此文记录目标与分阶段边界，尚未实现，不作为当前 spec。

## 问题与目标

目前 ValueCodec 使用字段值类型及 JsonSerializerOptions 进行转换；StructuredFieldEditor 自行反射嵌套 DTO Schema、计算 wire 名称和建立子绑定；LocalizationReferenceIndex 又独立识别 DTO/集合和反射成员。Transform、Flipbook 及动态参数编辑器还拥有各自的子字段描述与 JSON patch。内置 Transform 在 Entry DTO 中保存为 JsonElement，因此能被专用控件编辑，却被本地化索引判定为不可遍历。

目标是类似 SerializedObject / SerializedProperty 的字段描述、属性视图和迭代入口。序列化、通用与专用表单、子值校验、引用索引和字段定位共享同一结构事实。专用控件继续负责交互布局，领域服务继续拥有业务规则。消除 Transform 等已知结构的分析盲区，同时保留对真正未知结构的覆盖提醒。

不采用逐字段“确定不含引用”的跳过标记作为这次修复的主体，也不按字段名、EditorId 或看起来像 key 的字符串猜测语义。

## 统一结构描述

以现有 FieldDescriptor / ValueDescriptor / IFieldDto 为基础增加结构解析能力，避免建立第二套字段配置。结构种类包括标量、对象、序列、字符串键映射和不透明值；动态字段由解析器返回上述某一种结构或明确的未解析结果。

- 对象提供有序 FieldDescriptor、字段身份与实际 JSON 名称的映射；允许递归类型，子结构延迟解析，不能在初始化时无限展开。
- 序列提供元素描述；映射提供值描述和实际键，字典不能仅被当作任意对象，也不能让任意 JSON 自动变成已知映射。
- 每个叶字段保留现有类型、约束、默认值、编辑提示和 LocalizedText / CharacterReference 语义。引用语义始终来自契约。
- 生成器为可描述 DTO 提供结构入口，手写 schema 使用同一接口。实际 wire 名称与 converter 规则以 codec 为准，不能让遍历和落盘各用一套命名逻辑。
- 结构元数据按契约生命周期缓存；动态解析结果还绑定其作者依赖与资源版本，项目卸载不得留下对插件程序集或旧项目的永久缓存。

固定结构优先直接使用可描述的类型。对目前保存为 JsonElement 的兼容字段，允许契约声明其结构类型/适配器，例如 Transform 映射 LayerTransform、Flipbook 映射 FlipbookDefinition。具体声明 API 在基础层实现时确定；结构映射不能改变外层 wire 类型或变成绕过校验的机制。

## 属性视图与迭代

中立属性视图建立在不可变 JSON 快照与结构描述之上，不通过构造作者 DTO 或运行属性 setter 来扫描数据。属性提供当前值、缺省/null/已提供状态、实际 wire 路径、字段元数据、结构解析状态和子节点枚举。

提供类似 FindProperty 与 GetIterator 的入口。内部用显式栈进行深度优先遍历，并设置深度、节点预算、取消和未解析结构结果；消费者可选择只遍历当前层或进入子节点。对象字段缺省时可显示描述与默认值，但只读遍历不写入默认值。未知成员保留独立节点与未解析状态，不能悄悄认定其中无引用。

路径使用类型化的成员、索引和映射键片段；JSON Pointer 仅作对外编码，统一处理 `~` 与 `/`。同一路径由引用诊断、草稿、子值校验和导航共用。Group/Entry 的稳定身份与作者代次属于 Editor 的外层地址，不混入通用结构描述。

列表下标仅表示当前快照内的位置。删除、移动或替换列表使旧属性句柄失效，不能让旧子字段草稿或异步导航落到新的第 N 项；已有稳定元素身份的领域结构可提供身份映射。

## 读取、编辑与落盘

Core 提供平台无关的结构解析、路径、快照读取与遍历协议，现有 ValueCodec 仍是 JSON 转换入口，并逐步使用共享结构描述处理嵌套成员。编辑器项目层在其上包装 SerializedObject 风格的编辑会话和 SerializedProperty 风格的属性句柄，写入仍通过现有 FieldEditorContext、项目作者意图、历史与保存事务。

子属性写入生成局部 patch，不把整个根值反序列化再序列化；保留未知 JSON、原成员大小写、缺省/null 以及无关的兄弟字段。已存在的 JSON 字符串包裹对象格式由显式适配器读取和回写，保持原有编码方式；不把普通字符串当 JSON 递归解析。格式冲突或重复别名必须报告，不任意选择一个成员。

结构与字段规则的校验共用属性树；“目标是否存在”“缩放必须为正”“Flipbook FrameCount 不超过容量”等业务规则仍由各自领域拥有，诊断使用相同路径返回。不能把“可遍历”当作“值合法”，也不能把引用扫描成功当作完整项目校验通过。

## 动态结构

音效/视觉效果参数根据类型、program 或目标上下文查询对应目录的参数描述；Timeline 的固定轨道/关键帧结构可直接描述，事件参数再按事件类型解析。解析器是读取契约和依赖快照的纯查询，不执行游戏 Entry 或任意属性 getter，不把 Avalonia 控件作为结构来源。

解析缺少依赖、未知类型、结构损坏或达到预算时返回有位置的分析不完整结果。实际引用缺失则返回独立的引用错误。明确区分“已知结构且没有引用”和“还不知道内部结构”，不能通过统一隐藏 field.opaque 让角色删除等操作误判引用不存在。

## 分层与迁移

| 层 | 职责 |
| --- | --- |
| Core.Parameters | 字段/值结构、路径、codec 协议与有界快照遍历，无 UI 或项目 I/O |
| Contracts.Builtins | 内置结构声明、兼容适配及领域契约 |
| Editor.Shared / 项目查询 | 作者地址、动态结构上下文与只读引用索引 |
| Controls / Editor | 属性绑定、草稿与历史桥接、通用/专用控件布局、问题导航 |

按可验证阶段推进，不一次性重写所有存储格式：

1. **基础协议**：统一 DTO/对象、列表和映射的结构解析、命名、路径与有界迭代；覆盖递归类型、serializer options/converter、缺省/null、未知成员和失效句柄。
2. **固定内置结构与引用检查**：给 Transform、Flipbook 及其他确定的固定 JSON 结构提供正式描述，索引迁入统一遍历。正常非空 Transform 不再报 opaque；嵌套文本/角色仍能识别，未知扩展结构保持分析不完整。
3. **表单和校验接入**：通用对象/集合及 Transform、Flipbook 专用布局使用同一子属性与描述；验证局部 patch、关闭重开、Undo/Redo、跨视图草稿、深层字段定位和无默认写入。
4. **动态参数与 Timeline**：接入效果目录和事件契约，验证切类型/切资源、未知类型、局部 patch、异步结果过期及契约卸载；迁完对应消费者后删除重复的结构反射/字段清单。

每阶段必须验证相同字段在表单、校验、索引和 codec 中的名称、路径及类型一致。原作者 JSON、运行数据和旧项目兼容是退出条件；不能只用警告数量下降作为验收依据。

## 取舍与风险

采用共享结构与属性游标，而不是只在 LocalizationReferenceIndex 特判 Transform；前者能消除表单和分析长期分叉。保留契约控制的可遍历类型，不扫描所有 public getter，避免把计算属性（如 Flipbook Capacity）变成可写作者字段。

不强制所有 JsonElement 立即替换成 CLR DTO，否则未知成员、历史字符串编码、动态参数和 presence 都可能丢失。类型结构与 wire 表示可通过显式适配共存，最终是否迁移文件格式应另有明确版本与迁移方案。

本设计涉及共享元数据及多模块消费，范围超出原先仅修复警告定位的补丁；实现证据与实际退出状态应按以上阶段追加记录。当前尚未修改业务代码，不声称正常 Transform 警告已经消失。
