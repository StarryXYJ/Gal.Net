# Editor UI 第二轮优化分析

日期：2026-10-25。状态：analysis / proposed，尚未实施或完成视觉验收。

归属：原 Editor UIUX feature 的后续设计。用户本轮要求纯分析；不将此前实施授权延伸到本轮，不修改业务代码、运行配置或正式规范。本文基于当前工作区源码与规范，包含已有未提交改动；没有启动真实窗口测量像素、DPI 或输入法行为。

## 目标与边界

提高控件对齐、列表操作密度、表格可用面积与编辑连续性。沿用现有项目历史、稳定身份、作者文档与冲突检查，不引入文件格式、运行期语义或自动保存策略变化。

“减少文本”主要针对重复操作按钮与常驻说明；字段含义、状态区别及有影响的操作仍需可理解。沿用调试页已有 EditorIconButton：32×32 点击区域、16 左右图标、透明背景、键盘焦点框、禁用提示。新增、应用、还原、删除、定位、导入、导出使用一致图形与本地化 Tooltip/AutomationProperties.Name。不以 Unicode 字符或 emoji 代替正式图标资源，也不重新引入全局 hover 动画改造。

## 1. GameTextBox 的输入框对齐

当前事实：

- BranchOptionListEditorControl 中 GameTextBox 与 ConditionEditorControl 已同时设置 VerticalAlignment=Center。该文件有本轮开工前的未提交修改，应保留。
- GameTextBox 包装 FieldEditorRow，后者内部编辑器和操作区均为 Top，默认两行并有 RowSpacing=4。
- GameTextFieldEditor 返回输入框与可见性动态变化的提示 StackPanel；缺译、共享文本可能增加高度。ConditionEditorControl 也有独立错误行。

因此不能只在外层重复加 Center 就宣称解决。具体像素偏移仍需挂载测量；以上结构是调查线索，不是已复现的唯一根因。

建议：以“主输入行”作为对齐单位，正文输入、条件输入、拖动柄、删除及重置按钮对齐同一中线；缺译、共享、错误放到输入行下方。输入区保持横向填满，单行文字垂直居中，多行正文保留顶部阅读起点。优先提供局部紧凑/行内布局，避免修改通用 FieldEditorRow 后影响全部 DTO 多行表单。禁止用固定负 Margin 校正某个 DPI 的视觉误差。

验收：比较实际 TextBox.Bounds 而非仅外层 Bounds；覆盖普通/共享/缺译/错误、窄 Inspector、长条件、100%/150%/200% DPI。提示出现不使相邻主输入框上下跳动。

## 2. Inspector 将预览放到最后

当前事实：AssetInspectorControl 普通图片预览在 Filter/Compression 前；ImageVariantsEditor 自带预览，但其后还有 JSON 修复区。视频当前只有标题与压缩设置，没有真实视频播放器。

建议结构：

1. 对象信息：名称、路径、可复制 ID。
2. 编辑设置：过滤/压缩、变体目录、维度、默认值与应用操作。
3. 高级/JSON 修复及配置诊断。
4. 最后一块统一预览：普通图片、变体图片或音频控制；变体选择器、请求/实际结果、回退说明属于预览区。

建议将预览作为 Inspector 底部独立区域，上部属性滚动，下部预览高度可调并可折叠。与“仅把 Image 移到长 StackPanel 末尾”相比，可在编辑属性时持续看到结果；也避免预览内部与外部形成重复区域。低高度时允许收起，预览需有高度上限，防止属性区被挤没。视频保留当前能力，真实视频预览另行评估。

拆分的是视图区域，不复制 ViewModel、图像加载或音频播放器所有权。切对象、锁定/解锁和关闭仍按原生命周期处理，预览错误就近显示；配置错误保留在配置区。透明图片建议棋盘底色，点击原尺寸查看可列后续增强。

## 3. 角色表：列表与紧凑编辑条

当前为搜索+文字新增、双列表头、姓名/key 列表、双输入及三个文字操作按钮。固定双等宽列让短姓名与较长 key 竞争空间；未选中时编辑区仍占空间。

建议：

- 顶部搜索横向伸展，右侧固定“＋”图标，复用调试页工具栏视觉。
- 列表优先展示姓名，key 使用较弱颜色和省略号，完整值通过提示/复制获取。宽面板保留双列，窄面板改为姓名下方显示 key。
- 选中/新建时显示底部编辑区；姓名与 key 保留简短标签，key 不只依赖 placeholder 表达含义。
- 应用、还原、删除改为勾号/回转/垃圾桶图标，固定在编辑区操作侧；有草稿标记，未改动时禁用应用与还原。
- 删除不可用时解释“仍被引用”或“分析未完成”，不能只呈现灰色按钮。
- 新建后聚焦姓名；应用成功后保留并滚动到角色；不要在修改 key 时顺带修改姓名文本身份。

额外发现：当前选择变化会 Load 新声明，搜索刷新又可能保留旧草稿但让 Selected 变空。应明确绑定草稿所属角色，避免搜索过滤后编辑内容与可操作对象脱节。建议按角色身份保存草稿；尚未创建的新角色用独立草稿身份，key 可改，不能直接把可变 key 当成永久身份。此扩展需在实现时选择合适的会话身份方案。

## 4. 游戏本地化：表格优先，低频配置按需展开

当前事实：顶部常驻语言新增、放弃草稿、交换语言与选项、导入导出、开发语言预览/应用；导入预览还会继续增加顶部高度。分类固定 190，表格上下文约 188、每语言列 244；每行定位是文字按钮，每格另有状态与错误文本。当前没有表内搜索/状态筛选入口。横向滚动覆盖上下文列，长表纵向滚动时列头是否持续可见应实测。

建议主布局：

- 分类导航宽度可调，小窗口可折叠；保留分类名称。
- 一行主工具栏：文本搜索、目标语言与状态筛选；右侧定位明确的语言管理、导入、导出、更多图标。
- “语言管理”弹层承接新增、排序及开发语言切换；语言代码与“开发语言”标记保留文本。开发语言切换继续先检查、再明确应用，展示影响范围。
- 导出弹层保留目标语言、当前/全部分类、模板/运行文本等有意义的标签；导入采用独立预览对话框或展开面板，显示目标语言、变化/跳过/清空数量与明细，保留显式空串授权及应用/取消文字。
- 表格语言列头持续可见；上下文列固定，语言列共享横向滚动偏移。固定区和可滚动区必须共享行高与纵向位置，避免长译文使行错位。
- 列头调序按钮改为统一图标或列头菜单；行定位改为图标；状态用小图标/短标签+提示，错误文本仍贴近单元格。
- 常见筛选为缺译、待复核、有草稿；空字符串与缺译、复核未知与已完成不能被合并。搜索/筛选只影响投影，草稿仍绑定原文本与语言身份。
- 后续可考虑只显示开发语言+选定目标语言，其余语言按需显示，降低多语言横向滚动成本。

现有表格已有 ListBox 虚拟化，不应为了视觉重排改成全量 ItemsControl。列宽可调和冻结列有价值，但复杂度高于替换图标，宜单独验证。表头、错误行与列表的同步应在真实长表/长译文场景验收。

## 5. 变量子页选择、草稿与右上角新增

当前事实：OnScopeIndexChanged 明确清空 baseline 和 Selected，再 Refresh；没有每个作用域的最后 UID。选择变化会 LoadDraft，未应用输入也会随之被替换。列表宽度固定 240，新增文字按钮在列表下方。VariablesPanelViewModel 为 transient，关闭 Dock 时 Dispose，因此同一面板内切页保留与关闭重开保留是两个不同范围。

建议：

- 每个作用域保存 LastSelectedUid；切换前保存当前页状态，切回按 UID 恢复，禁止按行号或名称定位。
- 同时保存未应用草稿与原声明快照。最低要求是两个子页各保留当前编辑项；更一致的方案是用 (Scope, Uid) 缓存已编辑草稿，让同页换项也不丢输入。
- 状态先限定当前项目会话，不写作者 JSON、不进入撤销历史、不跨项目串用。若要求关闭重开也保留，用项目 scope 的状态服务承载，ViewModel/控件仍可正常释放，不靠保留旧控件实现。
- 外部改名按 UID 恢复；外部修改同一声明保留草稿并在应用时检查基线；目标删除后取消有效选择并显示失效草稿/显式放弃入口，禁止重绑到同名新变量。
- 新增后选中新 UID、滚动可见并聚焦名称。当前 Add 是立即创建声明的一条历史，图标调整不暗中改成“输入后才创建”。
- 列表顶端设置“搜索 / 数量 / ＋”标题条，右上角图标常驻。优先独立 Auto 行，避免覆盖第一项、滚动条或空状态。列表与详情改用可拖分隔条，窄宽度时允许上下布局。
- 如果采用叠加“＋”，只覆盖预留的标题空间；明确 Z 顺序和自身命中区域。按实际父控件监听的 PointerPressed/Released/Click 阶段阻止选择、清空或拖动副作用，不能只处理 Click 后认定事件已隔离，也不能在隧道路由里提前吞掉按钮激活。保留正常键盘激活与焦点导航。

不把切页操作做成隐式 Apply；保留用户对草稿提交的控制。Save All 当前只保存已应用的变量/角色声明，与本地化单元格会提交草稿的策略不同；本轮先让界面明确“未应用”，如要统一必须另列行为设计。

## 6. 其他 UI/UX 改进与优先级

| 优先级 | 建议 | 理由与边界 |
| --- | --- | --- |
| P0 | 变量选择与草稿分作用域保留 | 高频切换导致编辑上下文和输入丢失，应先解决 |
| P0 | GameTextBox 主输入行对齐 | 需要实际挂载证明；兼顾提示、错误与多行 |
| P1 | 预览统一放最后，属性与预览可分别分配空间 | 避免预览打断设置流程 |
| P1 | 角色/变量/本地化复用同一图标与工具栏规范 | 降低文字噪声；复用已有样式，不重做主题 |
| P1 | 本地化低频配置移入弹层 | 直接增加表格可见面积 |
| P1 | 变量列表搜索、类型小标记、描述截断 | 当前描述长文换行会让列表扫描效率下降 |
| P1 | 未选中、空列表、无搜索结果各有对应提示 | 不能都只留下大片空白或禁用表单 |
| P1 | 明确草稿/已应用未保存/错误状态 | 当前不同面板提交策略有差异，操作图标化后更需要反馈 |
| P2 | 本地化冻结上下文和列头、列宽/可见列、状态筛选 | 长表收益大，需要滚动同步和性能验证 |
| P2 | 角色与分类搜索前后的身份/滚动恢复 | 防止筛选使编辑对象丢失或跳到别项 |

建议额外统一：只读 ID/路径可选择与复制；长文本省略时可查看完整值；操作失败就近显示而非只有底部总错误；禁用动作说明原因；图标保留 Tab 焦点和可访问名称；窄 Dock 下不要依靠 WrapPanel 无限堆叠把内容区挤没。删除等操作已有项目撤销能力，不一律增加确认弹窗。

## 后续实施与验收影响

建议先做选择/草稿状态及主输入行布局，再收口图标与预览，最后重排本地化表格。前两部分验收通过后再扩大表格结构，便于定位回归。本文不替代实施 Phase 计划。

状态验证需要覆盖：玩家 A → 存档 B → 玩家 A、双方未应用输入、新增、改名、外部刷新、删除/撤销、同名新 UID、项目关闭；关闭重开的项目会话保留仅在采纳该扩展后加入。新加号要真实点击验证不触发列表选择/空白清除/拖动，且只新增一次。

视觉验收需要覆盖：宽/窄/低高度 Dock、浮动/最大化、四种 UI 语言、长姓名/key/描述/译文、亮暗主题、DPI、键盘与 IME；本地化大量行保持虚拟化，滚动后编辑身份正确。必须保留缺译/空串、过期导入预览、开发语言切换证据和单次历史等已有语义回归。
