# 游戏本地化 UI 再精简：分析与修订建议

日期：2026-10-25。状态：analysis / proposed。本轮分析当前实现、用户反馈和官方资源编辑器资料，不修改业务代码或正式规范。此前第二轮实施授权不作为本轮新行为的实施状态；语言移除、单元格浏览/编辑模式及状态降噪均尚未实现。

## 结论

上一轮将按钮图标化，但保留了大量常驻状态、整行筛选和每格独立的大输入框，信息密度仍然偏低。建议收敛成“紧凑资源表＋按需语言管理”，以对照原文、填写译文和定位出处为主流程。

## 当前事实

- GameLocalizationPanelView 主工具栏下仍有单独一整行目标语言与四种状态筛选。目标语言又与导出/平铺导入共用 ExchangeLanguage，显示所有语言的表格为什么还要选一个语言，不够直观。
- 每个单元格一直使用多行 TextBox，MinHeight=64、MaxHeight=160，下方再显示缺译/空串及复核状态；每列固定 244。表格观感更接近一排表单。
- 语言列头为每个非开发语言放两个左右按钮；行定位按钮则放在位置文字下方。即使内容很短，操作区仍明显抬高行高。
- 管理语言弹层目前只有新增输入和开发语言切换，没有展示“已有语言”的专门管理列表，也没有移除入口。服务只有 AddLanguageAsync、MoveLanguageAsync 和开发语言切换，没有 RemoveLanguageAsync。
- 语言管理图标是上一轮手写的 PanelLanguageIcon 复合 Path，不是现成的 Ursa 图标。用户已反馈显示不完整；本轮未挂载测量裁剪，不将原因直接断言为按钮宽度或某个模板问题。
- 固定列与左上角目前绑定 SemiColorBackground0；GameLocalizationPanelView 自身未显式建立表格底色。Violet/Aurora 的该画刷定义为不透明颜色，但它是否与实际 Dock/ListBox/选中行的底色一致，不能仅凭资源名认定。视觉反馈中的透明/不一致需要通过最终合成效果验收。

源码入口：Views/GameLocalizationPanelView.axaml 及 code-behind、ViewModels/GameLocalizationPanelViewModel.cs、Services/GameLocalizationPanelService.cs、Themes/AuthoringPanelResources.axaml，均位于 src/Editor/GalNet.Editor/。

## 1. 复核与草稿是否必要

| 概念 | 现在的含义 | 建议 |
| --- | --- | --- |
| 待复核 | 译文关联的原文指纹与当前原文不同；只说明原文变了，不能证明译文已经不正确 | 默认取消常驻筛选与格下文字。可选地显示小角标，提示“原文已变更”；不新增审核步骤或阻止正常保存 |
| 复核未知 | 没有足够的原文关联证据 | 正常表格不展示，避免导入后整表充满不能直接处理的提示 |
| 有草稿 | 当前输入还未通过失焦/Ctrl+Enter 等提交为项目内容，不是另存的翻译版本 | 保留防丢输入、冲突基线和 Save All 协调，取消常驻“有草稿”筛选和独立的用户流程 |
| 缺译 | 没有该语言的直接译文 | 保留为有用的筛选和单元格提示；默认用轻量占位/标记，不为每格增加状态行 |

原文指纹目前属于作者 metadata；Runtime 不依赖复核状态运行，当前发布语义检查也不把“待复核”作为缺译错误。复核证据可继续供导入判断与可选提示使用，没有必要让普通作者承担审核工作流。若以后决定完全移除这项功能，应另行清理 metadata 写入、复制及交换测试，不能仅删除表格文字后宣称机制已移除。

草稿与“已提交但尚未 Save All”的内容不同。保留内部草稿的理由是切分类、关闭重开、输入法组合和冲突时不丢输入；正常编辑不需要用户理解“存草稿”。保持现有失焦/Ctrl+Enter 提交与 Escape 取消，冲突发生时才展示就近错误；全局“放弃所有草稿”移到更多菜单，限定范围、只在有输入时可用。

## 2. 语言管理与新增候选

建议弹层或小型管理窗口分两段：

```text
项目语言
中文（简体）  zh-CN       开发语言
English       en-US         [移除]
日本語        ja-JP         [移除]
───────────────────────────────
[ 搜索语言名称或代码…        ▾ ] [+]
```

- 已有列表显示原生语言名＋标准 culture code；开发语言有清晰标记，不能直接移除。设置开发语言作为行菜单动作，只有执行该动作时展开影响预览与应用，不常驻另一整套表单。
- 新增候选来自 CultureInfo 的有效文化与常用预设，包含中性及地区/脚本文化；支持按 code、原生名和英文名搜索，排除已选的规范化 code，选择后得到确切 culture。允许直接输入合法 code，不强迫只选少数预设。
- 项目锁定 Irihi.Ursa 2.1.0。已安装 DLL 中可以确认 MultiAutoCompleteBox、MultiComboBox；项目现有 ComboBox IsEditable=True 也已有使用。单项新增先验证可编辑 ComboBox/AutoCompleteBox 在 Semi/Ursa 主题中的体验，不为单项新增强套多选控件。若不能提供期望的候选过滤/键盘行为，复用人物选择器的“输入＋候选列表”交互模式，候选数据与创建语义独立。
- Enter 接受高亮候选，明确“＋”或确认动作才添加；失焦搜索不新增语言。IME Enter 不被截走。输入无法解析时就近提示；不得把显示名当成 culture code 写入配置。
- 列调序集中到此处的拖动/行菜单，移除每个语言列头的两个常驻箭头。显示/隐藏语言列属于视图设置，必须与“从项目移除”区分。
- 替换手写语言图标为清晰的现成图形，保持统一图标尺寸和点击区域；以实际轮廓、缩放、主题及 Bounds 检查完整性，不把裁剪问题简单扩大按钮后了事。

### 移除语言的建议语义

当前 UI 没有办法执行该操作，属于缺失功能。建议默认动作命名为“从项目语言列表移除”：移除 AvailableLocales 中的该语言并隐藏其列，保留翻译文件与复核证据，重新添加可继续使用原译文，配置变更支持一次撤销。保留文件也意味着不承诺该语言字节已从发布包或磁盘清除。

“同时删除翻译文件”属于另一种有内容损失的操作，若需要应单独设计并显示文件范围，复用项目文件事务；本轮不把它偷偷附加到移除列表动作上。

有该语言未提交输入时，必须先解决这些输入或明确放弃后再移除，不把其他语言输入顺带提交；不允许留下隐藏、失效且持续阻止 Save All 的草稿。当前开发语言不可移除，需先切换。针对该语言的导入预览应失效，应用中的导入需协调，历史实际执行时还要复查语言与项目身份，防旧单元格继续写入被移除语言。

## 3. 定位列按用户提出的两列布局

去掉左上角“上下文”标题，保留与语言表头对齐所需的空白角格。行内使用文字列＋固定宽度操作列，按钮跨两行垂直居中：

```text
e84a…19c2      ┌────┐
content        │ ↗  │
               └────┘
```

- Group：左上为条目 ID（长 ID 省略显示，提示和复制提供完整值），左下为槽位，如 content 或嵌套字段路径。显示序号与稳定 ID 不混用，导航仍使用真实完整身份。
- 分支：左上为分支名/ID，左下为选项身份与槽位；完整分支、选项身份和路径放提示。不能仅用会随排序变化的“选项 2”承担导航身份。
- 角色：左侧显示角色名，ID 放提示或次级文字，右侧为居中定位按钮；没有意义的槽位不硬凑一行。
- Context 当前是拼接完成的展示字符串。需在服务投影中提供结构化主标签、副标签、完整路径和引用目标，不能通过拆分“·”或当前中文文案倒推身份。所有类别仍保留原引用对象供定位。
- 同一文本被多处共享时继续合并一行，用轻量数量提示；多引用定位能选择具体出处，避免按钮永远跳到第一处且界面看不出还有其他位置。

表格根面板、固定列、空白角格统一绑定同一个表面画刷，填充必须不透明，文字变浅使用文字颜色，不对固定列父容器降 Opacity。悬停/选中时固定列和其余行保持同样的表面状态；滚动后不得透出后方译文。验收同时检查原始画刷与最终渲染。

## 4. 参考资源编辑器后建议的整体布局

```text
[搜索…………………………] [仅缺译]   [语言] [导入] [导出] [更多]
──────────────────────────────────────────────────────
位置（不显示此标题） │ 中文（开发） │ English │ 日本語
条目 ID         [↗] │ 原文……       │ 译文……  │ 译文……
槽位                │              │         │
```

1. 默认仅一行工具栏，取消目标语言＋四状态占一整行的布局。导出/平铺导入的目标语言放进交换操作，不与表格筛选混用。仅缺译检查当前显示的非开发语言列，任一缺译即保留该行。
2. 表格浏览态使用紧凑文字单元格，默认约 48–56 DIP 的双行定位行；仅活动单元格进入输入态。移除所有格常驻输入框底色和最小 64 高限制；长文通过展开编辑器/弹层处理，不把整个表格持续撑高。
3. 开发语言固定显示，其他列按需显示。记住当前项目会话里的可见语言、列宽、分类和滚动位置；视图设置不写作者历史。列宽可调，避免固定 244 导致短文本浪费和长文本横向拥堵。
4. 缺译使用弱占位或小标记；显式空串与缺译继续区分，但不为每个空串开一行说明。冲突和错误才就近展开详情；复核提示可选，未知状态不展示。
5. 浏览态支持方向键、Enter/F2 编辑；编辑态保留文本箭头与多行 Enter、Ctrl+Enter 提交、Escape 取消，Tab/Shift+Tab 提交并切相邻单元格。冻结列不能遮住键盘聚焦的输入。
6. 保留真实行虚拟化和单元格稳定身份，避免为了固定列复制第二套列表。不预设必须换 DataGrid：当前项目没有该包依赖，具体控件需先验证 Avalonia 版本、虚拟化、多行编辑与输入法适配。

## 参考依据与取舍

- [Rider Localization Manager](https://www.jetbrains.com/help/rider/Resources__LocalizationManager.html)：左侧资源范围、行资源/列语言的工作表，可隐藏文化列，问题筛选按需开启。可借鉴语言可见性、集中表格和键盘定位；不照搬与 GalNet 稳定引用不同的 resx 身份规则。
- [Visual Studio Resource Explorer](https://learn.microsoft.com/en-us/visualstudio/ide/managing-application-resources-dotnet?view=visualstudio)：并列编辑译文、可见语言配置、工具栏搜索，以及单元格小标记和提示。可借鉴轻量提示、主题一致性；不直接把 .NET 占位符校验套到可能具有自定义富文本/参数语法的游戏正文。
- [Avalonia ComboBox](https://docs.avaloniaui.net/controls/input/selectors/combobox) 与 [AutoCompleteBox ItemsSource](https://api-docs.avaloniaui.net/docs/P_Avalonia_Controls_AutoCompleteBox_ItemsSource)：输入与候选列表已有基础能力；具体建议过滤与键盘体验仍要按项目版本挂载验证。
- [Ursa 官方仓库](https://github.com/irihitech/Ursa.Avalonia)：配合本机锁定的 2.1.0 包检查，不把当前网站或 main 分支的新 API 当成项目已安装能力。

建议顺序：先减去状态与重复工具栏、替换图标并完善已有语言列表；再完成定位列/不透明统一背景；最后验证紧凑浏览/活动编辑、列宽及可见语言。移除语言是新增作者行为，单独覆盖开发语言保护、撤销、草稿与导入交错。所有建议尚未实施，本轮不修改 Runtime、作者格式或既有保存边界。
