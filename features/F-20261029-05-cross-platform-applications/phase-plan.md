## P0 — 固定验证基线与关键风险

- **目标**：把平台支持建议变成可执行矩阵，避免先搭建大量模板再发现原生绑定或 AOT 不可用。
- **前置条件**：读取当时工作区状态，区分其他 feature 的变更；核对 global.json 和中央包版本。
- **涉及模块**：发布脚本、GamePackageExporter/GalpakInstaller、媒体后端、Avalonia 平台依赖、CI。
- **任务**：
  - 记录 Windows x64、Ubuntu 24.04 x64、macOS arm64/x64 的 SDK、编译器、原生库、显示/音频环境及最低版本证据；macOS 具体最低版本由依赖交集确定。
  - 对含剧情分片/资源补丁的真实夹具比较 galpak 与目录导出，追踪旁置内容、buildId、空目录及安装结果，确定完整交付集合。
  - 核对 Windows 宿主条件选择 VLC 与目标 RID 冲突的路径，记录 native 来源、架构和许可证。
  - 在 macOS 环境做 iOS 最小 Avalonia 页面、GameHost 会话、miniaudio 静态链接及 VLC 回调/AOT 探针；Android 对当前 .NET 目标和原生绑定做最小构建探针。
  - SDL3 验证 Avalonia 主线程中初始化与设备更新是否需要额外视频子系统，记录选定绑定及 native 版本来源。
- **测试**：先收集现有相关测试基线；探针使用隔离输出/restore 图。iOS 编译、模拟器、真机结果单独标识，不能用分析警告代替发布结果。
- **文档**：在 feature 下记录 environment-matrix.md 与验证日志索引，更新设计中的暂定方案和真实缺口。
- **风险**：WSL 权限、macOS/iOS 工具链、签名凭据或设备不可用；记录缺项并推进独立桌面工作。
- **退出条件**：内容闭包方案明确；桌面目标和依赖来源可复现；移动探针有真实结果或明确未验收项。未验证 iOS 时，P0 保持 in-progress，不能以桌面通过冒充整体 verified。

## P1 — Editor 内容导出切片

- **目标**：剧情作者无 SDK、无源码仓库也能导出可交付内容。
- **前置条件**：P0 的归档/目录完整性结论可用；不依赖移动探针完成。
- **涉及模块**：ExportPanelView/ViewModel、GameExportService、共享内容导出/安装器、CLI 内容导出、本地化及相关测试。
- **任务**：
  - UI 仅暴露 galpak 与内容文件夹，隐藏应用/整合 Sample 发行选项及其字段；保留维护者发布脚本。
  - 目录导出复用正式编译配置、验证及资源闭包，遵守现有作者快照/保存语义，不额外改变未保存内容策略。
  - 根据 P0 结论处理剧情包和资源覆盖包，确保单个导出操作得到明确完整的交付物；如需格式变化，先补兼容设计再实施。
  - 导出结果提示实际路径、错误与取消；相关语种同步。
- **测试**：同一项目两种导出安装后的内容身份、必要文件与补丁一致；无 SDK 的分发 Editor 实测导出；无效内容、取消和目标冲突不破坏原有产物。
- **文档**：更新内容打包与 Editor 使用说明，标明 galpak/目录交付方式。
- **风险**：旁置补丁漏收集、导出过程改变作者状态；针对这些行为设置回归。
- **退出条件**：两种 UI 导出都可安装并运行，原组合包入口不可见，导出不启动 PowerShell/dotnet 构建。

## P2 — 布局契约与无 SDK 合包

- **目标**：先在 Windows 交付“运行包 + 内容 -> 可运行游戏包”的完整切片，为其他平台复用。
- **前置条件**：P1；当前 Windows 运行包/契约基线可用。
- **涉及模块**：发行清单、应用路径定位、Editor.Headless 命令与服务、Storage 安装器、sh/ps1 薄入口。
- **任务**：
  - 定义版本化布局元数据，声明入口、RID、托管/原生/契约/内容根及 Player/Developer 能力；验证所有相对路径。
  - 发布工具与宿主共同使用布局规则，保留普通开发目录及现有 Windows 发行的明确兼容路径，不使用任意目录猜测。
  - 增加 compose 模式及跨平台工具分发约定，复用安装验证，不在脚本重复实现内容解析。
  - galpak 与内容目录输入均验证闭包；核对契约 IL 字节身份、运行包清单与目标架构。
  - 所有输出经自有暂存目录完成后提交；拒绝覆盖输入和非空冲突目标。
- **测试**：分发 CLI 在无 SDK/无 PATH dotnet 的 Windows 环境合包；含空格路径、任意工作目录；契约不匹配、缺补丁、坏 hash、路径逃逸、目标冲突的负向用例；最终 Sample 启动与正常退出。
- **文档**：记录布局元数据及 CLI 参数、错误与输入输出契约；验证后更新正式发布说明。
- **风险**：CLI 自包含载荷体积、旧包识别及契约闭包误排除；体积不通过削减校验来规避。
- **退出条件**：无 SDK 合包结果能运行，错误输入不生成成功产物，原运行包/内容未被修改。

## P3 — 桌面三平台媒体与应用发布

P3a 已实现并在 Windows 验证：统一所有桌面 VLC 初始化配置/会话工厂与诊断，保留各使用方的播放器所有权。P3b 接着按目标 RID 处理 native 部署、应用路径和完整运行包。P3a 的 Windows 自动化/原生媒体通过不使 P3 整体 verified；Linux/macOS 仍分别要求实际发布/运行证据，详见 execution.md。

- **目标**：Linux/macOS Editor、Sample 和 CLI 有可复现、可启动、媒体可用的运行包。
- **前置条件**：P2 布局契约；P0 对应平台工具链和原生依赖结论。
- **涉及模块**：Media.LibVlc、Miniaudio 构建、GameView 媒体/Gallery、Editor 预览/应用选择/外部调试、Sample 路径、发布配置。
- **任务**：
  - 按目标 RID 选择 native 资产，隔离 restore/bin/obj；保持当前 Windows R2R 通道与严格契约。
  - 接入 Linux/macOS CMake 音频，统一 VLC 初始化配置与工厂，覆盖剧情视频、Gallery、缩略图及 Editor 预览。
  - 打通 Linux 依赖闭包和 macOS .app/运行时/原生库加载；发行说明声明实际最低系统与依赖。
  - macOS 同级外置 pak，保持已签名 bundle 不因普通合包而变化；应用根/profile/log 不依赖工作目录。
  - 新建项目选择支持 Linux executable、macOS .app/入口；契约发现和可监控调试启动复用布局元数据。
- **测试**：各平台分发 CLI + 新建项目 + 导出 + 调试；Sample 剧情/存读档/音轨/视频层效果/Gallery/缩略图/正常退出；不同目录及只读安装根；native 架构与实际加载路径。Linux 开发阶段系统 VLC 成功单独记录，正式包还需无开发依赖环境验证。
- **文档**：更新 release-packaging、cross-platform-backends 和平台依赖矩阵。
- **风险**：VLC 插件缺失、macOS dylib install name/rpath、bundle 入口及不同 RID 契约 hash；不靠宽松匹配掩盖。
- **退出条件**：Windows 回归通过，Linux x64/macOS 两架构有匹配证据；设备或架构未测试时逐项保留，P3 不标整体 verified。

## P4 — 源码构建合包与三平台归档

- **目标**：统一两个发行模式，源码开发者可用应用工程路径与内容参数完成构建发行。
- **前置条件**：P3 的平台发布与加载规则可用。
- **涉及模块**：CLI 发行服务、SDK/工具探测、发布脚本、归档/清单/签名、工具包。
- **任务**：
  - build-compose 接收应用 csproj、内容路径、RID、配置和受控构建参数；区分宿主与目标，不支持的组合早期报错。
  - 预编译模式完全不依赖 SDK；源码模式检查精确 SDK/原生工具并保留结构化进程退出码与日志。
  - sh 入口直接运行自包含 CLI，ps1 支持声明版本，二者参数、错误与取消行为一致。
  - Windows ZIP、Linux tar.gz、macOS 归档保留权限及合法内部符号链接，拒绝逃逸链接/路径。
  - 构建模式在 bundle 最终修改后签名，合包模式不改已签名 bundle；签名/公证状态显式记录，无凭据仅生成候选。
- **测试**：各平台用预编译与源码两种模式生成并重新解包运行；无 SDK 合包与缺 SDK 构建分别验证；bundle 合包前后签名检查、可执行权限与链接恢复；失败输出和输入保护。
- **文档**：工具使用、定制宿主布局要求、签名/公证及平台构建前提。
- **风险**：自定义工程布局不符合协议、脚本转义、归档破坏权限；明确诊断，禁止静默猜测入口。
- **退出条件**：两种模式按声明矩阵可复现，归档恢复后功能与布局正确；未公证产物不会标成正式已公证产物。

## P5 — SDL 手柄与桌面验收

- **目标**：三平台共享标准手柄动作，完成桌面交付的完整验收。
- **前置条件**：P0 SDL 探针、P3 原生部署；最终发行验证使用 P4 产物。
- **涉及模块**：Avalonia.GameHost 输入适配、GameView 动作/提示、SDL native 部署与桌面 CI。
- **任务**：
  - 引入设备快照/动作边界和固定版本 SDL3 绑定；采集、事件泵与生命周期遵守 UI 主线程规则。
  - 替换 XInput 单平台实现，避免双后端重复事件；处理死区、导航连发、热插拔与首个有效设备策略。
  - 焦点丢失/断连清空按键；按布局呈现按钮提示；不可用状态可诊断，键鼠仍正常。
  - 添加真实应用发布矩阵，覆盖展示/宿主改动触发；分层记录自动化与人工验收。
- **测试**：动作映射/连发/断连等共享行为自动化；三平台真实手柄与键鼠回归，确认无多余 SDL 窗口、后台输入和退出泄漏；Editor Dock、中文 IME、文件选择、全屏/多屏按平台人工验证。
- **文档**：支持的标准手柄能力、已测设备、平台限制与桌面验收报告。
- **风险**：SDL 事件循环冲突及设备布局差异；设备不可用仅保留未验收，不用模拟快照代替实机通过。
- **退出条件**：标准手柄三平台验证，P1–P4 的正式桌面产物及 GUI 核心流程有证据；WSL 结果与真实 Linux 桌面分别记录。

## P6 — 集中同步 Sample 与跨平台宿主接入

- **目标**：桌面功能稳定后，将 Sample 最终基线集中接入用户已初始化的跨平台工程，从生命周期中提取真实可复用部分，提供可生成和构建的 Desktop/Android/iOS 工程。
- **前置条件**：P1–P5 桌面功能与交付稳定，P0 iOS/Android 探针解决影响模块/依赖选择的风险；本阶段前不维护第二份完整 Sample 内容。
- **涉及模块**：Sample 组合根、Avalonia.GameHost、显示/生命周期/内容路径边界、模板资源和平台工程。
- **任务**：
  - 复用 `src/Samples/GalNet.Sample.CrossPlatform/` 已有骨架，集中接入页面、资源、本地化与组合根；优先引用公共库，记录平台差异，避免长期复制相同业务代码。保留 Browser 工程，但不扩大本 feature 的验收平台。
  - 提取共享会话创建/关闭与主视图组合；桌面 lifetime、窗口关闭确认保留在 Desktop。
  - 会话重建替代移动端新进程重启，按能力提供显示/退出/返回行为。
  - 平台提供内容安装入口、可写 profile/cache/log；处理版本变化和媒体租约，不假定 APK 内路径可当普通文件。
  - 生成具有独立 package/bundle ID 和最小内容的模板；输出工程不依赖源码仓库的隐式 ProjectReference。
- **测试**：现有桌面正常退出、设置、清空玩家状态和会话重建回归；干净环境生成模板并恢复构建；三类宿主会话初始化与内容加载。
- **文档**：宿主职责、平台能力与模板创建/构建操作；不把骨架可编译写成五平台完整支持。
- **风险**：为复用引入过宽抽象、第三方桌面控件阻碍移动；按真实调用拆分，不大规模机械重命名。
- **退出条件**：已有跨平台工程完成一次集中接入，公共行为无第二套重复实现；五平台目标工程均有构建证据，移动主视图与会话能启动，桌面行为回归通过；完整移动运行在 P7 验证。

## P7 — 移动端完整运行与设备验证

- **目标**：Android/iOS 模板运行完整内容，具备平台生命周期和可发布产物。
- **前置条件**：P6；标准手柄动作层复用 P5，移动设备采集独立验证。
- **涉及模块**：Android/iOS 宿主、miniaudio native、VLC/展示、系统音频、输入布局、签名发布。
- **任务**：
  - Android 按 ABI 打包 native，接音频焦点、路由、返回键和后台；iOS 静态链接与 AVAudioSession、中断/路由、AOT 保留配置。
  - 验证剧情视频像素回调、Gallery 展示和缩略图；优先 VLC，失败记录具体证据后修订局部适配方案。
  - 触摸、安全区域、软键盘、方向与高 DPI；隐藏不可用桌面设置，验证可选移动手柄。
  - 后台/恢复协调剧情、媒体和持久化；以真实内容量验证 PAK 内存、视频帧耗时和资源释放。
  - 生成实际 APK/AAB 与 iOS 签名产物，审查 AOT/裁剪诊断，禁止全局屏蔽警告冒充兼容。
- **测试**：真机启动、剧情/选择/存读档/音视频/Gallery、打断与恢复、进程被系统终止后恢复、方向切换；iOS AOT 回调/释放，Android 发布模式/R8 后播放；设备与性能数据逐项记录。
- **文档**：移动构建签名、内容更新、生命周期恢复语义、资源预算和已知限制。
- **风险**：VLC Avalonia 控件、AOT/回调、移动高分辨率复制与内存；保持图层语义，不能以播放覆盖层替代场景合成验收。
- **退出条件**：Android/iOS 真机全流程和签名发布闭环；模拟器不能代替真实设备媒体/生命周期证据。

## P8 — 审核与收尾

- **目标**：把已验证能力同步为明确的支持声明和可复现操作。
- **前置条件**：P1–P7 必要退出条件满足；未满足项继续追踪，不宣称整体完成。
- **涉及模块**：相关测试、CI、spec/manual、feature review/summary 和 lessons。
- **任务**：独立 review 需求/设计/实现偏差；修复问题；同步正式文档；整理可复用 lesson、版本/许可清单及真实支持矩阵。
- **测试**：运行变更相关测试与仓库要求的 CI；固定最终候选重新解包、hash/契约/权限验证及对应平台 smoke。通过后不无故重复全量测试。
- **文档**：review.md、summary.md；所有阶段证据索引、未验收项与发布限制明确可见。
- **风险**：将候选/模拟器/后端测试误记为正式支持，或其他 feature 变更污染验收产物；核对最终版本与输入来源。
- **退出条件**：需求覆盖表无未解释缺口，目标平台产物可复现，重大问题已修复；缺平台证据时仅可声明已完成子范围。

## 执行记录规则

- 每阶段开始标 in-progress；验证完成才标 verified。skipped 必须记录原因与对应范围变化，不用作绕过验收。
- 同一输出目录的 build 完成并确认退出码后，再运行 no-build 测试。
- 平台环境缺失时继续独立任务，文档注明尚待运行；不把“脚本已经写好”当作目标平台成功。
- 设计修改保留原因、替代方案及对验收的影响；summary 汇总最终偏差。
- 后续实施从 P0 的内容闭包和本机基线、P1 的导出切片入手，移动探针按可用工具链尽早开展。
