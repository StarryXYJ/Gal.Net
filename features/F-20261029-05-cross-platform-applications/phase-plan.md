- **目标**：三平台共享标准手柄动作，完成桌面交付的完整验收。
- **前置条件**：P0 SDL 探针、P3 原生部署；最终发行验证使用 P4 产物。
- **涉及模块**：Avalonia.GameHost 输入适配、GameView 动作/提示、SDL native 部署与桌面 CI。
- **剩余任务**：适配/动作/native 与应用矩阵配置已总结；补矩阵 CI 的实际三平台执行及最终封包/运行，使用最终发行物补齐实际设备与桌面验收，分层记录自动化与人工证据。
- **测试**：动作映射/连发/断连等共享行为自动化；三平台真实手柄与键鼠回归，确认无多余 SDL 窗口、后台输入和退出泄漏；Editor Dock、中文 IME、文件选择、全屏/多屏按平台人工验证。

- **目标**：删除独立 Player 工程，让两个 Sample 成为可直接定制的模板源；通用机制和可选调试由适当的库层提供，项目配置与平台策略归宿主。
- **前置条件**：以 P6a/P7a–P7c 的已验证行为为基线，不等待手柄、macOS、iOS 验收；历史共享 Player 是待迁移实现，不是最终结构要求。
- **涉及模块**：两个 Sample 组合根、Avalonia.GameHost/GameView/Controls/Themes、Storage.FileSystem、可选调试模块、契约执行适配、构建/测试入口。
- **剩余任务**：
  - P6b 通用机制已归入总结；继续下面 P6c–P6e 的结构调整，不新建同职责的 Player 替代工程。
  - **延后**：独立模板生成/脱离仓库构建，待 Sample 本身可验收后再整理。
  - Android 真机资产安装、语言页与基础剧情会话已归入 P7b 总结；继续验证完整会话、退出/返回/显示，不把基础 smoke 写成可完整游玩。

- **文档**：实现后同步定制入口、依赖图、资源归属和平台能力；模板生成规则在真正实施时再补。
- **风险**：只重命名 Player、把项目契约或静态默认值移进框架、调试依赖污染玩家版、机械迁移制造依赖环、已有 profile/资源定位退化。

### P6c — 两个主项目独立配置并删除 Player（planned）

- **目标/前置**：依赖 P6b；让开发者在各自 Sample 主项目内找到完整定制入口，最终移除 `GalNet.Sample.Player`。
- **涉及模块**：Sample.Avalonia、CrossPlatform 共享主项目与平台入口、Sample.Contracts、解决方案/工程引用/锁文件、受影响测试与发布脚本。
- **任务**：两个主项目各自维护 `SampleCustomization`，配置 HostOptions、主题配色、页面/编辑器、本地化、catalog/执行模块和项目截图适配。主题及资源程序集从宿主传入，不由通用视图写死；少量相似接线允许重复。App 保留 lifetime 编排，平台保留路径/系统事件。迁移全部调用和测试后，删除 Player 源码、工程/解决方案引用及失效锁图，并核对隐藏的 CI/发布路径；Browser 不增功能，但不得留下断引用。
- **测试**：两个宿主分别替换主题/页面或注册项目模块，证明配置独立；当前 en-US/zh-CN、截图与内容契约不退化。保留 profile 身份和既有玩家数据，不混用 Debug/Release 契约；新引用图分别 locked restore/build。静态检查只要求生产代码/配置/当前测试无旧引用，历史 feature/lesson 允许记录旧名称。
- **文档/风险**：标明原入口到新入口的对应关系；避免两个 Sample 互相引用、文件链接共享项目配置，或引入改名后的 Player 替代库。
- **退出条件**：两个 Sample 不依赖彼此或 Player，均可从自身定制入口配置并启动；通用机制只有一个实现来源，相关测试和当前目标构建通过。

### P6d — 可选调试能力解耦并接入两个宿主（planned）

- **目标/前置**：依赖 P6b/P6c；把通用调试从原桌面 Sample 中抽出，保留宿主对平台操作和启用策略的控制。
- **涉及模块**：原 Sample 的 Debug/调试菜单与日志 UI、通用宿主、Presentation 下可选调试模块、GalNet.Debugging、两个 Sample 构建开关。
- **任务**：提取调试 VM、日志缓存/显示、快照和外部调试会话适配；保留协议/engine 实现在 GalNet.Debugging。用窄接口/回调替换 `App.LaunchOptions`、Sample 会话类型、MainWindow、进程重启和打开目录依赖；项目指令 replay 策略由 Sample 提供。两个 Desktop 宿主均可显式接入，移动仅接入适用的会话操作/可嵌入 UI，不把桌面窗口硬带入移动。沿用 EnableGameDebugging/EnableLaunchArguments 和独立锁图的能力规则，玩家构建完全排除调试。
- **测试**：日志、清空状态与确认、资源重载/重启、快照覆盖、外部连接/断开/停止/会话重建回归；两宿主 Developer/Player 构建与依赖/资源检查。关闭调试时保留正常日志，拒绝从运行期注册开关给玩家版重新启用调试；缺少平台能力时入口行为明确。
- **文档/风险**：记录模块启用、宿主动作与平台能力；可选调试项目的名称在实现时确定，不要求新增项目数量本身。移动外部调试传输、邀请和安全策略没有设备证据就继续未验。
- **退出条件**：通用调试不引用 Sample 类型/项目契约，两 Desktop 宿主可使用，玩家产物无调试实现/资源/协议依赖；移动适用范围有明确结果，不以桌面结果代替移动支持。

- **涉及模块**：两宿主/平台工程、架构/呈现/集成/调试测试、应用发布脚本/CI、spec/manual 与 feature 记录。
- **任务**：清理迁移临时委托和未使用骨架，核对全部工程/资源/锁图/发布触发；完成当前平台的匹配构建与打包，保证不依赖旧 bin/obj 或临时 targets 才能构建。按实现事实同步架构模块图、game-host、定制/参数编辑器/本地化文档及 CrossPlatform README；历史记录保留，不把计划写成当前 spec。
- **测试**：架构门禁及受影响 GameHost/Storage/Presentation/Integration/Debugging 测试；Windows 两宿主的启动/语言/设置/退出/重建和可选调试，Linux 原生构建及可用环境运行；Android 双 ABI Mono AOT/内容/native/16 KB 检查及 ARM64 真机复验启动、剧情音视频、无退出按钮、系统栏收起和 Back/Home 重进。新增通用接口用无 Sample.Contracts 引用的测试宿主验证。iOS/macOS/真实手柄延期结果单独记录。

## P7 — 移动端完整运行与设备验证

- **目标**：Android/iOS 模板运行完整内容，具备平台生命周期和可发布产物。
- **前置条件**：P6；标准手柄动作层复用 P5，移动设备采集独立验证。
- **涉及模块**：Android/iOS 宿主、miniaudio native、VLC/展示、系统音频、输入布局、签名发布。
- **任务**：
  - Android 真机安装/内容初始化与基础剧情音视频/触摸 smoke 已总结；继续确认系统音频焦点、路由、系统返回与后台事件在目标 OS 的实际行为。iOS 在 Mac 验证静态 native 构建/链接及 AVAudioSession API，修复平台编译和运行问题。
  - 在移动设备验证已接入的共享像素视频、Gallery 与缩略图，覆盖停止/跳过/释放及 AOT 回调；Windows/Linux 真实媒体回归已总结。
  - 补触摸、安全区域、软键盘、方向与高 DPI 的完整矩阵；基础触摸、Android 系统栏收起/无退出按钮与后台重进已总结，继续验证不可用桌面设置及可选移动手柄。
  - 设备验证稳定检查点、后台时限、进程终止后的“继续”、新游戏/显式读档/清空状态与方向重建；测真实内容量的内存、视频帧耗时和释放。
  - Android 双 ABI Mono AOT APK 与完整 GameTestCase 已生成；补设备播放、生产签名/AAB 与 iOS 签名产物。跟踪 Android 官方 VLC 3.7.0-beta 的设备兼容与稳定版替换，不压制 native/AOT 诊断。
- **测试**：真机启动、剧情/选择/存读档/音视频/Gallery、打断与恢复、进程被系统终止后恢复、方向切换；iOS AOT 回调/释放，Android 发布模式/R8 后播放；设备与性能数据逐项记录。
- **文档**：移动构建签名、内容更新、生命周期恢复语义、资源预算和已知限制。
- **风险**：VLC Avalonia 控件、AOT/回调、移动高分辨率复制与内存；保持图层语义，不能以播放覆盖层替代场景合成验收。
- **退出条件**：Android/iOS 真机全流程和签名发布闭环；模拟器不能代替真实设备媒体/生命周期证据。

## P8 — 审核与收尾

- **目标**：把已验证能力同步为明确的支持声明和可复现操作。
- **前置条件**：P1–P7 必要退出条件满足；未满足项继续追踪，不宣称整体完成。
- **涉及模块**：相关测试、CI、spec/manual、feature review/summary 和 lessons。
- **任务**：独立 review 需求/设计/实现偏差；修复问题；同步正式文档；整理可复用 lesson、版本/许可清单及真实支持矩阵。
- **测试**：运行变更相关测试与仓库要求的 CI；固定最终候选重新解包、hash/契约/权限验证及对应平台 smoke。通过后不无故重复全量测试。
- **文档**：review.md、summary.md；所有阶段证据索引、未验收项与发布限制明确可见。
- **风险**：将候选/模拟器/后端测试误记为正式支持，或其他 feature 变更污染验收产物；核对最终版本与输入来源。
- **退出条件**：需求覆盖表无未解释缺口，目标平台产物可复现，重大问题已修复；缺平台证据时仅可声明已完成子范围。

## 执行记录规则

- 每阶段开始标 in-progress；验证完成才标 verified。skipped 必须记录原因与对应范围变化，不用作绕过验收。
