## 用户目标与已确认决策

Editor 和现有 Avalonia Sample 支持 Windows、Linux、macOS；后续提供额外支持 Android、iOS 的 Avalonia 跨平台模板。普通剧情开发者能够在没有 .NET SDK 或原生编译工具的环境中导出内容，使用预编译运行包完成游戏发行。修改应用源码的开发者可指定工程路径和内容包，通过独立工具构建、合并并打包。

用户在本次讨论中确认：

1. Editor 提供压缩包（galpak）与文件夹两种内容导出。
2. 暂时隐藏 Editor 内应用组合包导出功能，保留维护者构建发布能力。
3. 独立工具提供预编译运行包合包、源码工程构建后合包两种模式，提供 sh / ps1 入口。
4. 统一手柄接口，桌面三平台支持标准手柄输入；SDL 作为后端设计方向。
5. 桌面先采用普通自包含发布，AOT 不作为桌面支持前置条件；iOS 的 AOT 发布风险提前验证。
6. 本次授权先整理待办、准备开始；实现细节与代码变更进入后续步骤。
7. 2026-10-29 用户要求继续，并指出 VLC 的跨平台能力。设计继续采用 VLC 作为视频首选，区分上游能力与当前原生部署、展示及发布验证缺口，不预设移动必须更换播放器。
8. 2026-10-29 用户已初始化 `src/Samples/GalNet.Sample.CrossPlatform/`，要求最后再同步现有 Sample 内容，避免同一改动更新两份。桌面阶段以现有 `GalNet.Sample.Avalonia` 和公共库为功能主线，新项目先保留骨架；桌面功能稳定后在 P6 集中接入，平台原生差异再由 P7 完成。
9. 2026-10-29 用户明确“不考虑向后兼容”。本次新导出/安装链路仅采用完整 galpak v4（包含所有剧情分片），不保留 v1/v2/v3 安装分支或旧式旁置剧情导出。旧游戏内容需重新导出；不为本 feature 维护旧发行兼容或旧 API 转发。
10. 2026-10-29 用户要求提交当前改动并持续开发，每完成一个可验证阶段提交一次；只提交本 feature 所属变更，不混入并行进行的 CI/release 优化。
11. 2026-10-29 换设备后用户要求先重新生成 Windows Release，再继续开发；macOS 当前无法验证。用户确认先前 Linux 曾弹出窗口，该观察保留为人工证据，具体程序与会话就绪/正常退出仍通过新设备探针分别确认；不将旧记录中的一次 Sample 未出窗口推断为所有 Linux GUI 不可用。

## 范围

| 交付物 | 平台与能力 |
| --- | --- |
| Editor | Windows、Linux、macOS；项目创作、保存、内容导出、媒体预览和外部调试 |
| 当前 Avalonia Sample | 桌面三平台；剧情、存读档、音频、视频、Gallery、键鼠与标准手柄 |
| 独立发行工具 | 合并预编译运行包与内容；或发布指定应用工程后合并内容；输出完整分发包 |
| 后续 Avalonia 模板 | 桌面三平台及 Android、iOS；共享引擎、内容与展示逻辑，各平台提供必要宿主适配 |

### 内容导出与发行

- 文件夹与 galpak 表达同一组交付内容，正确收集本体、当前构建的剧情包、资源覆盖包和必要目录；具体归档关系在设计时明确，不假定现有单个 galpak 已包含所有旁置补丁。
- 预编译合包模式输入运行包、galpak 或内容目录、输出位置；不重新编译，不要求 SDK。
- 源码模式输入应用工程路径、galpak 或内容目录、目标平台/架构、构建参数、输出位置；检查所需 SDK 和工具链，编译发布后执行相同内容安装与打包。
- 应用工程指 Sample 或自定义宿主源码工程，与剧情作者项目区分。
- 检查运行包与内容的严格契约兼容性，保持既有契约 DLL 字节身份规则。
- 维护 pak 布局、Unix 可执行权限、原生依赖、许可与清单；明确 macOS bundle、内容位置与签名顺序。
- 检测实际可用工具及版本，错误可诊断；不承诺任意宿主能交叉编译所有目标。
- SDK、PowerShell 和源码仓库不作为 Editor 日常创作与内容导出的前提。

### 统一手柄

- 标准按键、方向键、摇杆导航、死区、按住连发、热插拔、焦点与断连状态处理。
- 输入映射到共享玩家动作；按设备布局提供合理按钮提示。
- 桌面三平台随应用部署所需原生依赖，验证常见手柄。
- 移动模板复用动作与映射层，各平台设备接入单独验证。

## 当前事实与阻碍

以下来自源码和现有文档检查，不等同于跨平台实测结果。

跨平台项目骨架已存在：共享 net10.0 项目，以及 Desktop、net10.0-android、net10.0-ios 与 Browser 工程；App 已有 desktop/activity/single-view lifetime 分支，但尚未接入游戏会话。Browser 的存在不扩大本 feature 的五平台验收范围；保留现有工程，不删除、不承诺浏览器媒体/输入支持。此处只确认源码结构，未执行移动工作负载恢复或运行验证。

| 领域 | 现状与缺口 |
| --- | --- |
| 桌面发布 | Publish.ps1、WindowsReadyToRun profiles、包名与验收固定 win-x64；需扩展目标矩阵 |
| Editor 组合包入口 | 固定 powershell.exe 和 Windows 输出；按已确认决策隐藏 |
| 音频 | CMake 已有 Linux/macOS 动态库及移动端接入路径；应用构建自动化与实机证据不足 |
| 视频/Gallery | 只自动分发 Windows VLC 原生载荷；其他平台依赖部署及移动后端需落实 |
| 手柄 | 当前为 Windows XInput，其他桌面平台禁用；需统一后端 |
| macOS | 缺完整 .app 封装、内容定位、原生库加载与签名/公证交付流程 |
| Linux | 缺明确系统/ABI/桌面依赖基线与正式运行包；WSL2/WSLg 可承担早期验证 |
| GUI 与调试 | 缺三平台项目创作、窗口/Dock、文件选择、中文 IME、字体、全屏及外部调试完整验收 |
| CI | backend-portability 主要覆盖资源、音频解码和 CMake；不能证明 Editor/Sample GUI 或发行可用 |
| 移动宿主 | 当前 Sample 只创建桌面 lifetime 会话，重启与显示设置依赖桌面进程/Window；缺 Android/iOS 平台工程 |
| 内容与存储 | 默认安装内容读取展开目录；包内 PAK 流能力不代表整个内容加载已支持应用 bundle/APK |
| 移动生命周期 | 音频后端已有暂停/恢复接口，仍需系统音频会话、焦点、中断、路由、前后台和恢复接入 |
| 移动发布 | 缺完整 AOT/裁剪、签名、原生库部署、GPU/Shader、触摸布局及真机验收 |

## 验收标准

1. 无 SDK 环境中，分发 Editor 可创作、保存并导出 galpak/文件夹；不显示应用组合包导出入口。
2. 相同项目的两种内容导出可经合包工具安装到匹配运行包，剧情、存读档、音视频与 Gallery 可用，分离补丁不遗漏。
3. 合包模式不调用源码编译；源码模式使用指定应用工程和参数构建，环境缺失/目标不支持明确失败。
4. Windows/Linux/macOS 的 Editor 与 Sample 均有平台、架构和版本明确的可验证产物；从非应用工作目录及含空格路径正常启动。
5. 严格契约不匹配、错误原生架构和损坏内容不会产生成功的最终分发产物；不覆盖输入工程或原始内容。
6. 三平台标准手柄动作、焦点、热插拔与断连恢复经过验证，键鼠原流程无回归。
7. Editor 三平台覆盖项目打开/保存、内容导出、媒体预览、外部调试与正常退出；系统集成和 IME 的人工项有明确结果。
8. 模板生成的桌面、Android、iOS 工程具备独立构建和运行证据；移动覆盖内容加载、存读档、媒体、中断恢复、触摸及平台发布。
9. CI、模拟器、WSL 与真机证据分别记录；无法执行的项保留未验收状态，不用后端/headless 测试代替。

## 非目标

- Editor 移动端移植。
- 首期高级手柄能力：震动、陀螺仪、自适应扳机。
- 用此次工作强制完成桌面 NativeAOT。
- 支持所有 Linux 发行版、全部 CPU 架构或任意宿主交叉编译。
- 放宽严格契约规则，或修改与本 feature 无关的其他功能；galpak v4 是用户“不考虑向后兼容”修订后的明确格式变更。

## 约束、假设与开放事项

- 复用既有 Core/Runtime、PAK、存档、PCM 与 Avalonia 展示能力；具体依赖拆分由设计验证。
- SDL 是已接受的技术方向，具体版本、托管绑定与事件循环集成仍需验证。
- 桌面首批建议 Windows x64、Linux x64、macOS arm64/x64；这是待设计确认的架构基线，不宣称其他架构已排除或支持。
- 产品范围暂无必须向用户追问的问题。Linux 版本、包格式、macOS 签名方案、工具参数及移动首期调试方式在设计中给出明确方案；若发现改变范围的取舍，再提交用户确认。
- 工作区存在其他 feature 的进行中修改；实施前核对当时工作区，不覆盖或回滚其他工作。
