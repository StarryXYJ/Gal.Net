# 单项目 Sample UI 开发模板

状态：implementation，待 Android 真机验收（2026-11-01）。P1–P5 和 P6a 已验证；实现、仓库外定制、Windows/Linux 桌面与 Android AOT/打包完成，P6b 因无连接设备保留。用户已授权每完成并验证一个阶段单独提交一次，不包含发布。见 [summary.md](summary.md)。

## 用户原始目标

- “只有一个 sample”，让以它为 template 的开发者“以尽可能少的精力去做自定义”。
- 默认基于主题的控件设计，但允许对一个页面的按钮直接改写 XAML、完全自定义页面与 VM。
- “复杂机制和控件库在内置层，sample 应该就作为单个项目”。
- 尽可能简洁，同时职责分明；本轮“根据讨论做到 phase plan 阶段”。

## 问题与当前事实

当前唯一维护的图形示例为 CrossPlatform；普通页面分散在 Themes 的三套布局，页面 VM、导航、播放协调位于 GameView，启动视图和会话位于 GameHost。SampleCustomization 主要提供组合配置。

改变一个菜单的按钮可能涉及共享 TitleMenu、主题页面、VM 派生、DI 替代与实际类型映射。主题注册整套页面，默认注册强制检查全部内置页面。AvaloniaPlayerHost、GameLaunchFlow、GamePage 和运行适配还直接依赖内置页面 VM，存在真实迁移成本。

以上为当前工作区事实，包含正在进行的资源鉴赏改动；历史文档仍有两个 Sample、Editor 复用等叙述，不能仅据旧记录推断当前消费者。

## 已收敛的范围

1. 一个 Sample 应用项目集中拥有入口接线、页面 XAML、页面 VM、导航策略、项目流程、文案和局部样式；不新增 Sample.UI、Sample.ViewModels、Sample.Player 等应用拆分项目。
2. 内置层保留复杂运行机制、呈现状态、资源/媒体生命周期、安全与持久化能力，以及可复用控件。
3. 取消 GalNet 整套主题抽象，仅保留内置配色资源和控件必需的默认样式。字体、尺寸、应用样式、布局和装饰归 Sample；Avalonia Styles/ControlTheme 继续正常使用。
4. Sample 默认页面直接使用内置控件与主题，常改菜单/工具栏在项目 XAML 中可见。修改单页不要求派生默认页面 VM、重注册整套主题或复制播放机制。
5. 页面 VM 直接可编辑。抽出其复杂机制后，普通应用命令和页面状态迁至 Sample；内部运行状态不机械复制到 Sample。
6. 默认布局以现有 Classic 为迁移基线，不借重构改版；收敛为一套完整应用页面。以后新的页面设计通过新模板提供，当前只维护一个默认模板，不建设模板切换机制，不保留布局主题预设。
7. 迁移现有设置、存读档、鉴赏及详情、截图、语言选择、确认、历史和调试接线，维持当前能力与平台边界。
8. 使用现有 DI、导航与控件机制，去掉具体应用页面耦合；不新增平行扩展框架。

## 非目标

- 手机、商城、小游戏等业务系统，自动模板生成器或模板升级合并工具。
- 运行期切换主题，任意页面在三套整页布局间自动切换。
- 将 Core/Runtime/Contracts、全部内置库合并到 Sample；将项目契约编入平台 App 取代独立契约交付。
- 取消跨平台支持，或为满足单个 csproj 而强行合并 Avalonia 平台要求的构建入口。
- 移动端新视觉设计、方向/安全区改版，或补齐既有延期的 macOS/iOS/真实手柄验收。
- 改变 PAK、存档格式、profile 身份、契约严格字节身份、调试发行开关与内容安装规则。
- 未验证实现前将正式规范更新为目标状态；未经授权发布。

## 验收标准

1. 打开 Sample 应用项目即可找到标题、设置、存档、鉴赏和游戏页的 XAML、应用命令与导航；不增加应用 UI/VM 子项目。
2. 标题页增删按钮与重排布局只修改项目页面；新增命令可直接修改本项目 VM，无内置页面派生或 DI 别名要求。
3. 新增自定义页面只需 View、VM、集中注册和调用处；不要求实现新主题。可替换或移除一个非必要页面而不被整套默认页面校验阻止；留下的无效导航在组合验证中报告。
4. 配色可全局配置，控件样式可在项目中局部覆盖；普通 Button 获得模板默认外观，单按钮改模板不影响其他页面。
5. 游戏页可在项目 XAML 中修改工具栏、布局或使用自定义控件；继续使用唯一呈现对象，推进/自动/快进/选项/历史与取消语义保持。
6. 内置运行、控件和配色不引用 Sample 或项目页面类型；删除整套主题抽象，不保留依赖内置普通页面 VM 的隐藏路由，不把复杂状态机变成 Sample 的复制代码。
7. 当前默认功能通过相关回归及真实宿主 smoke；平台重挂载、暂停、恢复、退出与 scope 重建没有重复播放、丢页、资源泄漏或 checkpoint 回归。
8. 仓库外定制探针能复用内置能力完成“改按钮、改命令、新增页、改配色/局部样式、改游戏工具栏”，不引用旧默认页面类型或复制运行机制。
9. 构建、锁图、发布/调试开关和契约交付按受影响矩阵验证；正式文档在实现验证后同步。

## 约束、假设与开放事项

- “单项目”指一个承载应用 UI/VM/组合的 Sample 项目；现有平台必需的最小启动/打包项目不承载第二套应用逻辑。独立项目契约仍为内容工具与 App 共用的契约载荷，不是 Sample UI 拆分。此边界沿用讨论，不宣称整个跨平台产品只剩一个 csproj。
- 内置库的命名、是否合并某个既有程序集由实际依赖决定；不为了新分层增加程序集。
- 不假设需要长期兼容旧页面 API；删除前必须盘点仓库、测试、脚本及实际消费者，同步迁移。内容与持久化兼容另按现有规范保持。
- 工作区有其他未提交改动，特别是 F-20261031-01-resource-gallery；实现须建立基线并保留其当前功能，不能回滚其他任务。
- 无阻止形成计划的产品开放问题。精确服务名、控件绑定形态与程序集落点由 P1 核实，偏差更新设计与计划。
