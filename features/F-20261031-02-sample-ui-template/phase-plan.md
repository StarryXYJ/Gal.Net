# 单项目 Sample UI 模板实施阶段

状态：in-progress。依据 [需求](feature.md) 与 [设计](design.md)，2026-10-31 建立。用户已授权实现及每阶段独立提交；不包含发布。采用取消整套主题、只保留配色和默认控件样式的修订方案。

依赖：P1 → P2 → P3 → P4 → P5 → P6。按可运行切片推进，避免先移动全部文件导致长期不可构建。阶段状态只能在取得对应证据后改为 verified；外部环境缺失的验证明确记录，不以计划代替通过。

## P1：建立迁移基线与最终依赖边界

状态：verified（基线建立，包含已知失败与原生验收缺口；不代表全绿）。证据见 [baseline.md](baseline.md)。

阶段结果：Presentation 358 passed / 0 failed / 6 未执行，架构 56 passed，Sample 集成 79 passed / 1 既有 Editor dirty 失败。修正原生夹具漏复制资源文案后取得五个原生场景 PNG；主窗口枚举/正常退出检查仍失败，真实窗口存读档亦未验证，保留至后续平台验收，不伪造通过。

**目标**：确定当前行为和所有消费者，消除从旧文档推断边界的风险。

**前置**：获得实施授权；记录工作区现有变更，尤其资源鉴赏进行中的改动。

**模块**：Sample.CrossPlatform、GameHost、GameView、Controls、Themes、Debugging、真实 Editor/工具消费者、架构测试、构建发布脚本。

**任务**：

- 盘点页面/VM/路由/主题注册、GamePageViewModel 与 PlayerView 的实际消费者和所有权；标记搬迁、保留、提取三类，不以改名冒充解耦。
- 列出完整默认页面与功能矩阵，包括场景鉴赏、历史/重播、截图、首次语言、确认、音频公告、开发调试和平台生命周期。
- 明确单个应用项目与必要平台外壳/契约项目边界，确认构建/发布/锁图受影响入口。
- 为共享呈现状态、启动与 UI 协调确定最小接口和数据流，补入 design.md；无需新增无真实消费者的接口。

**验证**：运行受影响现有测试形成基线；记录通过、失败、未执行和已知环境限制。采集默认 Classic/Mono 中英文关键页及最小窗口参考；记录一次真实启动、播放、存读档与正常退出。

**文档**：本 feature 增加消费者/行为基线与证据索引；更新设计中尚待确定的接口落点，正式规范暂不宣称迁移完成。

**风险**：其他工作区变更继续演进；不冻结或覆盖他人改动，用明确源码状态和基线差异追踪。

**退出条件**：完整消费者清单、机制/页面归属及基线可复查；没有未分类的生命周期所有者；重大范围变化先更新需求。

## P2：提取共享游戏呈现状态，保持现有页面可运行

状态：verified。前置：P1。结果见 [execution.md](execution.md)：Presentation 361 passed / 0 failed / 6 未执行；Sample 集成 79 passed / 1 与 P1 相同的 Editor dirty 失败，无新增失败。文件夹模式格式检查通过。

**目标**：让运行/呈现/设置/输入不再依赖应用页面 VM，使后续迁移不复制复杂机制。

**模块**：GameView 的 GamePage/VM/输入/presenter，GameHost 的 GameRun、GamePresentation、GameSession、Settings，以及相关调试适配。

**任务**：

- 将场景集合、对白/NVL/选项等待、自动/快进、历史与交互阻塞等机制收敛到唯一 scope 内置状态对象；保持现有异步取消和资源所有权。
- GamePage、presenter、运行与设置直接消费该对象；应用命令与页面路由不进入该状态对象。
- 现有页面暂时接入新机制维持可运行；仅允许有明确删除时间的过渡适配，不维护双状态或全量转发属性。

**验证**：推进/补全文字、选项完成、NVL、自动/快进、历史重播、UI 隐藏/恢复；准备取消、读档替换和释放期间等待者收束；同 scope 状态与呈现对象身份一致。运行相关 Presentation/Integration 及实际受影响测试。

**文档**：设计记录最终对象和所有权；验证成立的机制变更同步呈现/生命周期 spec，不提前更新页面归属。

**风险**：重复等待者、事件订阅泄漏、旧运行回写、自动模式恢复顺序变化。

**退出条件**：运行链路不需要具体应用页面 VM；机制无双份状态；现有页面及机制回归保持基线行为。

## P3：在 Sample 接通标题—加载—游戏的可定制切片

状态：planned。前置：P2。

**目标**：证明项目页面、可编辑 VM 与内置机制可以直接组合，解决最核心开发体验。

**模块**：Sample 应用项目，宿主启动/挂载、导航和加载流程，游戏承载控件及主题资源。

**任务**：

- 在唯一 Sample 项目加入标题、加载、游戏页面与 VM；菜单、工具栏 XAML 可直接编辑，默认保持 Classic 布局。
- 一个组合入口集中注册 View/VM；明确默认启动页、返回目标和错误回退。解除 AvaloniaPlayerHost/GameLaunchFlow 对固定应用页面类型的依赖。
- UI 接线归 Sample；scope、初始化取消与停止释放仍由内置宿主负责，不能复制到项目页面。
- 游戏 XAML 组合唯一内置呈现对象；按钮和自定义交互区保留推进排除规则，承载布局明确可编辑。

**验证**：真实启动到标题、新游戏/继续、加载成功/失败/取消、返回标题、退出；修改一个标题按钮及其项目命令，加入自定义页面后进入/返回；修改工具栏按钮不会推进剧情。修改仅发生于 Sample 页面/VM及集中注册。

**文档**：在 feature 记录最小定制步骤和修改文件，保留与最终手册相同的可执行示例。

**风险**：页面呈现完成前开始播放、重复挂载 GamePage、基础导航仍隐藏固定 VM 路由。

**退出条件**：该切片无需内置普通页面 VM 派生、DI 别名或新主题；正常播放、取消和 scope 重建正确；Sample 未增加 UI/VM 子项目。

## P4：迁移全部应用页面与全局 UI

状态：planned。前置：P3。

**目标**：Sample 拥有完整可编辑应用 UI，内置保留每项复杂机制。

**模块**：设置、存读档、鉴赏及详情/replay、关于、截图、语言选择、确认/公告，平台与调试接线。

**任务**：

- 迁移其余页面 XAML、应用 VM与导航；将必要的列表加载/预览释放/持久化等机制留在现有功能服务，避免整类机械移动。
- 将语言选择、退出/返回确认和公告布局放入 Sample，保留取消、焦点、输入屏蔽及资源清理机制。
- Gallery 按实际内容类型注册；可选页面不受固定全量列表约束，启用功能及导航缺失仍有可定位错误。
- 保留平台返回优先级、Activity 重挂载、暂停落盘、debug/player 构建隔离。

**验证**：存档读写/改名/缩略图、本地化与设置保存恢复、全部现有鉴赏类型及播放停止、scene replay、截图预览/正式输出与取消；语言选择期间退出、模态取消与自动恢复、同页重挂载。回归当前资源鉴赏新增场景。

**文档**：维护迁移矩阵，逐项标记行为证据；按已验证实现同步 Sample/页面/宿主相关说明，不声称整个 feature 完成。

**风险**：漏迁移当前未提交功能，平台或调试代码继续解析旧 VM，弹窗布局迁移破坏释放顺序。

**退出条件**：默认完整应用不再依赖旧普通页面；项目页面/VM 可直接编辑；机制与平台边界保留，功能矩阵无遗漏。

## P5：主题职责收敛与旧入口清理

状态：planned。前置：P4。

**目标**：只保留一套默认应用页面，主题和内置库不含应用页面策略。

**模块**：Themes、GameView 的旧应用 VM/组合入口，相关消费者、测试、锁图与脚本。

**任务**：

- 删除 IGameLayoutTheme/GameLayoutTheme/Classic/Minimal/Paper 整套主题抽象及三套重复普通页面；保留 GamePalette 配色与内置控件必要默认样式。应用字体、尺寸、布局、装饰及样式迁入 Sample；不新建改名后的主题协议。
- 删除迁移适配、旧固定页面完整性检查、旧默认页面 VM 及无消费者入口；同步实际消费者，不增加长期兼容模式。
- 保留必要的控件运行契约；检查依赖方向，不为新命名做无关大规模格式化或工程拆分。
- 更新受影响包/项目引用、锁图与发布指向，保证默认/调试变体依赖真实匹配。

**验证**：默认外观与局部覆盖渲染，换配色不改变项目布局；多根样式隔离；移除可选页可启动、遗留无效导航有诊断；搜索旧类型/页面资源无悬空引用。架构/呈现/集成测试及受影响 locked restore/build 通过。

**文档**：更新 Themes README、模块和页面 spec，移除“主题负责整页注册”“派生默认 VM 是日常定制入口”等过时说明。

**风险**：资源 URI 悬空、锁图残留 Project 节点、旧测试以类型数量而非用户行为约束新结构。

**退出条件**：运行库不引用 Sample 或普通应用页面类型；默认页面仅一份；所有过渡适配与整套主题抽象删除；只保留内置配色和默认控件样式。

## P6：仓库外模板验收、平台回归与文档收尾

状态：planned。前置：P5。

**目标**：用开发者实际工作路径证明简洁性，并验证可交付性。

**模块**：仓库外定制探针、Sample 各受支持入口、发布/契约脚本、正式文档。

**任务与验证**：

- 复制一个 Sample 应用到仓库外，按当前真实发布方式引用内置库，保留必要平台与契约载荷；不建设正式模板生成器。
- 完成五项探针：修改标题按钮 XAML；新增/修改项目命令；新增页面并返回；全局配色与单按钮模板覆盖；改游戏工具栏/布局且不误推进。记录所需文件和操作，确认不修改内置源码、不派生旧页面 VM、不复制播放机制。
- Windows/Linux 已有支持环境跑真实启动、媒体、存读档、正常退出；Android 覆盖真实挂载/后台重进/返回/暂停落盘及必要发布验证。涉及设备或环境不可用时明确未验证，不用 cross-build/headless 代替。
- 验证受影响 Desktop Player/Developer 构建、发布布局与契约字节身份；Android 若重新构建契约/AOT，保持已有版本身份与双 ABI 锁图规则。macOS/iOS/真实手柄原延期项继续单列。
- 运行受影响完整回归和仓库要求的构建检查，区分基线失败与新增失败；检查存档/profile 与语言资源来源不变。

**文档**：完成 spec（modules/game-view/game-host/lifecycles）、manual（customize-sample/pages-and-themes）、quick-start、Sample/Themes README 与必要构建说明；仅记录已验证事实。生成 summary.md，列出最终实现、偏差、证据、未验证范围和用户迁移责任。

**风险**：仓库路径掩盖依赖、只验证编译未验证原生窗口/媒体、将原延期平台误记为完成。

**退出条件**：五项定制探针可复现；机制与受影响平台/发行证据齐全；阻断问题解决，环境限制及既有延期明确列出。缺少必要环境证据时不将相应验收标为完成；完成阶段后按用户授权提交，不发布或推进公开版本。
