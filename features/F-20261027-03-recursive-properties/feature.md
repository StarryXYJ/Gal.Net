# 递归属性访问与嵌套结构统一

状态：in-progress（P1–P4 已验证，P5 综合验证与收尾中）。
创建日期：2026-10-27。
用户已选择普通 feature 流程，并明确要求开始实现。正式 [设计](design.md) 和 [阶段计划](phase-plan.md) 已进入实施；当前证据见阶段计划，最终结果以 summary/review 为准。

## 用户目标

起点是 Editor 中正常填写的结构化字段出现 `Structured value has no traversable field schema.` 警告。问题导航已在 UI/UX 后续修复，但已知结构仍存在引用分析盲区。

用户原话：

> 嵌套结构应该也弄成类似unity的迭代序列化吧，逻辑统一也好用。

随后用户询问重构规模、现有特定设计是否可以复用以及收益，并确认“ok，走feature流程吧”。

目标是让嵌套对象和集合可通过一致的属性访问及遍历机制被编辑、校验、分析和定位，减少重复结构逻辑、误报警与引用漏检；保留已有效工作的专用编辑体验与项目作者机制。

## 当前问题

- FieldDescriptor / ValueDescriptor / IFieldDto.Schema 已存在，但嵌套结构的消费者分别解释类型、成员、实际 JSON 名称与路径。
- StructuredFieldEditor 与 LocalizationReferenceIndex 分别实现 DTO/集合遍历，支持边界不同。
- Transform、Flipbook 等字段在 Entry 契约中使用 JsonElement，专用编辑器知道子字段，本地化索引无法获取同一结构信息。
- 通用字典、按类型决定的动态参数与 Timeline 事件需要表达结构和上下文依赖，不能仅以“是 JSON 对象”判断覆盖完整。
- 只隐藏警告或增加逐字段跳过分析标记，不能满足用户提出的结构统一目标。

## 范围

- 以现有字段元数据、schema 生成和 codec 能力为基础，支持嵌套对象、数组、List 类集合及字符串键字典的结构描述、属性访问和有界遍历。
- 为编辑、校验、本地化文本/角色引用检查及问题导航提供一致的结构事实和字段路径。
- 让已知的固定内置结构能够被正确检查；优先打通 Transform 的完整编辑与检查闭环，Flipbook 为同类固定结构接入对象。
- 保留 NumericUpDown、Slider、无损文本等字段编辑器选择，以及类型、成员和 DTO 专用编辑器覆盖能力。
- 通用对象使用单一可折叠 Header 和缩进，集合/字典显示数量及对应操作；简单元素保持紧凑。通过主题统一组内/组间间距，不逐层插空白行；专用控件保留各自布局。此展示方向已由用户确认。
- 保留局部 JSON 修改、未知成员、缺省/null、既有编码兼容、项目草稿、撤销/重做和保存事务。
- 音效/视觉效果动态参数及 Timeline 作为扩展场景纳入设计；本次提供解析扩展入口与上下文失效验证，实际编辑器/索引全量迁移留待后续。未迁移的未知结构继续报告未覆盖。

## 非目标

- 重写整个 JSON 序列化器或把所有 JsonElement 一次性替换为 CLR DTO。
- 引入 Unity 的 Prefab override、多对象编辑或任意对象图持久化系统。
- 改变作者文件、编译内容、存档和运行时执行格式，或在内容中写入 CLR 类型身份。
- 重做 Transform、Flipbook、Timeline 的既有交互布局。
- 将领域业务校验搬入通用结构层，或将“引用分析完整”解释成“项目可运行”。
- 全局关闭不透明结构的提醒，或猜测普通字符串是否是本地化 key。

## 验收标准

1. 同一嵌套字段在编辑、校验、引用索引和问题导航中使用一致的字段身份、实际 JSON 路径及类型规则。
2. 正常非空 Transform 不再因为结构未知而触发 field.opaque；相关编辑和实际业务校验保持有效。Flipbook 及其他纳入实施范围的结构采用同样标准。
3. 嵌套对象、集合和字典中的明确文本/角色引用能够被识别；不存在的引用仍有准确定位。未知结构或超限不能被误判为“确定没有引用”。
4. 修改子字段只修改对应作者数据，保留未知成员、兄弟值、原有编码及缺省/null；只读展开和扫描不写入默认值。
5. 保留专用控件覆盖、数值编辑路径、跨视图草稿、关闭重开、Save All、Undo/Redo 和稳定 Entry 导航。
6. 列表结构改变、字段换类型、作者删除、异步结果过期及项目卸载后，旧属性访问不能写到新目标或持有旧项目契约。
7. 对递归/异常结构具有有界行为和可定位结果；遍历不执行游戏逻辑或任意计算属性 getter。
8. 被迁移消费者中的重复结构定义和遍历逻辑得到收敛；有构建、针对性回归与正式文档同步证据，不以警告消失作为唯一证明。

## 约束与复用边界

- Core/Runtime 保持平台中立，不依赖 Avalonia、编辑器项目 I/O 或内置业务实现。
- FieldDescriptor / ValueDescriptor、IFieldDto 生成器、ValueCodec / System.Text.Json 为优先复用资产。
- 现有 EditorRegistry 覆盖机制、FieldEditorContext / IFieldBinding、作者历史与保存入口继续承担各自职责。
- 实际 JSON 命名、converter 与历史字符串编码必须被兼容；不能为统一结构而丢弃作者扩展数据。
- 专用控件保留展示与交互，音效/视觉/场景等领域继续拥有业务规则。
- 实施需分阶段验证，首批验收优先覆盖基础能力和 Transform 闭环，再据证据推进更复杂的迁移。

## 假设与开放问题

已有讨论作为设计输入。正式设计已确定下列边界，具体 API 名称与实现细节可在不改变需求的前提下调整，并记录实际偏差：

- 复用现有 codec；以显式结构关联/适配解释固定 JsonElement，兼容对象和已支持的字符串编码。
- 结构缓存有作用域，读取快照与作者写入身份分离；列表结构变化不能复活旧索引句柄。
- 嵌套检查显式区分 Partial/完整规则；引用覆盖不等同运行有效性，UI 与扫描预算分离。
- 动态目录与 Timeline 暂不全量迁移，不将扩展入口解释为已有覆盖。
- 保留旧公开构造函数签名；按五个 Phase 逐步迁移并验证专用/通用消费者。

实施仍需验证 converter 组合、旧契约加载、旧草稿路径和卸载行为。它们是明确的测试与退出条件，不是已证实兼容的声明。
