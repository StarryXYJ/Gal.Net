# Group 自动热更新设计

状态：方案，未实现。2026-11-02。[需求归属](feature.md)。当前有效规则依次以“存档持久化修订”“执行位置修订”为准。第 1–11 节保留上一轮背景与取舍，其中内存限定、当前组自动重播等冲突规则已废止；实施前应合并整理历史段落。

## 存档持久化修订：读档后仍支持准确判断与组头重载

用户确认已经历 Group 记录需要随存档持久化。最终产品规则：当前组已执行部分变化，提示从组头热重载；当前组尚未执行的安全后缀和未经历的组自动生效；已经历的其他组变化，提示重开档，不强制退出或返回标题。

### 已经历记录

运行时使用按 Group ID 去重的集合/映射，不保存完整访问列表。记录属于 Save scope：保存时与同一个稳定剧情快照一起复制写入，读档时替换为该存档记录，不与当前运行或其他槽位取并集；新开档清空。自然进入组时登记，循环再次进入不无限增加记录。调试 seek/隔离测试不是自然历史，来源不可信时需要来源标记，不能伪装成未执行过的干净路径。

仅保存 Group ID 能识别运行期间的新修改，但不能发现加载前已经修改过的组。建议保存“Group ID → 最近自然执行版本的内容指纹”，并在旧副作用仍可能存在时保留状态过期标记；热更新接纳新定义不能把执行来源指纹直接更新成新版。已有组被移除也属于历史依赖变化，不能静默丢弃该记录。

有循环时同组可能按多个版本贡献过状态，无须保存无限版本列表：记录来源版本及不一致标记即可保守警告；只有从可信新起点重建或确认撤销全部相关差异，才清除过期标记。当前组的本次入口身份与之前访问该组的历史影响分别判断，不能因 Group ID 等于当前组就忽略前几轮旧结果。

### 当前组入口基线也需跨读档保留

如果只持久化已经历集合，加载到组中途后仍没有“进入当前组之前的场景/Save 值”，无法兑现从组头重载。建议同时随存档保存一份当前组自然入口数据：Group ID、场景 sections、Save 变量、前置来源记录和内容身份。它是扁平入口记录，不含另一个完整 GameSnapshot 或自己的入口基线，避免递归增长。

读档恢复当前位置和该入口记录；主动组头重载时恢复入口的 Save 值/场景，而非只把当前 EntryIndex 改成 0。Player/已读/Gallery 不回滚。自然进入下一组覆盖基线，当前组多次重载保留同一份入口。保存发生在组末尾时仍需当前组对应的入口；读档后再跨组才覆盖。

不要求每跨一组立即写磁盘：运行内更新记录，玩家正常保存/自动保存时随槽位原子写入。若以后需要崩溃后恢复未保存进度，应由独立 autosave 策略处理，不在此建立第二套持久化日志。

### 读档前后的版本与重开档提示

读档时将存档历史内容指纹与实际内容对比；存在已经历组变化时，显示“此存档经历过的组已修改，重开档或加载修改位置之前的有效存档以重建状态”。同一个存档反复读入不能消除旧结果，接受定义更新也不能冒充重新执行。

当前组内部修改仍分已执行/活动范围与安全后缀。若修改发生在读档之前，仅保存数字 EntryIndex 不足以定位：建议保存当前作者边界与已执行/活动范围的校验证据，结合当前组入口版本/编译映射识别。无法证明旧位置与新内容对应时不在自动载入阶段猜索引，允许明确选择从该存档携带的组入口重载，或主动重开档。普通玩家存档的严格身份门禁不因此全局放宽，开发调试恢复需独立能力和范围检查。

“重开档”指新游戏，或加载尚未受这些修改影响的更早存档；不表示重启 App，也不意味着清空玩家全部存档/已读/profile。前置依赖变化的警告范围高于当前组重载，UI 应说明仅重载当前组不足以重建更早结果。

### 数据契约与验证

当前 GameSnapshot 版本为 5，已有 Attachments 是宿主数据，Engine 不自动解释/恢复。执行历史应由拥有执行边界的层维护，不能单纯把字段塞入 Attachments 就认为 Runtime 会恢复。具体采用受控执行字段或宿主附加协议须在实现阶段统一选择，覆盖所有快照复制、精简工厂、调试 replay 与保存/恢复路径。

用户明确不考虑向后兼容。存档格式直接升级，旧版本明确拒绝，不做旧档迁移，也不把缺字段默认为“从未经历任何组”。已经历组来源记录等新契约必需数据缺失时按格式校验失败处理；当前组入口是否存在按新格式的合法运行状态显式表达，不为兼容旧档伪造入口。新调试协议同样直接升级，Editor 与 App 使用配套新版本，版本不匹配明确拒绝，不增加旧协议适配分支。无需为此保留旧格式实现或双写路径；普通玩家存档的完整性与内容身份检查仍保留。

补充验收：槽位之间历史不串；加载中途仍可恢复组头及 Save 值；修改发生在读档前可发现；循环同组旧来源不漏报；保存时入口与历史/当前位置属于同一稳定快照；反复保存体积不递归增长；同档重读不能消除过期警告；旧格式按契约拒绝。

## 执行位置修订：未来自动生效，过去由用户重载

用户最新方向：当前 Graph 后面的内容自动更新；Group 内前面的内容改变时用 Ursa Toast 提示“当前组前段已修改，从组入口重载以应用”，App 内调试菜单也提供该动作。不因编辑自动反复从组入口重播。无普通热更新按钮/自动开关，“从组入口重载”是明确重播动作，不与自动更新开关混同。

### 处理矩阵

| 变化位置 | 当前有效处理 |
| --- | --- |
| 尚未执行的后置 Group | 自动接纳定义，不中断当前运行 |
| 当前组严格尚未执行、未派发、无活动实例引用的作者后缀 | 自动接纳安全后缀，保留当前位置与画面 |
| 当前组已经执行的作者前缀 | 不追溯执行；Toast 提示，用户主动从入口重载 |
| 当前播放/等待中的作者条目，包括仍活跃的非阻塞演出 | 按非安全范围处理，不原地换时间线；提示从入口重载 |
| 以前执行过的其他 Group | Ursa Toast 提示重新开始游戏以重建前置结果，不强制执行；定义接纳策略尚待确认 |
| Graph/变量声明/共享资源等范围外变化 | 提示未应用原因，不强制回标题 |

前后按实际执行与当前路线判定，Graph 的视觉左右只作显示。分支/循环组仍按此前执行记录保守判定，不能只用屏幕坐标。

### 作者边界与结构修改

不能直接用 EntryIndex 划分。一条作者 Entry 可展开多条 Primitive，非阻塞实例可能在游标越过后仍运行。比较 Stable ID、完整编译展开及活动来源范围，只有受保护前缀/活动内容完全不变，后缀替换才可自动生效。需要保留下一条作者身份并重新映射编译位置。

后缀增删/排序可自动应用；跨越执行边界的移动、删除当前条目、修改已执行条目均要求组重载。插入点的“尚未执行”存在歧义时保守提示，不猜测新条目是否应该补执行。

为限制首版复杂度：同一当前组同时修改前缀和后缀时，建议整组暂缓，Toast 说明“当前组更新待从入口应用”；其他安全 Group 仍自动更新。此时不能把整份候选标为已接纳，必须显示当前组仍待应用，映射和内容身份对应实际生效组合。若要后缀也单独接纳，会引入组内多版本映射，建议后续再做。

这与上一轮“不能部分发布整份候选”的限制不同：本轮允许按 Group 接纳并明确 pending，但不允许静默混合或错报整份同步。实现必须管理实际生效内容/逐组映射身份；不能仅更新候选全局指纹。

### Ursa Toast 与 App 调试菜单

建议 Toast 放 Editor，文案：“当前组已执行部分发生变化，需从组入口重载后生效。”操作为“从组入口重载”和关闭；若当前条目修改，替换成“当前演出已修改”。本地 Ursa API 是否支持交互 action 需实现前核验，本文不假称已有该组件接入。

同组多次编辑更新同一通知/计数，防抖沿用有效提交后约 600ms，不逐次堆叠。Toast 消失/关闭不清除 pending，调试状态保留“当前组待重载”。App 顶部菜单提供长期可访问的“从当前组入口重载”，并显示不可用原因；无修改时也可作为重复测试入口。

两处调用同一宿主操作，使用当前有效交接基线和最新有效已准备内容；没有候选时先准备，不重播旧候选冒充更新。无有效基线、编译失败或切换中禁用/解释。操作成功后按原播放/暂停意图处理，清除已应用 pending 和相关 Toast。

Toast action 绑定其提示时的 Group/交接身份。玩家已跨组时不能点击旧 Toast 却重载另一个新组；旧通知关闭或变为历史提示，App 菜单按实际当前组更新。App 菜单触发后能向 Editor 请求最新准备状态，不能直接读取作者文件并另起编译流程。

### 前置组提示与环

前置组 Toast 建议：“前置组已修改，当前状态仍包含旧的执行结果。重新开始游戏后可重建。”动作“重新开始游戏”，不叫“重载整个 App”，不强制返回标题。宿主支持直接开始新运行时可直接重开，无需先展示标题；沿用玩家数据，不隐式清空 profile。若同时存在当前组待重载，优先展示范围更大的前置状态警告，详情保留两个动作，并说明只重载当前组不能修复更早结果。

当前 Runtime 已支持合法 Graph 循环，见 docs/spec/runtime/execution.md 的运行图契约，以及 GameEngineLifecycleTests.NonblockingCycleYieldsAndCallerCancellationKeepsRunUsable。调试路线搜索为有界简单路径，使用 Visited 防止搜索循环，不等于禁止游戏图存在环，也不支持从该搜索器枚举任意绕圈次数。

因此不要将“前置/后置”编码为全图拓扑序。A → B → C → A 在第二次进入 A 时，当前是 A 的第二次访问，B/C 已对当前状态产生历史影响；B 的新版可用于后续再次进入，但无法撤销此前旧 B 的结果，需要警告。当前执行实例与自然交接代次必须区分访问，单槽快照覆盖为本次 A 的入口，不额外保存整段访问历史。

未执行/已执行只表达状态依赖保守判定；曾执行过的组也可能再次执行。产品文案宜用“尚未执行内容”“已执行内容影响当前状态”，减少有环时固定前后关系造成的误解。图连线/结构热更新仍不在本期范围，支持已有环不代表支持运行中随意改环。

### 尚需确认与实施核验

建议默认“Toast 提示，用户点击后重载”，而不是 Toast 一闪就自动回组入口；这是防止编辑打断运行的关键解释。当前演出修改也走该路径。Ursa 交互通知、按组实际生效版本、受保护前缀识别和安全后缀接纳为新增能力，需要专项设计验证，不能当成现成机制。

以下第 1–11 节是上一轮记录，自动当前组重播与整份候选必须全部接纳等冲突条款不再有效。

## 1. 产品规则

当前和后置 Group 内部修改可自动更新；前置修改仅提示，不强制返回标题或重新开始。完全自动，不提供热更新按钮或自动开关。保留单槽自然交接快照，以及 App 顶部的全内容跳过开关和组末尾动作。

允许多个 Group 同时修改。Graph 拓扑、Group 身份/源路径、变量声明、settings/I18n、资源和契约不在本期范围；遇到这些变化提示未应用及原因，用户可以继续旧运行或主动重新开始。契约/代码可能需重启 App，不能伪装为内容已应用。

前置定义如何处理尚待确认。本文建议一并接纳新版，只是不重算过去副作用；下一次进入使用新版。自动当前组重播建议尊重应用时原意图：播放则重播，调试暂停则在入口保持暂停。后者不是“保留旧时间线帧”。

## 2. 当前事实与技术边界

- ProjectDebugPreparation 先断开旧连接再构建/监听，不能直接反复调用作为自动重载入口。
- ProjectContentBuilder 提供正式产物/SourceMap/作者指纹，同时复制 Assets/I18n/settings；作者指纹不足以证明共享内容没变。
- DebugContentIdentity 未覆盖 Assets，需要补齐完整差异检查，不能漏掉文件新增、删除和字节变化。
- Editor 对作者变化后的旧映射有定位/单步门禁，需分别显示作者版本、准备版本、实际接纳版本。
- DebugSession 现有多组自然入口 LRU 只缓存纯场景；seek 保留当前变量、忽略部分副作用，不是本设计含 Save 值的交接快照。
- Engine 导航器和内容身份目前构造时固定，尚无非当前组无缝接纳路径；改文件不会自动改变运行。
- GameSession 已有串行停止/释放/重建能力，可用于当前组重播。只有后置变化时不得以从当前组入口重播冒充不中断更新。
- App 顶部 DebugMenuView/GameDebugViewModel/GameDebugActions 已有调试菜单。协议 groupEnd 是调试定位，普通 SkipToGroupEndAsync(false) 保留条件和逻辑写入，不能互换。

依据：[当前调试规范](../../docs/spec/editor/debugging.md)、[手册](../../docs/manual/editor/preview-and-debugging.md)及上述源码。本轮静态核对，未构建或运行验证。

## 3. 前置与后置按实际执行分类

不用 Graph 左右位置或单纯可达性定义前后，分支和循环中这些判据会冲突。

| 类别 | 判定 | 自动处理 |
| --- | --- | --- |
| 当前 | 正在执行的 Group | 恢复交接基线，从组入口重播；保留原播放/暂停意图 |
| 后置 | 本次运行未执行过的非当前 Group，含未走分支 | 接纳待进入定义，当前场景/Entry/变量/媒体不中断 |
| 前置 | 本次运行执行过的非当前 Group | 建议接纳定义，不重算过去；非模态提示状态可能过期 |

仅需记录已执行 Group 的身份与内容来源，不建立访问快照历史。循环中的当前组可能早先执行过，其入口可能含旧版本结果，仍需保留状态来源警告。

读档/seek 的来源无法证明时标记未知，不伪造干净前缀。非当前定义仍可替换，当前组重播必须有自己的有效入口。

前置提示：“前置组 A 已修改，当前场景保留此前执行结果。可继续测试；重新开始可重建状态。”提供展开组列表和主动重新开始动作，不弹确认框、不重复逐条 toast。定义已更新不等于历史已重算；警告直到建立可信新起点或差异撤销后才清除。

## 4. 自动触发、防抖与卡顿

复用作者提交：字段确认、拖动松手、曲线/事件编辑完成、Undo/Redo、受管外部重载。未确认草稿、PointerMove 中间预览、无效输入不触发应用。

建议静默窗口初值 600ms，待实测调优，不增加设置面板。手势/输入尚未完成则继续等待。短时间连续变更合并到最新版本；撤销回已接纳内容不做无意义重载。

最多一个准备/应用任务与一个最新待处理代次，不堆积队列。新编辑取消或淘汰过期准备结果；已进入运行切换的必要清理必须完成，再处理最新版本。后台保存/正式编译/哈希，不占 UI 线程；UI 只发布阶段与结果。

自动更新建议在有效编辑完成并静默后调用现有保存流程，首次连接以状态说明告知会自动保存，不覆盖未确认草稿/外部冲突。完整正式编译可作为第一版，测出瓶颈再优化，不能为每次编辑复制工具缓存或环境。

同一失败版本只报告一次，不无限重试；新有效编辑触发下一次准备。断线/项目关闭取消准备，重连先核对实际版本，不重放旧队列。

准备期间游戏可继续。提交时按实际位置重新分类；游戏已跨组时不得使用旧组快照恢复新组。只有非当前变化则走无中断路径；新当前组也改了则用它自己的有效入口。保留最新用户暂停意图，不用准备开始时的旧状态覆盖。

## 5. 无按钮 UX

调试工具栏/状态栏显示小型状态指示，可使用已有矢量火焰/同步图标，但没有可点击火焰按钮或自动开关。不使用 emoji 作为正式资源，不只靠颜色，不抢作者焦点或改变时间线选择。

- 已同步：低强调标识，tooltip 说明已接纳版本。
- 编辑中：等待本次编辑结束；无闪烁和反复提示。
- 准备中：简短阶段/进度。
- 应用完成：例如“已更新 2 个后置组”或“已重播当前组”，随后恢复弱状态。
- 前置结果过期：独立警告标识，可展开详情；允许同时显示定义已同步。
- 编译失败/暂不支持：原因和 Problems/日志入口，主动重新开始动作，不弹模态框。

参考 Visual Studio 的立即应用和保存时自动应用概念；本产品按用户最新指示只保留自动应用与状态反馈。[Hot Reload](https://learn.microsoft.com/en-us/visualstudio/debugger/hot-reload?view=visualstudio)、[自动应用设置](https://learn.microsoft.com/en-us/visualstudio/debugger/how-to-enable-and-disable-edit-and-continue?view=vs-2022)。外部参考不代表 GalNet 已有能力。

## 6. 内容差异与版本

正式候选携带完整编译结果和配套 SourceMap，以 App 实际接纳版本为基线，不能只依赖 dirty/事件/时间戳。Graph 结构、每组内容、声明、共享文件与资源路径/字节必须检查；App 独立验证实际候选，不盲信 Editor 哈希。

多个 Group 内部变更本身不是拒绝原因。当前文本修改连带公共 I18n 变化时，说明共享部分暂不支持；不得偷偷挑部分发布，再把整份作者内容标为已应用。纯布局变化无运行影响时视为无变化。

明确区分“新定义已接纳”与“场景来自旧前置执行”。允许后者作为调试状态，不将新内容指纹等同于真实历史重建，不放宽玩家存档跨版本恢复校验。

## 7. 单槽自然交接基线

自然进入 Group、初始状态和变量应用完成、首条 Entry 前，在执行门内捕获不可变深快照。包含 Group、场景/可恢复演出、Save 变量、来源内容与交接代次；首组同理。自然交接覆盖一份，不写磁盘、不建立玩家回退历史。

重播、seek、重复状态发布不覆盖基线。读档/外部恢复或来源不可证明时失效。无有效入口时暂缓当前组重播并提示，非当前定义更新可独立处理。连续热更新沿用同一交接数据，不把当前组结束状态当下次入口。

恢复 Save 变量；Player、已读、Gallery/成就不回滚。前置修改不强制丢弃基线，但必须标记旧来源。单份快照有大小预算，超限或不可恢复时明确暂缓当前组重播，正常游戏继续。

交接可能保留上一组非阻塞演出。只移交已有恢复机制可完整表达的状态，不能简单改旧 GameSnapshot 指纹绕过恢复门禁，也不能为捕获方便强制完成全部上一组演出。仍被活动呈现或基线引用的旧定义保留到所有者释放，禁止就地改写。

现有多组纯场景 LRU 保留原定位用途，定义变化时清理过期缓存，不把它变成此单槽基线。

## 8. 接纳路径与职责

非当前组：后台准备不可变候选，检查共享内容不变，执行门下核对位置并原子接纳待进入定义。保留当前 Entry、活动 Primitive、场景、变量及媒体；后续导航必须用新版，不能从旧 navigator 缓存拿旧组。前置组旧活动任务可按它持有的不可变定义完成，保留状态来源警告。

当前组：预检候选和恢复能力，停止旧执行并等待呈现清理，沿现有宿主机制重建运行，接纳所有允许 Group 定义，恢复当前组入口及 Save 值。Player 使用提交时值。按原意图重播或暂停；不能做活动时间线原地替换。

两种路径都要推进 Engine/宿主/协议的接纳版本，按作者 ID 更新 SourceMap/断点，删除条目标失效；旧请求和旧响应不能覆盖新代次。非当前无缝接纳需核验导航、内容身份和快照验证的一致性，不增加第二套导航框架。

Editor.Shared 负责正式构建/差异/映射，GUI 负责合并与状态；Debugging 负责认证/能力/代次，宿主负责内容生命周期与运行切换，Runtime 负责受控接纳/恢复；Avalonia.Debugging 扩展现有 App 菜单。复用现有命令门和所有权，优先少量明确的方法，不另建通用调度层。

候选在受控版本目录准备，不覆盖活动文件；开发验证输出放根 output/，正式项目调试输出沿用既有布局。遇实际占用/环境冲突按约定说明等待，不自行隔离。协议直接使用新版本，不保留旧宿主适配；自定义宿主是否实现热更新能力仍需显式声明，能力缺失不能冒充成功。路径限制到本调试项目输出。

## 9. 失败与资源

提交前保存/编译/预检失败保留旧运行和旧映射。停止旧运行前取消可丢弃候选；停止后失败/取消完成清理，停在明确失败状态，不承诺还原旧执行。必要释放不可因取消跳过。

断线/超时不代表未应用，重查实际版本再重试；旧成功响应不能清除构建后新编辑的 pending。旧候选和内容目录在所有者释放后清理。前置变化只提示，不触发自动重启或玩家数据清除。

## 10. App 跳过与组末尾

允许跳过全部内容：独立的会话级开关，默认关，重建运行保留，结束会话清除。未读也可快进，演出用明确调试完成能力落终态；不批量写已读、不写玩家设置，必要加载/恢复仍等待。

条件、变量、对象和终态逻辑不能丢弃。自定义 Primitive 无安全完成能力时等待或说明，不抛弃实例冒充完成。正常游玩产生的进度不被此开关阻止，也不在重载时回滚。

跳到当前组末尾：采用普通 SkipToGroupEndAsync(ignoreConditions: false)，在出边前停止、保留逻辑写入，不直接用忽略写入的调试 groupEnd。开关关时遵守不可跳过限制，开时用调试完成路径。选择由玩家决定，可取消；与热更新提交串行，不能同时清理同一运行。

## 11. 验收与开放事项

未来验收，本轮未执行：

1. 当前组重复重播从同一场景/Save 基线开始；原暂停/播放意图正确，不抢编辑焦点。
2. 后置多组更新不打断当前对白/媒体，进入后执行新版；前置警告可继续，循环再进入用新版。
3. 分支/循环、读档/seek、准备期间跨组的分类与版本正确，旧前置状态警告不被接纳新版误清除。
4. 拖动/未确认输入无中间应用，连续编辑合并、过期结果不应用、同版本失败不循环；测量 UI 响应和提交耗时。
5. 共享变更、不支持恢复、断线/取消/关闭/停止后失败有明确状态与清理证据。
6. 上一组非阻塞动画/音频在两条接纳路径中不被旧任务覆盖；跳过/组末尾覆盖条件、变量、选择和自定义能力。

待用户确认：前置组定义一并接纳还是保留未应用。建议前者，避免逐组混合版本管理。自动当前组原播放重播/原暂停保留、600ms 防抖、有效编辑后自动保存及弱状态指示属于本轮建议默认，可继续修订。

实施前核验非当前内容接纳的导航/身份/恢复一致性、入口活动呈现的可恢复性，以及宿主内容/本地化绑定所有权。不能实现时先报告具体限制，不悄悄降级为每次后置更新也重播当前组。实现、阶段计划和正式规范同步另行处理。
