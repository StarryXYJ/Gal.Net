# Group 自动热更新与快速测试

状态：design；仅整理设计，未开始实现。2026-11-02。

## 已确认需求

- 不考虑向后兼容：存档/调试协议可直接升级，旧版本明确拒绝，不提供旧档迁移、缺字段回退或旧协议适配。Editor 与 App 使用配套新版本。
- 后置 Group 和当前组尚未执行的安全后缀自动热更新，避免退出 App 或返回标题重新开始。
- 当前组已执行部分或正在执行的条目改变，不自动打断/重播；用 Ursa Toast 提示并提供“从组入口重载”。App 内调试菜单也提供同一动作。
- 已经历的其他 Group 改动用 Ursa Toast 提示需要重开档，提供主动重新开始动作，不强制执行。读档后同样依据该存档已经历的组判断；读回同一个受影响存档不能清除提示。
- 用户最新修订：完全自动热更新，不提供手动火焰按钮和自动 ToggleButton；需要防抖、合并更新，避免卡顿。
- 已经历 Group 集合随存档持久化并在读档时替换恢复，不存全局 Player 数据，不建立完整访问顺序历史。
- 只保留一个当前 Group 自然入口基线，包含场景和 Save 变量。为支持从组中途读档后仍可从组头重载，设计建议将此基线也随当前存档保存；不递归嵌套历史快照。
- App 顶部仍提供“允许跳过全部内容”和“跳到当前组末尾”，不属于被取消的热更新按钮。

## 设计建议与待确认

已经历组的状态结果不追溯修复，提示重开档；是否提前接纳它们的新定义仍是实现策略，不能因接纳就清除重开档提示。为发现“修改发生在读档之前”，建议记录经历组的内容指纹，详见设计开头的持久化修订。

从组入口重载建议尊重原意图：原本播放则从入口重播，原本调试暂停则恢复入口后保持暂停。600ms 静默窗口、有效编辑后自动保存、弱状态图标均为设计建议，未作为用户已确认要求。最新有效设计见 design.md 开头“执行位置修订”；后文上一轮方案仅供历史取舍参考。

## 范围与验收

允许多个 Group 内 Entry 参数、条件、时间线、增删与排序；Graph、声明、资源、公共配置和契约暂不在热更新范围。不支持的变化提示尚未应用，提供主动重新开始，不强制执行。

验收：安全后缀与后置组修改不中断当前对白/动画；当前组前段修改只 Toast 提示，点击或使用 App 菜单后从同一基线重播；前置组只警告；拖动中间态和未确认输入不触发；连续修改合并、过期结果不应用；后台准备不阻塞 UI；版本/映射/断点一致；旧异步任务不会覆盖新版；错误不反复弹窗或无限重试。

遵守本地 SDK/缓存/bin/obj 约定，验证输出放根目录 output/；实际占用/环境冲突先说明等待决定。
