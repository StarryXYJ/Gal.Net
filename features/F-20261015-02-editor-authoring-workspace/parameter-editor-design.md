# 参数控件与场景目标设计（用户第 6 点）

日期：2026-10-17。状态：design，仅设计，尚未实现。所属：[Editor 创作工作区](feature.md) / P6；Group 交互第 1–5 点另见 [Group 编辑设计](group-editing-design.md)。本文件是第 6 点的唯一详细设计来源。

## 1. 目标与已确认边界

默认以 DTO/schema 生成参数面板；多数扩展只需声明类型、字段及值约束。需要特别交互时，可以替换一个字段的控件，也可以替换整个 DTO 的参数面板，其他字段仍能复用自动表单。Sample 设置页与 Editor 共用这套能力，开发者在程序入口注册扩展。

用户已确认：写演出/剧本的人不需要知道 handle。Editor 展示名称、缩略图和可选择的场景目标；底层继续使用 handle，C# 执行接口不在本轮更改。EditorId 也不作为普通控件扩展作者必须掌握的注册方式；内置 hint 可继续作为框架内部适配。

本轮不实现 registry 扩展、目标解析、timeline/曲线，也不迁移 Sample 或修改内容格式。后续实施不考虑旧 UI API 兼容层，但任何 wire 格式变动仍须统一处理 codec、编译、执行与 fixture，不能仅改一个控件。

## 2. 当前可以复用的事实

| 现有部分 | 复用方式 | 尚缺能力 |
| --- | --- | --- |
| EntryDefinition.FieldDataType | 精确定位根 DTO 类型 | 整 DTO 面板工厂入口 |
| FieldDescriptor / ValueDescriptor / ValueCodec | 字段类型、值约束、JSON 转换 | 成员路径与局部工厂映射 |
| SchemaForm / EditorRegistry | 默认表单及已有字段工厂 | 类型覆盖统一解析、嵌套组合 |
| IFieldBinding / FieldEditorContext / FieldEditorLease | 草稿、提交、诊断及控件生命周期 | 整 DTO 的多字段原子编辑上下文 |
| Editor 的作者 JSON 与项目历史 | 唯一内容真源及 Undo/Save | 复杂交互的手势事务适配 |
| SampleCustomization / DtoBinding | 程序入口组合及设置数据适配 | 新注册协议的共享接入 |
| IAssetManager / ISceneInstanceManager | 分别查询资产、运行时实例 | 未启动游戏时的作者场景目标分析 |

当前 AnimationPlanOptions.Plan 是 JsonElement，尚不是 AnimationPlanDefinition 类型字段；目前没有发现可直接复用的作者场景 Locator。不能把这些目标能力写成已存在服务。

## 3. 模块职责与数据流

~~~mermaid
flowchart TD
    Host[Editor / Sample 程序入口] --> Registry[参数控件注册表]
    Schema[DTO 类型与字段 schema] --> Presenter[参数面板宿主]
    Registry --> Presenter
    Presenter --> Root[整 DTO 自定义面板]
    Presenter --> Form[默认 SchemaForm]
    Form --> Field[成员覆盖 / 值类型覆盖 / 默认控件]
    Root --> Binding[宿主 binding 与编辑事务]
    Field --> Binding
    Binding --> Data[Editor 作者 JSON / Sample 设置]
    Targets[Editor 场景分析与资源候选] --> Field
~~~

共享 Avalonia.Controls Forms 层负责注册协议、控件解析、面板组合、上下文和 lease，不依赖 Editor 项目服务。Core/契约层只提供中立值与 schema，不引用 Avalonia。

Editor 提供作者文档 binding、项目历史、资源/场景目标服务和文案；Sample 提供设置 binding 与自己的服务。默认设置页不需要创建场景分析器。项目专属工厂可由独立 Editor UI 扩展程序集贡献，纯契约 DLL 仍不包含 Control；不通过扫描任意程序集自动启用扩展。

注册表在宿主组合期建立并冻结。应用内置注册可作模板，项目注册集合随项目 scope 释放；工厂只借用当前 scope 服务，不将项目 Type、Control 或项目服务长期缓存到全局单例。

## 4. 三种注册粒度与解析规则

以下名称仅说明拟议 API，不是现有接口：

~~~csharp
// 同一值类型在任何 DTO 字段中使用专属控件。
editors.RegisterValue<AnimationPlanDefinition>(ctx => CreateTimeline(ctx));

// 只覆盖特定 DTO 的特定成员；其他字段照常自动生成。
editors.RegisterField<AnimationPlanOptions>(x => x.Plan,
    ctx => CreateTimelineJsonAdapter(ctx));

// 替换根 DTO 的整个参数区。
editors.RegisterDto<MyOptions>(ctx => CreateCustomPanel(ctx));
~~~

成员选择器通过生成的成员/schema 映射定位 JSON 字段，不直接把 CLR 属性名当 wire ID，不要求开发者手写 EditorId。嵌套路径逐段解析；数组中的元素控件按元素类型或 schema 路径模板注册，不能把当前数组下标当作永久字段身份。

解析次序固定：

1. 根参数区先查精确 DTO 面板映射；未命中则创建默认自动表单。
2. 自动表单每个字段依次查指定 DTO 成员映射、精确值类型映射、已有 EditorRegistry 默认规则。
3. 对嵌套 DTO，父字段的成员/值类型覆盖优先；均未命中时再查嵌套 DTO 面板映射，否则递归生成字段。

因此字符串类型的“场景目标”和普通文本可以分别处理，不能为了一个 handle 字段全局覆盖所有 string。显式宿主注册允许覆盖内置 hint；未覆盖的字段继续遵循现有显式 EditorId、选项、标量和 JSON 回退规则。

重复注册报错，Replace 明确表示替换，不以最后注册者静默获胜。首版只做精确类型匹配，不猜测继承/接口优先级。nullable 可按基础类型选控件，但 presence/null 权限及转换器仍由原字段描述决定。递归类型设深度/循环防护；未知类型提供明确 JSON 回退或诊断。

## 5. 复用自动表单与编辑协议

整 DTO 自定义控件可组合：自定义区域 + 默认生成其余字段。例如 timeline 管理 Plan，BatchId 仍自动生成；不必重新写整套标签、校验、布局和保存。

面板上下文提供“创建默认表单并排除已负责字段”的能力。它只绕过当前根 DTO 的整面板映射，保留成员/值类型映射，避免再次创建自身。一个字段只由一个已挂载区域负责，避免两个草稿相互覆盖。自动生成按层级展开需要创建控件，循环结构显示可操作的回退。

整个 DTO 上下文不能假定作者内容已经是有效 DTO：Entry 可能缺必填值或含未知字段。建议暴露 schema、只读 JSON 快照、字段/子路径 binding、动态选项、原子 patch/手势事务、诊断、取消和版本戳；不向控件交出可直接修改的唯一作者对象。

- Editor 的真实数据仍为作者 JSON，控件通过 binding 提交字段或原子 patch；保留未知字段以及缺省/null/default，不用反序列化后重建 DTO 覆盖整个对象。
- Sample 仍用 DtoBinding/设置提交路径；复用控件协议，不借用 Editor 的历史或文件保存事务。
- timeline 关键帧拖动、曲线拖柄、颜色连续调整采用开始/预览/提交/取消手势；一次完整手势一条历史，取消恢复开始前状态。没有预览宿主时仍可编辑值，不依赖游戏启动。
- schema/type 切换、Entry 删除、列表元素移除或项目关闭后，旧版本上下文拒绝晚到提交；数组重排中的草稿绑定需稳定元素身份或在集合版本改变时取消，不能按旧下标写错对象。
- 每个工厂返回新建、无父级的控件及 lease；卸载/折叠释放控件订阅，作者数据仍留在项目文档。工厂失败保留诊断；有未提交输入时先按统一草稿协议提交或明确取消，不能靠控件销毁丢弃输入。

## 6. 资产选择与场景目标选择

二者共用候选列表的搜索/缩略图展示，但数据来源、身份和合法性不同：

| 选择内容 | 来源 | 身份与例子 |
| --- | --- | --- |
| 项目资产 | 项目 asset 索引 | 某张图片、音频文件的 asset ID |
| 在场实例 | 当前 Entry 位置的抽象场景 | 同一图片创建的左侧角色层、右侧角色层 |
| 播放/效果实例 | 创建它的 Entry 及领域语义 | 某次动画播放、某个效果或粒子实例 |

UI 根据字段语义提供目标类别与合法属性。例如动画先选择目标层，再选择该层可动画属性；effect 字段可按契约提供“整个场景”选项，不将空字符串当作可见业务选项。候选使用稳定身份与友好标签，改显示名不改变引用。

建议 Editor 内部 Locator 以创建者的稳定 Entry ID + 输出槽位描述目标，跨 Group 时带文档/Group 身份。它是作者目标解析模型，不是资产 URL，也不要求更改运行时实例管理接口。

创建型 Entry 自动分配不透明内部 handle，选择器把目标解析为对应 handle 保存到原参数字段。handle 生成独立于列表序号、文件路径和显示名；名称重命名、Entry 重排不改变目标。替换内容但保留实例身份与“销毁再新建”由该 Entry 的领域语义区别处理，不能一律每次生成新目标。

复制创建者时分配新的内部身份；批量复制同时重映射批内目标引用，外部引用保留原目标；撤销/重做恢复同一次操作的已分配身份。删除目标生产者后保留引用并显示未解析目标，不让刷新候选静默清空参数。

作者界面展示目标名称/类型/来源及无效原因，不展示或要求输入 handle。对手写内容中无法反查的 handle，同样显示“未解析目标”并允许重新选择，不把底层字符串原样当默认标签。

## 7. 未启动游戏时的场景分析

分析对象是当前 Entry 之前的作者内容，不是资源目录。为内置创建/替换/隐藏/停止等 Entry 提供纯场景语义贡献器；扩展 Entry 可显式贡献同一协议。分析器不调用游戏执行代码，不创建播放器、网络请求或游戏 UI。

候选分三种信息：确定存在、可能存在、分析未知。顺序内容可增量推演；分支汇合保留路径差异，条件/循环/未知扩展不能被当成没有副作用。跨 Group 的入口场景不同，无法确定调用上下文时展示带不确定性的候选，而不是构造一套假的当前场景。

界面允许看见并选择可能存在的目标，同时显示作用域/条件提示；确定的断链、目标种类或属性不匹配产生错误。对可能存在的目标不自动承诺编译必然成功，运行时缺目标行为继续按领域契约执行。未知 Entry 之后可保留已知来源但降低置信度，不能宣称完整推断任意自定义脚本。

实现时以文档 revision、当前位置及分析器版本缓存结果，前置 Entry/分支/资源变化使相关结果失效；异步结果需校验版本再显示。以后游戏预览可提供实时观测，但不能把预览某次路径看到的实例当作所有路径必然存在的事实。

## 8. AnimationPlan、timeline 与曲线

第一步可对 AnimationPlanOptions.Plan 做成员覆盖，适配现有 JsonElement；只替换这一字段，不对所有 JsonElement 注册 timeline。适配器只改负责的键，未知扩展字段无损保留；无法解析的内容显示诊断/原始值回退，不自动重置为新计划。

未来如果把 Plan 改为强类型 AnimationPlanDefinition，值类型映射即可复用。这个类型化属于契约变化，需要单独验证 codec 与执行参数，不是注册服务的先决条件。

timeline 可组合轨道列表、场景目标选择、关键帧视图、属性面板；曲线控件作为独立值/成员覆盖，也可嵌入 timeline。二者使用同一上下文、patch 和手势协议，算法/绘制与 Editor 历史分离。完整动画预览与游戏预览分开：可以先做数值曲线采样预览，游戏场景预览仍放后期。

## 9. Sample 接入方式

在程序入口组装默认表单注册，再显式添加项目自定义字段/值类型/整个设置 DTO 面板工厂。现有 SampleCustomization.CreateFieldEditors 是自然组合点，服务注入沿用其 scope。工厂只依赖共享表单协议和宿主提供的服务，Editor 专属资源/场景候选不成为共享控件的硬依赖。

同一个颜色/曲线控件可在 Sample 设置与 Editor 参数复用；两端使用不同 binding 适配实际数据及提交策略。运行时设置若需要即时预览、取消恢复，继续由设置服务管理，不强行建立 Editor 项目历史。启动入口注册不等于每个控件都是 singleton；控件实例仍逐次创建并释放。

## 10. 实施切片与验收

| 切片 | 可单独交付的结果 | 关键验收 |
| --- | --- | --- |
| A 注册与字段覆盖 | 默认表单 + 值类型/成员覆盖 | 同类型字段局部替换、优先级、重复/Replace、未覆盖字段不变、释放 |
| B 整 DTO 组合 | 整面板替换 + 自动生成剩余字段 | 不递归创建自身、不丢未知字段、缺省/null、原子多字段 Undo |
| C Sample 验证 | 程序入口注册并复用一组控件 | 两个宿主不同 binding、设置预览/取消、无 Editor 依赖 |
| D 场景目标基础 | 内置直线剧情的候选与隐藏 handle | 多实例、自动身份、复制重映射、重排/Undo、删除诊断 |
| E 控制流扩展 | 分支/跨 Group/未知语义反馈 | 确定/可能/未知标签、增量失效、无游戏执行副作用 |
| F 动画专属编辑 | Plan 成员覆盖及曲线手势 | 关键帧编辑、采样、取消、一次手势一条历史、未知 JSON 保留 |

这些是可选实施拆分，不把第 6 点直接变成已授权的六个实现阶段。P6 开始前按依赖与实际范围细化；P5 继续使用现有基础 SchemaForm，第 1–5 点不等待新 registry、Locator 或动画工具完成。

本设计没有新增必须由用户回答的阻塞项。最需要实测的风险是复杂表单草稿/事务生命周期、条件控制流下的目标置信度，以及现有 Plan JSON 的无损适配；逐切片验证后再更新正式 spec。
