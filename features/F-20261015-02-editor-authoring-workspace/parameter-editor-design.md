# 参数控件与场景目标设计（用户第 6 点）

日期：2026-10-17；补充：2026-10-18。状态：design；用户随后已授权实施，共享 UI 基础已由 [P6a](phase-6a.md) 验证，普通嵌套/列表和 presence 操作由 [P6b](phase-6b.md) 验证，其余部分仍为设计。所属：[Editor 创作工作区](feature.md) / P6；Group 交互第 1–5 点另见 [Group 编辑设计](group-editing-design.md)。本文件集中第 6 点的总体职责与状态查询设计；复杂控件的细节见 [对象树时间轴设计](complex-editor-design.md)，不重复建立另一套注册/查询架构。

## 1. 目标与已确认边界

默认以 DTO/schema 生成参数面板；多数扩展只需声明类型、字段及值约束。需要特别交互时，可以替换一个字段的控件，也可以替换整个 DTO 的参数面板，其他字段仍能复用自动表单。Sample 设置页与 Editor 共用这套能力，开发者在程序入口注册扩展。

用户已确认：写演出/剧本的人不需要知道 handle。Editor 展示名称、缩略图和可选择的场景目标；底层继续使用 handle，C# 执行接口不在本轮更改。EditorId 也不作为普通控件扩展作者必须掌握的注册方式；内置 hint 可继续作为框架内部适配。

原设计阶段不修改业务代码；用户随后授权开始，P6a 先落地三层注册/默认表单/多 DTO 面板及两个宿主接入，目标解析、timeline/曲线及内容格式不在 P6a 实施。后续实施不考虑旧 UI API 兼容层，但任何 wire 格式变动仍须统一处理 codec、编译、执行与 fixture，不能仅改一个控件。

## 3. 两个独立子系统

用户明确分成共享 UI 构建与 Editor 状态查询两部分。UI 不自行推演游戏状态，状态查询不创建 Control。二者只在 Editor 提供的动态候选 binding 处组合。

| 子系统 | 归属 | 职责 |
| --- | --- | --- |
| UI 构建 | 共享 Avalonia.Controls Forms 层 | 三层注册、默认 DTO 表单、多 DTO 面板、控件上下文与 lease |
| 状态查询 | Editor.Shared 的中立查询/分析服务，Editor UI 适配 | 按当前位置查询资源/实例及其存在性、增量推演与缓存 |

Sample 与 Editor 使用同一 UI 构建机制，分别注入设置 binding 与作者文档 binding。Core/契约 DLL 不依赖 Avalonia，默认设置页不依赖 Editor 状态查询。

~~~mermaid
flowchart TD
    Items[有序 DTO 项列表及各项 binding] --> Panel[多 DTO 面板]
    Registry[三层控件注册表] --> Panel
    Panel --> Choice{特定 DTO 控件映射}
    Choice -->|有| Custom[自定义 DTO 控件]
    Choice -->|无| Form[默认 DTO 表单]
    Registry --> Form
    Form --> Field[成员映射优先，否则默认类型映射]
    Custom --> Binding[共享编辑上下文 / 宿主 binding]
    Field --> Binding
    State[Editor 状态查询与缓存] --> Options[Editor 动态候选适配]
    Options --> Binding
~~~

共享面板只负责把一组 DTO 项转换成一组控件，不拥有 Group 的增删/排序/选择命令。项目扩展工厂可以由独立 Editor UI 扩展程序集贡献，纯 schema DLL 仍不包含 Control；不扫描任意程序集自动启用扩展。应用内置注册可作模板，项目集合随 scope 释放，避免全局缓存 Type/项目服务使程序集无法卸载。

## 4. 三层注册、默认表单与多 DTO 面板

注册表严格保留三层映射，不把内部 hint 再扩展成开发者必须注册的第四层：

| 映射 | 键 | 工厂负责的范围 |
| --- | --- | --- |
| 特定 DTO → 控件 | 精确 DTO 类型 | 一个 DTO 的整个参数区 |
| 特定 DTO 成员 → 控件 | 声明 DTO 类型 + 成员路径 | 该成员的单个字段区域 |
| 默认类型 → 控件 | 字段值的精确类型 | 没有成员覆盖时使用，例如 string/bool/数值/曲线 |

以下只是设计 API，不是已实现接口：

~~~csharp
editors.RegisterDto<MyOptions>(ctx => CreateCustomPanel(ctx));
editors.RegisterMember<AnimationPlanOptions>(x => x.Plan, ctx => CreateTimelineJsonAdapter(ctx));
editors.RegisterDefault<string>(ctx => CreateTextEditor(ctx));
editors.RegisterDefault<MyCurve>(ctx => CreateCurveEditor(ctx));
~~~

**默认 DTO 表单**负责实现普通 DTO → 控件。它读取同一 schema，逐字段查特定 DTO 成员映射；未命中才使用默认类型映射，然后生成标签、控件和诊断。它不负责“整 DTO 是否被覆盖”的分派，也不负责枚举一组 DTO。值约束、固定/动态选项、单位、格式、只读/可见状态通过字段上下文传入类型工厂；例如默认 string 工厂可以根据选项/多行提示选择内置展示，不需要开发者再注册 editor ID。

**多 DTO 面板**接收有序项列表，每项包含稳定 ItemId、DTO 类型/schema 和该项 binding。逐项查特定 DTO → 控件映射；存在则挂载自定义控件，不存在则挂载默认 DTO 表单。面板以 ItemId 复用/释放项，不能以 Type 作唯一 key，因为多个 Entry 常共享同一种 DTO。宿主负责提供顺序与条目外壳；Sample 的设置分组、Editor 的 Entry 列表都可复用其创建/生命周期逻辑，不要求使用相同列表皮肤。

嵌套对象由默认结构类型编辑器处理；需要应用整 DTO 覆盖时，复用面板背后的同一个“单 DTO 创建”方法，避免表单和面板各实现一套分派。成员覆盖始终先于默认结构编辑器，集合元素按稳定项身份或集合版本管理，不能把数组下标作为永久绑定身份。

成员表达式通过 schema/generated 成员信息解析 wire ID，不直接把 CLR 属性名当 JSON 字段名。首版精确类型匹配，不猜测继承/接口优先级；nullable 可解包基础类型选控件，但 null/presence 与 converter 保持原字段语义。重复注册报错，显式 Replace 才替换；注册完成冻结。

原有 EditorRegistry/EditorId 只作实施过渡与内置提示适配，最终公开组合入口是以上三层映射，不要求扩展作者理解字符串 editor ID。已有专属资源/表达式控件在 Editor 组合点注册到对应 DTO 成员，不能为了目标字段全局替换所有 string。未知类型统一走明确的 JSON/结构回退或诊断，递归类型防护不额外建立注册层。

## 5. 复用自动表单与编辑协议

整 DTO 自定义控件可组合：自定义区域 + 默认生成其余字段。例如 timeline 管理 Plan，BatchId 仍自动生成；不必重新写整套标签、校验、布局和保存。

面板上下文提供“创建默认表单并排除已负责字段”的能力。它直接调用默认 DTO 表单，保留成员/默认类型映射，不再次经过多 DTO 面板的整 DTO 分派，避免创建自身。一个字段只由一个已挂载区域负责，避免两个草稿相互覆盖。自动生成按层级展开需要创建控件，循环结构显示可操作的回退。

整个 DTO 上下文不能假定作者内容已经是有效 DTO：Entry 可能缺必填值或含未知字段。建议暴露 schema、只读 JSON 快照、字段/子路径 binding、动态选项、原子 patch/手势事务、诊断、取消和版本戳；不向控件交出可直接修改的唯一作者对象。

- Editor 的真实数据仍为作者 JSON，控件通过 binding 提交字段或原子 patch；保留未知字段以及缺省/null/default，不用反序列化后重建 DTO 覆盖整个对象。
- Sample 仍用 DtoBinding/设置提交路径；复用控件协议，不借用 Editor 的历史或文件保存事务。
- timeline 关键帧拖动、曲线拖柄、颜色连续调整采用开始/预览/提交/取消手势；一次完整手势一条历史，取消恢复开始前状态。没有预览宿主时仍可编辑值，不依赖游戏启动。
- schema/type 切换、Entry 删除、列表元素移除或项目关闭后，旧版本上下文拒绝晚到提交；数组重排中的草稿绑定需稳定元素身份或在集合版本改变时取消，不能按旧下标写错对象。
- 每个工厂返回新建、无父级的控件及 lease；卸载/折叠释放控件订阅，作者数据仍留在项目文档。工厂失败保留诊断；有未提交输入时先按统一草稿协议提交或明确取消，不能靠控件销毁丢弃输入。

## 6. 资产选择与场景目标选择

二者共用候选列表的搜索/缩略图展示，但数据来源、身份和合法性不同：

| 选择内容 | 来源 | 身份与例子 |
| --- | --- | --- |
| 项目资产 | 项目 asset 索引 | 某张图片、音频文件的 asset ID |
| 在场实例 | 当前 Entry 位置的抽象场景 | 同一图片创建的左侧角色层、右侧角色层 |
| 播放/效果实例 | 创建它的 Entry 及领域语义 | 某次动画播放、某个效果或粒子实例 |

UI 根据字段语义提供目标类别与合法属性。例如动画先选择目标层，再选择该层可动画属性；effect 字段可按契约提供“整个场景”选项，不将空字符串当作可见业务选项。候选使用稳定身份与友好标签，改显示名不改变引用。

建议 Editor 内部 Locator 以创建者的稳定 Entry ID + 输出槽位描述目标，跨 Group 时带文档/Group 身份。它是作者目标解析模型，不是资产 URL，也不要求更改运行时实例管理接口。

创建型 Entry 自动分配不透明内部 handle，选择器把目标解析为对应 handle 保存到原参数字段。handle 生成独立于列表序号、文件路径和显示名；名称重命名、Entry 重排不改变目标。替换内容但保留实例身份与“销毁再新建”由该 Entry 的领域语义区别处理，不能一律每次生成新目标。

复制创建者时分配新的内部身份；批量复制同时重映射批内目标引用，外部引用保留原目标；撤销/重做恢复同一次操作的已分配身份。删除目标生产者后保留引用并提示当前未匹配到目标，不让刷新候选静默清空参数；运行时目标不存在则跳过，不能仅因没有候选阻止保存/编译。

作者界面展示目标名称/类型/来源及可用性提示，不展示或要求输入 handle。对手写内容中无法反查的 handle，同样显示“未解析目标”并允许重新选择，不把底层字符串原样当默认标签。

## 7. Editor 当前状态查询与缓存

### 7.1 查询契约与执行语义

用户确认所有 Entry 对目标存在性的语义为“有则执行，没有则忽略”。查询结果是创作辅助，不是运行时存在性门禁；可能存在、当前未查到、生产者已删除均不因缺少目标自动成为编译错误。参数格式错误、类型/属性不匹配和非法曲线等值契约问题仍按原校验处理，不能被“缺目标忽略”吞掉。后续实现需核对现有执行器与该目标语义一致，有差异时统一修正，不能只在 UI 中隐藏异常。

查询位置默认是某个 Group 的某个 Entry **执行前**；列表末尾表示全部已知 Entry 之后，需要执行后状态的控件显式指定。查询包含目标种类过滤，返回稳定身份、名称、资源信息和存在性两种分类：

- **一定存在**：所有可达路径在该位置都存在。
- **可能存在**：至少部分路径可能存在，或分析无法保证其一定存在。

不向用户引入第三种“未知”资源类别。不确定/不支持的自定义语义只影响内部完整性标记，并将相关已知候选保守归入可能存在；界面可显示不确定原因，但分类仍只有两种。完全无法枚举的动态对象不能凭空产生候选，查询内部返回 incomplete 信息说明列表可能不完整，并保留已有引用。

资产库文件与在场实例仍是两种查询域。实际已索引的资产文件不因剧情分支变成可能存在；分支分析主要影响场景/播放/效果实例。两类候选采用相同的存在性字段，但分别判断，不把“资源文件存在”解释为“场上实例存在”。

### 7.2 状态表示与控制流

状态保存确定集合 D 和可能集合 P，满足 D 是 P 的子集；对外将 D 显示为一定存在，将 P 减 D 显示为可能存在。已知在该位置不可能存在的对象不列入候选，已有引用仍可保留且执行时缺目标跳过。资源身份与属性事实分开：对象一定存在不代表其图片/位置等属性值也唯一。

每种 Entry 由纯状态转换贡献器描述创建、替换、删除和无影响行为，不执行游戏命令。条件已知时取对应路径；无法确定时合并“执行”和“跳过”两种状态。可达分支汇合时 D 取交集，P 取并集，不可达前驱不参与。移除/替换按具体领域语义更新状态，不能把所有操作都当作创建新实例。

Group 初始状态来自可达前驱/调用上下文，不把每个 Group 都视为空场景。无入口/不可达 Group 提供结构化的未分析提示。跨 Group 复用输入摘要；循环通过工作队列求固定点，超出分析预算时保守扩大可能集合并减少确定事实，候选身份限于已知来源，避免无限枚举运行次数。

没有语义贡献器的自定义 Entry 不当作无影响：相关已知目标降为可能存在，内部标记分析不完整，直到后续确定性操作重新建立事实。后期游戏预览可提供某次实际路径的状态；它与静态两类结果来源分开，不用一次观测证明所有路径一定存在。

### 7.3 缓存与失效

优先缓存每个 Group 的入口状态、出口摘要和依赖信息；大 Group 再按固定间隔或结构节点缓存前缀状态，不为每个 Entry 保存完整场景副本。任意位置查询从最近有效检查点向前推演，结果不可变、可共享，优先使用结构共享或差量降低内存。

缓存键至少包含项目/schema/语义提供器版本、Group 文档 revision、入口摘要签名及所需资源索引版本。Entry 修改后失效本 Group 自修改位置之后的前缀与出口；出口摘要变化才传播给后继，分支/Graph 拓扑改变重建依赖。Undo/Redo 同样产生状态失效，不能只监听磁盘文件。纯显示名变化只刷新候选展示，不因名称改变内部身份。

跨 Group 输入多样时，默认用合并后的入口状态服务普通 Editor；如果宿主提供明确调用上下文，可以按输入签名分别查询/缓存。缓存设置数量/内存预算并淘汰，项目关闭释放全部分析状态。后台分析捕获一致作者快照，完成时核对 revision/请求位置再发布，过期结果丢弃；共享 UI 只订阅结果，不拥有分析任务。

## 8. AnimationPlan、timeline 与曲线

2026-10-18 用户补充对象/属性树和关键帧/切线/曲线交互，详细设计见 [complex-editor-design.md](complex-editor-design.md)。后者细化本节：对象父行分组、属性选择加入轨道、首帧/碰撞/时长/FPS 规则、Hermite 单位、局部草稿与单历史、事件和隐藏 handle；状态仍为 design。

用户进一步确认先做独立 Timeline Dock（默认资源区域），属性树叶节点值直接 upsert 当前帧键，再做 animate 自定义曲线。Timeline 名称替换和未来实时预览另有代码影响分析；Timeline 曲线按帧编辑属性，animate 自定义曲线按归一化时间编辑进度，复用画布但分开值契约。其余专业参数面板保留远期接点，不作为这一轮额外工具目标。

第一步可对 AnimationPlanOptions.Plan 做成员覆盖，适配现有 JsonElement；只替换这一字段，不对所有 JsonElement 注册 timeline。适配器只改负责的键，未知扩展字段无损保留；无法解析的内容显示诊断/原始值回退，不自动重置为新计划。

未来如果把 Plan 改为强类型 AnimationPlanDefinition，默认类型映射即可复用。这个类型化属于契约变化，需要单独验证 codec 与执行参数，不是注册服务的先决条件。

timeline 可组合轨道列表、场景目标选择、关键帧视图、属性面板；曲线控件作为独立值/成员覆盖，也可嵌入 timeline。二者使用同一上下文、patch 和手势协议，算法/绘制与 Editor 历史分离。完整动画预览与游戏预览分开：可以先做数值曲线采样预览，游戏场景预览仍放后期。

## 9. Sample 接入方式

在程序入口组装默认表单注册，再显式添加项目自定义 DTO/DTO 成员/默认类型三层工厂。现有 SampleCustomization.CreateFieldEditors 是自然组合点，服务注入沿用其 scope。工厂只依赖共享表单协议和宿主提供的服务，Editor 专属资源/场景候选不成为共享控件的硬依赖。

同一个颜色/曲线控件可在 Sample 设置与 Editor 参数复用；两端使用不同 binding 适配实际数据及提交策略。运行时设置若需要即时预览、取消恢复，继续由设置服务管理，不强行建立 Editor 项目历史。启动入口注册不等于每个控件都是 singleton；控件实例仍逐次创建并释放。

| A 注册与字段覆盖 | 三层注册 + 默认 DTO 表单的成员/默认类型覆盖 | 同类型字段局部替换、优先级、重复/Replace、未覆盖字段不变、释放 |

这些是候选实施拆分；后续用户已授权开始，P6a 先实现共享 UI 基础，不代表全部六个切片已经完成。P6 开始前按依赖与实际范围细化；P5 继续使用现有基础 SchemaForm，第 1–5 点不等待新 registry、Locator 或动画工具完成。

本设计没有新增必须由用户回答的阻塞项。最需要实测的风险是复杂表单草稿/事务生命周期、控制流与 Group 入口缓存的保守正确性，以及现有 Plan JSON 的无损适配；逐切片验证后再更新正式 spec。

2026-10-18 用户确认复杂定制与 AnimationPlan 一起放后续阶段；P6b 先交付普通自动生成 UI，不据此承诺 timeline/曲线或场景目标查询完成。

## 11. 本轮用户澄清

共享 UI 构建确定为特定 DTO、特定 DTO 成员、默认类型三层映射；默认 DTO 表单只负责后两层，多 DTO 面板负责第一层与默认表单的分派。Editor 状态查询独立，公开资源分类只有一定存在/可能存在，目标缺失跳过执行。缓存方案由实现设计决定，优先 Group 入口/出口摘要与按需前缀检查点。当前没有阻塞设计的问题。
