# GalGroup 属性编辑器改造设计

日期：2026-10-18；实施授权：2026-10-19。状态：verified；用户已确认没有阻塞即可实施，实际实现范围、验证及保留边界见 [实施记录](phase-group-properties.md)。下文保留设计阶段的候选与取舍，不将所有长期建议都标记为已实现。

归属：F-20261015-02 Editor 创作工作区，承接 P6a/P6b 的共享参数表单与 P6d/P6e 的 Timeline 会话。用户本次要求：布局整齐、属性标题左上对齐、重置移到同行右侧、移除 null/省略等常驻操作、常用复杂值尽量不用 JSON、Timeline 改为打开面板按钮、颜色用 ColorPicker。以下默认行为和扩展方式是建议，尚未经用户逐项确认。

## 1. 已核实的现状与原因

- `EntryListEditorControl.axaml` 覆盖共享 SchemaForm 模板，列宽为 `130,*`；标题 `VerticalAlignment=Center`，输入区域把输入、JSON 标签、FieldEditorActions 和错误纵向堆叠。复杂控件越高，标题越偏离左上，操作行又增加高度。
- `FieldEditorActions` 同时显示默认值、omit、null、恢复草稿及状态符号。`ResetDefaultAsync` 当前写入显式默认值，不等同于删除属性；只对有默认值的字段可用。
- EditorRegistry 已提供整 DTO、DTO 成员和值类型注册；字段解析依次考虑成员覆盖、自定义类型工厂、显式 EditorId、自动推导。普通 IFieldDto 对象和一维列表已能递归生成控件，不必重新建设属性系统。
- 更直接的 Transform 原因是 Builtins 的 Transform/ToTransform 字段实际声明为 `JsonElement`，且显式标记 `EditorId=json`；不是已经声明为 LayerTransform 而只缺一个模板。因此只注册 `LayerTransform` 默认工厂无法命中现有字段。LayerTransform 本身也没有生成字段 schema。
- TimelineOptions.Timeline 同样是 JsonElement；现有项目级 TimelineEditSession、活动 Entry 上下文和单实例 Dock 可以复用，不应再在行内构建第二个 Timeline 编辑器。
- LayerColorOptions.Color、ColorFadeOptions.Color 等颜色字段是字符串文本编辑器。Editor 已引入 ColorPickerSemiTheme；已有主题依赖不能代替实际绑定和提交验证。Layer 的颜色约定是 `#RRGGBB` / `#AARRGGBB`。
- 作者文档保留缺省、显式 null、未知 JSON 与不完整值；历史和保存归项目会话。嵌套字段当前仍做根字段校验，其他坏子值可能阻止局部修复。

## 2. 目标、边界和布局

默认表单以作者可理解的控件表达值。首批覆盖普通字段、Transform、普通对象/列表、颜色和 Timeline 入口，不把所有动态效果参数、粒子系统及 Flipbook 一次纳入。作者格式和 Runtime 含义本轮保持兼容，不因为 UI 扁平化更改 JSON 层级。

统一字段容器，负责标签、布局、重置、描述和错误；专属编辑器只负责值区域，避免每个控件各自安排标题和按钮。

宽布局：

```text
资源         [选择资源 / 当前资源名称                 ] [↺]
变换         [位置   X [       ]   Y [       ]        ] [↺]
             [旋转     [       ] °                   ]
             [缩放   X [       ]   Y [       ]        ]
颜色         [色块] [#AARRGGBB                       ] [↺]
时间轴       [打开时间轴]  120 帧 · 60 FPS · 3 条轨道   [↺]
```

- 使用三列 `标签 / 值 / 操作`；同一表单的标签和重置列统一，标题垂直靠上，与第一行控件文字有一致的顶部留白。重置与该属性的第一行同行，右侧对齐。
- 标签宽度用统一主题约束，并结合可用宽度换布局，不让每行独立测量造成错位。长标签换行；窄 Dock 改为标题行加下方值区，重置仍在标题行右侧，不掉到输入区底下。
- 输入高度、行距、组间距和嵌套缩进统一；普通对象用本地化组标题，去掉 CLR 类型名和重复的 element 标题。复杂编辑器内部可分组，避免层层边框。
- 错误放在值区下方，只在有内容时占空间。帮助优先 Tooltip，确实影响填写的说明才常驻。重置图标具备 Tooltip、键盘焦点及无障碍名称。
- 统一容器可放共享 Controls，Group 的简化交互策略由宿主显式选择；不依靠一个全局样式悄悄改变 Sample 设置页的业务语义。

## 3. 清空、缺省和重置

去掉常驻的省略、null、恢复草稿按钮和状态符号，只留一个右侧重置图标。Escape 继续恢复本次未提交输入，项目 Undo 恢复已提交操作；错误或空值不再自动触发 JSON 编辑器。

“没填就是空”需要按值类型定义，不能把数值空白解释为 0、把布尔空白解释为 false：

| 场景 | 建议行为 |
| --- | --- |
| 从未填写 | 保持缺省；有默认值显示其有效值，不自动写入作者文档 |
| 普通字符串清空 | 提交空字符串；空白字符串是否允许由字段校验决定，不统一 Trim |
| 资源/场景目标清空 | 取消已选引用：可选字段恢复缺省；必填字段显示未填写状态与诊断 |
| 数字/枚举清空 | 有默认或可缺省时提交缺省；必填无默认时保留空草稿并提示，不写 0/首项 |
| 有默认值点重置 | 恢复声明的默认值，沿用显式默认值提交；一次历史，等值无历史 |
| 无默认值点重置 | 可选字段恢复缺省，Tooltip 为“清空”；必填且无默认值时禁用并解释原因 |
| 已有显式 null | 保留原始状态，显示为空；仅显示/打开不转换为缺省。用户明确填写后才替换 |

这是简化 UI，不是合并持久语义。若确有“显式 null 才能关闭继承”等字段，应提供该领域的“无/禁用/自动”选项，不恢复通用 null 按钮。无默认字段不擅自把 CLR 零值当作声明默认值。

父对象从未提供时，只展示有效子默认值；首次修改才创建所需父对象并写入目标路径。子属性默认值与父字段 DefaultJson/运行期默认值必须一致，特别是 ScaleX/ScaleY 为 1。对象重置可替换整个对象，这是用户明确操作；普通子字段编辑则必须保留未知成员。

## 4. 自定义控件、自动对象与扁平化

采用“专属编辑器 + 通用结构表单 + 布局提示”的组合，三者不是互斥选择。

### 4.1 先复用注册，补 Transform 控件

第一步用现有成员注册覆盖所有 Builtins Transform/ToTransform 字段，即使它们的 EditorId 目前为 json，也能命中成员覆盖。控件提供 X/Y、角度和 ScaleX/ScaleY，显示逻辑画布像素与度；保留负缩放，0 是否允许按领域校验，不额外施加任意范围。比例锁定可后续增加，默认关闭。

编辑器通过隔离的 JSON 路径适配器读写当前字段，只 patch 被编辑成员，保留未知键与原字段序列化约定；不 deserialize 后重新 serialize 整个 LayerTransform。默认值需从已确认的领域定义与父字段配置取得，不能维护两份互相漂移的数字。

更长期可以把稳定结构的作者参数改成类型化 DTO，或给 JsonElement 增加中立的“语义结构描述”，使通用表单识别 Transform。两者都涉及 schema/校验和兼容性，单独评估；本轮无需为了换控件先迁移 Runtime 类型。

### 4.2 普通对象默认自动生成，视觉展开不改变数据

已有生成 schema 的 DTO 继续递归分派，短对象默认直接显示，较长对象可折叠。不添加一个让所有对象无条件反射展开的全局规则，避免把 converter、多态对象和递归类型错误当普通 DTO。

可后续扩展中立布局提示，以下名称仅为设计示意，不是现有 API：`Inline/Expanded/Collapsible`、分组和顺序。宿主注册可配置；确有跨宿主复用需求再扩展 Field/EditorHints 及 generator。属性特性只声明布局或 editor ID，不引用 Avalonia Control 类型。

扁平化指 `transform.x` 在同一值区显示，写回仍是 `transform: { x: ... }`，不是把 x 提升为 Entry 参数。小型数值结构用专属紧凑布局；普通业务对象用自动表单，避免给每个 DTO 手写控件。

### 4.3 列表按元素描述递归分派

- 数字、字符串、枚举：紧凑行。
- DTO：元素标题与操作栏，下方自动表单；已注册 DTO 面板仍优先。
- 特殊值：调用同一编辑器解析规则；元素描述必须携带语义提示和 converter，不能仅凭 CLR 类型猜颜色或 Transform。
- 新增/删除/移动各为一个意图；结构变化使旧索引 binding 失效，旧弹窗和异步提交不得写到新位置。
- 空列表显示空态和添加，不显示 `[]`。新元素使用声明默认值；复杂必填元素必要时先本地草稿确认，避免默默写一堆 null/0。
- 现有 200 元素/8 层防护不能直接移除。大列表优先分页或虚拟化；深递归显式按需展开。动态字典、多态等结构单列能力，不承诺任意 JSON 都能自动生成合适 UI。

注册优先级本轮维持现状，文档中明确成员覆盖、自定义类型工厂、显式 EditorId 和自动推导的顺序。若以后调整显式提示与类型工厂的优先级，应视作独立兼容性改动。

## 5. Timeline 入口

Timeline 字段用“打开时间轴”按钮与简短摘要替代 JSON。成员工厂由 Editor 注入打开/激活 Dock 的动作，不让共享 Controls 依赖 Dock 或 Editor 服务。

点击顺序：校验 Group/Entry 稳定身份与当前 scope → 将该行设为活动 Entry → 打开或激活项目单实例 Timeline Dock → 现有会话跟随目标。不能只打开面板而仍编辑上一个 Entry；也不能每点一次新建会话。

打开和读取摘要不写作者内容、不增加历史。缺省/null 时 Dock 保持现有明确创建入口；按钮本身不顺带创建空 Timeline。坏 Timeline 仍可打开，显示诊断与修复入口，不静默清空。关闭 Dock 后按钮可以重新打开。旧行在删除、换类型、项目关闭后不得导航或提交。

Timeline 没有声明默认定义，因此重置禁用，不把 `{}` 当合法默认，也不把“重置”暗中定义为清除全部轨道。若需要清空内容，未来另设有明确语义的 Timeline 操作。曲线、事件、实时预览仍按已有独立范围推进。

## 6. 颜色

颜色编辑器为色块按钮、ColorPicker 弹层及可直接输入的十六进制文本，支持透明度和棋盘格背景。使用成员/语义注册命中颜色字段，不按属性名 Color 或所有 string 全局替换。

新提交使用 `#RRGGBB` 或含透明度的 `#AARRGGBB`，明确 alpha 在前；打开旧值不重写大小写或格式。原值无法解析时保留原文本并显示错误，不能替换为黑色/透明。

弹层拖动只更新本地预览；明确确认后一次项目历史，取消/Escape 恢复。文本 Enter/失焦遵循既有提交规则。外部值改变、撤销、Entry 失效时取消旧预览。透明度与 Layer.Opacity 是独立字段，不互相覆盖。解析支持范围和格式需以项目实际消费者为准，不能仅以 ColorPicker 接受的格式扩展文件规范。

## 7. 数据流与职责

```text
字段容器 → registry 选择值控件 → 控件本地草稿
    → 字段/路径 patch → IFieldBinding / 项目作者意图
    → 局部校验 → 单次内容历史 → 作者文档 → 表单与 Timeline 刷新
```

共享 Controls 拥有布局、草稿、普通结构与 lease 生命周期；Editor 拥有 Builtins 成员组合、颜色/Transform 语义适配、Dock 跳转、项目历史与保存。Core/Contracts 只拥有中立字段事实，Runtime 不依赖 UI。

正常编辑不通过 DTO round-trip 丢失未知成员。初始化、打开/折叠、切语言和切选中项不写默认值。所有新编辑器复用现有版本/取消规则，清理订阅并拒绝失效 binding。

## 8. 问题、候选方案与风险

1. **只改模板**能解决 1–3 的外观，但不能解决 Transform 的 JsonElement 契约、清空语义和 Timeline 定位，因此需要一层小的交互策略。
2. **所有复杂值都改 DTO**能增强 schema，但波及契约/编译器/Runtime，收益不能只按少写几个控件衡量。本轮先成员覆盖，逐类迁移再议。
3. **所有对象都用反射展开**对 converter、动态参数、深递归不可靠；已有 DTO schema 优先，无描述时显式提示能力缺失。
4. **完全删除 JSON 修复能力**会让坏值、未知字段或不支持的 schema 无法修复。建议普通表单不露 JSON 按钮，异常时提供独立“高级源码/修复”入口；原有 UI 未提供的修复操作需要明确补齐，不能假设已存在。
5. **根字段校验**可能让正确的子字段修改被另一个坏子值阻止。第一步在诊断中指出具体路径；若要逐项修复，应设计保留原始作者 JSON 的局部 shape/value 校验，不通过关闭全部校验解决。
6. **一律把空值转 null**会覆盖缺省语义、默认值和继承含义。按第 3 节定义清空策略，旧值无编辑时无损保留。
7. **颜色拖动/数值滚动的历史噪声**需要以用户一次手势或一次确认合并；本轮 ColorPicker 已明确本地预览提交边界。
8. **布局仅在普通短文本验证**无法证明真实效果；必须覆盖嵌套、长标题、错误状态、主题模板、四语及缩放。

## 9. 建议推进和验收影响

建议拆为：A 统一字段容器与清空/重置策略；B Transform 与 ColorPicker；C Timeline 跳转与摘要；D 普通对象/列表展示完善及必要修复入口。A/B/C 先让高频创作摆脱 JSON，D 根据具体 schema 逐项补齐，不把整个任意结构编辑器作为前置工程。

验收至少包含：

- 窄/宽 Dock、长本地化标题、100%/150%/200% 缩放，标题左上、重置同行右侧，无遮挡错位；真正挂载主题后的交互与截图。
- 清空/默认/必填/可选/已有 null 的保存重开与 Undo/Redo；仅打开、切语言无 dirty；无默认字段不伪造默认值。
- 每个 Builtins Transform/ToTransform 注册命中；缩放默认 1、负值、未知键保留、错误对象不被自动替换。
- 普通 DTO、标量列表、DTO 列表、专属元素工厂、converter 与列表重排旧输入失效。
- 颜色 alpha 顺序、取消不写、确认一条历史、原有非法值可见、外部更新取消旧预览。
- 点击非活动 Timeline 行准确定位；关闭后重开、无值不创建、删除/换类型旧按钮失效；已有轨道与未知内容不丢。
- JSON 修复退出普通路径后，未支持类型和坏值仍有明确可行的诊断/修复路径。

本文保留设计阶段的目标与取舍；实际实现、验证结果和明确的延期项以 [实施记录](phase-group-properties.md) 为准。
