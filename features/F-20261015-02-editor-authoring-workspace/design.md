# Editor 创作工作区设计

日期：2026-10-15；进度更新：2026-10-17。状态：目标设计，P1a/P1b/P2/P2i/P3 已实施并验证，其余阶段未实施；产品范围以 [feature.md](feature.md) 为准，实际进度与证据见 [phase-plan.md](phase-plan.md)。第 1 节记录设计时的基线事实；本文中的类型名用于界定职责，不要求逐一新建接口或服务。

## 2. 选择与取舍

新建项目默认使用随 Editor 分发的契约模板，用户只需填写项目名称、位置等常规信息，不必准备 DLL。创建时将默认契约部署到项目 `Contracts/`，之后与自定义契约项目采用同一加载路径；自定义契约目录为可选输入。打开已有项目仍严格使用项目自己的契约，不用默认模板覆盖缺失或损坏的文件。

| 选择 | 原因与代价 |
| --- | --- |
| 项目统一历史，页面保留独立视图状态 | 跨 Graph/Group/文件操作有依赖，避免多栈乱序恢复；需要显示撤销对象并提供定位 |
| 明确的可撤销编辑 API，允许绑定与直接领域方法调用 | Editor 便利优先，不强制序列化命令；必须防止绕过记录的正式写入 |
| 中立作者文档 + Avalonia 可观察投影 | 页面可以关闭，内容和历史仍存在；需要按稳定 ID 增量同步，不能全树重建 |
| 以受影响字段/集合和文件备份为历史单位 | 避免每次按键复制整项目；复杂批次允许局部文档快照，先测量再优化 |
| Raw 参数使用拥有生命周期的 JSON 值 | 保存显式 null、缺省和复杂值，无需通过字符串往返；与现有 CLI 参数适配需一起更新 |
| 尽量保持当前 Raw/Compiled wire 格式与 Runtime 边界 | 不兼容不是主动改格式的目标；内部表示可以替换，确有必要改格式时一次更新所有消费者 |

不采用：每页一栈、所有 GUI 修改绕道 CLI、全项目快照式按键历史、以 Runtime Node 为作者文档、为新旧实现长期维护两套路径。无需仅为这些 Editor 内部决定新增 ADR；若实施发现必须修改跨宿主的正式协议，再单列 Proposed ADR。

## 3. 模块、数据与所有权

继续在现有程序集内分工，不默认增加新项目：

- `Editor.Abstraction`：作者文档、身份、诊断、变更/历史及快照的最小跨宿主契约。不能出现 Avalonia 控件、ICommand 或平台 Shell 类型。
- `Editor.Shared`：项目文档库、编辑与历史、文件计划/失败恢复、保存基线、引用索引、校验与编译。CLI 可以复用领域操作，但不要求 GUI 使用 CLI 信封。
- `Editor`：项目组合、页面/Inspector、可观察投影、输入手势与草稿、文件对话框、快捷键、原生预览。平台能力留在外层适配。
- `Editor.Headless`：继续承担 CLI 参数、协议和结果输出；共用作者序列化和领域规则。
- `Avalonia.Controls`：保留通用 SchemaForm/字段工厂/lease，不认识项目历史、Graph 或文件操作。

项目会话的逻辑组成：文档库、资源/文件索引、项目内容历史、持久化基线、操作协调与取消、schema scope。会话随当前项目 scope 创建和异步释放；应用单例只保留当前项目指针、最近项目和应用偏好。不能继续让全局 singleton 成为当前作者文档的另一个可变真源。

### 3.1 作者与页面模型

- Graph 文档拥有节点、稳定边 ID、分支选项/条件、Group 文档引用和变量定义；不保存运行状态或已解码媒体。
- Group 文档独立拥有稳定 Entry ID、typeId、condition 和 JSON 参数。显示序号从位置派生；复制产生新 ID，移动保留 ID。
- Settings 文档是项目配置唯一真源，包括 AudioTracks、Speakers、locale 等完整字段；变量声明以 Graph 文档为权威，settings 中现有消费者需要的变量副本由序列化派生，不能独立编辑。
- 会话内 `DocumentId` 与路径分离；Graph/Group 使用已有稳定领域身份关联文档，普通文件会话内分配 ID。路径索引按操作系统比较规则处理，Windows 保留显示大小写。
- 页面使用 DocumentId/对象 ID 定位内容，拥有选中项、展开状态、滚动、输入草稿及控件 lease。关闭最后一个页面仍不卸载 dirty 或历史引用的文档。
- 所有受 Graph 引用的 Group 建立描述项；内容可延迟加载。引用分析/保存必须使用 dirty 文档覆盖磁盘，不能只扫描当前已打开页面。
- 节点删除使相关页面进入“对象已删除”状态并禁用编辑，保留文档身份；撤销可恢复，页面重开不创建另一份文档。

### 3.2 最小职责接口

| 概念性入口 | 责任 |
| --- | --- |
| 文档库 Get/Open、ResolvePath、Changed | 统一作者内容、身份与路径；暴露有版本的只读视图 |
| Edit/SetField/Insert/Move、BeginGesture | 显式构造一次可撤销编辑，不依赖事后 PropertyChanged 猜测意图 |
| History ExecuteAsync/UndoAsync/RedoAsync | 串行提交、分组合并、事务补偿、游标与备份所有权 |
| FileOperations Prepare/ApplyAsync | 预检源/目标、引用、metadata、文档与文件备份，实施复合计划 |
| Persistence SaveAllAsync/CaptureBaseline | 保存已捕获版本、外部冲突检查与发布后基线更新 |
| Snapshot Capture/Validate/CompileAsync | 在一致版本上进行无写回检查/编译，结果携带来源定位 |

入口可以是少量具体类；不为表格中的每一行强制创建接口。单属性编辑不额外绕完整文件事务。

## 4. 编辑、撤销与线程模型

1. UI 输入在控件草稿中进行；转换成功后用稳定对象 ID、字段路径和值提交。一次提交写作者数据，再按变更范围更新投影。
2. 项目修改协调者串行处理提交、文件操作和 Undo/Redo；UI 对象只在 UI 线程通知。I/O 可异步执行，不能持锁同步等待 UI continuation。
3. 一次编辑记录描述、涉及文档/对象、前后字段值或局部快照、必要文件备份和补偿信息；不闭包捕获页面/控件。
4. 执行先预检和准备可恢复信息，再应用；全部成功才增加会话 revision 和历史游标，并发布一次完成事件。未改变内容不入栈。
5. 复合操作按顺序执行、逆序补偿；Undo/Redo 同样有预检和补偿。任何失败都不提前移动游标，也不清空 redo 分支。
6. 补偿失败时保留操作清单和备份，进入 RepairRequired：停止进一步写入，允许查看/复制恢复材料与重新打开核对。不能声称失败后总能自动恢复，也不能继续伪造一致状态。

连续文字编辑按对象/字段/手势合并，焦点切换、Enter、显式提交及保存形成合并边界；保存后的继续输入不能并入保存前记录。IME composition 不逐段提交；Esc 取消草稿。节点拖拽只更新手势预览，结束形成一次位置编辑，取消恢复。数组/对象的结构化编辑作为叶值编辑或一次集合操作。

文本框本地撤销优先消费未提交草稿；事件被处理后不传播给项目历史。项目菜单明确显示下一步撤销名称，跨页面撤销后高亮目标并提供跳转，不强制反复抢焦点。

保存不是历史编辑。内容 dirty 按每份文档当前持久化表示与最近成功保存基线比较，不能仅用历史位置判定；异步保存记录捕获版本，后续编辑保持 dirty。路径/文件结构变化的 dirty 与写盘时机见第 6 节。

## 5. Graph 与 Group 关系

- 保留一个受保护的 Entry 入口节点，其出边指向剧情起点；不通过显示名推断身份，不在加载失败时静默替换为样例图。
- 一个输出槽最多一条后继边；允许多个前驱连接同一目标节点。现有 GUI Connect 会删除指向同一输入的其他边，重构时移除此人为限制。是否成环由校验报告，不因画布交互先验删除合法汇合边。
- 画布连接器用选项/条件稳定 ID 关联出口；序列化时计算顺序 outlet，重排不会串线。Runtime 的位置出口格式无需因此改变。
- Group 显示名与文件名分离，节点改名不自动改文件名；文件树改名更新 Graph 中 source path，Group ID 不变。
- 创建 Group 产生节点和独立空 Raw 文档，Graph 阶段即支持这种最小生命周期；不依赖“默认添加第一种 entry”才能创建。
- 删除 Group 默认组合删除节点、边和其独占源文档；存在其他已知引用时先显示影响，未知候选须明确展示。保留文件是可选操作，不能静默形成孤儿。
- Graph 复制粘贴复制所选节点与内部边；Group 内容深复制，节点/边/Entry/选项 ID 全部重建，内部引用按声明映射，外部自定义引用不猜测替换。
- 允许孤立 Raw 文档在文件树中打开和编辑；默认整项目构建只处理 Graph 可达/声明的源集合，并单独报告孤立文件，避免无提示打包或删除。

## 6. 项目文件与磁盘语义

### 6.1 文件类别与操作矩阵

2026-10-17 用户确认文件面板采用左侧目录树、右侧当前目录网格的双栏布局。目录树只展示层级导航，网格展示当前目录的文件与子目录；面包屑、树选择与网格导航共用状态。目录展开、选择与缩略图大小不进入内容历史，重命名/移动/删除等动作共用 P4a 的项目事务。界面在 P4b 实施。

| 类别 | 浏览/打开 | 改名、移动、删除与创建 |
| --- | --- | --- |
| `Graph/**/*.rawgalgroup` | Group 专属页面，支持孤立文档 | 在 Graph 内移动/改名并更新绑定；删除关联节点走复合操作；新建空源后可绑定 Group |
| `Assets/**` 原始资源 | 资源 Inspector/已有媒体预览 | 资源与 meta 整体操作；移动限 Assets 内，GUID 不变；复制/导入分配新 GUID 并检查重复 |
| `.meta` | 随所属资源查看和编辑字段 | 隐藏独立改名/移动/删除入口，统一由资源操作处理，保留 extension data |
| `I18n/**` | 文本/JSON 页面 | 同文化目录内部的普通文件操作可用；人物表、文化目录和 External 有语义限制，跨文化移动需明确视作内容变更并验证 |
| 普通项目文件/目录 | 通用文本页，二进制提供信息和外部打开 | 支持项目内常规 CRUD，字节保留；跨类别位置变更按目标规则预检，不自动把任意文件转成资源 |
| `settings.json`、`Graph/graph.json` | 专属设置/Graph 页面 | 固定入口路径，禁用单独删除/改名/移动；内容通过领域编辑 |
| `Contracts/**` | 显示契约状态/文件信息 | 活跃契约由项目 scope 使用，更新通过“关闭项目后重新部署/打开”；首期不提供会话内 DLL 热替换 |
| `Output/`、`Temp/` | 默认隐藏，可查看产物 | 由构建/清理入口管理，不混进作者历史 |
| `.galnet/`、恢复/事务目录、版本控制元数据 | 默认不进入内容树 | 编辑器内部管理，不能经普通文件操作移动或删除 |

“项目内部文件”不等于所有系统入口均允许任意路径操作。树上对禁用操作提供原因；本设计不增加通用游戏 UI 设计器。首期通用文本页提供查看、编辑、保存与撤销，不承诺 IDE 级语法服务。

### 6.2 文件结构立即写盘，内容编辑按保存提交

设计假设：采用已向用户提出的推荐选项，文件创建/导入、改名、移动、删除立即写盘；用户尚未单独确认该选项，可以在实施前修订。它不同于已经确认的项目统一历史、会话内撤销等需求。本计划已按该假设完整细化，无未选分支阻塞计划评审。

不选“全部文件变化延迟到 Save All”的原因是：文件树操作后外部程序、文件选择和资源读取通常需要实际新路径，暂存虚拟文件树会增加一整套路径解析与产品语义。立即写盘的代价是必须区分工作版本和保存基线，不能靠单一历史 checkpoint 判断 dirty。

每份受管理文档持有工作内容 W 和最近成功落盘的基线 B，磁盘内容 D 必须与 B 一致才可提交。改名/移动准备一个显式结构变换 T：

1. 对 W 更新路径绑定及已知引用，对 B 独立更新同类结构引用；用户无关的未保存字段只在 W，不能顺带写入 B。
2. 将 B 的结构变更、源/目标文件移动、metadata 和必要目录写入同一文件计划，完成冲突检查和备份。新建但尚未保存的对象在 B 不存在时，只修改其 W 引用，不凭空将整个对象写入 B。
3. 磁盘全部成功后发布路径索引、W、B 与历史记录。文件页标题立即变化，原来 dirty 的内容继续 dirty，干净内容不因路径本身留下待保存标记。
4. Undo/Redo 将逆/正结构变换应用于当时的 W、B；保留期间 Save All 已成功保存的无关字段。不能简单用旧整份 graph/settings 字节覆盖当前基线。
5. 删除文档保存其工作快照、基线内容、引用关系及原始文件；复合删除/恢复同时处理节点/引用和文件。未保存的新文档没有源文件时按存在性处理，不制造虚假文件移动。

结构变换只面向已知文档/对象/字段，基于稳定 ID 定位；发现字段已外部变化、目标占用或无法无损解析时停止并报告冲突。JSON 任意字符串匹配不能作为落盘修改器。对未知格式普通文件只改路径/字节，不猜测其内部引用。

例：用户未保存地修改某 Entry 文本后，将它的 Group 文件改名。磁盘移动的是已有已保存内容，Graph 中已保存的 source path 同步变化；内存文本仍为新值。随后 Save All 保存文本，再 Undo 改名，只还原路径和对应引用，刚保存的文本不回退。这个用例必须在 P4a 实际验证。

立即落盘的文件操作及其 Undo/Redo 成功后，本身属于已持久化结构变化，仍留在历史；关闭时“放弃未保存内容”只丢弃 W 与当前 B 的差异，不反向撤销已经完成的文件操作。界面在首次文件操作说明立即生效，关闭提示写明“放弃未保存内容”，不能暗示会恢复整个打开项目时的磁盘状态。

为可恢复地发布，先持久化备份与操作 manifest，再实施文件变更；异常退出发现未完成计划时核对旧/新哈希再恢复，不能覆盖外部新内容。此处是操作恢复材料，不是跨重启恢复 Undo 栈，也不承诺断电下多文件整体原子性。发布中暂停相关文档提交；可取消到准备结束，发布后的取消按失败补偿处理。

### 6.3 不随策略变化的规则

- 路径必须在项目内，拒绝目录自移动、碰撞、非法名称及链接逃逸；Windows 仅大小写改名通过独占临时路径实现。批量父子路径预先折叠，目标冲突一次预检。
- 导入先复制到会话备份区，重做使用该副本。删除保留原始内容、metadata 和必要目录信息；移动以 manifest 记录原/目标位置而不是全量载入大文件内存。
- 已打开文档的未提交草稿先请求该页结束有效编辑；无效草稿明确提示，不静默丢弃。已提交未保存作者内容由文档库持有，不靠重新加载磁盘迁移。
- 引用分析使用所有作者文档的工作版本；记录结构化路径字段、已知资源 GUID、Graph source path 等可解释引用。普通字符串/自定义 JSON 的匹配仅为候选，不做全局字符串替换。
- 默认拒绝删除有确定引用的内容，并提供跳转；用户明确选择连同引用修改/对象删除时产生复合操作。引用来源不完整的强制操作明确列出影响，不假装自动修好。
- metadata 写回使用现有 codec 保留未知扩展；不能重新构造少数字段导致 Gallery 或自定义数据丢失。
- 文件监听仅作外部变化提示，不直接重载 dirty 文档；自己的事务按操作标识/期望内容过滤通知。真正提交前仍检查字节/哈希基线，不能依赖监听事件保证一致。
- 通用文本编辑保留编码/BOM/换行信息；无法无损识别的文本仅只读或外部打开。二进制支持文件操作，不自动转成文本。

## 7. 保存、恢复与资源预算

- `Ctrl+S` 首期定义为保存整个项目的已提交作者修改，避免项目统一栈下隐含的跨文档部分保存。关闭项目提供保存全部/放弃未保存内容/取消；已经立即落盘的文件结构操作不会因放弃内容编辑而自动撤销，规则见第 6 节。
- 保存只要求作者结构可序列化、身份和路径不冲突，不要求所有业务字段完整。空参数、未填写必填字段可作为合法作者草稿保存，Problems 和编译仍报告完整错误；语法无效的控件文本留在页面草稿并阻止无提示关闭。
- 手动和自动保存共用串行协调者；自动保存暂沿用 500ms 空闲合并的现有习惯，并在文件事务/手势结束后执行。取消尚未开始的排队项，不能中途取消发布而跳过补偿。
- 捕获所有文档、设置和结构变化的同一 revision；准备写入/删除计划，校验基线，暂存，发布，成功后更新对应基线。不能 Graph 已保存而 settings 失败仍标记全项目已保存。
- 备份和事务材料统一放在 `.galnet/editor/` 下，替换现有分散 `.editor-tx/.editor-trash`；不扫描/打包成内容。多文件发布不承诺跨进程整体原子性。
- 恢复快照初始策略：有变化时每 30 秒、项目切换前和事务失败时捕获，保留最近 3 份完整有效快照；采用稳定快照与临时目录发布，不能保存一半也覆盖上一份。
- 恢复快照记录项目身份、基线摘要和未保存内容；重开时发现候选供用户选择，外部内容不同先显示冲突。只恢复工作内容，不复活旧 Undo 栈。
- 历史初始容量为 200 个顶层编辑，持有文件备份软预算 1 GiB；大于预算的单次操作仍可执行并完整可撤销，先淘汰更旧记录并显示实际可用步数。预算和步数可在后续测量后调整，不静默把超大操作改成不可撤销。
- 备份按引用计数保留：Undo/Redo、未完成事务、恢复候选任一引用时均不可清理。正常关闭完成保存/恢复处理后释放会话历史；启动清理只处理可证明不再被引用的材料，磁盘不足在修改前报错。
- 外部修改冲突首期提供保留本地恢复副本并重新打开核对，不实现通用三方合并。重新加载会影响旧历史时明确提示并结束旧会话，不把外部变化混进原栈。

## 8. galgroup 与 schema 表单

作者参数以 `Dictionary<string, JsonElement>` 或等价拥有型结构保留 JSON；缺少 key 表示省略，JSON null 是提供的值，默认值仅作显示提示或显式“重置为默认”。不能打开表单即写入默认值、删除未知字段或 Normalize 全部参数。

`IFieldBinding.Read/CommitAsync/Changed` 继续作为控件边界；Editor 的 binding 通过 DocumentId、EntryId、字段路径读写并登记历史。`ValueCodec` 只在控件文字与 JSON 之间转换，完整 DTO 不成为另一份可变作者真源。复杂数组/对象先以最小结构化编辑覆盖，允许 schema 指定自定义 EditorId；无法表达的 schema 节点提供明确诊断/JSON 编辑回退，不显示为空值。

验证分三层：

1. 输入转换与字段约束：提交失败保留草稿，不改作者数据或历史。
2. 作者结构/局部参数：允许内容逐步构建，检查 ID、值形态和局部合法性。
3. 完整语义与编译：补默认/Normalize 后检查跨字段、资源、表达式与指令要求。

切换 Entry 类型作为一次编辑保存旧 type/全部参数，显式展示不兼容字段处理；Undo 完整恢复。schema 失效或 Entry 删除后旧 binding 拒绝晚到提交。列表控件使用视口虚拟化，字段表单按展开需要创建并释放；动态选项、主题和真实视觉树必须验证。

未知 entry/未知字段的原始值保留，不能为了生成 UI 静默丢失。无法安全类型化的节点只读展示/原始 JSON 编辑并给出诊断；完整编译可以失败，其他已知内容仍可编辑保存。CLI 类型化输入继续严格校验命令参数，与作者文件无损保留规则分开。

## 9. 快照、诊断与未来预览边界

快照捕获项目 revision、schema 会话身份、Graph/Group/settings/I18n 的作者版本与资源清单。编译使用同一快照，不能一半读内存、一半读后来变动的磁盘；必要时实体化到独立 staging 目录，资源通过独占副本或使用前后哈希校验保证版本一致，变化则取消结果并报告过期；最终输出仅成功时发布。

复用 GalgroupCompiler/ProjectContentBuilder 中实际规则，抽出消费快照的入口；磁盘 CLI 先捕获磁盘快照再调用。结果携带原始 Group/Entry ID、编译后 primitive 映射、字段 JSON Pointer 和来源文档；Problems 导航以 ID 为准，文件改名后仍可定位。结果显示 revision；内容已变化则标记过期，不将旧成功当作当前内容验证。

本 feature 不创建新的 Engine/Runner/Preview 抽象，不修复独立游戏侧问题。基础工作区不默认开启预览；旧预览如依赖已删除作者路径，可暂时关闭入口并明确待后续 feature 接入，不保留第二套作者数据维护兼容。

## 9.1 编辑器 UI i18n（2026-10-16 追加计划）

现有 Editor 已有 IEditorLocalizationService、DynamicLocalization 和四语嵌入 JSON，见 `src/Editor/GalNet.Editor/Services/EditorLocalizationService.cs` 与 `Localization/`。本次补齐硬编码文案、动态刷新和验收，不重建服务。编辑器语言属于 Editor 偏好，与游戏 TargetLocale、项目 I18n 翻译分开；切换不提交作者编辑、不改 dirty、不清空历史。

P2i 先补齐已实现的启动/项目设置/关闭恢复/基础 Graph 与语言偏好闭环；P3–P6 新功能在各自阶段完成四语接入，P7 整体验收。语言集为 zh-CN、en-US、ja-JP、ko-KR，不默认新增语言。

历史与诊断保留稳定 key/code 和参数，在展示时按当前 Editor culture 格式化；不能只在执行时保存翻译文本，导致旧历史/旧错误不随切换更新。路径、作者名称、字段 ID 等作为参数原样保留。Shared 输出中立错误码、定位和细节，UI 翻译；Core/Runtime/CLI 不引入 Editor 的本地化框架或 Avalonia 依赖，机器协议不随显示语言改变。

已打开页面、Dock 标题、Inspector、菜单、历史菜单、状态/错误、关闭/恢复对话框均需响应切换并释放订阅。参数表单复用 schema LabelKey/DescriptionKey、枚举和专属编辑器的文案键；自定义契约缺译时回退到可读名称/字段 ID，不把作者值或任意字符串当 key，不推断游戏文本翻译。

统一声明基准语言、缺 key 与无效 locale 回退规则，四语发布资源具有相同键和兼容格式占位符，不能用回退掩盖缺译。数字控件可按 culture 显示/解析，但作者 JSON、数值和机器 ID 不变。验收包括资源/占位符检查、硬编码文案清单（允许技术名称与作者值）、真实控件动态切换和长文案布局。

## 10. 迁移、风险与验证影响

按基本页面 → Graph → 文件 → Group → 自动生成 UI → 前期整体验收推进。每个领域接入新作者数据与项目历史时，同阶段删除该领域旧写入口/事件记账，CLI 受影响适配同步更新；纯搬迁/重命名与行为变化尽量分开提交。

不写旧格式自动迁移层，不主动修改用户已有项目；真实验收使用新建临时项目及受版本控制 fixture。无必要时保持 Raw v2/Compiled v3；如 wire 格式必变，必须更新 codec、validator、CLI、compiler、fixture 和 sample，并显式拒绝旧格式。游戏侧注册重构仍有独立工作树改动，实施前重新建立基线，不混入本 feature。

高风险验证重点：失败 Undo 游标；跨页面对象删除；文件与 dirty 文档/引用的组合；保存并发；备份淘汰；JSON 缺省/null/default；Graph 汇合边与分支重排。性能用代表性大型 fixture 测量，不凭项目数或总行数判断。正式 spec 只在实现验证后同步，本设计不将目标状态写成现状。

### P4b 实施补充（2026-10-17）

用户确认行为层面参考 Unity Project 窗口：目录树/网格、原生 Ctrl/Shift 多选、双击打开、F2 改名、Ctrl+C/X/V/D、拖放、全项目文件名搜索与缩略图大小。保持 GalNet 的固定入口、资源 sidecar 与 Group 归属规则，不复刻 Unity 导入管线或 Asset Store。通用文本缓冲由项目拥有并进入 Working/Saved、项目历史与事务保存；关闭 Dock 页面不销毁缓冲。支持严格 UTF-8 与带 BOM 的 UTF-16/32，无法确认无损往返、二进制和超过 2 MiB 的文件只读，提供外部打开。参考：https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-windows-views-reference/project-view 。

复制资源同时处理身份冲突：资源 ID 必定重新分配；Gallery 注解的正整数 ID 若已被项目或同批导入占用，则为副本分配新的未占用 ID，保留 type/title。移动保持全部身份。这样 Duplicate 不会生成无法构建的重复 Gallery ID，也不会让副本复用原条目的解锁身份。

用户追加界面规则：地址栏默认内嵌可点击的目录块，点击空白切换相对路径输入，Enter 导航、Escape/失焦退出；树目录与地址块均接收文件移动。创建和导入仅从右键菜单进入，新建为二级菜单；刷新放在底部缩略图滑条右侧。网格 tooltip 显示完整文件名。右上搜索目前只做全项目文件名连续子串匹配，类型筛选作为独立查询参数保留，未来再提供类型/范围控制；不解析 t: 语法。非空搜索显示圆形 × 按钮，清空搜索与点击该按钮一致：有选中结果时导航到首个选中结果的父目录并保留选中，否则返回开始搜索的目录。

### Group 编辑交互与类型控件扩展（2026-10-17）

详细补充见 [galgroup 编辑设计](group-editing-design.md)。P5 纳入搜索型 Entry picker、顶部添加/追加/数量、按稳定 Entry 身份保存折叠状态、尾部空白取消选择和 Space 快速插入。第 6 点仅设计：共享 SchemaForm 的成员/值类型控件替换、整个 DTO 面板替换、Sample 入口注册复用及 Editor 场景目标 Locator；底层 handle 保留，剧情/演出作者不需感知。数量作用两个按钮，picker 直接确认一条，均已获用户确认。新增注册服务、场景分析与 timeline/曲线不在本轮实现。
