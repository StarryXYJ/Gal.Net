# Editor 创作工作区重构

## 用户原始目标与澄清

UI Editor 的功能落后于当前项目能力，需要分析并重构整体架构，使基本创作流程跟上进度。最初讨论了接入现有命令模型；用户随后明确：

- 以 Editor 的使用和实现便利为优先，不强制所有操作采用命令模型。
- 主要操作需要支持回滚，重点解决操作历史的归属与一致性。
- 功能推进顺序为：基本页面 → Graph 操作 → 文件操作 → galgroup 操作及自动生成 UI → 游戏预览。
- 文件操作指项目内部文件，重点包括重命名、移动等操作，不限于 Assets 目录。
- 撤销历史只要求在当前项目会话内有效，不要求关闭重开后继续撤销。
- 游戏预览最后处理，游戏侧可能先进行重构；当前主要关注前期编辑能力。
- 本次允许大规模重构，不考虑向后兼容。
- 新建项目不要求用户准备或编译 DLL：Editor 自带默认契约并自动部署，自定义契约目录是可选项。
- 每次完成阶段或修正后提交 Git，仅提交本任务改动。
- 2026-10-16 用户追加：将编辑器 UI i18n 纳入本 feature 的实施计划。
- 2026-10-17 用户确认文件面板采用左侧目录树、右侧当前目录网格的双栏布局，作为 P4b 的界面要求。

## 问题与现有基础

P6e2 用户反馈进一步收敛交互：持续显示轨道的绝对值/叠加偏移模式；结束帧/FPS 直接确认、保留帧号，结束帧至少覆盖全部键/事件，关键帧越界拖动自动延长；移除保留秒数、裁剪和应用入口及旧路径。修订进度见 [Timeline 交互简化](timeline-simplification.md)。

- Editor.Shared 已有类型化编辑命令、项目查询、校验、编译和文件操作；GUI 仍有直接修改可观察模型、独立历史及保存映射路径，需要重新明确作者数据与页面状态的所有权。
- 当前历史按 Graph、UI、Settings 等领域组织，并根据激活目标路由。跨 Graph、Group 内容和文件的操作需要一致的撤销边界，不能简单以页面实例划分。
- 项目已有契约加载、DTO/字段描述、SchemaForm 与资源/表达式专属编辑器，应基于实际能力接入，不重新声明另一套字段事实。
- 新建项目逻辑要求契约目录，但当前页面没有对应输入；基本创作入口仍需补齐。
- 文件操作会影响磁盘、metadata、资源索引、已打开文档和引用；仅修改磁盘路径不能满足 Editor 使用要求。

这些是设计调查的起点，不代表已完成实现审计或 GUI 验收。

## 目标

1. 形成清晰的项目会话、作者文档、页面状态、历史与持久化边界。
2. 打通项目创建/打开、Graph、项目文件、galgroup 和参数编辑的前期创作流程。
3. 为主要内容和文件操作提供一致、可理解的撤销与重做；失败操作不留下半次修改。
4. 让项目契约驱动基础参数 UI，并保留必要的专属编辑体验。
5. 以保存、重新打开、校验和编译验证前期编辑结果，不依赖游戏预览才能验收。

## 范围

### 基本页面与工作区

- 启动、新建、打开、最近项目及关闭流程，补齐契约选择。
- 工作区、Dock、页面注册与生命周期、Inspector、状态与错误反馈。
- 项目作者数据与页面草稿/视图状态的归属。
- 历史、保存、自动保存和恢复所需的最小基础。

### 编辑器 UI i18n

- 延续现有 IEditorLocalizationService、DynamicLocalization 与嵌入 JSON，覆盖 zh-CN、en-US、ja-JP、ko-KR 四语，不另建翻译框架。
- 覆盖启动/新建/设置、菜单和 Dock/Inspector、Graph/文件/Group/参数表单、关闭/恢复对话框、历史描述、状态与错误提示；后续功能随阶段接入。
- 已打开页面、历史和诊断随语言切换更新，语言选择按 Editor 设置持久化；切换不改变作者数据、dirty 或内容历史。
- 项目名、路径、用户输入、机器错误码和契约 ID 保持原样；游戏文本翻译、I18n 内容编辑器及新增语言不由本次 UI 本地化需求自动扩大。

### Graph 编辑

- 节点增删改、位置调整、连线/断开、入口与选择操作。
- 分支选项、条件与出口的一致性。
- 多选、批量操作、复制粘贴、快捷键与定位。
- Group 节点与内容文档的最小创建、删除及恢复；完整文件管理界面可后续接入。

### 项目内部文件操作

- 项目文件树，文件/目录创建、导入、重命名、移动、删除与恢复。
- 协调相关 metadata、资源身份、索引、文档路径/标题与引用。
- 已打开且有未保存内容的文件参与操作；不能通过重新读取磁盘丢弃其编辑。
- 批量操作、路径冲突、外部修改与执行失败的明确反馈和恢复。
- 项目生成目录、契约文件及内部状态目录的可操作边界在设计中逐类列明；不能把“项目文件”默认为仅资源文件。

### galgroup 与自动生成 UI

- 按 Group 打开文档，条目增删、排序、多选、复制粘贴、类型选择、条件及项目变量定义。
- 最小可用参数表单随 galgroup 核心操作接入，再完善复杂结构。
- 基于现有唯一 schema 的表单生成、嵌套对象/列表、可选值与默认值、专属资源/表达式编辑器及字段诊断。
- 稳定身份与显示序号分离；保存并重新打开保持作者值语义。

### 前期整体验收

- 跨页面历史、文件与未保存文档交互、自动保存、关闭重开、恢复区生命周期。
- 校验/编译链路与代表性项目下的交互表现。
- 为后续预览提供一致作者内容快照/编译边界，不提前固定游戏运行架构。

## 已确认约束与操作语义

- 每个打开的项目使用统一内容历史；不同项目隔离。页面关闭不清空内容历史，同一文档的多个视图共用内容与历史。
- 文本框尚未提交的输入可使用控件本地撤销；不能与项目撤销重复消费同一操作。
- 选择、滚动、缩放、布局等视图状态不进入项目内容栈，不单独使作者内容 dirty。
- 成功的复合操作作为一次编辑撤销，包含必要的跨文档和文件变更；批量失败应恢复执行前状态。
- 连续输入按编辑意图合并，拖拽和批量操作应有合理的历史粒度。
- 保存不清空历史；撤销回已保存内容时 dirty 状态应正确。保存期间的新编辑不能被错误标记为已保存。
- 文件撤销恢复内容、路径及关联变更；资源文件与 metadata 保持身份一致。撤销导入不修改项目外源文件，重做不能依赖源文件仍存在。
- 无法可靠分析的自定义引用要暴露检查边界，不宣称已经完整自动修复。
- 历史限当前会话，不要求历史跨重启持久化；自动恢复快照与撤销历史是不同能力。
- 不强制所有编辑通过可序列化命令，不以命令覆盖率作为验收指标。现有命令和共享服务按实际收益复用。
- 不要求旧 API、旧作者格式或旧内部实现兼容；不为兼容保留双套编辑路径。格式变化仍需在设计中明确读写消费者范围。
- Core/Runtime 的平台无关边界继续成立；Editor 重构不默认扩大为游戏运行架构重写。

## 非目标

- 游戏预览的运行会话、启动/停止/重启、运行变量、平台资源接入及调试 UI；另立后续 feature。
- 断点、单步、从指定位置开始、热更新等高级调试能力。
- 跨重启恢复完整撤销栈、多人协作或跨进程共享操作历史。
- 为统一形式建立通用命令总线，或强制 GUI 通过 CLI/磁盘操作入口编辑。
- 整个项目删除、构建产物发布等操作全部纳入普通内容撤销的承诺。
- 不经需求确认将自动生成参数 UI 扩大为游戏 UI 可视化设计器。

## 验收标准

1. 能通过 GUI 完成创建/打开项目、选择契约、编辑 Graph、管理项目文件、编辑 Group 内容并保存重新打开。
2. Graph、galgroup、项目设置及项目文件的主要操作有明确的撤销/重做支持清单和例外说明。
3. 跨页面按项目操作顺序撤销；关闭/重开页面不丢历史，历史执行不依赖已关闭页面实例。
4. 删除 Group 等复合操作及其撤销完整恢复相关节点、连线、内容与文件；分支重排不改变原有连线语义。
5. 项目文件移动/改名/删除与已打开文档、未保存内容、metadata、索引及已知引用保持一致；冲突和失败不静默覆盖内容。
6. 撤销、重做或复合执行失败时，历史位置与实际内容保持一致，不发布虚假的成功状态。
7. 保存后历史可继续使用，dirty 与保存版本一致；外部文件修改不会被静默覆盖。
8. 参数 UI 消费项目唯一 schema；省略、显式 null、默认值、枚举与嵌套值有明确且经验证的保存语义；字段局部校验与完整编译校验分开。
9. 项目内容在不启动游戏预览的情况下可校验/编译；错误能定位至对应文档及相关对象/字段。
10. 实际验证包含代表性 GUI 创作流程和有意义的自动化测试；阶段退出不能只凭服务单元测试或构建成功。
11. 编辑器四语覆盖本 feature 用户可见 UI，键与格式占位符一致；打开页面/历史/诊断随语言切换刷新，重启保留选择，切换不改作者数据与历史；真实控件验证布局、回退和格式化。
