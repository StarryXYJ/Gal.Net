# 项目内置资源目录设计

状态：设计提案，尚未实现。2026-11-04。归属：默认视觉库的后续资源组织设计；本文不改变该 feature 已交付的历史状态或当前正式规范。粒子通用化另见 [方向记录](../F-20260929-02-particle-system-v2/weather-preset-direction.md)。

## 目标与已确认范围

- 用户要求项目自带资源与 `Assets/` 分开，项目根目录使用用户指定拼写 `Buildin/`。首批覆盖现有默认视觉 Shader 与天气粒子贴图，不将项目自己的其他素材仅凭类型判定为内置。
- 用户确认 `Buildin/` 资源在项目中可查看、可编辑。这里的“内置”指项目来源和初始用途，不表示受保护的引擎私有资源、只读文件或运行时隐藏回退。
- 用户确认新项目使用新布局，不考虑向后兼容；不设计旧项目资源迁移、旧路径回退或自动识别旧模板。已有工作区和作者数据不得被实施过程静默覆盖或删除。
- 用户确认内置资源 ID 固定；预设直接选定对应固定 ID 的内置资源作为默认，不因为项目没有配置用途绑定而留下空资源引用。固定 ID 是跨新项目一致的资源身份，不表示不同项目对资源内容的修改会同步。
- 用户确认不需要项目级设置来统一更换预设默认资源；作者可以在单条预设上改选其他兼容资源。
- 用户确认 Editor 内禁止删除和移动内置资源；外部工具仍可能删除或移动，发现异常时报告错误。禁止保护身份不影响对内容的编辑。
- 作者资源继续以稳定 ID 引用，保持按需打包、同一资源类型目录、相同资源选择与运行时加载语义。目录划分不应引入第二套特效系统或每种 Shader 的 Entry。
- 本设计只针对项目文件和管线；编辑器自身图标、应用打包资源、PAK 安装目录及外部项目自定义资源不自动迁移或重新分类。

```text
<项目>/
  Assets/                     # 作者资源
  Buildin/
    Effects/Default/          # 默认 effect-program 与粒子贴图，保留原相对路径
  Graph/  I18n/  settings.json
```

目录示例沿用当前 `Effects/Default` 相对路径，避免为了调整文件名同时改变路径语义。后续目录整理是独立决定，不以 `BuiltIn` 或 `Builtin` 偷换用户指定的 `Buildin` 拼写。入口若发现仅大小写不同的根目录或保留名冲突，必须可诊断并拒绝产生两套根。

## 当前事实

`DefaultVisualTemplate.Prepare` 从编辑器内嵌模板创建每项目独立 ID，将 16 个 Shader 和 5 个天气用途贴图及 `.meta` 写入 `Assets/Effects/Default/`，并写入项目用途到资源 ID 的映射；已有绑定不被覆盖。新建项目与显式补入通过该模板，参见 [模板](../../src/Editor/GalNet.Editor.Shared/Visuals/DefaultVisualTemplate.cs) 和 [安装器](../../src/Editor/GalNet.Editor.Shared/Visuals/DefaultVisualInstaller.cs)。

目前 `Assets/` 是作者资源单根：`.meta` 的 `path` 和 `IGameFile.Path` 是相对于该根的路径，ID 在整个项目内唯一；详情见 [资源规范](../../docs/spec/content/assets.md)。构建只复制 `Assets/`，目录运行的内容及资源加载、导出与独立资源覆盖导出均以单根扫描；Editor 文件事务、索引、选择器、shader 元数据、引用、本地化和 debug 内容指纹也有 `Assets/` 专用判断。现有 `AssetManager` 跨 provider 使用优先顺序，不能仅添加一个 provider 就声称重复 ID 会被拒绝。

## 建议方案：两个物理根，一份项目资源清单

1. 默认项目创建时，将模板内容和相邻 sidecar 写入 `Buildin/Effects/Default/`，各内置资源使用跨新项目相同的固定 ID。固定 ID 与预设默认值来自同一套显式目录，不能各处另写一份或使用每项目随机 ID。为避免与现有 GUID 解析与编辑器校验冲突，建议使用一组固定、唯一的 GUID；具体值在实现前统一分配并保留，不按路径或内容临时生成。自定义项目是否安装内置资源继续由其契约和创建流程明确决定，不能在运行时隐藏注入。
2. 预设创建时直接以固定 ID 填入默认资源字段，明确存在选择器和编译后数据中；已有显式选择不被刷新或改写，作者仍可为单个预设另选兼容资源。删除现有 `defaultVisualPrograms` / `defaultWeatherTextures` 项目级映射及其设置 UI、填充逻辑和仅为它们存在的导出根；依赖收集根据实际 Entry 与其他显式使用点决定是否打包，不因移除映射遗漏引用。源创作、纯编译和外部工具需要共同遵守默认值与显式字段语义，不能只修编辑器而让 CLI 仍填空。固定 ID 对应资源缺失、ID 被占用、类型或 Shader 契约不匹配时明确报错并定位，不回退空值、同名文件或内嵌副本，也不自动覆盖作者修改来修复。
3. 把两个根纳入同一项目资源清单、类型校验与依赖分析。根是文件系统位置及编辑器展示信息，不是第二种资源类型；调用方继续提供同一资源类型目录和 Gallery 目录。编译后时间线引用、Shader 引用、变体与自定义声明都通过现有 ID 及依赖机制处理，非默认资源不可按文件名推断为内置。
4. 为保留已有逻辑路径，建议两个根内仍使用相对路径作为统一逻辑路径：例如 `Assets/characters/a.png` 对应 `characters/a.png`，`Buildin/Effects/Default/Blur.sksl` 对应 `Effects/Default/Blur.sksl`。sidecar 的 `path` 对所属物理根相对；物理根标签由索引携带，不能仅凭 `IGameFile.Path` 推断来源。
5. 两根的资源 ID **和逻辑路径**必须在全项目范围唯一，比较规则沿用资源索引/PAK 的大小写无关语义。无论内容是否相同，发现重复即指出双方物理路径并拒绝发布及相关的资源视图；不能依赖 provider 顺序覆盖，或先按 ID 去重把冲突吞掉。需要在多根合并时明确检查，单个 `LocalFileProvider` 的内部检查不足以发现跨根冲突。
6. 按 ID 和路径访问、资源枚举、开发预览、开发目录运行、配置/Gallery 与资源名校验、目录导出和 galpak 必须消费同一经过校验的合并视图；调用方不分别发明优先级。实际实现可复用现有本地 provider 与归档及共同的清单校验；先验证生命周期和资源租约，不预设新增常驻抽象。安装包仍由同一 PAK 管线保存这些资源，PAK 路径保持既有约定，不因源目录拆分引入新的包格式。

固定 ID 只定义身份，不定义资源内容不可变：同一 ID 在不同项目中可对应各自修改过的内容，打包、hash 和缓存必须以实际项目内容/会话为准。默认 Shader 可编辑，但改坏预设依赖的 stage 或字段时须有明确校验。资源包之间如合并使用同一个固定 ID，也不能假定内容一致；对已有的覆盖/依赖语义应验证内容一致性并在冲突时报错。

根级相对路径设计意味着未来确需在两个根使用相同相对路径时必须先明确命名空间方案，而不是隐式覆盖。正常跨根移动遵守现有资源事务和引用约束，不把它作为旧项目自动迁移机制。

## 编辑与构建数据流

```text
项目创建 / 显式安装 → Buildin/ + 固定 ID 的 .meta
预设创建 → 填入固定 ID → 作者可在单条预设中改选
Assets/ + Buildin/ → 校验并形成同一项目资源清单 → Editor 查询 / 校验 / 预览
                                            → 开发构建与运行
                                            → 依赖收集 → 现有 PAK / 发布载荷
```

- **Editor**：资源面板显示两个清晰的根，搜索、类型筛选和资源选择器覆盖两根并标明来源。已注册的内置资源允许编辑内容、查看元数据及复制，但 Editor 禁止删除、改名或移动（包括通过父目录批量操作间接删除、改名或移动）；根目录本身受保护。复制为独立作者资源时生成新 ID，不能复制出第二个固定 ID。Buildin 中其他作者新增的资源按普通项目资源规则管理；失败时保留工作稿及诊断。普通资源跨根移动保留 ID，复制生成新 ID；路径变化只更新已知路径依赖，不做未知字符串全局替换。GUI 和 CLI 应在共享文件事务入口执行同一限制，不能仅禁用按钮。
- **一致性**：按现有结构事务分别维护工作版本与保存版本，sidecar 与文件一起提交；检查跨根 ID、路径、大小写及目的冲突，保留 metadata 扩展和显示名称。纹理及 Shader 字段选择器、Inspector、资源名称本地化、依赖校验与问题定位都必须能找到两根。预览缓存/监视器、变更通知和项目关闭时的资源所有权同样覆盖两根。
- **图集与根边界**：现有图集相对目录解析限制在单个 Assets 根内。设计首版保持每个物理根内解析、禁止图集的相对路径越过所属根；跨根移动图集/图片需由现有投影预检验证完整关系，不能生成越界 folder。是否让 Buildin 放自定义图集由其可编辑项目资源语义支持，但不自动把其他项目资源归类到 Buildin。
- **构建与运行**：开发构建快照同时捕获两根；`Buildin/` 加入禁止构建输出覆盖的受保护目录。`ProjectGameContentProvider`、`GameInstallation` 及各预览/Headless 组合根均使用同一合并视图。资源根缺失、路径穿越、符号链接、大小写及重复身份处理应与现有安全规则一致，不扩展读取项目外文件。
- **导出与资源覆盖**：目录和 galpak 导出共享两根资源清单，再沿用依赖闭包和现有 PAK；验证实际引用的内置资源真正进入应有的包。独立资源覆盖导出及其目标路径保护同样检查两根，保持显式映射语义；不能因导出是独立入口而丢掉内置资源。
- **调试**：构建指纹与调试内容变更分类需纳入 Buildin 的文件变化，保持现有自动热更新安全边界；缓存旧代和资源租约仍按现有会话所有权释放。
- **项目历史和外部编辑**：ProjectApply/文件命令、快照、项目刷新、资源索引和检查器使用相同根规则；验证对 Buildin 内作者编辑的检测、并发冲突及恢复，不让资源面板与构建看到不同版本。

## 旧项目与兼容边界

按用户决定，本次只以新布局作为目标，不提供旧项目迁移或向后兼容方案，也不承诺旧工具能读取新布局。实施时仍需明确新项目输入的必要结构及错误诊断；缺失可选内置目录与识别、转换或兼容旧项目是不同的行为。不得在打开或构建过程中静默搬移、重装或覆盖现存作者文件。

## 取舍与待确认

- 不保留项目级预设默认资源映射；单条预设可改选。固定 ID 不按资源内容生成，编辑资源内容不会更改身份；引用该 ID 的预设会看到当前项目中的编辑结果。
- 固定 ID 的内置文件被外部删除、移动或改写 sidecar 时，Editor 无法阻止外部操作；按固定 ID、预期目录和类型检查并提示具体问题，不静默补建、改写 ID 或将默认选择变空。应区分新项目缺少必需资源、自定义契约不使用内置库和显式引用损坏，避免把所有未安装内置库的项目一律判错。
- 备选：把 `Buildin/` 映射为逻辑路径前缀，可避免跨根同名，但会改变路径引用、PAK metadata 和一部分既有调用；当前方案优先保留路径，明确拒绝冲突。两种均需全局 ID 校验。
- 备选：所有内置资源都由引擎加载或自动覆盖。此方案与已确认的项目内可编辑性和显式引用冲突，故不推荐。
- 用户指定目录拼写为 `Buildin`；避免不同平台产生两套路径。
- 是否需要存档或内容格式版本变更要基于实施设计和验证，不因删除旧兼容而无条件扩大格式变更范围。

## 验收与风险

1. 多个新建默认项目中逐一验证内置 ID 相同且相互唯一、实际文件存在且类型正确；不安装内置资源的自定义项目不意外注入。创建每类预设检查固定默认值、显式选其他资源，以及编译/CLI 与 Editor 一致；缺失资源清晰报错，绝不自动改为空或覆盖作者内容。
2. 两根内和跨根验证 ID、逻辑路径、仅大小写冲突、坏 sidecar、缺文件、链接和目录越界；冲突不得导致遗漏或静默选中另一资源。
3. 在资源面板和选择器完成查看、内容修改、复制、普通资源移动、撤销/重做、引用提示、外部修改刷新与搜索；验证 GUI/CLI 不能直接或经父目录删除、改名或移动已注册的内置资源，外部操作后可诊断且不会悄悄修复。资源索引、Shader 参数/预设校验和本地化均找到正确根。
4. 使用真实默认 Shader 和粒子贴图验证开发构建、Preview、目录运行、目录导出、galpak 安装运行、独立资源覆盖导出及调试变更识别；比较两条发布路径的依赖闭包、ID、逻辑路径和 payload。
5. 测试新布局中跨根操作的未保存内容、目的冲突、半途失败/取消与撤销恢复；移动后 ID 保持，已知路径依赖正确更新。
6. 测试 `Buildin/` 及后代不能被构建输出覆盖；文档在实现验证后同步 [资源规范](../../docs/spec/content/assets.md)、[项目文件规范](../../docs/spec/editor/project-and-files.md)及 [Editor 手册](../../docs/manual/editor/resources.md)，不提前把提案写成当前行为。
