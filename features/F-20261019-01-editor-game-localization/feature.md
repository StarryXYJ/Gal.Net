# 默认开发语言创作、角色表与游戏 i18n 面板

## 用户目标与已确认需求

普通游戏创作界面使用项目默认开发语言，内部保存稳定 key；只有 i18n 面板提供多语言对照。Editor 自身 UI 语言仍独立。

- 项目已有默认语言，作为开发语言使用，不另外维护一份开发语言设置。
- 角色表根据全部 galgroup 使用的 speaker 持续补充，只增、不因引用消失自动删除。人物表页面可删除未使用角色。
- 人物表是开发语言角色名和唯一 key 的二元组；允许同名，不允许 key 重复。
- 自动角色 key 使用持久化的只增编号，可以手动修改。
- speaker 支持直接输入和搜索选择，候选同时匹配开发语言角色名与 key；失焦时不是已有角色则创建。
- DTO 需要有明确标记，声明哪些成员值是本地化文本；标记成员在 galgroup 内保存 key，在普通表单里显示、填写开发语言文本。
- i18n 面板左侧为可滚动分类列表，包含角色表、全部 galgroup 和分支选项。
- 右侧是语言列组成的表格，不显示底层文本 key；开发语言固定最左，支持加语言与其他列调序。
- 支持单语言模板等导出，以及外部填写后的导入。
- 修改开发语言原文保留其他语言译文。
- Entry 换位不能导致译文丢失。key 具体格式为实现细节，优先利用已有 StableId，生成后保持不变。

## 开工时的问题与基础

- Runtime 已支持 CharacterCatalog、speaker 角色 ID、姓名 DisplayNameKey、对白/NVL/分支文本 key、默认语言验证和语言回退。
- Editor 的 FieldAttribute/FieldDescriptor 没有声明成员值本地化语义的元数据；现有 LabelKey/DescriptionKey 是字段 UI 文案。
- Entry 创建时已有 GUID StableId，作者文件保存到 id；移动保留、复制生成新 ID，整数 Id 只是位置。
- Group 表单仍从 Settings.Speakers 补全，Editor 项目校验目前跳过 localization-semantics。
- 项目已有单一内容历史、文件文档、保存事务和文本缓冲；I18n/catalog 受普通文件策略保护。

## 范围

2026-10-20 用户修订：不考虑向后兼容，删除本功能的全部旧数据兼容和迁移入口。移除 ProjectSettings.Speakers 及其候选/回调/迁移 UI；未知角色 ID 作为当前格式错误，不自动补建或解释成姓名。后续实现只针对当前作者格式。

字段语义及 generator、项目本地化作者文档与引用索引、角色面板和 speaker 输入、默认语言文本表单、i18n Dock、语言管理、导入导出、保存历史协调、必要的校验和回归测试。

## 非目标

自动机器翻译、角色立绘/音色配置、本地化二进制资源、运行中剧情热重译、多人实时协作、游戏预览、第三方翻译安装/覆盖协议重做、重写编辑器 UI 本地化服务。

## 验收标准

1. 创建/选择同名角色有明确身份，不重复创建；空输入不创建角色。全部未打开 Group 的引用也纳入使用统计。
2. 自动角色编号保存重开后继续增长；删除不回收。改角色 key 同步全部明确引用且可一次撤销；被引用角色禁止删除。
3. 被标记字段在普通创作界面编辑开发语言文本，作者文件保留 key；自定义未标记字符串不被误判。
4. 修改文本、Entry 重排、保存重开和撤销重做保留原 key 及译文；复制文本引用得到独立 key，已有翻译随副本复制。
5. i18n 左侧包含角色/全部 Group/分支；右侧开发语言固定第一列，支持新增语言、其他列排序，正常表格不显示文本 key。
6. 修改默认语言文本保留译文；模板导出再导入按稳定身份匹配，不能依赖行号或原文。
7. 面板、普通文本页和 Group 共用作者文档，不互相覆盖未提交草稿；跨文件操作形成完整历史，纳入 Save All、关闭与恢复。
8. 格式损坏、重复 key、未知角色和默认语言缺译有可定位诊断；作者保存与可运行内容检查区分。
9. Core/Runtime 保持平台独立，现有回退与外部覆盖行为不回归。
