# 设计

## 分类缩进与交互反馈（P8）

根据用户圈图，移除Tab自身的左右Padding，以项间Margin维持分类间隔，首个标题文字与页标题/正文起点对齐。整个设置区域仍居中。

普通按钮hover/pressed使用同一中性颜色的轻/重背景，不切换前景；Mono主按钮按下也避免纯黑。用户追加明确不要下划线和加粗，分类Tab及工具栏交互均以背景反馈。工具栏合并重复样式和adaptive-target标记，正常文字/字号/字重保持稳定，hover/pressed/checked仅改变灰色背景，键盘焦点单独保留稳定边框；文本阴影仅作用于文字，避免背景也出现阴影。取消基础主题仍保留的按压缩放与变换过渡。保留原尺寸、收纳、命令和播放状态。

## 设置居中区域内左对齐（P7）

按用户澄清，整个设置区域居中，页头、分类、正文与页脚共用最大宽800的PageFrame；标题从面板左边界开始，不增加左侧空隙。正文Stretch，移除误解时添加的宽度绑定。保留原分类、滚动和编辑器。配色仅调研分析，不修改资源或交互样式。

### 配色分析（建议，未实施）

当前 Mono 的正文对比已经充足；不足主要在普通按钮按下时整块深色反白、Selection 同时承担悬停色、TextSecondary/TextDisabled 使用相同色，结构与交互层级容易混淆。应优先统一交互色规则，再微调颜色。

参考成品：Linear 的界面更新强调弱化分隔线、降低底色饱和度并向微暖中性灰调整（https://linear.app/now/behind-the-latest-design-refresh）；Things 用白色内容承载阅读、减少干扰（https://culturedcode.com/things/features/）。可借鉴底色与内容面的轻层次；不新增主题框架。

建议候选：页面底 #F7F7F5，内容面 #FFFFFF，正文 #292D34，辅助文字 #646C78，边框 #DDE1E6，少量灰蓝强调 #526B86、选中浅底 #E8EFF6。普通按钮悬停/按下仅轻微加深中性底，正文保持；主操作才用强调色与白字。Tab选中用背景区分，按P8用户要求不使用下划线或加粗；焦点清楚，禁用与模态压暗分开处理。整套候选底色/强调色尚未实施；P8仅落实用户明确要求的中性灰交互。

## Tab 与卡片统一（P6）

按用户复查，设置分类 Tab 改用已有 GroupHeadingSize，比 Action 更突出。图片、视频、场景鉴赏复用存档的卡片尺寸与网格：共用 AdaptiveCardGrid、CardColumns 与 CardHeight，统一外边距7、列距6、行距8、底部标题区最小高84。三类鉴赏只共用一份 DataTemplate，保留名称提示、解锁状态与各页打开命令；删除旧鉴赏比例面板，不增加卡片行为类。

## 极简排版修订（P5）

用户明确保留现有极简风格，本轮只调整排版并减少重复代码。普通页统一页头、返回按钮和分隔线位置；设置页改为仅正文居中限宽，分类、表单与提示保持同一列。数值输入缩短，选项框和滑条按可用宽度伸展，窄屏原地上下重排。

布局常量只放在 Dimensions.axaml；字体继续由 PlayerTypography 定义，页面标题、返回、Tab 和辅助文字直接复用现有字号角色。移除 PlayerView 测量阶段的资源覆写及备份恢复，保留同一 GameShell 的 Viewbox 比例和资源/订阅清理。不新增模板系统，不调整配色与交互。

## 用户复查后的最终修订（2026-11-02）

用户否定首版自由重排，并进一步明确：只有首页横竖屏切换，切换只改变标题/按钮靠左或居中的水平对齐；其他页面继续自适应。尺寸比例参考最初固定分辨率画布，移动端低 DPI 的操作控件适度增大。

- 复用 PlayerView 中一个 Viewbox 缩放同一 GameShell。普通页面保持实际视口纵横比，以 1600×900 为尺寸参考，整体缩放限制在 0.65–1.25，移动端下限 0.7；低 DPI 移动端增加 8%。边距、字号、控件和间距共同缩放，页面仍按内容空间自然排版，不建立其他页面的横竖版。
- 游戏页与场景鉴赏保持实际视口和原截图/工具栏机制。导航仅改变同一容器的尺度，不复制页面、编辑器或状态。
- 首页恢复标题在上、菜单靠下的原构图。仅根据横竖屏改变左对齐/居中，按钮宽度及字号关系不分别改变。
- 设置页统一在居中的 1000 设计单位区域内，分类、页头和表单对齐；正文只保留一个滚动区。标签列稳定为 260，空间不足时自然上下排列；数值与下拉输入保持接近的宽度，滑条保持可用轨道。
- 验收实际截图、同方向比例稳定、旋转只改变首页水平对齐、编辑器和滚动位置保持，以及游戏页实际视口和输入不回退。

## 首版设计（历史，已被用户否定）

复用现有 PlayerLayout、PlayerView、SettingsCategories 与 SettingRow，不引入新的布局框架或页面状态服务。

1. 普通页面由同一个逻辑视口计算有上下限的边距、页头及内容间距；页面主体限制最大宽度。取消根据窗口大小连续折算普通 UI 字号，保留用户字号档位及固定场景字号。
2. 设置页用有限高度的 Grid 承载 SettingsCategories，取消灰底大卡片和外层 ScrollViewer。分类头单行，当前分类正文负责滚动；分类滚动偏移由控件本地保存，卸载时解绑外部事件。
3. 首页保留现有装饰和菜单顺序。主体最大宽度受限，菜单按主体可用宽度分配并限制上下限，按钮同宽且由文字自然撑高。矮视口收紧标题和间距，再让菜单区域滚动；不等比缩放整页。
4. 表单依据自身宽度决定标签列宽及是否上下排列，编辑器实例原地重排。数字控件、下拉框和滑条分别设置合适的最大宽度。存档预览比例与文字信息区在矮窗口协同收紧。

风险：Avalonia 资源优先级及控件重新测量可能覆盖本地尺寸；验证最终 Bounds 和渲染截图。Tab 模板必须保留原生选择、焦点与键盘行为。用户已有字体档位调整原样保留。
