# Editor UI 与配置体验设计

状态：设计草案，待用户评审。本文描述建议方案，尚未实施；视觉效果需在真实桌面上验证。

## 问题与目标

Editor 的设置、文件和问题面板已经具备功能，但页面层级、控件对齐、选择与状态反馈缺乏统一；设置窗口初始宽度只有 480/520，编辑器快捷键列表还需要逐项应用。复杂设置虽然有字段元数据，仍存在 JSON 输入或修复入口。目标是在保持现有作者数据、历史、扩展与布局能力的前提下，让日常工作流清晰、精致且稳定，颜色更有层次但保持克制。

## 现状和证据

- [编辑器设置](../../src/Editor/GalNet.Editor/Views/EditorSettingsPanelView.axaml) 将常规设置和快捷键放在同一滚动页；项目设置已有左侧 Tab。两个独立窗口分别为 480×380、520×480，见各自 Window AXAML。项目设置仍有草稿、失焦提交和冲突检查，不应因为视觉统一而改成编辑器偏好的保存语义。
- [配置字段](../../src/Editor/GalNet.Editor/Services/ConfigurationSectionEditor.cs) 对未指定编辑器的非标量字段指定 JSON 编辑器；项目音频 buses/tracks 已有 sequence/object 描述及成员标签，而非完全没有结构。默认视觉程序已有 map 结构。需要识别各内置和扩展 section 实际回退，而不是假设全部已覆盖。
- 共享 [StructuredFieldEditor](../../src/Presentation/GalNet.Avalonia.Controls/Forms/StructuredFieldEditor.cs)、[EditorRegistry](../../src/Presentation/GalNet.Avalonia.Controls/Forms/EditorRegistry.cs) 和 [修复入口](../../src/Editor/GalNet.Editor/Controls/PropertyEditorSupport.cs) 在未知结构、深度、无效值或显式修复时可回退 JSON。Transform、Flipbook、Timeline、Shader vector、音效等会用到修复入口。图集文档也描述了异常配置通过通用入口修复。静态检索不等于所有实际用户入口均已盘点。
- 文件网格同时绘制图标和缩略图；空白及项目菜单顺序不一致。Problems 将详情放在每行 Expander，导航目前通过行内按钮；[Inspector 协调器](../../src/Editor/GalNet.Editor/Dock/DockInspectorCoordinator.cs) 特意不让辅助面板覆盖当前目标，锁定 Inspector 不跟随。
- [快捷键服务](../../src/Editor/GalNet.Editor/Commands/EditorShortcutService.cs) 负责冲突、持久化和通知，当前冲突检查按相同 context，执行时也包含 Global；单项重置未检查默认键与其他覆盖的冲突。Sample 绑定录入可参考 [InputBindingCapture](../../src/Presentation/GalNet.Avalonia.GameView/Input/InputBindingCapture.cs) 的交互，不能直接假定其 Player 数据模型适用于 Editor。

## 整体视觉方向

沿用现有主题体系及密度，不引入新的全局皮肤。通过清晰的标题、正文、辅助文字三级层次，一致的组间/行间距、适度边界和对齐建立秩序；优先消除重复标题、无意义边框和不必要的常显标识。主题沿用中性背景和文字，使用当前主题强调色提示选择、键盘焦点与关键操作；错误/警告使用既有语义色并配文字或图标。选中、悬停、按下、禁用、焦点须能区分，不只靠颜色；不要给每个分组或按钮引入独立色块。

先在设置、文件、Problems/Inspector 及关联弹窗形成一套一致规则，再审视共享标题栏、按钮、菜单等影响其他面板的公共样式。对其他面板只修复这些共享规则引起的不一致或明显状态辨识问题，不在未盘点时承诺整站重画。明暗及现有主题都要检查，对比、选中和焦点可读；具体色值根据实际窗口比对确定，不预先假定截图或色值可用。

## 标题栏和设置

所有使用共享窗口模板的最小化、最大化/还原、关闭按钮常态透明，指针悬停和按下使用主题反馈，关闭保留清楚的危险动作反馈。检查普通、浮动、设置及其他对话框实际模板、系统装饰和平台差异；原生窗口无法套共享样式时记录真实边界，不声称已覆盖。

两个设置窗口采用一致的左侧分类、右侧标题和表单结构；编辑器设置至少分为常规与快捷键，项目设置保留现有项目与调试分类，音频等项目领域可按内容与密度合理分组。建议初始参考 800×600 逻辑像素，依据实测调整，限制到可用屏幕；窗口可调整，窄宽下优先保证可滚动与字段不重叠，标签和字段可改上下排列。核对是否存在窗口尺寸/布局持久化，优先保留用户已保存的尺寸与布局；默认只用于首次或没有有效记录。右侧表单统一标签、输入、说明、组间距和宽度上限；状态只在有意义时显示，长本地化文字换行。

### 快捷键

采用类似 Sample 的“选择绑定 → 按键捕获 → 成功立即生效”体验，不使用逐项应用。每行显示命令名称、当前绑定及一个带 tooltip/无障碍名称的重置图标；分类用于浏览，搜索支持名称、分类和 ID，避免每行常显技术 ID。保留全部重置作为列表级操作，执行前通过确认弹窗说明将重置全部快捷键；取消不改变任何绑定。

捕获时显示等待提示，Escape 取消并保留原绑定；提供明确清除绑定方式（不能依赖捕获 Escape 作为普通快捷键），离开页面/失焦取消捕获。可用组合一次提交并即时持久化，保存失败说明且恢复原有效值；冲突显示命令名称，旧绑定不变，不静默覆盖。重置也先校验与当前其他绑定的冲突，失败保留旧值并提示；全局和局部上下文实际同时生效的组合应按执行语义判冲突，避免查重规则与路由不一致。上述规则需先验证现有命令上下文与默认绑定，避免误封合法组合；不可将界面检查当作唯一保护。

## 结构化配置与音频

2026-11-03 用户确认的音频界面修订：一个“音频设置”入口展示总线列表，各总线为 Expander，内含总线属性和轨道列表；轨道自身可展开，常用字段两列排列，低频字段放入“进阶设置”。标题显示名称、弱化的 ID 和轨道数量/播放摘要，增删和更多操作保持轻量。采用普通嵌套列表和既有字段绑定，不依赖展开事件重建整个列表。项目文件可继续使用现有字段；用户明确不要求向后兼容。编辑器和项目设置导航均采用带图标、独立背景的左侧分类。

配置数据继续保留当前格式，字段经现有 schema、registry、binding、草稿、校验、项目事务和历史提交。优先使用已有专用字段与递归结构（对象、列表、字典），字段修改只 patch 目标，保留未知兄弟字段、缺省与 null；UI 展开或只读检查不产生写入。移除 ConfigurationSectionEditor 对可遍历非标量一律强制 JSON 的路径，保留扩展自定义 editor 的优先权。

音频设置建议以 Bus 和 Track 两组清晰列表/表单呈现：可识别名称与 ID，选中后编辑相关字段；bus 引用从可用项选择，并显示失效引用；增删、排序是否可用取决于现有数据契约。常用音量、播放策略等用类型合适的输入及可读标签，详细选项分组而不是一次堆满。字段范围、默认值和关联验证来自现有契约，不能由 UI 猜测或静默重置。先比较现有历史音频 UI 与当前 schema，借鉴有价值的交互而不恢复过期数据模型。默认视觉映射以及其他内置复杂字段同样采用合适结构视图或扁平字段。

设计按三种情况处理：

1. **有 schema 的合法值**：专用控件或通用结构化 UI，覆盖已盘点的 Editor 正常作者流程；扩展字段优先使用扩展提供的 schema/editor。
2. **没有 schema 但可解析的结构**：建议通用类型化树显示对象成员、列表及标量，提供明确的类型和值；只允许能够无损 patch 的局部操作，不猜测业务含义。重复键、深度/数量超限等不可安全表示时转入下一类，不静默截断或重写。
3. **损坏、类型不匹配或无法安全解释的值**：显示可理解的诊断和保留原始数据状态；已知字段可在明确提示影响后提供按字段替换/重置，支持取消及撤销；对未知或不可无损修复的部分保留原文，禁止自动写回。可提供复制或外部打开作为异常恢复途径，不把 JSON 输入框作为日常配置 UI。针对解析失败的整文件、重复键和未知扩展，是否可以提供足够安全的结构化修复须先验证，不能承诺任意损坏数据都能在 Editor 内修好。

盘点范围覆盖设置、Entry/Inspector、Timeline、资源 sidecar 与通用文件入口，记录每一处正常/异常/扩展路径与处理结果。普通非配置文本文件的编辑用途与 JSON 格式文件的路由需核实，禁止仅按扩展名盲目改写或拦截用户文件。共享 Forms 也被 Player/扩展使用：优先通过 Editor 的注册与策略处理，若需改变共享行为须验证其他消费者；有界遍历与深层/大集合仍有清晰不可编辑状态，不以 JSON 回退悄悄破坏边界。

## 文件和右键菜单

网格缩略图成功可用时仅绘制图片，无图、加载中或失败时显示类型图标；透明图片不再透出图标。异步缩略图更新、回收与资源释放沿用现有机制，列表视图及非图片不退化。

右键菜单先盘点文件空白、文件/目录、多选以及其他工作区菜单。建议一致顺序为打开/定位、剪切复制粘贴和复制副本、新建/导入、重命名、删除、外部打开/刷新，按功能用分隔线；根据上下文只呈现有意义的操作并正确禁用，危险操作远离高频动作。具体排序针对各上下文调整，快捷键提示与真实作用对象一致；右键点击未选中项和多选行为保持可预测，并验证不会意外作用于旧选择。

## Problems 和 Inspector

Problems 保留简洁的级别、消息、来源和必要草稿操作；去掉行内技术详情 Expander。单击/键盘选择问题只更新 Inspector，双击/Enter 调用现有导航，目标不可用时仍可查看详情并说明不能跳转；内部草稿操作按钮不触发导航。Inspector 中展示可复制的消息、来源、代码和详情，以及适用的输入内容，不改变诊断数据。

建议通过现有 dock contribution/Inspector 协调机制让 Problems 成为可检查目标，而不是开一套详情面板；仅在明确选择问题后跟随，打开空 Problems 不清空原目标。沿用现有 Inspector 锁定语义：锁定后保持当前目标，未锁定的 Inspector 跟随所选问题；不额外增加全锁定提示或解锁流程。双击导航后的目标切换可能影响详情显示，应验证焦点、锁定与导航的实际时序；不改变稳定 ID、过期目标防护和草稿恢复/丢弃语义。

## 方案取舍与边界

- 选择逐步复用主题与现有表单，而非全局换肤：减少视觉和扩展回归，仍需实机检查共享状态。
- 选择 schema/专用编辑器优先、无 schema 的安全结构视图兜底，而非所有值强制转成固定 DTO；保留扩展兼容与未知字段。任意损坏文件的完全可视化修复不能保证，必须如实提示。
- 选择 Inspector 跟随而非行内详情：符合用户单击/双击规则，但需要处理锁、多 Inspector 和导航先后顺序。
- 不改变项目文件格式、Runtime、CLI 机器接口、既有项目事务或跨项目历史语义；不将普通文本编辑一概消除。

## 验证与风险

1. 先对现有主题、窗口模板、菜单、JSON 入口和设置字段做可追踪清单；在真实桌面取得前后视图，覆盖正常及窄尺寸、不同字号、长文本和各主题，检查视觉层次、焦点与标题栏。
2. 验证快捷键捕获、取消、清除、冲突（含 Global/局部）、重置冲突、搜索、语言切换、重开及保存失败；检查全局按键路由不会在捕获期间误触命令。
3. 验证音频增删编辑、非法值和引用、未知字段、扩展 schema、深层与无效数据的保全；覆盖项目设置草稿、关闭、Undo/Redo、保存重开与外部修改冲突。针对旧输入和不支持结构应有明确诊断而非数据丢失。
4. 透明缩略图、加载失败与切换视图实际显示；菜单在空白、单选、多选及右键改变选中场景行为准确。
5. Problems 普通/不可定位/过期/草稿项的单击、双击、键盘、Inspector 锁定、多 Inspector、导航时序和目标被移除；保留定位回归。
6. 覆盖四种现有界面语言及主题对比、无障碍名称、窄窗口；无法覆盖的平台或原生窗口明确记录。变更验证后再更新正式文档，不把草案写成现状。
