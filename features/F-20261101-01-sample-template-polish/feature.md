# Sample 模板交付与接线精简

状态：completed，2026-11-01。P1–P3 已取得范围内验证证据；完整回归保留 3 个既有 Editor 相关失败，延期平台与 Browser 环境哈希差异见 summary.md。原 fast-track 因公开便利入口和时长属性转普通流程，未扩大为公开拆包或全局契约变更。

## 目标与问题

在已完成的单项目 Sample 架构上，进一步降低开发者复制、构建和定制的成本。保留当前页面归项目、复杂机制归内置、平台外壳与项目契约独立的边界。

当前证据来自 [上一条复核](../F-20261031-02-sample-ui-template/review.md)：

1. 仓库外探针需要改写工程引用、中央版本和编译属性，独立包消费已证明，复制即可构建的交付形态尚需整理。
2. 标题与读档 VM 重复识别 IPreparedGameSessionService、选择准备/启动流程，项目业务编辑仍接触运行协议。
3. GameLaunchFlow 固定 350ms 加载停留；PlayerSurface 固定 2.8 秒公告并解释具体入场动画，视觉策略尚在内置层。
4. 普通游戏按实际映射创建，场景重播直接构造 Views.GamePage，后续替换游戏视图可能只覆盖一条路径。

## 范围

- 整理同一个 Sample 所需的独立包引用、编译属性与版本配置；仓库开发继续可用，不增加第二份应用源码。
- 收敛准备/启动协议适配，Sample VM 保留项目命令、业务前后动作、页面选择与必要 UI 状态。
- 加载停留和公告时长由 Sample 决定；取消、等待收束、输入屏蔽、焦点恢复与资源释放继续由内置层负责。
- 统一项目游戏视图的创建选择，普通游戏与场景重播使用相同布局来源，同时保持各自独立状态和生命周期。

## 非目标

- 恢复整页主题、增加 Sample.UI/VM 子项目、正式模板生成器或模板自动升级合并器。
- 扩展 PlayerSurface 全局部件协议、替换 Ursa、支持多个同时活跃宿主或迁移静态本地化解析。
- 改变存档/profile/PAK/契约身份、调试发行边界，或升级 Avalonia/媒体依赖。
- 修复历史 Editor 失败、扩大移动 UI 设计、补做用户已延期的 Android 真机或其他延期平台。

## 验收标准

1. 复制规定的 Sample 文件集合到仓库外后，不手工改写项目 XML 即可按文档还原和构建；内置依赖来自同版本包，无仓库源码引用。该集合及版本选择必须明确，不能只宣称复制单个 csproj 即可。
2. 新游戏、继续、读档的准备/开始顺序、取消、失败回退及项目业务前后操作保持；普通 VM 不再重复实现相同协议分支。
3. 默认 Sample 仍呈现现有加载/公告时序；改项目配置即可改变对应视觉时长，不修改内置机制。无效时长须有明确处理。
4. 修改或替换游戏布局同时覆盖普通游戏和场景重播；重播不复用主游戏 state/VM，不污染进度或重复释放。
5. Player/Developer 构建、内容契约闭包和必要锁图无新增回归；真实包消费者、生命周期及场景重播相关定向验证通过，原失败与未验项分别记录。

## 约束与流程边界

- 继承分阶段验证与提交偏好；实现授权后才修改产品代码，不发布包或推送版本。
- 当前工作区的 Sample csproj DependentUpon 修改、用户 lesson 和上一条 review 更新保持，不能当作新 feature 的实现提交。
- 建档期间另有窗口位置、Editor/Sample 窗口、平台入口和手册的并行修改出现；它们不属于本 feature。实现前须重新检查工作树并核实重叠；存在冲突时按快速通道规则退回普通流程，不覆盖或混合提交。
- 快速通道只用于边界可控的兼容接线精简。若必须修改公共 API、核心分层、全局构建/契约规则或与并行改动冲突，按 fast-track skill 转普通流程；不以“快”为理由隐藏接口设计。
- 无产品范围开放问题。内置启动适配能否利用现有入口完成，以及独立项目配置的最小文件集合，在实现前以实际构建图核实；若触发上述边界，先更新计划。
