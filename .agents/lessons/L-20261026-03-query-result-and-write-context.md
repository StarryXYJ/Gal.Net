# 查询结果与写入上下文必须分别验证

- 状态：confirmed
- 日期：2026-10-26
- 来源：F-20261015-02-editor-authoring-workspace，GC4

## 现象与根因

将场景选择 lease 从全项目 Revision 改为结果版本后，首轮 Editor 回归的六个转场用例发现：选择器写入当前条目的目标参数后，条目前方候选完全相同，旧选择仍能 Resolve。候选相等只证明读取事实相等，不能证明原写入位置和基线仍有效。相同 JSON 替换 DTO 也有同样的身份问题。

## 正确做法

分开维护查询事实版本与写入方上下文版本。前者比较目标、能力、数值、存在性和完整性；后者比较写入方作者对象身份、类型和参数基线。每个成功提交主动核对已借出的查询，相关变化后再 Undo 也不得复活旧版本。展示变化和无关作者编辑不能代替实际依赖变化。

后台资源准备另保留查询局部的作者依赖版本与资源代次：同一请求准备完成可换发结果，资源刷新、相关作者改变或项目关闭后的迟到结果不可续租。

## 验证与适用范围

初轮证据：artifacts/group-consistency-gc4/results/gc4-editor-first.trx；修复后完整 Editor 322 项通过，写入上下文补充 9 项、资源准备相关 22 项通过。新增测试覆盖相同 JSON 替换 DTO、相关改变再 Undo、无关后文编辑保留 Timeline 输入。

适用于依赖缓存的 Picker、Timeline、异步表单和其他先读后写的编辑器意图。禁止只用“候选相同”允许任意旧操作，也禁止用全局作者版本替代局部依赖来取消所有输入。
