# 控制台输入取消与读取所有权

- 状态：confirmed
- 来源：features/F-20261102-08-sample-architecture
- 现象：对同步或不可取消的 ReadLine 只使用 WaitAsync(token) 能结束等待，但不会结束底层读取；随后的另一次读取可能与旧任务争夺输入。
- 根因：取消的是等待者，不是 TextReader 的未完成读取。某些同步包装的 ReadLineAsync 也可能同步阻塞调用方。
- 验证：Sample 的可控 TextReader 回归覆盖取消推进后选择、排队等待取消和 EOF；确认新提示复用唯一待完成读取，旧提示不触发推进。
- 做法：一个会话统一拥有输入，串行分配结果；取消等待时保留底层读取交给下一请求，不无限等待它完成。明确会话退出与不可中断读取的边界。
- 禁止：将 WaitAsync 的取消误作底层 ReadLine 取消，或在旧读取仍在运行时为新提示另起读取。
