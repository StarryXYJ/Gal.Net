# 移动工具栏的命中大小不等于视觉大小

现象：独立工具栏移出固定画布后，直接使用 24/28 的设计字号，并在 320×56 的命中区绘制整块面色，按钮比对白显著更大。用户明确指出“这按钮也太大了吧”。

根因：脱离 Viewbox 的交互层把设计空间字号当作实际视口字号，又让容器绘制填满整个触摸区；只验证 48×48 命中与无溢出，不能验证构图和视觉密度。

正确做法：字号先按画布基准折算，再限制可读范围；48×48 只约束透明命中容器，文字/选中反馈使用居中的自然尺寸内容。不要用大背景填满命中区。跨黑边的对比需求可以用紧贴文字的小底色解决。

验证：MobileLayoutTests 同时断言按钮命中至少 48×48、可见内容高度不超过 30、透明区与可见内容有高度差、工具栏整块背景透明；桌面 PNG/几何与原版一致。修正后 21 项布局/播放交互回归通过。截图见 output/mobile-layout/revised/（不提交）。

范围：固定设计画布之外的触摸交互层。不借此修改玩家已有字号配置或整体放大其他 UI。规范见 docs/spec/presentation/game-view.md 的移动页面与工具栏。
