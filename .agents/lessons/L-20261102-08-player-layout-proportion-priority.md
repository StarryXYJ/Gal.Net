# 玩家页面优先保持构图与控件比例

用户明确否定首版：虽然几何/状态回归通过，首页把标题和菜单挤到上方、设置页缩成左侧零散小控件，主观效果比原固定画布更差。最终要求只有首页根据横竖屏改变左对齐/居中；其他页面自然自适应，按钮尺寸关系参考初始画布，移动端低 DPI 仅小幅放大。

后续不能仅靠无溢出、最小点击尺寸或测试计数认定视觉验收。先检查标题/菜单纵向构图、控件相对大小、表单列对齐和整体空间，再验证边界。不要给每个元素分别计算窗口比例或自行添加所有页面的横竖版。

统一缩放后，控件 Bounds 属于设计坐标，和真实窗口比较应使用 TranslatePoint 转换起点与终点；不能把已变换的起点直接加上未变换的 Bounds.Width。几何通过仍不能替代实际截图与用户的视觉评价。

当前实现与验证见 feature 的 P3、revision 截图及 docs/spec/presentation/game-view.md。
