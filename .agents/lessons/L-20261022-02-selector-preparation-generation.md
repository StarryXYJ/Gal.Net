# 选择器准备完成不等于作者内容失效

状态：confirmed
日期：2026-10-22
来源：F-20261021-02-image-variants / P4b

现象：选择器首次打开时捕获场景查询 Revision，然后等待后台资源定义准备；准备完成正常推进 Revision，选择器自身变成过期，必须关闭重开才可选择。仅测试已预热的查询会漏掉问题。

根因：单一结果 Revision 同时表示作者内容/资源代次变化和同代异步准备完成。等待前后的结果版本不同，不足以证明原作者上下文失效；也不能在等待后无条件重建快照，否则会接受等待期间修改、撤销、刷新或关闭后的旧手势。

发现与验证：ImageVariantsSceneTests.ColdAtlasSelectorCanFinishPreparationButAnAuthorEditStillInvalidatesIt 用受控资源读取 Gate 验证冷启动等待后可解析；既有刷新、关闭与作者修改测试继续验证旧选择被拒绝。

正确做法：等待前保存不可变作者快照身份与资源代次。准备完成后，只有作者快照仍为同一对象、资源代次未变且 scope 有效时，才允许刷新结果快照；最终确认仍走当前 Revision 与 Locator 校验。Undo 回到相同 JSON 不复活旧快照身份。

适用：异步准备资源后再呈现候选的字段、Timeline 或类似选择 lease。
禁止：无条件接受等待后的当前快照；只在预热后验证选择；仅因预期的后台准备推进结果版本而永久禁用本次选择。


GC4 后续（2026-10-26）：托管选择器现在按查询局部作者依赖版本和资源代次检查准备请求，允许无关作者修改保留请求；写入方上下文另有版本，详见 [查询事实与写入上下文](L-20261026-03-query-result-and-write-context.md)。原始整作者快照身份是当时的保守实现，不是永久要求全局失效。

2026-10-28 远端 CI 跟进：首次远端运行 40559879643 在上述冷图集用例的初始 Select 失败。项目/条目创作会自动 QueuePreparation，测试若在插入条目之后才设置资源 Gate，先前启动的读取仍可在查询快照与选择之间完成。测试应在创建项目/服务之前安装 Gate，并断言显式释放前 PrepareAsync 未完成，不能用机器速度推断“冷启动”。
