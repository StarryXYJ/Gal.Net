# 游戏内容分包与资源补丁

项目保持一张 Graph。章节可在入口按 save 变量分支，首页按钮传不同初始值；见[自定义 Sample](customize-avalonia-sample.md#单图章节启动参数)。

## 剧情包

选中 Group，在节点检查器填写「剧情包名称」，移开焦点提交。留空属于本体，相同名称聚合为一个剧情包；名称区分大小写，但不允许仅大小写不同的两组名称。候选列表提供已有名称。不需要另建剧情补丁面板。

正常 galpak 导出会先保存当前项目，再从受保护的作者快照生成本体及全部剧情包。基础 PAK 放入 galpak，剧情 PAK 放在旁边 `StoryPatches/<buildId>/`。目录导出将它们放在输出目录内相同位置。分发时可以不带某个剧情包的所有分片，运行会沿其正常出口跳过；只缺一个分片、损坏或错版会报错。旧构建的剧情包不能配到新构建。

本体先对全部普通 Group 和明确的基础根收集依赖。每个剧情包只扣除本体已有资源：A/B 都使用而本体没使用的资源，两包各带一份。条件分支里的静态资源全部计入，图集带齐其声明图片；不会因某次试玩没有走到分支而漏包。

项目设置的 `galnet.packaging` 提供 maxPakBytes（默认 64 MiB）、includeResources 和 declaredCompleteResources。阈值按未压缩编译资源字节计算，单个超大资源独占一片，不拆资源。includeResources 用于 UI、自定义代码等静态剧情外的根；未知/动态引用还需在 declaredCompleteResources 中确认已补全依赖（资源 ID 或 Group 节点 ID）。声明完整不会自动添加资源。

布局报告为 galpak 旁的 `<项目>.layout.json`，目录导出为 packaging-layout.json，可查看每个资源的归属、直接依赖及未打包项。已有 Gallery 和默认视觉程序绑定属于基础根。文本和人物文件完整保留在基础内容，不单独做剧情语言补丁。

## 资源补丁矩阵

从面板菜单打开「资源补丁」。左列列出所有 Group（含剧情包）的资源引用，勾选「显示间接资源」可看到图集图片等依赖。点击原资源定位到编辑器文件管理器，悬停查看使用位置。没有静态引用的原资源可通过「补充原资源」加入，它也成为基础打包的显式根。

1. 点击「新建补丁列」，修改列名和优先级。回车提交，或随项目保存一起提交；无效草稿会保留并阻止保存，可点击「放弃草稿」。
2. 在格子里用现有资源选择器选择替换资源，空格子不覆盖。替换资源须有独立 ID 且类型相同；图集还须保留原维度名和原变体键，可以增加变体。
3. 点击该列「保存并导出 PAK」。它保存作者工作版并独立导出当前列，不需要先导出 galpak。普通 galpak 导出不会自动生成资源覆盖包。
4. 将 PAK 放在安装目录或其父目录的 `ResourcePatches/` 下，重新启动/新建安装会话采用它。

所有列、映射和补充原资源保存在 settings.json 的 `galnet.resourceOverrides`，支持项目撤销/重做、保存、恢复和重开。改名/移动资源保持 ID，因此映射仍有效；复制产生新 ID，不自动替换旧映射。删除原资源或目标会显示缺失，导出不能静默忽略缺失目标。

优先级数值越大越优先；相同时按完整 PAK 的 SHA-256 字典序，较大者优先，同文件重复放置只算一次。没有语言条件或人工冲突选择页。每次引用只映射一次，A→B/B→C 不会把 A 直接变成 C。

覆盖包携带 B 的完整依赖，明确读取该包内 B。携带资源不会隐式替换本体同 ID 资源；递归依赖同 ID 却内容不同会拒绝，应给修改后的依赖分配新 ID，必要时另建显式映射。通过「项目设置」中的资源补丁 section 可补充当前列的 includeResources / declaredCompleteResources，用于自定义资源的动态依赖。

未安装的剧情包不会因资源覆盖包存在而被当作已安装。Graph/Group 不能通过资源矩阵覆盖。当前不提供运行中热装卸和 Gallery 补丁。

## 存档与格式

存档 v5 校验基础构建和准备时已安装的全部剧情包。删除其中任意剧情包都会阻止恢复，即使当时尚未播放到该包。旧 galpak/PAK 需重新导出；不自动转换旧格式。
