# 编辑游戏文本与翻译

在视图菜单打开“游戏本地化”。左侧选择角色表、任意 GalGroup 或分支选项，右侧按语言显示文本；开发语言始终在最左列。普通剧情表单和角色表仍直接填写开发语言，移动条目不会改变译文身份。

点击工具栏的“管理语言”图标，输入语言名称或代码（如 en-US、ja-JP、zh-Hans-CN），选择候选或直接输入有效代码，再点击“＋”。候选排除已添加语言，新语言不会复制原文。已有语言前的勾选控制列显示，开发语言始终显示；拖动列头右侧边缘调整列宽。语言行的更多菜单调整顺序或切开发语言，移除按钮将该语言从支持列表移除，但保留翻译文件；重新添加可恢复文本。开发语言需先切换后才能移除。

单元格默认紧凑显示，点击后从左上角开始多行编辑。失去焦点或按 Ctrl+Enter 提交，输入过程中不逐字更新项目，无需保存草稿或复核。Enter 换行，清空后提交会写入空字符串；缺译格按 Ctrl+Enter 可明确保存为空串。输入法组字期间保留候选，不提前提交。Escape 放弃未提交输入，已经提交的内容通过项目撤销恢复。修改原文保留其他语言的译文。

分支选项或其他 `LocalizedText` 字段留空时会显示为空文本，不要求在本地化文件中建立空 key；只有非空 key 才参与缺译检查。

同分类内共享文本只显示一行，并提示引用数量；修改会影响共享位置。使用行内的定位图标打开对应创作位置，多处引用时可选择目的位置。表格横向滚动可查看更多语言，上下文列保持可见，语言列头不随文本行上下滚动。左侧分类和右侧文本行可独立纵向滚动；窄面板通过分类下拉框选择范围。

顶部搜索匹配原文、译文及定位信息；缺译图标开启“仅缺译”，检查当前显示的非开发语言列。显式空字符串不算缺译，隐藏的语言列不参与筛选。

需要更换项目开发语言时，先添加该语言，再打开“管理语言”，在该语言的更多菜单中选择“应用开发语言”。弹层显示目标语言缺译数量；检查后点击“应用开发语言”。这不会自动翻译或复制文本，普通创作页随后使用新的开发语言。检查后文本发生变化时，需要重新检查。项目设置页面的开发语言仅显示当前值。

所有文本和语言操作支持项目撤销/重做。失焦提交修改项目工作内容，Save All 也会提交当前尚未失焦的输入并统一写盘。切换分类或关闭面板会保留尚未提交的内容。遇到原文、译文、引用或 JSON 冲突时，失败输入保留并就地提示；检查现值后可用错误旁的重新读取按钮放弃失败输入。未解决错误会阻止保存。项目关闭后不再接受旧面板写入。

点击导出图标，在弹层中选择交换语言，保留“全部分类”或取消以导出当前分类，再点击“导出 JSON”。默认输出带上下文和原文指纹的单语言模板；只修改 rows 中的 translation，保留项目身份、key、语言和原文列。行顺序可以调整。勾选“运行文本”会输出直接译文的平铺 JSON，缺译不输出。导出位置须在项目目录之外。

点击导入图标，在弹层选择交换语言后点击“导入预览”，选择模板或平铺 key→string/null JSON。平铺文件使用该交换语言；模板按自身目标语言预览。目标语言必须先添加，且不能是当前开发语言。预览显示当前原文、导入值与状态，勾选要应用的行；未知文本不能选，null 跳过，空字符串须同时选择该行并勾选“允许空字符串清空译文”。模板原文发生变化时预览会提示“原文已变更”，应用不覆盖原文。预览过期时重新打开文件，不能强行覆盖当前值。

点击“应用所选”把整批译文和复核状态纳入一次撤销/重做，随后 Save All。应用开始前可取消预览，应用期间控件暂时禁用。首次模板导出会持久分配项目交换 GUID，改目录名不影响匹配；后续文件输出失败时该身份仍保留，不会保存其他 dirty 文本。

发布前运行完整项目检查或构建。包内开发语言缺译、未知角色和损坏来源会阻止替换构建输出，外部覆盖包不能补足默认语言。仅切换开发语言时看到的缺译数量不能代替发布检查；自定义无法分析的范围会明确提示不完整。

扩展 DTO 可声明文本与角色语义：

```csharp
[GenerateFieldSchema]
public partial class MyLineOptions
{
    [Field(0, AllowNull = true), CharacterReference]
    public string? Speaker { get; set; }

    [Field(1, AllowNull = true, EditorId = "entry.multilinetext"), LocalizedText]
    public string? Content { get; set; }
}
```

使用 GalNet.Core.Parameters 中的特性和项目 schema generator；注册生成的字段 schema 后，工具按开发语言编辑并保存 key。自定义运行指令仍需通过 ITextResolver 解析文本 key，角色名通过 catalog 的姓名文本 key 解析；不把任意字符串或 opaque JSON 自动当成本地化文本。作者数据及分析边界见 [游戏本地化规范](../spec/editor-game-localization.md)。
