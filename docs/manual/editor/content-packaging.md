# 游戏内容分包与资源补丁

项目保持一张 Graph。章节可在入口按 save 变量分支，首页按钮传不同初始值；见[自定义 Sample](../extensions/settings-and-variables.md#单图章节启动参数)。

## 剧情包

选中 Group，在节点检查器填写「剧情包名称」，移开焦点提交。留空属于本体，相同名称聚合为一个剧情包；名称区分大小写，但不允许仅大小写不同的两组名称。候选列表提供已有名称。不需要另建剧情补丁面板。

Editor 的「导出游戏」提供「Galpak 游戏包」和「内容文件夹」两种格式，无需安装 .NET SDK 或脚本工具。两种导出都先保存当前项目，再从受保护的作者快照生成本体及全部剧情包。压缩包输出为所选目录内的 `<项目>.galpak`，包含全部剧情分片，可单独移动；文件夹输出为所选目录中新建的 `pak/`，目标已存在时拒绝覆盖。维护者应用发布仍使用独立脚本，Editor 不再显示应用组合包选项。

新 galpak 使用 v4 安装索引，所有归档条目位于 `pak/` 下。使用普通解压工具解压到播放器目录后得到应用同级的 `pak/`。配置/人物/Gallery/清单封装为 `game.pak`，内置文本封装为 `localization.pak`，每种语言合并成一个逻辑条目。玩家目录无需分发这些散装 JSON。`pak/I18n/<culture>/**/*.json` 只用于民间翻译等外置重载，缺省为空，详见[国际化](../../spec/content/localization.md#外部文本覆盖)。

剧情与资源覆盖包分别放入 `pak/StoryPatches/<buildId>/`、`pak/ResourcePatches/`；即使没有任何补丁，也会保留这些目录和 I18n 空目录。资源覆盖补丁独立导出，再显式放入目标 ResourcePatches；两种内容导出都不自动收集归档旁或工作区中其他补丁。完整 galpak 安装前校验全部已声明剧情分片，不从旁置目录补齐。目录导出 CLI 与 `galpak install --output` 的参数均表示内容根，应指定 `app/pak`，不会生成双层 `pak/pak`。安装器只接受 v4，旧包需重新导出。

安装/解压后，可以显式移除某个剧情包的全部分片以生成精简发行，运行会沿其正常出口跳过；只缺一个分片、损坏或错版会报错。此时不再是完整 galpak 的原样安装，不能把缺分片的归档作为有效完整包。旧构建的剧情包不能配到新构建。

本体先对全部普通 Group 和明确的基础根收集依赖。每个剧情包只扣除本体已有资源：A/B 都使用而本体没使用的资源，两包各带一份。条件分支里的静态资源全部计入，图集带齐其声明图片；不会因某次试玩没有走到分支而漏包。

项目设置的 `galnet.packaging` 提供 maxPakBytes（默认 128 MiB）、includeResources 和 declaredCompleteResources。阈值按未压缩编译资源字节计算，单个超大资源独占一片，不拆资源。includeResources 用于 UI、自定义代码等静态剧情外的根；未知/动态引用还需在 declaredCompleteResources 中确认已补全依赖（资源 ID 或 Group 节点 ID）。声明完整不会自动添加资源。

布局报告为 galpak 旁的 `<项目>.layout.json`，目录导出内置于 game.pak 的 packaging-layout.json，可查看每个资源的归属、直接依赖及未打包项。已有 Gallery 和默认视觉程序绑定属于基础根。文本和人物完整保留在本体文档包，不单独做剧情语言补丁。封装复用压缩 JSON，不引入 BSON；封装不是加密。

## 资源补丁矩阵

从面板菜单打开「资源补丁」。左列列出所有 Group（含剧情包）的资源引用，勾选「显示间接资源」可看到图集图片等依赖。点击原资源旁的定位图标进入编辑器文件管理器，悬停查看使用位置。没有静态引用的原资源可通过「补充原资源」加入，它也成为基础打包的显式根。

1. 点击工具栏的新增图标创建补丁列。名称回车或移开焦点后自动保存，优先级用数字输入调整；列头图标分别用于导出和删除。
2. 在格子里用现有资源选择器选择替换资源，空格子不覆盖。替换资源须有独立 ID 且类型相同；图集还须保留原维度名和原变体键，可以增加变体。
3. 点击该列的导出图标独立生成 PAK，不需要先导出 galpak。导出只读取已保存的补丁定义和资源快照，不保存其他项目内容，也不提交其他页面未完成的输入。普通 galpak 导出不会自动生成资源覆盖包。
4. 将 PAK 放在安装目录或其父目录的 `ResourcePatches/` 下，重新启动/新建安装会话采用它。

列、映射和补充原资源的有效修改会立即写入 settings.json 的 `galnet.resourceOverrides`，无需应用或另行保存。撤销/重做也同步写盘，只发布该配置节，不顺带保存其他剧情或设置改动；失败会保留原版本并显示错误。定义继续支持恢复和重开。改名/移动资源保持 ID，因此映射仍有效；复制产生新 ID，不自动替换旧映射。删除原资源或目标会显示缺失，导出不能静默忽略缺失目标。

优先级数值越大越优先；相同时按完整 PAK 的 SHA-256 字典序，较大者优先，同文件重复放置只算一次。没有语言条件或人工冲突选择页。每次引用只映射一次，A→B/B→C 不会把 A 直接变成 C。

覆盖包携带 B 的完整依赖，明确读取该包内 B。携带资源不会隐式替换本体同 ID 资源；递归依赖同 ID 却内容不同会拒绝，应给修改后的依赖分配新 ID，必要时另建显式映射。通过「项目设置」中的资源补丁 section 可补充当前列的 includeResources / declaredCompleteResources，用于自定义资源的动态依赖。

未安装的剧情包不会因资源覆盖包存在而被当作已安装。Graph/Group 不能通过资源矩阵覆盖。当前不提供运行中热装卸和 Gallery 补丁。

## 存档与格式

存档 v5 校验基础构建和准备时已安装的全部剧情包。删除其中任意剧情包都会阻止恢复，即使当时尚未播放到该包。文档封装格式参与 buildId，新旧布局不会误用同一构建存档。旧 galpak v1/v2 与 content v2 安装目录保持读取兼容，旧 GPAK v2 需重新导出；不自动转换旧格式。

资源覆盖不改变存档中的逻辑资源 ID。图集替换后，读档会保留差分选择意图，并按当前有效图集重新解析实际图片；移除覆盖后也会重新解析。普通未覆盖图集仍严格校验保存结果与内容是否一致。

例如目标为 128 MiB 时，300 MiB 的单文件会完整独占一个约 300 MiB 载荷的分片，不截断、不切碎，也不与后续资源混装。分包阈值是布局目标，不是内存限制；当前归档写入和读取仍会保留整片缓冲。使用大资源时应结合实际导出与运行峰值调整阈值，单资源超过阈值时仍完整保留。

当前归档使用 byte[]，单资源与单 PAK 受约 2 GiB 的缓冲容量限制，实际还受可用内存约束；更大的媒体需要流式归档能力，不能通过调高阈值获得支持。
