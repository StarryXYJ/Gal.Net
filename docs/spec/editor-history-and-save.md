# Editor 项目历史与保存

当前实现见 `features/F-20261015-02-editor-authoring-workspace/phase-1b.md`。P2/P3 已接入 [Graph 编辑](editor-graph.md)，包括分支与整批粘贴；项目文件界面及文本页已接入，见 [项目文件操作](editor-files.md)；完整 Group 参数 UI 继续按后续阶段迁移。

## 操作与输入

一个项目拥有一条内容历史，页面、Inspector 和 Dock 焦点不切换内容栈。页面展开、选择、滚动与 Dock 布局不进入内容历史。撤销/重做菜单显示下一项操作描述。关闭设置页面后，已提交的设置仍可撤销；关闭项目后不恢复旧 Undo 栈。

本地化作者文档与单次文本修改也使用该内容历史，见 [游戏本地化基础](editor-game-localization.md)。JSON 文件缓冲按文件身份注册草稿；结构化编辑只预先校验并提交相关文件草稿。文档刷新不会覆盖已有冲突草稿，过期输入必须取消或重新核对后才能提交。

设置页的名称、分辨率、存档槽、音频与语言输入先保留为本地草稿，点击 Apply changes 或 Enter 提交为一次编辑，Escape 或 Cancel changes 取消草稿。保存全部及项目菜单撤销/重做会先尝试提交有效设置草稿；无效草稿显示错误并阻止保存关闭。文本控件先处理自己的撤销，再冒泡至项目快捷键。提交不逐字符记账，不依赖 IME 的逐段文本事件构造历史。

历史串行执行异步编辑；同步入口在有编辑执行时拒绝重入。执行、撤销与重做都在成功后移动游标；失败不截断 redo。复合操作补偿已完成步骤，每个单独步骤必须自行保证失败时保持输入状态。补偿失败进入 RepairRequired，禁止继续编辑/写盘并保留作者恢复快照，用户需检查恢复材料再重新打开。通知观察者失败记录日志，不将已提交内容伪装为应用失败。

## 保存全部与关闭

GUI 的项目保存统一经过项目 scope 的 `ProjectContentSession`。先提交设置草稿，在历史捕获租约中复制同一版本的 Graph、全部 Group 与完整设置，再形成一次写入/删除计划。普通保存的后台文件发布不持有历史捕获租约，用户后续编辑保留为新的未保存内容。不能在持有发布门时等待历史门，否则会与结构编辑形成锁反转。

Graph、Group、settings 与当前 editor-state 在同一作者文件事务发布。变量定义以 Graph 为准，settings 中的变量副本由序列化派生。视口状态可以单独保存，不会自动保存其他作者内容。外部改变已有作者文件或 settings 后，保存明确失败，不以自己的旧内容覆盖；不承诺跨进程多文件原子性。

GUI 的 Repository 显式使用 Authoring 验证策略：Raw Group 可以保留未知类型/参数、缺必填值、无效参数类型或未完成条件表达式，Graph 分支条件也可保留未完成文本；保存不 Normalize、不补默认值。当前格式、稳定身份、严格 JSON shape、重复属性、Graph 拓扑、源路径/归属及外部冲突仍检查。仓库默认 Complete 供 CLI 严格写入使用，validate/group compile 和预览编译不因 GUI 草稿可保存而放宽。保存后继续撤销类型变更会恢复原作者 JSON，并重新成为未保存内容。

GUI 的 dirty 状态统一由 ProjectContentSession 依据当前作者内容与最近成功保存内容比较，独立于历史位置；History.IsDirty 查询同一会话，保存和关闭检查不依赖 Document 或 GalProject 的手工 dirty 标记。比较忽略 Group 查询字典的插入顺序、参数查询顺序和显示行号；保留实际 Graph/Entry 顺序与 JSON 值。保存失败不更新基线，保存期间产生的新编辑仍为 dirty。设置草稿也参与关闭脏检查。

关闭项目或应用时先挂起并等待当前编辑与保存队列，取消尚未开始的自动保存。若有未保存内容，提供 Save All、Discard Unsaved Content、Cancel；取消保持原项目与草稿，保存失败也保留会话。保存期间再次产生未保存内容时重新检查，不能保存旧捕获版后直接关闭。放弃只丢弃未保存内容；已经完成的结构写盘不反向撤销。

## 结构计划与恢复材料

`IProjectStructureChange` 分别对 Working 与 Saved 版本应用同一结构意图，允许删除/恢复保留各自的 Group 内容。`PublishStructureAsync` 只发布变换后的保存基线，内存仍保留原有未保存字段。后续保存再撤销路径变更时，变换应用于当时的基线，不用旧整份文件覆盖刚保存的其他字段。`IProjectFileStructureChange` 可附带普通文件、目录与大小写改名计划，与 Graph/Raw Group/settings 一起发布；项目文件界面与文本缓冲已接入。项目拥有的文件描述项使用稳定会话 ID，独立保存 path、存在状态和受管理文本字节；关闭视图不删除该状态。删除项的保留字节不参与当前 dirty 比较，但仍保留于历史/恢复材料，以支持分别恢复 Working/Saved。支持矩阵与引用规则见 [项目文件操作](editor-files.md)。

作者文件事务材料位于 `.galnet/editor/transactions/<id>/`：manifest 记录路径、前后内容哈希与 prepared/publishing/committed/repair-required 状态，编号 `.old`/`.new` 文件保留备份与新内容。失败逆序恢复；恢复失败保留目录。打开项目时检查未完成计划，只在现有内容匹配记录的旧/新哈希时恢复，发现外部内容则拒绝覆盖并报告材料位置。成功材料清理失败只记录并延后清理，不将已成功发布报告为保存失败。

作者恢复快照位于 `.galnet/editor/recovery/`，包含版本、时间、载荷及 SHA-256；`ProjectRecoveryStore.Read` 验证完整性。默认有变更时每 30 秒捕获，关闭前及事务失败时也捕获；仅保留最近 3 份。历史默认 200 步，已声明的持有数据和恢复快照各按可配置 1 GiB 软预算淘汰，最新完整快照即使单份超预算仍保留。淘汰历史或截断 redo 会释放该记录自有的 disposable 资源。它不是进程堆内存硬限制，也不是跨重启历史。

删除记录为历史保留，路径复用后同一路径可以同时拥有删除身份与一个有效身份；保存期望按有效路径归并，不分别要求同一路径既存在又不存在。多个有效身份占用同一路径仍是冲突。

## 当前边界

- Graph 基本节点、连线、名称与坐标已迁移为项目数据记录；Group 生命周期接入双版本结构计划，见 [Graph 基础编辑](editor-graph.md)。分支字段、Entry 类型/条件/参数及变量声明使用显式项目意图；Preview 只编辑运行时当前值，不补记声明历史。Entry 字段与新增条目历史不持有 Workspace/Group 页面，见 [Group 编辑](editor-groups.md)。
- 已提交的 Group 作者 JSON 可在 P5e 保存重开，包括未知/不完整语义；Entry 表单中尚未转换成 JSON 的输入由项目会话保留，见下文；Timeline 关键帧行等专属工具仍使用各自的本地输入生命周期。损坏 JSON 和不安全结构不作为作者草稿写盘。
- 事务恢复可在打开时自动核对；作者快照提供材料及读取校验，尚无交互式快照还原页面。
- 原生 IME 候选输入及完整桌面人工操作未验收；已通过 Headless 实际控件的本地文本撤销、设置提交和关闭对话框验证。

## Entry 输入草稿与保存反馈

`EntryEditSession` 为项目 scope 拥有的输入会话，以 Group、Entry 稳定身份、来源代次和字段路径管理草稿。行内和 Inspector 创建各自控件，共享输入状态与现有作者提交意图。切条目、折叠、关闭面板、切语言或套用布局保留尚未提交的输入；Escape 或 Problems 中取消草稿明确丢弃它。源值、类型或列表结构改变后，旧草稿标记冲突，不写入新来源，也不因撤销而静默复活旧绑定。

项目内容变化时检查草稿来源；已经观察到的来源冲突不会因为撤销恢复了相同 JSON 而自动解除，需明确取消旧草稿后重新编辑。

Save All 经过现有草稿登记统一尝试提交；有效提交进入项目历史，不能转换、冲突或正在组合输入的草稿阻止此次写盘并保留输入。保存前已有的有效草稿提交可能已成为作者修改，保存失败不会伪装为这些修改从未发生。自动保存沿用相同规则，不弹出打断式对话框。未完成控件输入仅保留在当前项目会话，不承诺跨进程恢复。

状态栏分别显示保存状态、待处理输入和作者检查状态；保存成功不等于可以运行。发布期间的新编辑仍为未保存内容。Problems 检查当前作者快照并复用 Graph/Group/本地化规则；不完整分析与已过期结果明确显示，普通日志不靠解析字符串猜测跳转位置。
