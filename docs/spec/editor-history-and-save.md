# Editor 项目历史与保存

当前实现见 `features/F-20261015-02-editor-authoring-workspace/phase-1b.md`。P2/P3 已接入 [Graph 编辑](editor-graph.md)，包括分支与整批粘贴；项目文件界面及文本页已接入，见 [项目文件操作](editor-files.md)；完整 Group 参数 UI 继续按后续阶段迁移。

## 操作与输入

一个项目拥有一条内容历史，页面、Inspector 和 Dock 焦点不切换内容栈。页面展开、选择、滚动与 Dock 布局不进入内容历史。撤销/重做菜单显示下一项操作描述。关闭设置页面后，已提交的设置仍可撤销；关闭项目后不恢复旧 Undo 栈。

本地化作者文档与单次文本修改也使用该内容历史，见 [游戏本地化基础](editor-game-localization.md)。JSON 文件缓冲按文件身份注册草稿；结构化编辑只预先校验并提交相关文件草稿。文档刷新不会覆盖已有冲突草稿，过期输入必须取消或重新核对后才能提交。

设置页的名称、分辨率、存档槽、音频与语言输入先保留为本地草稿，点击 Apply changes 或 Enter 提交为一次编辑，Escape 或 Cancel changes 取消草稿。保存全部及项目菜单撤销/重做会先尝试提交有效设置草稿；无效草稿显示错误并阻止保存关闭。文本控件先处理自己的撤销，再冒泡至项目快捷键。提交不逐字符记账，不依赖 IME 的逐段文本事件构造历史。

历史串行执行异步编辑；同步入口在有编辑执行时拒绝重入。执行、撤销与重做都在成功后移动游标；失败不截断 redo。复合操作补偿已完成步骤，每个单独步骤必须自行保证失败时保持输入状态。补偿失败进入 RepairRequired，禁止继续编辑/写盘并保留作者恢复快照，用户需检查恢复材料再重新打开。通知观察者失败记录日志，不将已提交内容伪装为应用失败。

### 作者内容提交通知

`UndoRedoHistory.AuthorChanges` 在一次成功 Execute、Undo 或 Redo 完成并更新历史游标后发布一个 `AuthorChangeSet`，版本单调增加。Group 范围包含稳定 Group/Entry 身份、最早受影响位置及条件/参数/类型/成员/顺序变更标记；复合操作合并子范围。尚未声明完整范围的旧操作及混合复合操作标记 UnknownScope，消费者保守刷新。失败及其补偿不发布内容结果；Clear、MarkSaved、忙碌状态和空 Undo/Redo 不生成内容提交。发布期间禁止历史重入，单个订阅者异常记录在通知错误中，不阻止后续订阅者。

Entry 字段、批量新增/粘贴/删除/重排直接修改项目作者数据。Group 的可观察集合只由投影同步更新，外部不能通过增删该集合写回作者文档；列表通知的接收者读取到的是完整作者操作。投影集合的单个观察者异常单独记录，既有内容与历史继续有效。Group 投影和 Timeline 的内容刷新使用成功提交事件；历史按钮、保存状态及其他尚未迁移的界面仍可使用 History.Changed。已知 Group 范围按 Entry 身份刷新投影，场景查询按受影响 Group 更新作者快照并复用分析；现有查询结果与写入上下文未变化时不广播作者刷新。Timeline 自身按活动 Group 接受作者提交，其他 Group 通过实际场景查询变化触发刷新。UnknownScope 仍保守刷新。

## 保存全部与关闭

GUI 的项目保存统一经过项目 scope 的 `ProjectContentSession`。先提交设置草稿，在历史捕获租约中复制同一版本的 Graph、全部 Group 与完整设置，再形成一次写入/删除计划。普通保存的后台文件发布不持有历史捕获租约，用户后续编辑保留为新的未保存内容。不能在持有发布门时等待历史门，否则会与结构编辑形成锁反转。

Graph、Group、settings 与当前 editor-state 在同一作者文件事务发布。变量定义只保存在 Graph 中，settings 不再包含同名列表。视口状态可以单独保存，不会自动保存其他作者内容。尚未采纳的外部作者文件或 settings 变化会使保存明确失败，不以自己的旧内容覆盖；不承诺跨进程多文件原子性。

GUI 的 Repository 显式使用 Authoring 验证策略：Raw Group 可以保留未知类型/参数、缺必填值、无效参数类型或未完成条件表达式，Graph 分支条件也可保留未完成文本；保存不 Normalize、不补默认值。当前格式、稳定身份、严格 JSON shape、重复属性、Graph 拓扑、源路径/归属及外部冲突仍检查。仓库默认 Complete 供 CLI 严格写入使用，validate/group compile 和外部调试构建不因 GUI 草稿可保存而放宽。保存后继续撤销类型变更会恢复原作者 JSON，并重新成为未保存内容。

GUI 的 dirty 状态统一由 ProjectContentSession 依据当前作者内容与最近成功保存内容比较，独立于历史位置；History.IsDirty 查询同一会话，保存和关闭检查不依赖 Document 或 GalProject 的手工 dirty 标记。比较忽略 Group 查询字典的插入顺序、参数查询顺序和显示行号；保留实际 Graph/Entry 顺序与 JSON 值。保存失败不更新基线，保存期间产生的新编辑仍为 dirty。设置草稿也参与关闭脏检查。`ProjectContentBaseline` 保留已保存快照，直接比较当前内存内容，读取状态不再执行全项目 JSON 克隆和序列化；可变作者模型的直接修改仍可被识别。草稿登记、预校验、提交和取消由 `ProjectDraftRegistry` 管理，发布门与历史捕获门仍由 ContentSession 统一协调。

关闭项目或应用时先挂起并等待当前编辑与保存队列，取消尚未开始的自动保存。若有未保存内容，提供 Save All、Discard Unsaved Content、Cancel；取消保持原项目与草稿，保存失败也保留会话。保存期间再次产生未保存内容时重新检查，不能保存旧捕获版后直接关闭。放弃只丢弃未保存内容；已经完成的结构写盘不反向撤销。

## 外部内容热重载

`ExternalProjectSnapshotReader` 后台读取 Graph、Raw Group、settings、本地化和受管理文本的独立候选，前后核对文件集合与字节，使用 Authoring 结构策略校验。项目级 `ProjectExternalChanges` 合并文件事件并定期复核；prepared/publishing/repair-required 事务尚未完成时不采纳中间文件。

`ProjectContentSession.ReloadExternalAsync` 在历史捕获门及发布门内重新核对候选。项目干净且无输入草稿时自动采纳；项目有本地修改时保留并报告冲突。明确放弃并重新加载会先捕获作者恢复快照，调用已注册草稿的取消方法；未能取消的组字/进行中输入仍阻止采纳。这里的作者恢复快照只包含已应用作者内容，不承诺保存所有控件原始输入；已归档 Entry 输入另有独立恢复文件。

采纳保持当前项目 scope、Graph 和既有 Group 文档身份，按稳定 ID 更新内容与视图，并同时推进 Repository 源字节、settings、受管理文本和 GUI 保存基线。旧内容 Undo/Redo 作为历史边界释放，外部修改不生成 AI 专属历史。自己的保存/结构发布推进相同基线，后续监听事件不清除其历史。跨会话回退可由 Git 完成。

首版以整个项目判断本地冲突，不做自动三方合并。契约 DLL 变化单独报告并要求重新打开项目；正在运行的游戏预览不自动重演。操作说明见[外部工具创作](../manual/external-project-authoring.md)。

## 结构计划与恢复材料

`IProjectStructureChange` 分别对 Working 与 Saved 版本应用同一结构意图，允许删除/恢复保留各自的 Group 内容。`PublishStructureAsync` 只发布变换后的保存基线，内存仍保留原有未保存字段。后续保存再撤销路径变更时，变换应用于当时的基线，不用旧整份文件覆盖刚保存的其他字段。`IProjectFileStructureChange` 可附带普通文件、目录与大小写改名计划，与 Graph/Raw Group/settings 一起发布；项目文件界面与文本缓冲已接入。项目拥有的文件描述项使用稳定会话 ID，独立保存 path、存在状态和受管理文本字节；关闭视图不删除该状态。删除项的保留字节不参与当前 dirty 比较，但仍保留于历史/恢复材料，以支持分别恢复 Working/Saved。支持矩阵与引用规则见 [项目文件操作](editor-files.md)。

作者文件事务材料位于 `.galnet/editor/transactions/<id>/`：manifest 记录路径、前后内容哈希与 prepared/publishing/committed/repair-required 状态，编号 `.old`/`.new` 文件保留备份与新内容。失败逆序恢复；恢复失败保留目录。打开项目时检查未完成计划，只在现有内容匹配记录的旧/新哈希时恢复，发现外部内容则拒绝覆盖并报告材料位置。成功材料清理失败只记录并延后清理，不将已成功发布报告为保存失败。

输入生命周期通过结构发布的同步过渡注册接入：候选 Working/Saved、验证和文件计划已准备后，过渡包装实际文件/作者发布。等待期间的输入由这个边界重新捕获，期间不再 await。Group 删除的归档失败先于文件写入；发布失败恢复原归档，恢复失败封锁项目写入。归档仍是独立恢复文件，不承诺与作者事务跨进程共同原子提交。文件操作的草稿提交上下文可声明即将移除的 Group；仅这些 Entry 输入留待归档，其他登记草稿继续原提交规则。

作者恢复快照位于 `.galnet/editor/recovery/`，包含版本、时间、载荷及 SHA-256；`ProjectRecoveryStore.Read` 验证完整性。默认有变更时每 30 秒捕获，关闭前及事务失败时也捕获；仅保留最近 3 份。历史默认 200 步，已声明的持有数据和恢复快照各按可配置 1 GiB 软预算淘汰，最新完整快照即使单份超预算仍保留。淘汰历史或截断 redo 会释放该记录自有的 disposable 资源。它不是进程堆内存硬限制，也不是跨重启历史。

删除记录为历史保留，路径复用后同一路径可以同时拥有删除身份与一个有效身份；保存期望按有效路径归并，不分别要求同一路径既存在又不存在。多个有效身份占用同一路径仍是冲突。

## 当前边界

- Graph 基本节点、连线、名称与坐标已迁移为项目数据记录；Group 生命周期接入双版本结构计划，见 [Graph 基础编辑](editor-graph.md)。分支字段、Entry 类型/条件/参数及变量声明使用显式项目意图；Preview 只编辑运行时当前值，不补记声明历史。Entry 字段与新增条目历史不持有 Workspace/Group 页面，见 [Group 编辑](editor-groups.md)。
- 已提交的 Group 作者 JSON 可在 P5e 保存重开，包括未知/不完整语义；Entry 表单中尚未转换成 JSON 的输入由项目会话保留，见下文；Timeline 关键帧行等专属工具仍使用各自的本地输入生命周期。损坏 JSON 和不安全结构不作为作者草稿写盘。
- 事务恢复可在打开时自动核对；作者快照提供材料及读取校验，尚无交互式快照还原页面。
- 原生 IME 候选输入及完整桌面人工操作未验收；已通过 Headless 实际控件的本地文本撤销、设置提交和关闭对话框验证。

## Entry 输入草稿与保存反馈

`EntryEditSession` 为项目 scope 拥有的输入会话，以 Group、Entry 稳定身份、来源代次和字段路径管理草稿。行内和 Inspector 创建各自控件，共享输入状态与现有作者提交意图。切条目、折叠、关闭面板、切语言或套用布局保留尚未提交的输入；Escape 或 Problems 中取消草稿明确丢弃它。源值、类型或列表结构改变后，旧草稿标记冲突，不写入新来源，也不因撤销而静默复活旧绑定。

项目内容变化时检查草稿来源；已经观察到的来源冲突不会因为撤销恢复了相同 JSON 而自动解除，需明确取消旧草稿后重新编辑。

Save All 经过现有草稿登记统一尝试提交；有效提交进入项目历史，不能转换、冲突或正在组合输入的草稿阻止此次写盘并保留输入。保存前已有的有效草稿提交可能已成为作者修改，保存失败不会伪装为这些修改从未发生。自动保存沿用相同规则，不弹出打断式对话框。活动控件输入仅保留在当前项目会话；Entry 作者操作归档的输入另按下面的恢复区规则持久保留，不承诺恢复所有未归档控件输入。

状态栏分别显示保存状态、待处理输入和作者检查状态；保存成功不等于可以运行。发布期间的新编辑仍为未保存内容。Problems 检查当前作者快照并复用 Graph/Group/本地化规则；不完整分析与已过期结果明确显示，普通日志不靠解析字符串猜测跳转位置。

删除/换类型/跨 Group 移动以及 Undo 新增/粘贴导致 Entry 移除时，项目输入会话在同一历史门内协调受影响输入，采用独立恢复区保存原始文本。归档不参与 dirty/Save All，明确恢复至新绑定后才成为活动输入。恢复区有独立硬预算，不因历史淘汰或 Clear 自动删除；完整规则见 [Group 输入归档](editor-groups.md#entry-输入归档与恢复)。

整 Group/文件删除及 Undo Group 创建同样进入输入归档边界，保留 Working/Saved 结构语义。活动草稿仓库只强保留未完成输入；干净字段随控件借用者释放，输入提交适配不强持有页面或 Entry ViewModel。保留未完成输入的容量取决于实际用户输入，不静默截断文字；持久归档另受明确硬预算约束。

输入归档先发布恢复文件，再执行作者步骤；步骤失败恢复旧恢复文件，复合操作后续失败还通过本次事务的逆序回滚钩子恢复草稿状态。任一输入补偿失败进入 RepairRequired，历史门在同步/异步失败路径上均释放。观察者通知仍发生于稳定提交后，不参与作者补偿。跨 Group 移动在 AuthorChangeSet.Moves 中附带实际方向的地址迁移；Undo/Redo 发布新的单调版本。
