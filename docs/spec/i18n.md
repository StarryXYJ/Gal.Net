# 国际化

## 两条边界

编辑器 UI 与游戏文本使用不同的边界。

- 编辑器 UI 使用 `IEditorLocalizationService`。它通过 DynamicLocalization 从 `GalNet.Editor/Localization` 的嵌入 JSON 资源加载 `zh-CN`、`en-US`、`ja-JP`、`ko-KR`，切换语言时通知 `CurrentCulture` 与索引器绑定。
- Avalonia Sample UI 使用 `DynamicLocalization.Core` 2.1.2 与 Sample 自有的 Avalonia 12 绑定适配层，从 Sample 程序集 `Localization/` 的嵌入 JSON 加载 `en-US` 与 `zh-CN`；`{loc:Localize ...}` 绑定读取同一 culture service。该 Sample UI 来源与游戏包 `I18n/` 内容仍是不同边界。
- Runtime 不依赖 DynamicLocalization 或某种 JSON 结构。宿主向 `GameEngine` 提供 `ITextResolver`；内置 dialogue、NVL 和分支选项在展示前调用它。未提供时使用 `PassthroughTextResolver`，即把 key 原样返回。

内置 `content` 与分支选项文本从 raw 开始就是 key；编译和复合展开原样传递。`speaker` 是人物 ID，空值表示无说话人。宿主把 `CharacterCatalog` 传给 `AddBuiltins`、`AddBuiltinImplementations` 或 `AddBuiltinDialogue`；catalog 记录唯一 `Id` 和非空 `DisplayNameKey`，内置对话先查人物再解析姓名 key，未知人物 ID 抛出内容错误。自定义参数如何本地化由 implement 决定。

## 键与稳定性

Sample UI 按 DynamicLocalization 官方 Avalonia JSON demo 绑定 `LocalizedString.Value`；这些对象自行监听 `CultureChanged` 和 `ProvidersChanged`，因此直接更改 culture 也会刷新已有绑定。Sample 使用 Avalonia 12 的 `ReflectionBinding`，并在退出时释放缓存的 `LocalizedString` 订阅。共享页面通过宿主提供的 observable text 适配获取文案。

共享 Settings 页依赖通用 `IPlayerSettingsService.Items`，按选择项与数值范围项的模板显示宿主设置，不依赖语言专用服务。Sample 注册语言和文字速度两项，变更写入当前 session 使用的 `FileVariableService`：`player.galnet.settings.locale` 与 `player.galnet.settings.textSpeed` 位于 profile 的 `player-variables.json`，不进入游戏存档。成功初始化 session 后恢复偏好；正常关闭等待已排队的保存，清空玩家数据同时删除这些偏好。首次语言选择页仍未实现。

`I18nKey` 是点分隔键的轻量封装。推荐使用稳定的 Group/Branch ID，而不是可变的显示名称：

```csharp
I18nKey.ForEntry(groupId, rawEntryId, "content");
I18nKey.ForBranchOption(branchId, optionIndex, "text");
```

条目 helper 接收 raw ID（字符串或整数），生成如 `group.group-1.entry.3.content` 的键；分支 helper 生成 `branch-1.option_0.text`。未来 Editor 在生成 key 时使用 raw 阶段的 ID；保存后的 key 不随位置重排或组合展开改变。编译前后的整数 `Entry.Id` 表示所在阶段的顺序位置，无需为本地化新增 source ID 属性。翻译文件加载与回退由宿主提供。

## 项目设置

`ProjectSettings` 保存默认语言 `TargetLocale` 与可用语言 `AvailableLocales`；`I18nLocale` 内置常用的 `zh-CN`、`zh-TW`、`en-US`、`ja-JP`、`ko-KR` 值。项目构建递归复制 `I18n/`，导出作为 `.galpak` 的特殊内容逐文件分发，不进入资源 PAK。

## 包内游戏文本加载

项目和安装内容 provider 使用相同的 `GameLocalizationLoader`，从游戏根目录读取：

```text
I18n/catalog/characters.json      人物 metadata 数组
I18n/<culture>/**/*.json          平铺或嵌套对象，叶值必须是字符串
```

人物记录如 `{"id":"guide","displayNameKey":"character.guide.name"}`。文本文件按规范化相对路径的 ordinal 顺序递归加载；catalog 与 External 子树不作为内置文本源，递归枚举不跟随 reparse point，根和 catalog 路径拒绝链接。`GameContent.Localization` 提供 catalog 和 JSON 来源描述，Core/Runtime 不引用 DynamicLocalization。

加载时验证默认语言包含所有人物姓名、编译后的内置 dialogue/NVL content 和 choice 文本 key，并拒绝未知 speaker ID。无效包内 JSON 或默认语言缺 key 拒绝内容加载；自定义 entry 参数不作本地化推断。构建器只编译/复制，此检查发生在内容加载时。

Sample 的 `GameTextResolver` 为每个文件创建独立 DynamicLocalization JSON provider，不合并文件；同 culture 内后文件覆盖前文件，独有 key 保留。查询顺序为当前语言 → 父语言链 → 游戏默认语言及其父语言 → key。Avalonia 使用同一个 CultureService 配置 UI 与游戏 resolver，切换设置影响后续展示文本，不重新翻译已有剧情历史。Headless 使用游戏默认语言。游戏来源替换不会卸载嵌入 UI provider。外置 JSON 覆盖和首次语言页尚未实现。

资源的区域变体可由 `AssetLocaleResolver` 通过宿主选择的目录规则定位；这与文本的 `ITextResolver` 相互独立。
